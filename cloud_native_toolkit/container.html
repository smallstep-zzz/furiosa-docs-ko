컨테이너 지원#

컨테이너 Runtime 지원#

우리는 뒤에 오는 콘테이너 runtimes를 지원합니다:

  • Docker: v25.0.0 또는 이후 버전

  • 포드맨

  • ContainerD: v1.7.0 또는 이후 버전

  • CRI-O: v1.28.0 또는 그 이상

참고

지원되는 컨테이너 런타임 (Docker, Podman, ContainerD, CRI-O)는 low-level 컨테이너 런타임으로 검증됩니다. runc and crun. 다른 low-level 런타임 또는 고립 기술 (와 같은) gVisor or firecracker) 아직 공식적으로 시험되지 않으며 호환성 제한이 있을지도 모릅니다.

경고

몇몇 콘테이너 runtimes는 다음과 같이 필터링하는 과태 seccomp 단면도를 이용합니다 io_uring syscalls로 인해 보안 고려 사항:

  • io_uring_setup

  • io_uring_enter

  • io_uring_register

RNGD driver는 이 syscalls에 의존합니다. 따라서 사용자는 이 syscalls를 허용하거나 unconfined seccomp 조정을 가진 콘테이너를 실행하는 관례 seccomp 단면도를 창조하고 적용합니다.

컨테이너 장치 인터페이스 지원#

컨테이너 장치 인터페이스 (CDI)는 컨테이너 런타임에 기기를 탐험하기위한 표준 인터페이스 및 사양입니다. 이 장치를 용기에 할당하고 노출하기 위해 필요한 초기 메커니즘을 제공합니다. 이 요약은 장치 관리 단순화 및 복잡한 장치 통합 세부 사항을 숨겨서 사용자 경험을 향상시킵니다.

설치 furiosa-cdi CLI#

설치하기 위해 furiosa-cdi CLI furiosa-cdi 패키지

설치를 위한 최소 요구 사항 furiosa-cdi 다음 사항이 적용됩니다:

  • Ubuntu 22.04 LTS (Debian Bookworm) 이상

  • Linux 커널 6.3 또는 이후 버전

  • 시스템의 관리자 권한 (root)

  • 패키지 저장소 설정 and 사전 설치

그런 다음, 다음을 설치하십시오. furiosa-cdi 패키지:

sudo apt update
sudo apt install -y furiosa-cdi

이 명령은 패키지를 설치합니다. furiosa-libsmi and furiosa-cdi.

CDI 사양 생성#

다음 명령은 CDI 사양 파일을 생성합니다. /etc/cdi 디렉토리는 컨테이너 runtime를 사용하여 Furiosa NPU를 CDI 리소스로 식별하고 관리합니다.

sudo furiosa-cdi generate

컨테이너 런타임 구성#

컨테이너 runtime 및 버전에 따라 CDI 기능은 구성을 통해 명시적으로 활성화되어야 할 수 있습니다. 아래의 섹션은 각 지원 runtime에 대한 CDI 구성에 대한 자세한 지침을 제공합니다.

Docker#

Docker는 현재 실험적인 특징으로 CDI를 지원합니다. Docker daemon 구성 파일을 업데이트하십시오 daemon.json CDI 기능을 활성화하고, /etc/cdi 이 cdi-spec-dirs 설정을 선택합니다. 아래는 예시입니다. daemon.json 구성:

{
  "features": {
     "cdi": true
  },
  "cdi-spec-dirs": ["/etc/cdi/", "/var/run/cdi"]
}

자세한 내용은 공식 Docker 문서 참조 CDI 장치를 활성화.

컨테이너#

ContainerD는 기본적으로 버전 2.0.0에서 시작하는 CDI를 지원합니다. 이전 버전의 경우, CDI는 구성 파일 config.toml를 통해 명시적으로 활성화해야 합니다. /etc/containerd/config.toml.

CDI 지원을 활성화하려면 다음 구성을 추가하십시오.

[plugins."io.containerd.grpc.v1.cri"]
enable_cdi = true
cdi_spec_dirs = ["/etc/cdi", "/var/run/cdi"]

구성을 수정한 후, ContainerD를 다시 시작해서 변경 사항을 적용할 수 있습니다.

sudo systemctl restart containerd

자세한 내용은 공식 ContainerD 문서 참조 CDI 지원 활성화.

CRI-O#

CRI-O는 표준 CDI 디렉토리를 사용하도록 구성된 기본으로 CDI 지원을 가능하게 합니다. /etc/cdi and /var/run/cdi.

CDI를 사용하여 컨테이너에 Furiosa NPUs 할당#

CDI 사양을 생성한 후 furiosa-cdi 목록 명령을 사용하여 NPU 리소스를 검색할 수 있습니다. 특수 항목 all 동시 할당을 위한 모든 유효한 NPUs 집계:

furiosa-cdi list
+----------------+------+
|      KIND      | NAME |
+----------------+------+
|                | npu0 |
|                | npu1 |
|                | npu2 |
|                | npu3 |
| furiosa.ai/npu | npu4 |
|                | npu5 |
|                | npu6 |
|                | npu7 |
|                | all  |
+----------------+------+

아래는 할당 예시입니다. npu0 Docker 컨테이너에 CDI를 사용하여:

docker run --security-opt seccomp=unconfined --device=furiosa.ai/npu=npu0 -it ubuntu:latest /bin/bash

여러 NPU를 할당하려면 반복하십시오. --device 선택 또는 all 항목:

# Allocating multiple NPUs
docker run --security-opt seccomp=unconfined \
  --device=furiosa.ai/npu=npu0 \
  --device=furiosa.ai/npu=npu1 \
  -it ubuntu:latest /bin/bash

# Allocating all NPUs at once
docker run --security-opt seccomp=unconfined \
  --device=furiosa.ai/npu=all \
  -it ubuntu:latest /bin/bash

컨테이너 (ctr/nerdctl) 및 CRI-O에 대한 마찬가지로, Furiosa NPU 장치를 참조하기 위해 각각의 CDI 구문을 사용합니다.

수동으로 콘테이너에 Furiosa NPUs 할당#

CDI 지원이 사용할 수 없거나 Furiosa NPU의 수동 할당이 선호되는 환경에서, 이 섹션은 수동으로 Furiosa NPU를 컨테이너로 할당하는 지침을 제공합니다.

컨테이너 내부의 Furiosa NPU를 사용하려면 해당 장치 노드가 컨테이너로 매핑되어야 합니다. 각 Furiosa 카드에는 35가 필요한 장치 노드가 있습니다. 장치 노드 경로는 아래 형식을 따르며, 여기서 {index} NPU 장치 번호를 나타냅니다 (e.g., npu0, npu1):

/dev/rngd/npu{index}ch0

아래는 디바이스 노드를 할당하는 방법의 예입니다. npu0 Docker를 사용하여 컨테이너에. 컨테이너 (ctr/nerdctl) 및 CRI-O의 경우 위의 장치 노드를 통과하고 필요한 seccomp 설정을 구성합니다.
