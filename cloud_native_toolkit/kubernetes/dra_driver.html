Furiosa DRA Driver 설치#

참고

Furiosa DRA Driver는 알파 단계에 있으며, 그 특징은 실험적이며 향후 릴리스에서 변경할 수 있습니다.

사용자는 driver가 완전히 안정되거나 feature-complete가 될 수 없다는 것을 인식하고 생산 환경에서 배포 할 때주의를 기울여야합니다.

Furiosa DRA Driver#

Furiosa DRA Driver는 구현합니다 Kubernetes DRA FuriosaAI NPU 장치를 위한 공용영역, 그리고 그것의 특징은 다음과 같이 입니다:

  • FuriosaAI NPU 기기를 발견하고 DRA 리소스로 Kubernetes 클러스터에 등록하십시오.

  • 장치의 건강을 추적하고 Kubernetes 클러스터에보고.

  • Furiosa NPU 장치의 상단에 AI 워크로드를 실행하십시오.

전제 조건#

Furiosa DRA Driver는 다음과 같은 필수품을 요구합니다:

  • Kubernetes 1.34+ 필요해요.

    • 이 경우, CDI 각 노드에서 활성화해야 합니다.

    • 시작으로 컨테이너 2.0, CDI는 기본적으로 활성화됩니다.

Helm와 Furiosa DRA Driver 배포#

Furiosa DRA Driver Helm 차트는 사용할 수 있습니다 furiosa-ai/helm-charts.

설치를 구성하려면 수정할 수 있습니다. charts/furiosa-dra-driver/values.yaml.

다음 명령을 실행하여 Furiosa DRA Driver를 배포할 수 있습니다.

helm repo add furiosa https://furiosa-ai.github.io/helm-charts
helm repo update
helm install furiosa-dra-driver furiosa/furiosa-dra-driver -n furiosa-system

DRA Driver가 성공적으로 배포되면 다음 명령을 실행하여 등록 된 FuriosaAI NPU 리소스를 볼 수 있습니다.

사용 가능한 속성#

아래 테이블 목록은 FuriosaAI NPU 장치에 대한 속성을 사용할 수 있습니다.

연결해야 합니다 npu.furiosa.ai 각 속성 키의 앞에에서 사용할 때 ResourceClaimTemplate.

  • 예외는 다음과 같습니다. resource.kubernetes.io/pcieRoot and resource.kubernetes.io/pciBusIDKubernetes에 의해 정의된 표준 특성인 .

속성

종류

설명

예제 사용#

단일 요청 NPU#

아래 예제는 Pod spec에서 단일 FuriosaAI NPU를 요청하는 방법을 보여줍니다. ResourceClaimTemplate.

먼저, ResourceClaimTemplate 단일 NPU 장치에 대한 요청을 정의합니다. 그런 다음 NPU 리소스를 주장하기 위해 템플릿을 참조하는 파드를 만듭니다.

apiVersion: resource.k8s.io/v1
kind: ResourceClaimTemplate
metadata:
 name: single-npu
spec:
 spec:
   devices:
     requests:
       - name: npu
         exactly:
           count: 1
           deviceClassName: npu.furiosa.ai

apiVersion: v1
kind: Pod
metadata:
  name: furiosa-llm
spec:
  containers:
    - name: furiosa-llm
      image: furiosaai/furiosa-llm:latest
      command:
        - sleep
        - "86400"
      env:
        - name: HF_TOKEN
          valueFrom:
            secretKeyRef:
              key: token
              name: hf-token-secret
      resources:
        claims:
          - name: npu
  resourceClaims:
    - name: npu
      resourceClaimTemplateName: single-npu
---
apiVersion: v1
kind: Secret
metadata:
  name: hf-token-secret
type: Opaque
data:
  token: <your_base64_encoded_hf_token>

동일 NUMA 노드에서 NPU 4개를 요청합니다.#

이전 예와 마찬가지로, 예를 들어, Pod spec에서 동일한 NUMA 노드에 위치한 4 FuriosaAI NPU를 요청하는 방법을 보여줍니다.

먼저, ResourceClaimTemplate 같은 NUMA 노드에서 4 FuriosaAI NPU에 대한 요청을 정의합니다. 그런 다음 NPU 리소스를 주장하는 템플릿을 참조하는 파드를 만듭니다.

apiVersion: resource.k8s.io/v1
kind: ResourceClaimTemplate
metadata:
  name: quad-npu-with-same-numa-node
spec:
  spec:
    devices:
      constraints:
        - matchAttribute: npu.furiosa.ai/numaNode
      requests:
        - name: npu
          exactly:
            count: 4
            deviceClassName: npu.furiosa.ai

apiVersion: v1
kind: Pod
metadata:
  name: furiosa-llm
spec:
  containers:
    - name: furiosa-llm
      image: furiosaai/furiosa-llm:latest
      command:
        - sleep
        - "86400"
      env:
        - name: HF_TOKEN
          valueFrom:
            secretKeyRef:
              key: token
              name: hf-token-secret
      resources:
        claims:
          - name: npu
  resourceClaims:
    - name: npu
      resourceClaimTemplateName: quad-npu-with-same-numa-node
---
apiVersion: v1
kind: Secret
metadata:
  name: hf-token-secret
type: Opaque
data:
  token: <your_base64_encoded_hf_token>
