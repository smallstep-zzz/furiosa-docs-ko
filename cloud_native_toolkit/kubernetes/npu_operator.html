Furiosa NPU 운영자 설치#

참고

Furiosa NPU 운영자는 [ ]에 있습니다. 알파 단계. 그것의 특징은 실험적이고 미래 방출에서 변화할지도 모릅니다.

운영자는 완전히 안정되거나 feature-complete가 될 수 없습니다. 생산 환경에서 배포 할 때주의를 사용합니다.

Furiosa NPU 운영자#

The Furiosa NPU 운영자 FuriosaAI Kubernetes 클러스터 내에서 NPU 장치의 배포 및 관리를 자동화하는 Kubernetes 운영자입니다. 그것은 컨테이너 작업 부하에서 FuriosaAI NPUs를 사용하는 데 필요한 드라이버 및 cloud-native 구성 요소를 배치하고 구성합니다.

관리된 구성요소#

다음 구성 요소는 Furiosa NPU 운영자에 의해 관리됩니다.

  • Furiosa 기능 탐색

  • Furiosa 장치 플러그인

  • Furiosa DRA Driver

  • Furiosa 메트릭스 내보내기

  • Furiosa 시스템 관리자

전제 조건#

Furiosa NPU 운영자는 다음과 같은 필수 조건을 요구합니다:

  • 배포 노드 기능 탐지 클러스터에서 FuriosaAI NPU 장치를 발견하는 것이 좋습니다.

    • FuriosaAI NPU 장치를 가진 노드는 상표가 있어야 합니다 feature.node.kubernetes.io/pci-1200_1ed2.present: "true".

  • Kubernetes 1.34+ Furiosa DRA Driver를 사용하려는 경우 필수입니다.

    • 이 경우, CDI 각 노드에서 활성화해야 합니다.

    • 시작으로 컨테이너 2.0, CDI는 기본적으로 활성화됩니다.

Helm와 Furiosa NPU 운영자 배포#

Furiosa NPU 운영자 Helm 차트는 다음과 같습니다. furiosa-ai/helm-charts

배포 설정을 구성하려면 다음을 수정합니다: charts/furiosa-npu-operator/values.yaml

운영자 배포:

helm repo add furiosa https://furiosa-ai.github.io/helm-charts
helm repo update
helm install furiosa-npu-operator furiosa/furiosa-npu-operator \
  -n furiosa-system --create-namespace

Furiosa NPU 운영자가 성공적으로 배포 한 후, 생성 FuriosaClusterConfig FuriosaAI NPU 장치에 대한 cloud-native 구성 요소를 관리 할 수있는 사용자 정의 리소스.

예제 사용#

아래 예시는 다음과 같이 작동합니다: FuriosaClusterConfig 관리 구성 요소를 배포하는 리소스.

apiVersion: furiosa.ai/v1alpha1
kind: FuriosaClusterConfig
metadata:
  name: example
spec:
  featureDiscovery:
    enabled: true
    registry: docker.io/furiosaai/furiosa-ai
    tag: 2026.1.0-rc0
    image: furiosa-feature-discovery
  devicePlugin:
    enabled: false
    registry: docker.io/furiosaai/furiosa-ai
    tag: 2026.1.0-rc0
    image: furiosa-device-plugin
  draDriver:
    enabled: true
    registry: docker.io/furiosaai/furiosa-ai
    tag: 2026.1.0-rc0
    image: furiosa-dra-driver
  metricsExporter:
    enabled: true
    registry: docker.io/furiosaai/furiosa-ai
    tag: 2026.1.0-rc0
    image: furiosa-metrics-exporter
    config:
      serviceType: ClusterIP
      servicePort: 6254
      enableScrapeAnnotations: true
      collectInterval: 10
  systemManager:
    enabled: true
    registry: docker.io/furiosaai/furiosa-ai
    tag: 2026.1.0-rc0
    installerImagePrefix: furiosa-system-manager-installer
    validatorImage: furiosa-system-manager-validator
    enableFirmwareInstall: false
    enableDriverInstall: true
    upgradePolicy:
      autoUpgrade: false

위와 같은 것을 만드는 것 FuriosaClusterConfig 자원은 Furiosa 기능 디스커버리, Furiosa DRA Driver, Furiosa Metrics Exporter 및 Furiosa System Manager를 배포합니다. FuriosaAI NPU가 현재 있습니다.

구성 furiosa-metrics-exporter#

설정할 수 있습니다 furiosa-metrics-exporter 이 조항의 config 아래의 필드 metricsExporter 이 부분에서 FuriosaClusterConfig.

사용할 수 있는 옵션:

  • serviceType: Kubernetes 서비스의 종류가 생성됩니다. 기본값: ClusterIP.

  • servicePort: 메트릭 수출업자가 들어갑니다. 기본값: 6254.

  • enableScrapeAnnotations: If true, Prometheus 스크랩 annotations metrics exporter Pod 를 추가한다. 기본값: true.

  • collectInterval: 메트릭이 수집되는 인터밸브(초). 기본값: 10.

배포를 위한 노드 선택#

노드가 관리된 구성 요소를 설정하여 배포할 수 있습니다. nodeSelector in FuriosaClusterConfig.

예제: 노드에서만 라벨을 배치 furiosa.ai/npu: "true":

apiVersion: furiosa.ai/v1alpha1
kind: FuriosaClusterConfig
metadata:
  name: example
spec:
  nodeSelector:
    furiosa.ai/npu: "true"
  # ... other configurations ...

여러 개의 FuriosaClusterConfig 리소스, 각 노드는 관리할 수 있습니다. one FuriosaClusterConfig.

복수의 경우 FuriosaClusterConfig 같은 노드와 일치하는 리소스는 모두 표시될 것입니다. nodeCoverageCollision 상태와 재조합은 멈추게 합니다.

관리 구성 요소에 대한 어피니티#

설정할 수 있습니다. affinity 관리되는 구성 요소에 사용되는 FuriosaClusterConfig.

  • The affinity 설정은 모든 관리 구성품에 적용됩니다.

기본 설정 affinity:

apiVersion: furiosa.ai/v1alpha1
kind: FuriosaClusterConfig
metadata:
  name: example
spec:
  affinity:
    nodeAffinity:
      requiredDuringSchedulingIgnoredDuringExecution:
        nodeSelectorTerms:
          - matchExpressions:
              - key: feature.node.kubernetes.io/pci-1200_1ed2.present
                operator: In
                values:
                  - "true"
  # ... other configurations ...

설정하지 않는 경우 affinity, 연산자는 위의 기본 구성을 적용합니다.

과장하기 affinity, 당신의 자신의 윤곽을 놓으십시오. 전적으로 affinity를, 빈 목표에 그것을 놓기 위하여:

apiVersion: furiosa.ai/v1alpha1
kind: FuriosaClusterConfig
metadata:
  name: example
spec:
  affinity: {}
  # ... other configurations ...

관리 구성품에 대한 일반적인 구성#

이러한 관리 구성 요소에 대한 일반적인 옵션을 구성할 수 있습니다:

  • featureDiscovery

  • devicePlugin

  • draDriver

  • metricsExporter

일반적인 옵션:

  • enabled: Enable/disable 구성 요소. 기본값 : false.

  • registry: 컨테이너 이미지 레지스트리. 기본값: docker.io/furiosaai.

  • image: 컨테이너 이미지 이름. 기본값은 구성 요소 (e.g., furiosa-feature-discovery).

  • tag: 컨테이너 이미지 태그. 필요해요

  • imagePullPolicy: 이미지 풀 정책. 기본값: IfNotPresent.

  • imagePullSecrets: 이미지 풀 시크릿.

  • resources: 리소스 요청 및 제한.

  • tolerations: 용납성

  • updateStrategy: 데몬셋 업데이트 전략.

Furiosa 시스템 관리자 구성#

Furiosa 시스템 관리자 구성 systemManager 부문

사용할 수 있는 옵션:

  • enabled: Enable/disable 구성 요소. 기본값 : false.

  • registry: 컨테이너 이미지 레지스트리. 기본값: docker.io/furiosaai.

  • installerImagePrefix: Installer 이미지 이름 접두사. 기본값: furiosa-system-manager-installer.

  • validatorImage: 검증 이미지 이름. 기본값: furiosa-system-manager-validator.

  • tag: 컨테이너 이미지 태그. 필요해요

  • enableDriverInstall: driver 설치가 가능합니다. 기본값: true.

  • enableFirmwareInstall: firmware 설치가 가능합니다. 기본값: false.

  • imagePullPolicy: 이미지 풀 정책. 기본값: IfNotPresent.

  • imagePullSecrets: 이미지 풀 시크릿.

  • resources: 리소스 요청 및 제한.

  • tolerations: 용납성

  • upgradePolicy: 개선 정책.

    • autoUpgrade: 자동 업그레이드 활성화. 기본값: false.

    • maxParallelUpgrades: Max 노드가 병렬로 업그레이드되었습니다. 기본값: 1.

    • maxUnavailable: 업그레이드 중 최대 사용 가능. 기본값: 25%.

중요 참고: 장치 플러그인 및 DRA Driver 사용#

FuriosaAI NPU는 장치 플러그인 또는 DRA Driver를 사용하여 관리될 수 있습니다.

그러나 동일한 노드에서 동시에 사용하는 것은 지원되지 않으며 충돌이 발생할 수 있습니다.

둘 다 활성화된 경우 FuriosaClusterConfig, 운영자는 다음을 설정합니다. invalidSpec 자원의 상태와 재건축을 중지합니다.

중요한 점: DeviceClass 부차원 자원#

DRA Driver를 활성화하는 경우: FuriosaClusterConfig, a DeviceClass 리소스는 고정 된 이름으로 만들어집니다 : npu.furiosa.ai.

예를 들어:

apiVersion: resource.k8s.io/v1
kind: DeviceClass
metadata:
  name: npu.furiosa.ai
  labels:
    app.kubernetes.io/instance: npu.furiosa.ai
    app.kubernetes.io/managed-by: furiosa-npu-operator
    app.kubernetes.io/name: furiosa-dra-driver
  ownerReferences:
    - apiVersion: furiosa.ai/v1alpha1
      kind: FuriosaClusterConfig
      name: example
      uid: 78ddc742-2c01-4201-bdca-306d8f8931d9
spec:
  selectors:
    - cel:
        expression: device.driver == 'npu.furiosa.ai'

복수의 경우 FuriosaClusterConfig 리소스는 기존의 DRA Driver를 활성화합니다. DeviceClass 는 다음 사항을 제외하고 수정되지 않습니다. metadata.ownerReferences.

두 명의 소유자를 사용하는 예시:

apiVersion: resource.k8s.io/v1
kind: DeviceClass
metadata:
  name: npu.furiosa.ai
  labels:
    app.kubernetes.io/instance: npu.furiosa.ai
    app.kubernetes.io/managed-by: furiosa-npu-operator
    app.kubernetes.io/name: furiosa-dra-driver
  ownerReferences:
    - apiVersion: furiosa.ai/v1alpha1
      kind: FuriosaClusterConfig
      name: example
      uid: 31553189-c4be-4865-be51-0f5ea29387f4
    - apiVersion: furiosa.ai/v1alpha1
      kind: FuriosaClusterConfig
      name: example2
      uid: eeecf263-5468-4b5f-b298-ad2419023009
spec:
  selectors:
    - cel:
        expression: device.driver == 'npu.furiosa.ai'
