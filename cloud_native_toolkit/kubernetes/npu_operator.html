Furiosa NPU 운영자 설치#

참고

Furiosa NPU 운영자는 알파 단계입니다. 기능은 실험적이며, 향후 릴리스에서 변경될 수 있습니다.

운영자는 완전히 안정적이지 않거나 모든 기능을 제공하지 않을 수 있습니다. 프로덕션 환경에 배포할 때는 주의하십시오.

Furiosa NPU 운영자#

Furiosa NPU 운영자는 Kubernetes 운영자로, Kubernetes 클러스터 내에서 FuriosaAI NPU 장치를 배포하고 관리하는 것을 자동화합니다. 컨테이너 기반 워크로드에서 FuriosaAI NPUs를 사용하기 위해 필요한 드라이버 및 클라우드 네이티브 구성 요소를 배포하고 구성합니다.

관리되는 구성 요소#

Furiosa NPU Operator는 다음 구성 요소를 관리합니다.

  • Furiosa Feature Discovery

  • Furiosa 장치 플러그인

  • Furiosa DRA 드라이버

  • Furiosa 메트릭스 내보내기

  • Furiosa 시스템 관리자

필수 구성 요소#

Furiosa NPU 운영자는 다음 전제 조건이 필요합니다:

  • 클러스터에 Node Feature Discovery를 배포하여 FuriosaAI NPU 장치를 검색하는 것이 권장됩니다.

    • FuriosaAI NPU 장치를 가진 노드는 상표가 있어야 합니다 feature.node.kubernetes.io/pci-1200_1ed2.present: "true".

  • Furiosa DRA 드라이버를 사용하려면 Kubernetes 1.34 이상이 필요합니다.

    • 이 경우, 각 노드에서 CDI (Container Runtime Interface)를 활성화해야 합니다.

    • containerd 2.0부터는 CDI가 기본적으로 활성화됩니다.

Helm을 사용하여 Furiosa NPU Operator 배포#

Furiosa NPU Operator Helm 차트는 다음 위치에서 사용할 수 있습니다: furiosa-ai/helm-charts

배포 설정을 위해 다음 파일을 수정합니다: charts/furiosa-npu-operator/values.yaml

Operator 배포:

helm repo add furiosa https://furiosa-ai.github.io/helm-charts
helm repo update
helm install furiosa-npu-operator furiosa/furiosa-npu-operator \
  -n furiosa-system --create-namespace

Furiosa NPU Operator가 성공적으로 배포되면, FuriosaAI NPU 장치에 대한 클라우드 네이티브 구성 요소를 관리하기 위한 FuriosaClusterConfig 사용자 정의 리소스를 생성합니다.

사용 예시#

아래 예시는 관리형 구성 요소를 배포하기 위한 FuriosaClusterConfig 리소스를 생성합니다.

apiVersion: furiosa.ai/v1alpha1
kind: FuriosaClusterConfig
metadata:
  name: example
spec:
  featureDiscovery:
    enabled: true
    registry: docker.io/furiosaai/furiosa-ai
    tag: 2026.1.0-rc0
    image: furiosa-feature-discovery
  devicePlugin:
    enabled: false
    registry: docker.io/furiosaai/furiosa-ai
    tag: 2026.1.0-rc0
    image: furiosa-device-plugin
  draDriver:
    enabled: true
    registry: docker.io/furiosaai/furiosa-ai
    tag: 2026.1.0-rc0
    image: furiosa-dra-driver
  metricsExporter:
    enabled: true
    registry: docker.io/furiosaai/furiosa-ai
    tag: 2026.1.0-rc0
    image: furiosa-metrics-exporter
    config:
      serviceType: ClusterIP
      servicePort: 6254
      enableScrapeAnnotations: true
      collectInterval: 10
  systemManager:
    enabled: true
    registry: docker.io/furiosaai/furiosa-ai
    tag: 2026.1.0-rc0
    installerImagePrefix: furiosa-system-manager-installer
    validatorImage: furiosa-system-manager-validator
    enableFirmwareInstall: false
    enableDriverInstall: true
    upgradePolicy:
      autoUpgrade: false

위 FuriosaClusterConfig 리소스를 생성하면 Furiosa Feature Discovery, Furiosa DRA Driver, Furiosa Metrics Exporter, 그리고 Furiosa System Manager가 FuriosaAI NPUs가 있는 노드에 배포됩니다.

furiosa-metrics-exporter 구성 설정#

furiosa-metrics-exporter는 FuriosaClusterConfig의 metricsExporter 섹션 내의 config 필드를 수정하여 구성할 수 있습니다.

사용 가능한 옵션:

  • serviceType: 생성할 Kubernetes Service의 유형. 기본값: ClusterIP.

  • servicePort: 메트릭스 에렉터가 수신하는 포트. 기본값: 6254.

  • enableScrapeAnnotations: true로 설정하면, 메트릭스 에렉터 Pod에 Prometheus 스크랩 어노테이션이 추가됩니다. 기본값: true.

  • collectInterval: 수집 간격 (초 단위). 기본값: 10.

배포 대상 노드 선택#

FuriosaClusterConfig의 nodeSelector 설정을 통해 관리되는 구성 요소가 배포될 노드를 지정할 수 있습니다.

예제: 노드에서만 라벨을 배치 furiosa.ai/npu: "true":

apiVersion: furiosa.ai/v1alpha1
kind: FuriosaClusterConfig
metadata:
  name: example
spec:
  nodeSelector:
    furiosa.ai/npu: "true"
  # ... other configurations ...

여러 개의 FuriosaClusterConfig 리소스를 생성할 수 있지만, 각 노드는 단 하나의 FuriosaClusterConfig만 관리할 수 있습니다.

동일한 노드에 여러 개의 FuriosaClusterConfig 리소스가 일치하는 경우, 모든 리소스에 "nodeCoverageCollision" 조건이 적용되고, 재조정이 중단됩니다.

관리되는 구성 요소에 대한 Affinity 설정#

설정할 수 있습니다. affinity 관리되는 구성 요소에 사용되는 FuriosaClusterConfig.

  • The affinity 설정은 모든 관리 구성품에 적용됩니다.

기본 affinity:

apiVersion: furiosa.ai/v1alpha1
kind: FuriosaClusterConfig
metadata:
  name: example
spec:
  affinity:
    nodeAffinity:
      requiredDuringSchedulingIgnoredDuringExecution:
        nodeSelectorTerms:
          - matchExpressions:
              - key: feature.node.kubernetes.io/pci-1200_1ed2.present
                operator: In
                values:
                  - "true"
  # ... other configurations ...

affinity를 설정하지 않으면, 운영자는 위의 기본 설정을 적용합니다.

affinity 설정을 덮어쓰려면, 사용자 정의 설정을 설정합니다. affinity를 완전히 제거하려면, 빈 객체로 설정합니다:

apiVersion: furiosa.ai/v1alpha1
kind: FuriosaClusterConfig
metadata:
  name: example
spec:
  affinity: {}
  # ... other configurations ...

관리형 구성 요소에 대한 일반 설정#

다음 관리형 구성 요소에 대한 일반 옵션을 구성할 수 있습니다:

  • featureDiscovery

  • devicePlugin

  • draDriver

  • metricsExporter

일반 옵션:

  • enabled: 구성 요소 활성화/비활성화. 기본값: false.

  • registry: 컨테이너 이미지 레지스트리. 기본값: docker.io/furiosaai.

  • image: 컨테이너 이미지 이름. 기본값은 구성 요소에 따라 달라집니다 (예: furiosa-feature-discovery).

  • tag: 컨테이너 이미지 태그. 필수.

  • imagePullPolicy: 이미지 가져오기 정책. 기본값: IfNotPresent.

  • imagePullSecrets: 이미지 가져오기 비밀.

  • resources: 리소스 요청 및 제한.

  • tolerations: 허용 목록.

  • updateStrategy: 데몬셋 업데이트 전략.

Furiosa 시스템 관리자 구성#

Furiosa 시스템 관리자 구성 systemManager 부문

사용 가능한 옵션:

  • enabled: 구성 요소 활성화/비활성화. 기본값: false.

  • registry: 컨테이너 이미지 레지스트리. 기본값: docker.io/furiosaai.

  • installerImagePrefix: 설치 이미지 이름 접두사. 기본값: furiosa-system-manager-installer.

  • validatorImage: 검증 이미지 이름. 기본값: furiosa-system-manager-validator.

  • tag: 컨테이너 이미지 태그. 필수.

  • enableDriverInstall: 드라이버 설치 활성화. 기본값: true.

  • enableFirmwareInstall: 펌웨어 설치 활성화. 기본값: false.

  • imagePullPolicy: 이미지 가져오기 정책. 기본값: IfNotPresent.

  • imagePullSecrets: 이미지 가져오기 비밀.

  • resources: 리소스 요청 및 제한.

  • tolerations: 허용 목록.

  • upgradePolicy: 업그레이드 정책.

    • autoUpgrade: 자동 업그레이드 활성화. 기본값: false.

    • maxParallelUpgrades: 병렬로 업그레이드할 최대 노드 수. 기본값: 1.

    • maxUnavailable: 업그레이드 중 최대 사용 불가 노드 비율. 기본값: 25%.

중요 참고: Device Plugin 및 DRA Driver 사용 시#

FuriosaAI NPUs는 Device Plugin 또는 DRA 드라이버를 사용하여 관리할 수 있습니다. (영어: Device Plugin 또는 DRA Driver을 사용하여 관리할 수 있습니다.)

그러나 동일한 노드에서 둘 다 동시에 사용하는 것은 지원되지 않으며, 충돌이 발생할 수 있습니다.

FuriosaClusterConfig에서 둘 다 활성화하면, 운영자는 해당 리소스에 "invalidSpec" 조건을 설정하고, 리소스 일치(reconciliation)를 중단합니다.

중요 참고: DeviceClass의 부가 리소스#

FuriosaClusterConfig에서 DRA 드라이버를 활성화하면, 고정된 이름의 DeviceClass 리소스가 생성됩니다: npu.furiosa.ai.

예시:

apiVersion: resource.k8s.io/v1
kind: DeviceClass
metadata:
  name: npu.furiosa.ai
  labels:
    app.kubernetes.io/instance: npu.furiosa.ai
    app.kubernetes.io/managed-by: furiosa-npu-operator
    app.kubernetes.io/name: furiosa-dra-driver
  ownerReferences:
    - apiVersion: furiosa.ai/v1alpha1
      kind: FuriosaClusterConfig
      name: example
      uid: 78ddc742-2c01-4201-bdca-306d8f8931d9
spec:
  selectors:
    - cel:
        expression: device.driver == 'npu.furiosa.ai'

복수의 경우 FuriosaClusterConfig 리소스는 기존의 DRA Driver를 활성화합니다. DeviceClass 는 다음 사항을 제외하고 수정되지 않습니다. metadata.ownerReferences.

두 명의 소유자를 사용하는 예시:

apiVersion: resource.k8s.io/v1
kind: DeviceClass
metadata:
  name: npu.furiosa.ai
  labels:
    app.kubernetes.io/instance: npu.furiosa.ai
    app.kubernetes.io/managed-by: furiosa-npu-operator
    app.kubernetes.io/name: furiosa-dra-driver
  ownerReferences:
    - apiVersion: furiosa.ai/v1alpha1
      kind: FuriosaClusterConfig
      name: example
      uid: 31553189-c4be-4865-be51-0f5ea29387f4
    - apiVersion: furiosa.ai/v1alpha1
      kind: FuriosaClusterConfig
      name: example2
      uid: eeecf263-5468-4b5f-b298-ad2419023009
spec:
  selectors:
    - cel:
        expression: device.driver == 'npu.furiosa.ai'
