Furiosa-LLM를 llm 방법을 사용하여 배포#

llm-d Kubernetes-native 분산 inference 프레임 워크는 클러스터 전반에 걸쳐 LLM 모델을 제공합니다. llm-d를 분산 inference 프레임 워크로 채택하면 다음과 같은 혜택을 누릴 수 있습니다.

  • 지능형 Inference 일정 관리: llm-d는 최적의 팟에 대한 요청을 제공하는 configurable Load Balancer 및 Pluggable scorers를 제공합니다. llm-d는 metrics-based scoring 및 prefix-cache-aware scorers를 제공합니다.

  • Prefill/Decode 분리: llm-d는 Prefill 및 Decode 팟을 선택하여 지정된 팟간에 KV Cache 전송을 릴레이합니다.

  • 넓은 Expert-Parallelism 설정: llm-d는 대형 Mixture-of-Experts (MoE) 모델을 배포하는 광범위한 전문 병렬화를 지원합니다.

llm와 Furiosa-LLM의 통합#

Furiosa-LLM는 RNGDs를 사용하여 LLM 모델의 배포 서빙을 지원하는 llm-d와 통합 할 수 있습니다. 현재 다음과 같은 통합이 지원됩니다.

  • 지능형 Inference 일정 관리 Furiosa-LLM는 모델 서버 프로토콜을 구현합니다 매트릭스 보고 Intelligent Inference Scheduling을 지원하기 위해. 해당 미터는 다음과 같습니다.

    모델 서버 프로토콜 메트릭#

    메트릭

    Furiosa-LLM 메트릭

    전체 요청

    furiosa_llm_num_requests_waiting

    전체수행 요청

    furiosa_llm_num_requests_running

    KVCache 사용

    furiosa_llm_kv_cache_usage_percent

    블록사이즈
    이름: furiosa_llm_cache_config_info
    라벨: block_size

    NumGPUBlocks
    이름: furiosa_llm_cache_config_info
    라벨: num_gpu_blocks

다음 통합은 현재 지원되지 않습니다 :

  • 정확한 Prefix-Cache-Aware 점수: Furiosa-LLM는 현재 KV Cache 이벤트를 구현하지 않습니다.

  • Prefill/Decode 분리: Furiosa-LLM는 현재 prefill/decode 분해를 지원하지 않습니다.

  • 넓은 Expert-Parallelism 설정: Furiosa-LLM는 현재 광범위한 전문 병렬을 지원하지 않습니다.

Furiosa-LLM를 llm 방법을 사용하여 배포#

이 섹션은 llm-d를 사용하여 Furiosa-LLM를 배포하는 방법을 설명합니다. 배포 된 llm-d는 Inference Scheduling을 활성화하여 metric-based 요청 여정을 가능하게합니다. 이 가이드는 llm-d의 기반입니다. Well-lit 경로: 지능형 Inference 스케줄링 가이드

전제 조건#

  • Kubernetes 클러스터는 두 개 이상의 Furiosa RNGD 장치를 갖추고 있습니다.

  • Hugging Face 계정 및 액세스 token.

  • 동적 볼륨 프로비저닝을 지원하는 Kubernetes 스토리지 클래스.

RNGD 클러스터 설정에 대한 자세한 지침은 참조하시기 바랍니다 사전 설치 and Kubernetes.

아래 단계에서 Gateway API 및 GIE-compatible Gateway (Istio)를 설치합니다.

llm-d-modelservice 및 Helm 저장소#

llm-d는 llm-d-modelservice Helm 차트를 제공하여 LLM 배포를 단순화합니다. RNGDs에서 Furiosa-LLM를 실행하는 차트의 포크를 제공합니다. Furiosa Helm 저장소를 지금 추가하면 단계 5에서 모델 서버를 배치할 수 있습니다.

helm repo add furiosa https://furiosa-ai.github.io/helm-charts
helm repo update

단계 1: 게이트웨이 API CRD 설정#

llm-d는 Kubernetes를 사용합니다. 게이트웨이 API Inference 확장 (GIE). CRDs가 클러스터에 설치되어야 합니다.

# Install Gateway API CRDs
kubectl apply -f \
    https://github.com/kubernetes-sigs/gateway-api/releases/download/v1.4.1/standard-install.yaml
# Install Gateway API Inference Extension CRDs
kubectl apply -f \
    https://github.com/kubernetes-sigs/gateway-api-inference-extension/releases/download/v1.3.0/manifests.yaml

단계 2: 배포 GIE-compatible 게이트웨이#

GIE-compatible 게이트웨이 목록에서 찾을 수 있습니다. 여기. 이 가이드를 위해, 우리는 GIE-compatible 게이트웨이로 Istio를 배치 할 것입니다. 기본 차트를 먼저 설치하고, GIE가 활성화 된 발견 차트 (istiod)를 설정합니다.

Istio Helm 저장소를 추가하고 istio-base를 설치하십시오:

helm repo add istio https://istio-release.storage.googleapis.com/charts
helm repo update
helm install istio-base istio/base -n istio-system \
    --set defaultRevision=default --create-namespace

GIE 지원으로 Istio discovery 차트를 설치하십시오.

istiod.yaml#
meshConfig:
  defaultConfig:
    proxyMetadata:
      ENABLE_GATEWAY_API_INFERENCE_EXTENSION: "true"
pilot:
  env:
    ENABLE_GATEWAY_API_INFERENCE_EXTENSION: "true"

helm install istiod istio/istiod -f /path/to/istiod.yaml -n istio-system --wait

단계 3: Kubernetes 비밀 준비#

우리가 사용할 것입니다 llm-d namespace to deploy llm-d with llm-d-modelservice Helm chart. Create a Kubernetes secret for your Hugging Face token:

hf-secret.yaml#
apiVersion: v1
kind: Secret
metadata:
  name: hf-token-secret
type: Opaque
data:
  HF_TOKEN: <your_base64_encoded_hf_token>

다음 명령을 사용하여 token를 인코딩하십시오.

echo -n '<your_HF_TOKEN>' | base64

그런 다음 비밀 기능을 적용합니다:

kubectl create namespace llm-d
kubectl apply -f /path/to/hf-secret.yaml -n llm-d

단계 4: 대상 LLM 모델 다운로드#

Furiosa-LLM deployed using llm-d-modelservice can utilize PVCs to pre-download Hugging Face models. In this guide, we will pre-download the furiosa-ai/Llama-3.1-8B-Instruct 모델은 Hugging Face 허브에서 설정됩니다.

모델을 저장하기 위한 PVC 생성:

model-pvc.yaml#
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: model-pvc
spec:
  accessModes:
    - ReadWriteOnce
  resources:
    requests:
      storage: 20Gi
  # The storage class "default" is an example, use an appropriate one for your cluster.
  storageClassName: default

kubectl apply -f /path/to/model-pvc.yaml -n llm-d

모델을 다운로드하는 팟을 생성합니다:

model-downloader.yaml#
apiVersion: v1
kind: Pod
metadata:
  name: model-downloader
spec:
  volumes:
    - name: model-storage
      persistentVolumeClaim:
        claimName: model-pvc

  initContainers:
    - name: download-model
      image: python:3.10-slim
      env:
        - name: HF_TOKEN
          valueFrom:
            secretKeyRef:
              name: hf-token-secret
              key: HF_TOKEN
      command:
        - /bin/bash
        - -c
        - >
          pip install --no-cache-dir huggingface_hub &&
          python -c "from huggingface_hub import snapshot_download; snapshot_download(repo_id='furiosa-ai/Llama-3.1-8B-Instruct', cache_dir='/models')"

      volumeMounts:
        - name: model-storage
          mountPath: /models

  containers:
    - name: model-consumer
      image: ubuntu
      command: ["sleep", "infinity"]
      volumeMounts:
        - name: model-storage
          mountPath: /models

  restartPolicy: Never

kubectl apply -f /path/to/model-downloader.yaml -n llm-d

진행하기 전에 완료하는 모델 다운로드를 기다립니다 (e.g. 팟 상태를 확인 kubectl get pods -n llm-d 그리고 로그 kubectl logs model-downloader -n llm-d -c download-model). pre-download에 관하여 상세한 지시를 위해 PVCs에 모형은, 참고합니다 이전 버전의 문서.

단계 5: 배포 llm-d#

먼저, 우리는 Helm 차트를 사용하여 네임스페이스에 llm-d Inference Scheduler를 배포해야 합니다. Inference Scheduler를 배포하기 전에 llm-d-infra Helm 차트를 배포해야 합니다.

llm-d-infra.yaml#
gateway:
  gatewayClassName: istio

helm repo add bitnami https://charts.bitnami.com/bitnami
helm repo add llm-d-infra https://llm-d-incubation.github.io/llm-d-infra/
helm repo update
helm install llm-d-infra llm-d-infra/llm-d-infra -n llm-d -f /path/to/llm-d-infra.yaml

그런 다음, Helm 차트를 사용하여 llm-d Inference Scheduler를 배포합니다. Furiosa-LLM의 각 모델 서버 프로토콜 메트릭에 플래그를 설정하여 metric-based 요청 라우팅을 가능하게합니다.

inference-scheduler.yaml#
inferenceExtension:
  replicas: 1
  flags:
    cache-info-metric: "furiosa_llm_cache_config_info"
    kv-cache-usage-percentage-metric: "furiosa_llm_kv_cache_usage_percent"
    lora-info-metric: ""
    total-queued-requests-metric: "furiosa_llm_num_requests_waiting"
    total-running-requests-metric: "furiosa_llm_num_requests_running"
  image:
    name: llm-d-inference-scheduler
    hub: ghcr.io/llm-d
    tag: v0.5.0
    pullPolicy: Always
  extProcPort: 9002
  pluginsConfigFile: "default-plugins.yaml"
  monitoring:
    interval: "10s"
    # Prometheus ServiceMonitor will be created when enabled for EPP metrics collection
    secret:
      name: inference-scheduling-gateway-sa-metrics-reader-secret
    prometheus:
      enabled: true
      auth:
        # To allow unauthenticated /metrics access (e.g., for debugging with curl), set to false
        enabled: true
inferencePool:
  targetPorts:
    - number: 8000
  modelServerType: vllm
  modelServers:
    matchLabels:
      llm-d.ai/inferenceServing: "true"
provider:
  name: istio
  istio:
    destinationRule:
      host: "gaie-epp.llm-d.svc.cluster.local"

helm install gaie \
    oci://registry.k8s.io/gateway-api-inference-extension/charts/inferencepool \
    --version v1.3.0 \
    -n llm-d \
    -f /path/to/inference-scheduler.yaml

llm-d의 Inference Scheduler는 GIE의 InferencePool helm 차트를 사용하여 배포됩니다. 배포를 사용자 정의하는 방법에 대한 자세한 내용은 참조하시기 바랍니다 InferencePool Helm 차트 문서.

마지막으로 Furiosa-LLM 모델 서버를 실행하기 위해 llm-d-modelservice Helm 차트를 배포합니다.

llm-d-modelservice.yaml#
multinode: false

modelArtifacts:
  name: "furiosa-ai/Llama-3.1-8B-Instruct"
  uri: "pvc+hf://model-pvc/furiosa-ai/Llama-3.1-8B-Instruct"
  size: 20Gi
  authSecretName: "hf-token-secret"
  labels:
    llm-d.ai/inferenceServing: "true"
    llm-d.ai/model: "Llama-3.1-8B-Instruct"

accelerator:
  type: "furiosa"

routing:
  proxy:
    enabled: false
    targetPort: 8000

prefill:
  create: false

decode:
  parallelism:
    tensor: 8
  replicas: 2
  containers:
    - name: "furiosa-llm"
      image: furiosaai/furiosa-llm:latest
      modelCommand: furiosaLLMServe
      args:
        - --enable-prefix-caching
        - --disable-uvicorn-access-log
      ports:
        - containerPort: 8000
          name: furiosa-llm
          protocol: TCP
      mountModelVolume: true
      startupProbe:
        httpGet:
          path: /v1/models
          port: furiosa-llm
        initialDelaySeconds: 15
        periodSeconds: 30
        timeoutSeconds: 5
        failureThreshold: 60
      livenessProbe:
        httpGet:
          path: /health
          port: furiosa-llm
        periodSeconds: 10
        timeoutSeconds: 5
        failureThreshold: 3
      readinessProbe:
        httpGet:
          path: /v1/models
          port: furiosa-llm
        periodSeconds: 5
        timeoutSeconds: 2
        failureThreshold: 3

helm install ms furiosa/llm-d-modelservice -n llm-d -f /path/to/llm-d-modelservice.yaml

llm-d-modelservice Helm 차트는 위의 예에서 보여지는 것보다 다른 구성 손잡이를 제공합니다. 참고하십시오. llm-d-modelservice Helm 차트 문서 세부사항을 알려주세요.

단계 6: HTTPRoute로 서비스를 노출#

inference 요청이 llm-d Inference Scheduler로 전달되는 HTTPRoute를 만듭니다.

httproute.yaml#
apiVersion: gateway.networking.k8s.io/v1
kind: HTTPRoute
metadata:
  name: llm-d
spec:
  parentRefs:
    - group: gateway.networking.k8s.io
      kind: Gateway
      name: llm-d-infra-inference-gateway
  rules:
    - backendRefs:
        - group: inference.networking.k8s.io
          kind: InferencePool
          name: gaie
          port: 8000
          weight: 1
      timeouts:
        backendRequest: 0s
        request: 0s
      matches:
        - path:
            type: PathPrefix
            value: /

kubectl apply -f /path/to/httproute.yaml -n llm-d

경로가 적용되면 게이트웨이 주소 (e.g)에 inference 요청을 보낼 수 있습니다. Istio 진입을 통해). 게이트웨이 URL를 얻는 방법에 대한 자세한 내용은 API로 전화하여 llm-d를 참조하십시오. Inference llm에 대한 가이드
