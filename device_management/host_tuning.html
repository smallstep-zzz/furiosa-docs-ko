호스트 PCI 최적화 튜닝#

이 문서는 PCIe/DMA/P2P 성능을 향상시키고 Linux 서버에서 latency 변동을 줄이는 데 일반적으로 사용되는 호스트 레벨 튜닝 단계를 설명합니다.

1. 대용량 구성#

할당 64K (65536) 용량의 2MB 크기의 큰 페이지.

거대한 페이지 (i.e., "HugeTLB" 페이지)는 더 큰 페이지 크기를 사용하여 TLB 압력과 page-table 도보 오버 헤드를 감소시킵니다. 종종 큰 메모리 영역 (e.g., DMA 버퍼, 패킷 버퍼, 큰 핀 할당)를 접촉하는 워크로드의 경우 :

  • CPU 오버헤드를 주소 번역에서 감소 (fewer TLB misses)

  • 페이지 관리 오버헤드를 감소시켜 latency 안정성을 향상

  • 큰 윤곽선을 위한 파편 문제점을 감소시키십시오 (이전에 할당된 때)

One-time 설정#

즉시 적용 (Reboot까지 유효):

echo 65536 | sudo tee /sys/kernel/mm/hugepages/hugepages-2048kB/nr_hugepages

노트#

  • 이것은 2MB HugeTLB 페이지의 수를 조정합니다.

  • KV Cache offloading와 관련된 추가 캐싱 최적화를 사용할 때, 이 번호를 증가하는 것은 할당 된 host-side KV cache 풀의 크기에 따라 핀 DMA 버퍼에 대한 충분한 거 대 한 페이지 가용성을 보장 할 필요가 있을 수 있습니다. 참조 계층적 Prefix Caching 구성 및 sizing 지침에 대 한.

  • 할당은 실패 할 수 있습니다 (partially 또는 완전히) 메모리가 파편되면; 부팅 후 일찍 적용은 일반적으로 가장 잘 작동합니다.

지속적인 설정 (부팅 시마다)#

sysctl 규칙을 만들기 때문에 부팅에 적용됩니다 :

sudo tee /etc/sysctl.d/90-hugepages.conf <<EOF
vm.nr_hugepages = 65536
EOF

그런 다음 재부팅없이 즉시 적용하십시오.

sudo sysctl --system

2. PCI ACS (액세서리 제어 서비스)를 비활성화#

언제 사용해야 할까요?#

특정 시스템 (e.g 등에서) NXT RNGD 서버), 장치는 PCIe 스위치 뒤에 연결됩니다. peer-to-peer (P2P) 자료 경로가 예상되는 경우에, PCI ACS 상류 스위치 포트에 활성화는 P2P 트래픽을 방지하거나 penalize 할 수 있습니다.

예를 들어:

  • 장치는 PCIe 스위치, 및 P2P throughput/latency 사정의 밑에 있습니다.

ACS가 P2P 성능에 미치는 영향#

ACS는 security/isolation 및 topology 교정 시스템에서 security/isolation 및 topology 교정을 개선하는 고립과 라우팅 제어 기능을 제공합니다. 그러나 ACS가 리디렉션을 실행할 때, 전환 직물 내에서 오히려 루트 복잡하게 (근법적 복잡한)을 경로를 강제 할 수 있습니다. 이것은 할 수 있습니다 :

  • 홉 수/지연 증가

  • 효과적인 대역폭 감소

  • 업스트림 링크에 대한 경쟁을 추가

  • 동일한 스위치의 밑에 endpoints 사이 가장 직접적인 P2P 경로 방지

ACS를 비활성화하면 스위치 내에서 더 직접 라우팅을 허용함으로써 P2P 성능을 향상시킬 수 있습니다.

경고

ACS가 엔드포인트 사이의 고립을 감소시키고 multi-tenant / 엄격한 보안 환경에서 허용되지 않을 수 있습니다. 플랫폼과 use-case tolerate가 PCIe 고립을 줄 때만 적용하십시오.

지원된 서버 및 PCIe 스위치 조합#

다음 표 문서는 ACS가 검증되고 지원되는 서버 구성을 공식적으로 지원했습니다.

서버 플랫폼

PCIe 스위치

판매자 / 장치 ID

ACS 컨트롤 오프셋

NXT RNGD 서버 (Supermicro)

Broadcom / LSI PEX890xx PCIe Gen 5 스위치 (rev b0)

0x1000 / 0xc030

0x176

위의 구성을 위해 ACS는 비활성화되어 있습니다. RNGD 장치에 연결된 PCIe 스위치 다운스트림 포트 스위치 직물 안에 최적의 PCIe P2P 트래픽을 허용하기 위해.

다음 명령을 실행하십시오:

sudo setpci -s ${PARENT_BDF} ${ACS_OFFSET}.W=0x0

  • ${PARENT_BDF} RNGD 장치 (e.g)에 직접 연결된 PCIe 스위치 포트의 BDF입니다., 0000:02:03.0).

lspci -D -d 1ed2: -PP | head -n 1

0000:00:01.1/01:00.0/02:03.0/06:00.0 Processing accelerators: FuriosaAI, Inc. Device 0001 (rev 01)

lspci -D -s 0000:02:03.0 -nn

0000:02:03.0 PCI bridge [0604]: Broadcom / LSI PEX890xx PCIe Gen 5 Switch [1000:c030] (rev b0)

결과 확인#

실행:

lspci -vv -s ${PARENT_BDF}

비활성화 후, 다음과 같은 플래그를 관찰해야합니다:

Capabilities: [170 v1] Access Control Services
        ACSCap: SrcValid+ TransBlk+ ReqRedir+ CmpltRedir+ UpstreamFwd+ EgressCtrl- DirectTrans+
        ACSCtl: SrcValid- TransBlk- ReqRedir- CmpltRedir- UpstreamFwd- EgressCtrl- DirectTrans-

해당 ACS 컨트롤 비트가 명확하게 표시한다.

Auto-apply udev 규칙과 함께 사용#

기기(포트)가 열릴 때 ACS를 자동으로 적용할 수 있는 udev 규칙을 사용할 수 있습니다. 다음 스니펫은 템플릿을 제공합니다. 해당 키(vendor/device, BDF, 또는 driver)를 조정하여 환경의 영향을 받습니다.

규칙 파일 (예: 규칙 파일 생성) /etc/udev/rules.d/99-furiosa.rules:

# Disable ACS on a specific upstream PCIe port to improve P2P performance.
SUBSYSTEM=="rngd_mgmt", ATTR{device_type}=="RNGD", ACTION=="add", ENV{BUSNAME}="$attr{busname}", RUN+="/usr/local/sbin/furiosa-acs-clear"

다음과 같은 스크립트 파일을 생성합니다: /usr/local/sbin/furiosa-acs-clear:

#!/usr/bin/env bash
set -euo pipefail

if [[ -z "${BUSNAME:-}" ]]; then
  echo "Error: BUSNAME is not set" >&2
  exit 1
fi

DEVICE_ROOT="/sys/bus/pci/devices"
DEVICE_PATH="${DEVICE_ROOT}/${BUSNAME}"
if [[ ! -e "$DEVICE_PATH" ]]; then
  echo "Error: PCI device not found: ${DEVICE_PATH}" >&2
  exit 2
fi

READLINK=$(readlink ${DEVICE_PATH} 2>/dev/null)
if [ -z "$READLINK" ]; then
  echo "Error: Unable to read link for ${DEVICE_PATH}"
  exit 3
fi

PARENT_BDF=$(basename $(dirname $READLINK))
PARENT_PATH="${DEVICE_ROOT}/${PARENT_BDF}"
if [[ ! -e "${PARENT_PATH}" ]]; then
  echo "Error: Parent device not found: ${PARENT_PATH}" >&2
  exit 4
fi

if [[ ! -r "${PARENT_PATH}/vendor" || ! -r "${PARENT_PATH}/device" ]]; then
  echo "Error: Cannot read vendor/device IDs for ${PARENT_BDF}" >&2
  exit 5
fi

VENDOR_ID=$(cat ${PARENT_PATH}/vendor)
DEVICE_ID=$(cat ${PARENT_PATH}/device)

if [[ "${VENDOR_ID,,}" != "0x1000" ]]; then
  echo "Error: Parent device ${PARENT_BDF} vendor_id is '${VENDOR_ID}', expected '0x1000'" >&2
  exit 6
fi

if [[ "${DEVICE_ID,,}" != "0xc030" ]]; then
  echo "Error: Parent device ${PARENT_BDF} device_id is '${DEVICE_ID}', expected '0xc030'" >&2
  exit 6
fi

ACS_OFFSET="0x176"
CURRENT_ACS=$(setpci -s ${PARENT_BDF} ${ACS_OFFSET}.W)

if [[ -z "${CURRENT_ACS}" ]]; then
  echo "Error: Failed to read ACS register on ${PARENT_BDF}" >&2
  exit 7
fi

if [[ "${CURRENT_ACS}" == "0000" ]]; then
  echo "already set on ${PARENT_BDF}"
else
  setpci -s ${PARENT_BDF} ${ACS_OFFSET}.W=0x0
  echo "ACS clear for ${PARENT_BDF} completed"
fi

3. tuned-adm: latency-기능 단면도#

개요#

The tuned daemon은 사전 정의된 시스템 조정 프로파일을 제공합니다. latency-performance 일반적으로 latency를 낮추고 CPU 지배자, 동력 관리, 커널 scheduler-related 설정 및 기타 시스템 손잡이를 조정하여 지터를 감소시킵니다.

정렬 설치#

sudo apt update
sudo apt install -y tuned
sudo systemctl enable --now tuned

latency-performance에 프로필을 설정#

sudo tuned-adm profile latency-performance

활성 프로필 확인:

sudo tuned-adm active

예상되는 효과#

널리 발생하는 결과 (사용 시) latency-performance 다음을 포함합니다.

  • 짐의 밑에 낮은 latency variance (감축한 지터)

  • 더 일관된 CPU 주파수 행동 (힘 절약에 호의를 베푸는 성과)

  • 공격적인 힘 관리 국가에서 감소된 충격

  • latency 민감하는 PCIe/DMA-driven 작업 부하를 위한 더 나은 꼬리 latency

참고

정확한 변경은 배포 및 조정 버전에 달려 있습니다. 아래에서 조정 된 프로필 내용을 검토 /usr/lib/tuned/latency-performance/ 적용된 손잡이의 정확한 목록이 필요한 경우.
