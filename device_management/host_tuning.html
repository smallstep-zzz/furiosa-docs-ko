호스트 레벨 PCI 최적화 튜닝#

이 문서는 Linux 서버에서 PCIe/DMA/P2P 성능을 개선하고, 특히 지연 시간 변동을 줄이기 위해 일반적으로 사용되는 호스트 레벨 튜닝 단계를 설명합니다.

1. Hugepage 구성#

2MB 크기의 큰 페이지(hugepage) 64K (65536)를 할당합니다.

큰 페이지(즉, "HugeTLB" 페이지)는 더 큰 페이지 크기를 사용하여 TLB 압력을 줄이고 페이지 테이블 탐색 오버헤드를 줄입니다. DMA 버퍼, 패킷 버퍼, 큰 고정 할당과 같이 자주 큰 메모리 영역에 접근하는 워크로드의 경우, 큰 페이지는 다음과 같은 이점을 제공할 수 있습니다:

  • 주소 번역(fewer TLB misses)에서 발생하는 CPU 오버헤드를 줄입니다.

  • 페이지 관리 오버헤드를 줄여 지연 시간 안정성을 향상시킵니다.

  • (초기 할당 시) 큰 연속적인 할당에 대한 분할 문제를 줄입니다.

단일 설정#

즉시 적용 (재부팅 시까지 유효):

echo 65536 | sudo tee /sys/kernel/mm/hugepages/hugepages-2048kB/nr_hugepages

참고 사항#

  • 이는 2MB의 HugeTLB 페이지 수를 조정합니다.

  • KV Cache를 활용한 추가적인 캐싱 최적화 시, 특히 고정된 DMA 버퍼에 충분한 HugePage가 확보되도록 하려면, 할당된 호스트 측 KV Cache 풀의 크기에 따라 이 값을 늘리는 것이 필요할 수 있습니다. Hierarchical Prefix Caching에서 구성 및 크기 지침을 참조하십시오.

  • 메모리가 분할되어 있는 경우 할당이 부분적으로 또는 완전히 실패할 수 있습니다. 부팅 후 즉시 적용하는 것이 가장 좋습니다.

영구 설정 (부팅 시마다 적용)#

부팅 시 적용되도록 sysctl 규칙을 생성합니다:

sudo tee /etc/sysctl.d/90-hugepages.conf <<EOF
vm.nr_hugepages = 65536
EOF

재부팅 없이 즉시 적용합니다:

sudo sysctl --system

2. PCI ACS (액세스 제어 서비스) 비활성화#

이 기능을 사용할 경우#

특정 시스템 (예: NXT RNGD 서버)에서는 장치가 PCIe 스위치를 통해 연결됩니다. P2P (Peer-to-Peer) 데이터 경로가 예상되는 경우, 업스트림 스위치 포트에서 PCI ACS를 활성화하면 P2P 트래픽을 방지하거나 제한할 수 있습니다.

예시 시나리오:

  • 장치가 PCIe 스위치 아래에 위치하며, P2P 대역폭/지연 시간이 중요합니다.

ACS가 P2P 성능에 미치는 영향#

ACS는 (요청/완료 재지정, 상류 포워딩 제어 등) 보안/격리 및 복잡한 시스템의 토폴로지 정확성을 향상시키는 기능(요청/완료 재지정, 상류 포워딩 제어)을 제공합니다. 그러나 ACS가 재지정을 강제하면 트랜잭션이 스위치 �브릭 내에서 유지되는 대신 상류(루트 복합으로)로 라우팅될 수 있습니다. 이는 다음과 같은 결과를 초래할 수 있습니다:

  • 홉 수/지연 시간 증가

  • 효과적인 대역폭 감소

  • 상류 링크에서의 경쟁 증가

  • 동일 스위치 내 엔드포인트 간의 가장 직접적인 P2P 경로를 차단합니다 (Direct P2P path between endpoints under the same switch).

ACS 비활성화는 스위치 내에서 더 직접적인 경로를 허용하여 P2P 성능을 향상시킬 수 있습니다 (Disabling ACS can therefore improve P2P performance by allowing more direct routing within the switch).

경고

ACS 비활성화는 엔드포인트 간의 격리를 줄일 수 있으며, 다중 테넌트/엄격한 보안 환경에서는 허용되지 않을 수 있습니다. PCIe 격리 감소를 허용하는 플랫폼 및 사용 사례에만 적용하십시오 (Disabling ACS reduces isolation between endpoints and may not be acceptable in multi-tenant / strict security environments. Apply only when your platform and use-case tolerate reduced PCIe isolation).

지원되는 서버 및 PCIe 스위치 조합#

다음 표는 ACS 비활성화가 검증되고 지원되는 공식적으로 지원되는 서버 구성에 대한 정보를 제공합니다 (The following table documents officially supported server configurations where ACS disable is validated and supported).

서버 플랫폼 (Server Platform)

PCIe 스위치

공급업체 / 장치 ID

ACS 제어 오프셋

NXT RNGD 서버 (Supermicro)

Broadcom / LSI PEX890xx PCIe Gen 5 스위치 (rev b0)

0x1000 / 0xc030

0x176

위 구성에 따라, ACS는 RNGD 장치에 연결된 PCIe 스위치의 다운스트림 포트에서 비활성화됩니다. 이는 스위치 내에서 최적의 PCIe P2P 트래픽을 허용하기 위함입니다. (ACS: Adaptive Carrier Sensing)

다음 명령을 실행하십시오:

sudo setpci -s ${PARENT_BDF} ${ACS_OFFSET}.W=0x0

  • ${PARENT_BDF}는 RNGD 장치에 직접 연결된 PCIe 스위치 포트의 BDF입니다 (예: 0000:02:03.0).

lspci -D -d 1ed2: -PP | head -n 1

0000:00:01.1/01:00.0/02:03.0/06:00.0 Processing accelerators: FuriosaAI, Inc. Device 0001 (rev 01)

lspci -D -s 0000:02:03.0 -nn

0000:02:03.0 PCI bridge [0604]: Broadcom / LSI PEX890xx PCIe Gen 5 Switch [1000:c030] (rev b0)

결과를 확인하십시오.#

다음을 실행하십시오:

lspci -vv -s ${PARENT_BDF}

비활성화 후, 다음과 같은 플래그를 확인해야 합니다:

Capabilities: [170 v1] Access Control Services
        ACSCap: SrcValid+ TransBlk+ ReqRedir+ CmpltRedir+ UpstreamFwd+ EgressCtrl- DirectTrans+
        ACSCtl: SrcValid- TransBlk- ReqRedir- CmpltRedir- UpstreamFwd- EgressCtrl- DirectTrans-

이는 해당 ACS 제어 비트가 지워진다는 것을 의미합니다.

udev 규칙을 사용하여 자동 적용#

udev 규칙을 사용하여 장치(포트)가 인식될 때 ACS를 자동으로 비활성화할 수 있습니다. 다음 스니펫은 템플릿을 제공합니다. 환경에 맞게 일치하는 키(vendor/device, BDF, 또는 드라이버)를 조정하십시오.

다음과 같은 규칙 파일을 생성합니다 (예: /etc/udev/rules.d/99-furiosa.rules):

# Disable ACS on a specific upstream PCIe port to improve P2P performance.
SUBSYSTEM=="rngd_mgmt", ATTR{device_type}=="RNGD", ACTION=="add", ENV{BUSNAME}="$attr{busname}", RUN+="/usr/local/sbin/furiosa-acs-clear"

다음과 같은 스크립트 파일을 생성합니다 (예: /usr/local/sbin/furiosa-acs-clear):

#!/usr/bin/env bash
set -euo pipefail

if [[ -z "${BUSNAME:-}" ]]; then
  echo "Error: BUSNAME is not set" >&2
  exit 1
fi

DEVICE_ROOT="/sys/bus/pci/devices"
DEVICE_PATH="${DEVICE_ROOT}/${BUSNAME}"
if [[ ! -e "$DEVICE_PATH" ]]; then
  echo "Error: PCI device not found: ${DEVICE_PATH}" >&2
  exit 2
fi

READLINK=$(readlink ${DEVICE_PATH} 2>/dev/null)
if [ -z "$READLINK" ]; then
  echo "Error: Unable to read link for ${DEVICE_PATH}"
  exit 3
fi

PARENT_BDF=$(basename $(dirname $READLINK))
PARENT_PATH="${DEVICE_ROOT}/${PARENT_BDF}"
if [[ ! -e "${PARENT_PATH}" ]]; then
  echo "Error: Parent device not found: ${PARENT_PATH}" >&2
  exit 4
fi

if [[ ! -r "${PARENT_PATH}/vendor" || ! -r "${PARENT_PATH}/device" ]]; then
  echo "Error: Cannot read vendor/device IDs for ${PARENT_BDF}" >&2
  exit 5
fi

VENDOR_ID=$(cat ${PARENT_PATH}/vendor)
DEVICE_ID=$(cat ${PARENT_PATH}/device)

if [[ "${VENDOR_ID,,}" != "0x1000" ]]; then
  echo "Error: Parent device ${PARENT_BDF} vendor_id is '${VENDOR_ID}', expected '0x1000'" >&2
  exit 6
fi

if [[ "${DEVICE_ID,,}" != "0xc030" ]]; then
  echo "Error: Parent device ${PARENT_BDF} device_id is '${DEVICE_ID}', expected '0xc030'" >&2
  exit 6
fi

ACS_OFFSET="0x176"
CURRENT_ACS=$(setpci -s ${PARENT_BDF} ${ACS_OFFSET}.W)

if [[ -z "${CURRENT_ACS}" ]]; then
  echo "Error: Failed to read ACS register on ${PARENT_BDF}" >&2
  exit 7
fi

if [[ "${CURRENT_ACS}" == "0000" ]]; then
  echo "already set on ${PARENT_BDF}"
else
  setpci -s ${PARENT_BDF} ${ACS_OFFSET}.W=0x0
  echo "ACS clear for ${PARENT_BDF} completed"
fi

3. tuned-adm: latency-performance 프로필#

개요#

The tuned daemon은 사전 정의된 시스템 조정 프로파일을 제공합니다. latency-performance 일반적으로 latency를 낮추고 CPU 지배자, 동력 관리, 커널 scheduler-related 설정 및 기타 시스템 손잡이를 조정하여 지터를 감소시킵니다.

tuned 설치#

sudo apt update
sudo apt install -y tuned
sudo systemctl enable --now tuned

프로필을 "latency-performance"로 설정#

sudo tuned-adm profile latency-performance

활성 프로필 확인:

sudo tuned-adm active

예상되는 효과#

"latency-performance" 프로필을 사용할 때 나타나는 일반적인 결과는 다음과 같습니다:

  • 부하 시 더 낮은 변동성 (낮은 지터)

  • 더 일관된 CPU 주파수 동작 (일반적으로 성능을 우선시하며, 전력 절약을 덜 중요하게 함)

  • 공격적인 전력 관리 상태의 영향 감소

  • 특히 지터에 민감한 PCIe/DMA 기반 워크로드에 대한 더 나은 꼬리 지터

참고

정확한 변경 사항은 배포 및 튜닝된 버전에 따라 다릅니다. 정확한 목록을 확인하려면 /usr/lib/tuned/latency-performance/ 아래의 튜닝된 프로파일 내용을 참조하십시오.
