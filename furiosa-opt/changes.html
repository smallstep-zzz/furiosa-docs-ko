변경 이력(Changelog)

이 파일은 furiosa-opt의 주요 변경 사항(notable changes)을 기록합니다.

형식은 Keep a Changelog 1.1.0을 따릅니다.

[미출시(Unreleased)]

[v0.10.0]

변경(Changed)

  • Device::new는 Topology 또는 Placement를 받습니다. 전자를 주면 그 형태에 맞는 첫 번째 빈 배치(placement)를 열고, 후자를 주면 지정한 위치를 정확히 엽니다. 열린 구성은 device.placement(), device.topology()로 확인합니다. CPU에서는 칩(chip) 수 1~8개, 칩당 PE 수 1~8개를 벗어나는 토폴로지(topology)를 거부합니다.
  • Kernel<F>가 Kernel<F, Args>로 바뀝니다. 커널(kernel)은 적재(load)할 때 정한 인수(arguments)로만 실행할 수 있으며, 다른 인수는 컴파일 오류(compile error)가 됩니다.
  • 직접 작성한 DeviceSend는 bind(&self, buffers) 대신 arguments(&self, access, bind)를 구현하며, 각 (HbmBufferSlice, Access)를 선언 순서(declaration order)대로 bind에 넘깁니다. #[derive(DeviceSend)]는 수정할 필요가 없습니다.
  • HbmTensor::new()는 장치 함수(device function)용입니다. 호스트 측 텐서(host-side tensor)는 HbmTensor::alloc(&device)로 할당하세요.
  • HbmBuffer::alloc과 HbmTensor::alloc은 칩 로컬 DRAM(chip-local DRAM)에 할당합니다. 다른 칩(chip)이 쓰는 버퍼(buffer)는 HbmBuffer::alloc_shared로 만들어야 합니다. 다른 칩이 쓰는 인수(peer-written argument)에 칩 로컬 메모리를 바인딩(binding)하면 거부합니다.
  • Device::memory()는 두 백엔드(backend) 모두에서 capacity(), usage()를 제공하는 Memory를 반환합니다. 기존 코드는 memory().usage().available을 사용하도록 변경하세요.
  • scalar.write(value, dma) 대신 HbmScalar::from_host(value, dma).output(&mut scalar)를 사용하세요.
  • 프렐루드(prelude)는 런타임 API(runtime API)만 내보냅니다. 내부 연결용 타입(plumbing type)은 furiosa_opt_std::runtime 또는 furiosa_opt_std::backend에서 가져오세요.
  • HBM 뷰(view)의 chip_tile은 HbmTensorView<.., SomeChips>를 반환합니다. 장치 DMA(device DMA)는 이를 받지만, 커널 실행(launch)에 전달하면 컴파일 시 거부합니다.
  • main 문맥(context)의 to_trf는 sub 문맥을 받습니다. to_vrf처럼 .to_trf(&mut device.sub)로 작성하세요.
  • 텐서 유닛(Tensor Unit)의 수축 단계(contraction stage)와 commit_cast / commit_cast_relu는 main 문맥(context)에만, commit_valid_count_pack은 sub 문맥에만 존재합니다. 다른 문맥에서 호출하면 컴파일 오류(compile error)입니다.
  • 반복문 전에 선언한 스칼라(scalar)에 값을 다시 대입하는 for 반복문(loop)은 cannot carry a scalar across iterations 오류로 거부합니다. 반복 사이에 유지할 값은 텐서(tensor)에 담으세요.
  • PaddingKind::Bottom(#{!}) 패딩(padding)은 임의의 값(arbitrary value)을 담으며 읽을 수 있습니다.
  • 제출(submit)한 실행(launch)은 Future를 버려도 끝까지 진행합니다. 그 메모리는 장치(device)가 작업을 마칠 때까지 사용 중으로 유지됩니다.
  • 장치 작업(device task)이 패닉(panic)을 일으키면, 그 실행(launch)을 기다리는 코드도 작업의 메시지와 함께 패닉을 일으킵니다. CPU 동작과 같습니다.
  • 실행(launch)은 종전의 5초 대신 커널 드라이버(kernel driver)의 마감 시간(deadline, pe_ipc_timeout_ms, 기본 60 s) 1초 전까지 진행할 수 있습니다. 이를 넘으면 Error::Device로 실패합니다.
  • 호스트(host) 또는 다른 칩(peer)의 메모리를 이동하는 장치 코드(device code)에는 PDMA 채널(channel)을 예약하는 커널 드라이버(kernel driver, NPU_PDMA_CAPS_RESERVE)가 필요합니다. 그러한 드라이버가 없으면 실행(launch)은 DeviceError::Unsupported로 실패합니다.
  • DeviceError는 실패한 단계(stage) 대신 실패 원인을 나타냅니다. 예: Busy, Capacity, Invalid, Unsupported, Panicked, OutOfMemory, SramOverlap, ...
  • 함수의 프로파일(profile)은 처음 적재(load)할 때 정해집니다. 처음 실행(launch)하기 전에 FURIOSA_OPT_PROFILE을 설정하고 span::npu 구독자(subscriber)를 설치하세요.
  • cargo furiosa-opt가 새 이미지 형식(image format)을 생성합니다. 이 릴리스(release)로 프로그램을 다시 컴파일하세요.

추가(Added)

  • HbmBuffer::alloc(&device, bytes)는 타입 없는 메모리(untyped memory)를 할당하며, to_hbm / to_host로 전송합니다. HbmTensor::try_from(buffer)와 into_buffer는 복사 없이 변환하고, split_at은 분할하며, alias는 공유합니다. buffer.slice(chips, bytes) / slice_mut는 칩(chip)과 바이트 범위(byte range)를 선택합니다.
  • HostBuffer는 전송할 바이트(transfer byte)를 보유하며, 지원되는 환경에서는 페이지 고정(page-locked) 메모리를 사용합니다(is_pinned()). HostTensor와는 복사 없이 양방향 변환합니다.
  • 실행(launch)과 전송(transfer)은 .await 또는 .submit() 전까지 Prepared 상태입니다. 이 호출이 작업을 시작하고 Submitted Future를 반환합니다.
  • HbmBuffer::ready(), HbmTensor::ready(), Device::synchronize()는 복사 없이 앞선 장치 작업(device work)이 끝나기를 기다립니다.
  • device.pdma.to_hbm(pairs)는 여러 항목(batch)을 한 번의 쓰기로 기존 HBM 슬라이스(slice)에 복사합니다.
  • function.load(&device)?는 조회(lookup)를 반복하지 않고 실행할 수 있는 Kernel을 반환합니다. 제네릭 함수(generic function)는 Loadable::<Args>::load로 인스턴스화(instantiation)를 선택합니다.
  • runtime::DeviceError와 Error::Invalid는 런타임 실패(runtime failure)와 버퍼(buffer)·텐서(tensor) 범위를 벗어난 요청을 보고합니다.
  • 장치 함수(device function)가 클로저(closure)를 호출할 수 있고, 클로저는 캡처(capture)한 값을 읽습니다.
  • 런타임(runtime) if가 스칼라(scalar)를 반환하므로, 실행 중의 값으로 배열 원소(array element)를 선택할 수 있습니다. inputs[if pick == 0 { 0 } else { 1 }].
  • 조건을 컴파일 시점(compile time)에 알 수 있는 if는 선택하는 분기(arm)만 컴파일합니다.
  • DMA가 축(axis)의 크기를 나누어떨어지게 하지 않는 너비(width)의 타일(tile)도 이동할 수 있습니다. 예: 크기 8인 축에서 너비 3인 타일.
  • Mapping::abstract_limits와 abstract_limits_upperbound.

제거(Removed)

  • DeviceFn::execute, execute_into를 제거했습니다. launch(f, args)와 .output(&mut out)을 사용하세요.
  • NPU의 HbmTensor::into_vec, to_vec, to_buf를 제거했습니다. to_host(&mut device.pdma).await?.into_vec()를 사용하세요.
  • runtime::Buffers, TupleApply, backend::npu를 제거했습니다.
  • Error::Chips, Error::Poisoned를 제거했습니다. Error::Device를 매칭(match)하세요.
  • Address(u64로 작성)와 DpeTensor를 제거했습니다.
  • furiosa-opt-rt 명령줄 실행기(command-line runner)를 제거했습니다.

수정(Fixed)

  • 서로 다른 호스트(host)·HBM 배치(layout) 사이의 NPU 텐서 전송(tensor transfer)을 수정했습니다.
  • 짧은 텐서 유닛(Tensor Unit) 연산을 많이 실행하거나 클러스터 동기화(cluster sync)를 연속해서 많이 수행해도 시간 초과(timeout)나 멈춤(hang)이 발생하지 않습니다.
  • 4 GiB 이상의 호스트 전송(host transfer)과 여러 전송의 동시 진행(in flight)이 완료됩니다.
  • CPU에서 축(axis) 범위를 벗어나는 창(window)의 tile은 패닉(panic)을 일으킵니다. 재구성한 뷰(reshaped view)의 타일(tile)은 새 축을 기준으로 셀(cell)을 선택합니다.
  • 축(axis) 크기는 같지만 타입(type)이 다른 제네릭 함수(generic function)의 인스턴스화(instantiation)들이 더 이상 하나의 커널(kernel)을 공유하지 않습니다.
  • 컴파일러(compiler)가 잘못 거부하던 다음 커널(kernel)을 컴파일할 수 있습니다. 스칼라(scalar) !=, collect 직후의 to_vrf, 벡터 엔진(Vector Engine) 산술 연산을 동반한 sub 문맥 읽기(fetch), 상주(resident) DmTensor로의 to_dm_view, 최대 16행의 4비트 전치(transpose), 전체 너비(full-width)의 i4 수축(contraction).
  • 끝부분(tail)이 정렬되지 않은 gather의 to_dm을 직접 to_dm과 마찬가지로 거부합니다.

[v0.9.0]

변경(Changed)

  • dma_gather_scaled / dma_gather_unscaled 대신 gather::<IndexedAxis, Payload>().by_byte_offsets(index) / .by_positions::<Domain>(index)를 사용하고, 이어서 .to_dm(&mut device.tdma)를 호출하세요.
  • dma_scatter / dma_scatter_unscaled 대신 dst.view_mut().scatter::<IndexedAxis, Payload>().by_byte_offsets(index) / .by_positions::<Domain>(index)를 사용하고, 이어서 .from_dm(&mut device.tdma, updates)를 호출하세요. 갱신값 뷰(updates view)를 넘길 때는 from_dm_view를 사용합니다.
  • 저수준(low-level) Tensor::gather는 더 이상 공개(public) API가 아니며, Tensor::scatter는 scaled: bool 인수(argument)를 더 이상 받지 않습니다. 위의 단계별(staged) HBM gather/scatter API를 사용하세요.
  • NPU 백엔드(backend)의 Function::{alloc,write,write_into,read,read_into}는 더 이상 공개(public) API가 아닙니다. furiosa-opt-rt::Device::alloc, HostTensor::to_hbm, HbmTensor::to_host를 사용하세요. 기존 텐서(tensor)로 전송할 때는 .output(..)을 사용합니다.
  • MappingExt::split_at은 Result<(Mapping, Mapping), SplitAtError>를 반환합니다. FindAxisError::SpanExceedsMapping과 WindowAxisError::SpanExceedsMapping은 SpanDoesNotDivide로 바뀝니다.
  • Mapping::remove_padding() 대신 remove_outermost_padding()을 사용하세요.
  • TileError::Split은 SingletonLength, IndexNotLocated, WindowDoesNotFit으로 바뀝니다.
  • furiosa-opt-lower::ElementSizeError에는 이제 NotByteAligned, NotElementAligned만 있습니다. 모든 경우를 나열하는 매칭(exhaustive match)을 이에 맞춰 수정하세요.
  • furiosa-opt-rt에서 device.alloc(bytes) 대신 HBM은 device.alloc(image::Memory::Dram, bytes), 상주 SRAM(resident SRAM)은 image::Memory::Sram을 사용하세요. 할당 실패(allocation failure)는 Error::Allocation(AllocError)를 사용합니다. FunctionError::UnsupportedSlotMemory는 WrongSlotMemory { slot, expects, has }로 바뀝니다.
  • 장치 함수(device function)는 0.9.0 컴파일러(compiler)로 다시 컴파일하고 furiosa-opt-rt도 함께 갱신하세요. 이전 버전으로 컴파일한 이미지(image)는 새 런타임(runtime)과 호환되지 않습니다.

추가(Added)

  • gather::<..>().by_byte_offsets(index).sparse_prefix(valid_length)는 gather에 런타임 접두 범위 제한(runtime prefix limit)을 추가합니다.
  • DmTensorView::to_spm은 DM 뷰(view)를 SPM 텐서(tensor)로 복사합니다.
  • HbmScalar<T>는 from_host와 to_spm을 통해 런타임(runtime)의 bool, i32, u32, i64, u64, 64비트 usize 값을 장치 코드(device code)에 전달합니다. 새 스칼라(scalar)를 만들거나 .output(&mut scalar)로 기존 스칼라에 넣을 수 있습니다.
  • 장치 스칼라 표현식(device scalar expression)이 i32, u32, i64, u64, usize 사이의 Rust 정수 as 형 변환(cast)을 지원합니다. 텐서 인덱스(tensor index)의 usize도 포함합니다.
  • 런타임 스칼라 조건(runtime scalar condition)으로 반복 범위가 정적으로 정해진(statically bounded) for, #[unroll] 반복문(loop) 내부 작업의 실행 여부를 제어할 수 있습니다.
  • DmTensor::alloc(&device)?는 여러 실행(launch)에 걸쳐 유지되는 SRAM을 할당합니다. &DmTensor 또는 &mut DmTensor로 커널(kernel)에 전달합니다.
  • furiosa-opt-rt::Device::memory()와 furiosa-opt-std::Device<Npu>::memory()가 칩별(per-chip) HBM 용량(capacity), 사용 가능한 바이트(available byte), 가장 큰 연속 여유 영역(largest contiguous free span)을 보고합니다.
  • furiosa-opt-lower가 간접 DMA(indirect DMA) 검증을 위한 gather_payload, scatter_payload, validate_* 보조 함수(helper)를 공개합니다.
  • 매핑 검사(mapping inspection)에 MappingExt::{remove_axis,is_broadcast,has_bottom_pad,has_no_padding}와 Mapping::innermost_writable_size를 추가했습니다.

수정(Fixed)

  • DmTensorViewMut::to_dm_view가 대상 매핑(destination mapping)의 Bottom 패딩(padding)을 보존합니다.
  • 벡터 파이프라인(vector pipeline)이 VRF 값 하나를 반복해서 읽는 동작을 지원합니다.
  • 최적화 빌드(optimized build)에서 런타임 반복문 인덱스(runtime loop index)의 갱신값이 반복(iteration) 사이에 유지됩니다.
  • 지원하지 않는 레지스터 파일 저장(register-file store)이 계산 결과를 버리게 되는 경우 컴파일 오류(compilation error)를 보고합니다.
  • 연속 전송 한계(consecutive-transfer limit)를 넘는 차원 간 전치 배치(inter-transpose layout)는 컴파일에 실패합니다.
  • trace 프로파일링(profiling) 용량(capacity)을 넘는 커널(kernel)도 프로파일링 없이 실행하거나 info / debug를 사용할 수 있습니다.
  • 실행(launch)은 충돌하는 인수 바인딩(argument binding), 겹치는 쓰기 가능 버퍼(writable buffer), 정렬되지 않은 SRAM 뷰(view)를 거부합니다. 완료된 실행은 임시 버퍼(temporary buffer)를 해제합니다.

추가(Added)

DmTensor::to_spm과 SpmTensor::to_dm은 텐서 DMA(Tensor DMA)로 조밀한 텐서(dense tensor)를 DM과 SPM 사이에서 이동하며, Pe::SIZE == Slice::SIZE / 64를 요구합니다. Element는 PE 하나의 4 KiB 스크래치패드에 들어가야 하며, 컴파일 시점(compile time)에 검사합니다.

Buffer의 뷰(view)는 slice, 특정 칩의 on, 전체 칩의 on_all 형태입니다.

  • 작업 패닉(task panic)이 메시지를 보고합니다. 펌웨어(firmware)가 실패 코드(failing code)와 함께 메시지를 보내고, 호스트 오류(host error)가 이를 표시합니다.
  • HostTensor::pinned()는 텐서(tensor)를 페이지 고정 메모리(page-locked memory)로 옮깁니다. to_hbm(..).output(&mut hbm) / to_host(..).output(&mut host)는 기존 텐서로 전송합니다. 고정 메모리(pinned memory)를 오가는 전송에서는 해당 메모리가 DMA의 직접 원본(source) 또는 대상(destination)입니다. 페이지 교체 가능한 메모리(pageable memory)는 호출마다 페이지(page)를 고정하므로 페이지당 수 마이크로초(microsecond)의 비용이 듭니다.

  • 장치 매개변수(device parameter)가 고정 크기 배열(fixed-size array)과 빌린 중첩 구조체(borrowed nested struct)를 지원합니다. 런타임 반복문 인덱스(runtime loop index)로 model.layers[index].weight.x 같은 텐서 참조(tensor reference)를 선택할 수 있습니다.
  • 매핑 인자(mapping factor)가 제네릭 축(generic axis)과 괄호로 묶은 개수(parenthesized count)를 허용합니다. 예: m![Width / Factor], m![Width / (Width / 256)].
  • #[unroll]은 스케줄링(scheduling) 전에 정적 for 반복문(static loop)을 완전히 펼칩니다. 반복문 펼치기(Unroll a loop)를 참고하세요.

변경(Changed)

호환성을 깨는 변경(breaking change)을 먼저 나열하고, 각각 대체하는 작성법을 함께 설명합니다.

  • 칩(chip)과 장치(device)의 명칭을 구분했습니다. #[device(chip, pe)]는 PE들로 구성된 칩들을 선언합니다. 따라서 런타임(runtime)의 Topology { chips, pes }에서 종전 devices는 chips, DeviceRank는 ChipRank, DEVICE_PES는 CHIP_PES, FURIOSA_VISIBLE_DEVICES는 FURIOSA_VISIBLE_CHIPS가 됩니다.
  • 칩(chip)을 여는 데 실패했을 때의 오류 이름을 Error::Group에서 Error::Chips로 바꿨습니다.
  • FunctionError::WrongTopology의 필드(field) image_devices를 image_chips로 바꿨습니다. 오류 메시지에서 이미 칩(chip)이라고 부르던 대상에 맞춘 이름입니다.
  • Device는 프로세스(process)가 여는 대상이자 장치 함수(device function)가 실행되는 대상을 뜻합니다. 기존 Context와, Device가 칩을 가리키던 탓에 필요했던 DeviceGroup을 대체합니다. Device::new(topology)는 자체 칩(chip) 집합을 여므로 같은 토폴로지(topology)의 장치 두 개도 서로 다른 PE를 보유합니다. 장치 함수의 첫 매개변수(parameter)는 &mut Device입니다. Context라는 이름은 실제 문맥(context)인 장치 내부 텐서 유닛(tensor-unit)·DMA 문맥 main, sub, tdma, pdma에 남습니다.
  • Topology를 하나로 통합했습니다. furiosa-opt-rt에 정의하고, 같은 두 필드(field)를 별도로 갖던 furiosa-opt-std에서는 재공개(re-export)합니다. 정확한 칩(chip) 지정은 Builder::among이 담당하므로, 칩 목록(chip list)을 담던 변형(variant)과 그 유일한 생성 경로였던 변환(conversion)을 제거했습니다.
  • HbmTensor::dma_gather_unscaled는 원시 행 위치 인덱스(raw row-position index)를 DmTensor<i32> 대신 SpmTensor<i32>로 받습니다. 컴파일러(compiler)가 전송을 삽입하게 두지 않고, 커널(kernel)이 to_spm으로 직접 인덱스를 SPM에 준비합니다(stage). gather가 PE 0에서 전체 목록(list)을 읽으므로 인덱스의 Pe는 패딩만 있는 형태(padding-only)인 m![1 # 4]여야 합니다.
  • TuContext::{parallel_copy_chip_slice,parallel_copy_cluster_slice}를 DmTensor::{asymmetric_chip_slice,asymmetric_cluster_slice}로 대체했습니다. 입력 텐서(input tensor)가 메서드 수신자(receiver)가 되고, sub 문맥(context)은 첫 인수(argument)가 됩니다. 입력 스칼라(scalar)·차원 타입(dimension type)과 슬라이스 인덱스(slice index) 수는 제네릭 인수(generic argument)로 지정하지 않고 추론합니다.
  • DmTensorView::{dm_chip_shuffle,dm_cluster_swap}를 단계별(staged) chip_shuffle(...).to_dm(...), cluster_swap().to_dm(...) 형태로 대체했습니다. 기존 뷰(view)에 쓰려면 마지막 연산(terminal operation)으로 to_dm_view를 사용하세요. 명시적인 뷰가 필요 없다면 DmTensor에서 같은 연산을 바로 시작하면 됩니다.
  • VectorInitTensor::vector_intra_slice_unzip은 그룹 단위로 타일링된(group-tiled) 입력 Time 매핑(mapping)을 추론합니다. 이제 축 이름(axis name)과 출력 Time 매핑만 지정합니다. 예를 들어 vector_intra_slice_unzip::<I, m![R, 1 # 2], m![R]>() 대신 vector_intra_slice_unzip::<I, m![R]>()를 사용합니다.
  • DmTensor::to_dm은 모든 DM 차원(dimension)을 재배치(relayout)할 수 있습니다. 제네릭 인수(generic argument)는 <Slice2, Element2>에서 <Chip2, Cluster2, Slice2, Element2>로 바뀝니다. 변경 없는 차원은 명시적으로 반복하거나, 예상 출력 타입(expected output type)에서 _로 추론할 수 있습니다.
  • 장치 호출 ABI(device-call ABI)는 이제 Binding, 구조적(structural) Bindings, DeviceOutput을 사용합니다. Buffer, BufferList, FixedBufferList, KernelOutput, KernelOutputDestination은 제거했습니다. derive로 생성한 DeviceSend 구현은 자동으로 갱신됩니다. 수동 구현(manual implementation)은 bind()에서 impl __private::Bindings를 반환해야 하며, 수동 DeviceFn 출력 타입(output type)은 DeviceSend와 __private::DeviceOutput을 모두 구현해야 합니다.
  • DM을 생성하는 슬라이스(slice)는 이제 8바이트 경계에 정렬된 AxisToSlice 스트라이드(stride)를 요구합니다. 비대칭 슬라이스(asymmetric slice)는 그 축(axis)이 Element의 가장 바깥쪽에 있어야 하며, 칩 섞기(chip shuffle)는 텐서의 칩들에 대한 순열(permutation)이어야 합니다. 재분배 원본(redistribution source)과 슬라이스 인덱스(slice index)는 컴파일 시 상수(compile-time constant)여야 합니다. 잘못된 매핑(mapping)이 커널(kernel)에 선언된 것과 다른 하드웨어 연산으로 전달되는 일을 막았습니다.
  • 실행(launch)과 전송(transfer)은 Result를 반환합니다. 모든 백엔드(backend)에서 launch(f, args).await, device.launch, to_hbm, to_host, 각각의 .output(..), Device::acquire는 Result<_, furiosa_opt_std::Error>입니다. 큐(queue) 포화, 장치 실패·시간 초과(timeout), 메모리 부족, to_hbm으로 배치한 적 없는 HBM 텐서(tensor), 바이너리(binary)에 이미지(image)가 없는 장치 함수(device function)는 패닉(panic) 대신 호출자가 처리하는 오류(error)가 됩니다. #[derive(DeviceSend)]도 이에 맞춰 bind에서 Result를 반환합니다.
  • Device::new(function.topology())는 열 장치 그룹(device group)을 지정합니다. 이전의 Device::new()는 프로세스 전체 문맥(process-wide context)을 반환하고 장치 선택을 Acquired::bind에 맡겼습니다. #[device]는 모든 함수에 topology()를 제공하며, Acquired와 그것이 보호하던 싱글턴(singleton)을 제거했습니다. 각 획득(acquisition)은 독립된 그룹을 여므로 같은 토폴로지(topology)의 문맥 두 개도 서로 다른 PE를 보유합니다.
  • 장치 함수 이미지(device-function image)는 컴파일 대상 토폴로지(topology)와 각 인수 슬롯(argument slot)에 담아야 하는 내용을 기록합니다. 런타임(runtime)은 적재(load) 시 다른 토폴로지용 이미지를, 실행(launch) 시 필요한 것보다 작은 버퍼(buffer)를 거부합니다.
  • 장치 함수(device function)는 포함된 공급업체 장치 런타임(vendored device runtime) 대신 독립적인 furiosa-opt-rt 런타임(runtime)에서 실행합니다. 각 NPU는 서명된 부트로더(signed bootloader)와 런타임 자체의 펌웨어(firmware)로 부팅합니다. 따라서 실행(launch)이 별도의 런타임 프로세스(runtime process)를 거치지 않으며, 유휴 장치(idle device)에서 실행을 시작하는 데 수십 마이크로초(microsecond)가 듭니다. Linux NPU 빌드에서 furiosa-opt-rt는 furiosa-opt-std의 의존성(dependency)입니다. 공개 런타임은 공급업체가 빌드한 펌웨어 이미지(firmware image)를 내장하지만, 그 소스(source)는 공개 배포에 포함하지 않습니다.
  • 프로파일링(profiling)은 TUC_PROFILE_LEVEL이 아니라 FURIOSA_OPT_PROFILE로 켭니다. span::npu 추적 대상(tracing target)은 그대로입니다. 잘못된 수준(level)이거나 이미지(image)가 제공할 수 없는 수준이면 패닉(panic) 대신 경고(warning)를 출력하고 프로파일링 없이 함수를 실행합니다.
  • 장치 함수 이미지 형식(device-function image format)은 새 런타임(runtime)의 ABI 1입니다. 작업(task)을 256바이트 경계에 맞춘 청크(chunk)로 나누며, 청크 한도(chunk limit)는 1 MiB입니다. 프로파일 영역(profile section)의 크기는 깊이(depth)에 따라 정합니다. 여러 청크가 필요한 테스트에서는 cargo furiosa-opt가 FURIOSA_OPT_CHUNK_LIMIT으로 한도를 낮춥니다.
  • 기본 스칼라 타입(primitive scalar)은 더 이상 DeviceSend를 구현하지 않습니다. 런타임 데이터(runtime data)는 HBM 텐서(tensor)로 전달하고, 컴파일 시 값(compile-time value)은 상수 제네릭(const generic)을 사용하세요.
  • Kernel::alloc의 이름을 alloc_binding으로 바꿨습니다. Kernel::run 대신 launch를 사용하세요.
  • Stride, Modulo, Resize, Padding은 인자(factor)로 매핑 타입(mapping type)을 받습니다. N을 Broadcast<N>으로 바꾸세요. 기존 리터럴(literal) 및 이스케이프 상수(escaped-constant)의 m! / i! 문법(syntax)은 그대로입니다.
  • TableLookup의 이름을 TableLookupCast로 바꿨습니다. 가져오기(import)와 트레이트 한정(trait bound)을 수정하세요. fetch_table_lookup() 호출은 그대로입니다.
  • commit_view::<Element>(dst) 대신 commit_view::<_, Element>(dst) 또는 commit_view(dst)를 사용하세요. 호환되는 대상 슬라이스 매핑(destination slice mapping)은 이제 서로 다른 패딩 종류(padding kind)를 사용할 수 있습니다.
  • Mapping 디버그 출력(debug output)이 Display와 같은 매핑 표기(mapping notation)를 사용합니다.

수정(Fixed)

  • 대상 슬라이스(destination slice)에 패딩(padding)이 있는 사용자 지정 브로드캐스트(custom broadcast)를 잘못 거부하던 문제를 수정했습니다.
  • 일부 수축 커널(contraction kernel)의 사이클 추정(cycle estimation) 중 발생하던 컴파일 실패(compilation failure)를 수정했습니다.
  • 지원하지 않는 스칼라 변환(scalar conversion)은 호출 위치(call site)에 지원 타입(supported type)을 보고합니다.
  • 비어 있거나 잘못된 m!, i! 표현식(expression)은 매크로 호출(macro invocation) 위치에 오류(error)를 보고합니다.

  • launch(function, args)는 이제 기다릴 때 실행되는 Launch 빌더(builder)를 반환합니다. 기존 launch(function, args).await 호출은 그대로입니다. 아직 기다리지 않은 값을 Future가 필요한 API에 전달하는 코드는 .into_future()를 호출해야 합니다. #[device]가 생성한 DeviceFn 구현은 launch(function, args).output(&mut output).await도 지원합니다. NPU 빌드에서 실행마다 새 출력 버퍼(output buffer)를 할당하지 않고 기존 출력 HBM을 바인딩(binding)합니다. 수동 DeviceFn 구현은 기본 할당 후 대입(allocate-and-assign) 구현을 통해 계속 동작합니다.
  • vector_intra_slice_reduce는 쌍 모드(pair mode)에서 _zip 전후 모두 사용할 수 없습니다. 축약기(reducer)는 그룹 조건(group condition)을 받지 않으므로 _zip이 쓴 그룹만 접어 모을 수 없습니다. 결합된(zipped) 텐서(tensor)에 호출하면 컴파일되지 않으며, vector_intra_slice_unzip을 거친 스트림(stream)도 컴파일 시 거부합니다.
  • vector_intra_slice_reduce는 필요한 누산기 슬롯(accumulator slot) 수를 검사합니다. 가장 바깥쪽 축약 축(reduced axis)보다 안쪽의 비축약(non-reduce) Time 위치마다 활성 누산기(live accumulator)가 필요하며, 축약기(reducer)에는 8개가 있습니다. 더 많이 요구하는 매핑(mapping)은 요청한 개수와 함께 거부합니다. 시간 축약기(Time Reducer)가 이미 검사하던 한계를 이제 두 엔진이 공유합니다.
  • vector_intra_slice_unzip은 생성하는 교차 배치 그룹(interleaved group)의 크기를 제한합니다. 그룹 축(group axis) 안쪽의 크기(volume)가 분기 그룹 크기(branch group size)가 됩니다. 한 그룹이 들어오는 동안 다른 그룹은 VE 레지스터 파일 캐시(register-file cache, 1 KiB, 32비트 레인 256개)에서 기다리므로, 더 큰 그룹은 요청 크기와 함께 거부합니다. 크기를 줄이려면 fetch/collect의 시간(time) 매핑에서 그룹 축을 더 안쪽에 놓으세요.

추가(Added)

  • 제네릭 #[device] 함수(generic function)를 컴파일할 수 있습니다. 제네릭 인수(generic argument)는 실행(launch)할 때 결정되며, 모든 실행을 아는 것은 링크(link)되는 바이너리(binary)입니다. 따라서 이제 해당 바이너리에서 커널(kernel)을 컴파일합니다. cargo furiosa-opt 빌드는 각 바이너리가 실행하는 커널을 그 바이너리 안에 포함하고, 실행 시 현재 바이너리 안에서 커널을 찾습니다. 별도의 커널 파일을 옆에 배포하지 않습니다. 실행 파일(bin), 예제(example), 테스트 하니스(test harness), Python wheel의 확장 모듈(extension module) 같은 cdylib 등 모든 링크 형태(linked shape)와 다른 크레이트(crate)가 정의한 커널 실행을 지원합니다.
  • DmTensorView::dm_cluster_swap이 두 클러스터(cluster)를 교환하고 EDF로 하향 변환(lowering)됩니다. VISA/LIR/EDF 회귀 검증(regression coverage)을 포함합니다.
  • 전치 엔진(Transpose Engine)이 8비트·16비트 원소(element)의 두 배 입력 패킹(doubled input packing)을 허용합니다. 패킷(packet) 하나가 사이클(cycle)마다 유효 원소(valid element) 16개를 제공할 수 있습니다. 4비트와 32비트의 두 배 패킹은 계속 지원하지 않습니다.
  • fetch_chip_lift, fetch_cluster_lift, fetch_slice_lift는 일반 fetch가 Time에서 순회할 축(axis)을 Chip, Cluster, Slice 배치(placement)의 브로드캐스트 슬롯(broadcast slot)으로 옮깁니다. 각 목적지(destination)가 로컬 복사본(local copy)에서 다른 오프셋(offset)을 읽으며, 데이터 전송(data transfer)이나 OutPacket 변경은 없습니다. 원본 영역(source region)은 이미 복제되어 있어야 합니다.
  • 축 올리기(lift)는 두 실행 문맥(execution context) 모두에서 동작하고, 런타임(runtime)에 선택한 원본 뷰(source view)를 따릅니다. 슬라이스 기준 주소(slice base)는 해당 문맥의 원본 주소(source address)에 상수 오프셋(constant offset)을 더합니다. 올린 읽기(lifted read)는 사용자 지정 브로드캐스트 교환(custom-broadcast switch)과 DM·VRF·TRF 출력을 지원합니다.

제거(Removed)

  • DmTensor::to_dm_pcopy, DmTensorView::to_dm_view_pcopy를 제거했습니다. 둘 다 MIR 이후 단계까지 컴파일된 적이 없습니다. 같은 DM 간 복사는 텐서 유닛(Tensor Unit)의 읽기·쓰기 왕복(fetch/commit round trip), 즉 begin -> fetch -> collect -> commit_trim -> commit / commit_view로 작성하거나, DMA 복사(copy)인 DmTensor::to_dm / DmTensorView::to_dm_view를 사용하세요.

변경(Changed)

  • Emulation 백엔드 타입(backend type)의 이름을 Cpu로 바꿨습니다. 별도로 선택하는 모드(mode)가 아니라 CPU에서 실행한다는 뜻이며, 일반 cargo build/cargo test가 이 빌드입니다.

제거(Removed)

  • typecheck 백엔드(backend)를 제거했습니다. Typecheck 타입, PhantomStorage, --cfg backend="typecheck" 환경, cargo furiosa-opt --backend typecheck가 모두 없어졌습니다. 맡던 두 역할을 적절한 곳으로 옮겼습니다. 커널 본문(kernel body)의 매핑(mapping)·모양(shape) 검증은 cargo furiosa-opt compile이 수행합니다. 변환기(translator)가 선택한 모든 커널을 정적으로 검증하며, 팬텀 실행(phantom execution)으로 잡지 못하던 장치 제약(device constraint)도 검사합니다. 값 검증(value validation)은 CPU 테스트가 담당합니다. backend cfg는 이제 NPU 전용입니다. cfg 없는 빌드가 곧 CPU 빌드이므로 일반 cargo build/cargo test와 프록시 없는 호출(proxy-less invocation)은 바이트 단위까지 같은 빌드를 만듭니다.
  • 원시 주소(raw address)를 받던 모든 API를 제거했습니다. HbmTensor::from_addr, TrfTensor::from_addr, VrfTensor::from_addr, TrfAddress 열거형(enum), *_at 변형인 to_dm_at, to_dm_pcopy_at, dma_gather_scaled_at, to_trf_at, to_vrf_at, commit_at이 해당합니다. 주소(address)는 호출자가 선택할 대상이 아닙니다. 컴파일러(compiler)가 커널 자체의 텐서(tensor)를 배치하고, 스케줄러(scheduler)가 레지스터 파일 영역(register-file region)을 지정하며, 런타임(runtime)이 호스트 업로드(host upload) 메모리를 할당합니다. 주소 없는 호출로 바꾸세요. 장치 함수(device function)에 출력이 필요하면 DmTensor::new()의 HBM 대응물인 HbmTensor::new()를 사용합니다. 담당하는 쪽에서 할당을 받습니다.
  • f16은 더 이상 vISA 스칼라(scalar)가 아니며 DMA 데이터 타입(dtype) 목록 등에서도 제거했습니다. RNGD는 이에 대한 네이티브 산술 연산(native arithmetic)이 없고, 읽기 확장(fetch widen)과 형 변환 축소(cast narrow)만 지원합니다. 따라서 커널(kernel)이 타입 이름을 쓸 수는 있어도 계산할 수는 없었습니다.

변경(Changed)

호환성을 깨는 변경(breaking change)을 먼저 나열하고, 각각 대체하는 작성법을 함께 설명합니다.

  • cargo furiosa-opt compile은 제네릭 함수(generic fn)를 지정하는 필터(filter)를 함수별로 거부합니다. 제네릭 함수에는 단독으로 컴파일할 인스턴스화(instantiation)가 없기 때문입니다. 대상(target)에서 함수를 실행하고 cargo furiosa-opt build/test로 그 대상을 빌드하세요. compile은 구체 함수(concrete fn)의 산출물(artifact)을 직접 만드는 도구로 유지합니다.

  • furiosa-opt-examples는 처음부터 끝까지 컴파일되는 커널(kernel)과 반드시 거부되어야 하는 검증 사례(fixture)를 담은 negative 모듈만 보유합니다. 유효하지만 컴파일러(compiler)가 아직 EDF로 하향 변환(lowering)하지 못하는 함수인 matmul, attention, vrf_add, 값 반환 형태(value-form)의 runtime_if, 병렬 복사(parallel-copy)·섞기(shuffle) 전송은 크레이트(crate) 밖으로 옮겼습니다. 따라서 여기서 찾는 예제는 negative 아래가 아니라면 컴파일됩니다.

  • 일부 원소(element)에만 적용하는 VE 피연산자(operand)는 Branched로 작성합니다. 구동할 하드웨어 슬롯(hardware slot)의 종류에서 시작하며 여러 슬롯을 지정할 수 있습니다. 예: Branched::imm(guard, 100).imm(other, 200).rf(rest, &vrf). imm은 한 처리(pass)의 즉시값 레지스터(immediate register) 세 개 중 다음 것을 사용합니다. rf는 레지스터 파일 포트(register-file port) 하나를 사용하므로 마지막에 한 번만 지정합니다. 조건 없는 피연산자는 .vector_fxp(op, 16384i32)처럼 그대로 작성하며, 커널이 쓰는 이름으로서의 VeOperand는 제거했습니다.

  • TagFilter는 TagGuard가 되었으며, 그룹(group)만이 아니라 실행 ID(execution id)를 비트(bit)별로 제한합니다. TagFilter::All 대신 TagGuard::all(), TagFilter::Group { id } 대신 TagGuard::group(id)를 쓰세요. 새 TagGuard::matches([BitReq; 4]), not_matches는 태그 비트(tag bit)마다 One, Zero, Ignore 중 하나의 BitReq를 받습니다.

  • 같은 실행 ID(execution id)를 허용하는 가드(guard)는 이제 같은 값(value)이므로 가드 비교는 조건(predicate) 비교입니다. matches([Ignore; 4])는 all()과 같고, 비트(bit) 3만 제한하는 패턴(pattern)의 not_matches는 해당 group()과 같습니다.

  • 비교(comparison)는 이제 스트림 스칼라(stream scalar)로 타입이 정해지고 경계(boundary)를 위치 인수(positional argument)로 받는 Cmp<D>입니다. InputCmp와 그 두 형태인 InputCmpI32/InputCmpF32를 대체합니다. InputCmp::I32(InputCmpI32::Less { boundary: 0 }) 대신 Cmp::Less(0)을 사용하세요. 이에 맞춰 TagMode도 TagMode<D>가 됩니다.

  • TagMode::ValidCount, TagMode::Vrf의 제공을 중단했습니다. 둘 다 호스트(host)에서 실행되지 않았고, ValidCount는 장치(device)용으로 컴파일되기까지 했으므로 이를 쓴 커널(kernel)이 실행 시점에야 실패했습니다.

  • 절대로 참이 될 수 없는 가드(guard)를 컴파일하지 않고 거부합니다. 어떤 실행 ID(execution id)도 만족하지 않는 not_matches([Ignore; 4]), 그리고 이미 남은 모든 원소(element)를 차지한 무조건 슬롯(unconditional slot) 뒤에 오는 슬롯이 해당합니다.

  • 하나의 Cast가 네 하드웨어 변환 집합(hardware conversion set)을 모두 나타내지 않도록 바꿨습니다. Cast는 호스트 측 기능 모델(host-side functional model)이며, 각 단계는 자기 집합을 사용합니다. 읽기 어댑터(Fetch Adapter)는 FetchCast, 형 변환 엔진(Cast Engine)은 CastEngineCast, 쓰기 어댑터(Commit Adapter)는 CommitCast입니다. 쓰기 유닛(commit unit)은 정확히 f32 -> bf16만 수행하는데도, 예전 commit_cast는 Cast 구현(impl)이 있는 모든 타입을 받았습니다.

  • commit_cast와 commit_cast_relu를 두 메서드(method)로 분리하고, 공유하던 Activation 인수(argument)를 제거했습니다. 하드웨어에는 선택할 모드(mode)가 없으므로, 컴파일러(compiler)가 상수 평가(const-evaluate)해야 하는 값 대신 메서드 이름으로 선택합니다.

  • ContractionCast는 이제 곱셈기(multiplier)가 실제로 받는 일곱 피연산자 타입(operand type) i4, i5, i8, i9, f8e4m3, f8e5m2, bf16만 포함합니다. i16, u8, i32, f32는 제거했으므로 벡터 엔진(Vector Engine)의 슬라이스 내부 축약(Intra-Slice Reduce) 경로를 사용하세요. 누산 너비(accumulation width)는 별도 ContractionAccumulator(i32, f32)로 옮겼습니다. 지원하지 않는 타입의 스트림(stream)에는 수축 메서드(contraction method)를 아예 제공하지 않으므로, 컴파일 후 나중에 실패하지 않습니다.

  • DM reshape는 Element 파티션(partition)을, HBM reshape는 전체 크기(whole size)를 보존해야 합니다. reshape는 바뀌지 않은 버퍼(buffer)의 축(axis) 이름을 다시 붙이는 연산인데, 이전에는 같은 이름으로 크기 변경(resize)도 통과했습니다. 범위(extent)를 바꾸려는 경우 pad / unpad 또는 tile을 사용하세요.

  • 벡터 임시 저장(vector stash)은 쓸 때의 스칼라(scalar)와 경로(way)로 읽습니다. 다른 스칼라가 필요하면 쓰기 전에 재해석(reinterpret)하세요. 경로를 넘는 임시 저장(cross-way stash)은 여전히 버퍼링 분할(buffering split)이 필요합니다. 쌍 모드(pair mode)의 stash는 emulation에서 실행 시 패닉(run-time panic)이 나는 대신 컴파일 오류(compile error)가 됩니다.

  • dma_tails는 DMA가 실제로 발행할 수 있는 최대 버스트(largest burst)를 보고합니다. 바이트보다 작은 값을 패킹한 전송(packed sub-byte transfer)은 한 버스트로 128개 원소를 옮기는데도 이전에는 꼬리(tail) 크기가 8개로 나왔습니다.

  • 슬라이스(slice)의 일부를 브로드캐스트(broadcast)하면서 다른 일부의 축(axis)을 순회하는 SwitchConfig를 컴파일할 수 있습니다. 이전에는 전체 구성을 거부했습니다. 여전히 잘못된 구성은 하나의 알기 어려운 매핑(mapping) 오류로 처리하는 대신 문제가 있는 축을 표시합니다.

  • 스케일 없는 gather(unscaled gather)는 하드웨어가 허용하는 것보다 큰 인덱스 텐서(index tensor)를 거부합니다. 엔진이 실행할 수 없는 형태로 하향 변환(lowering)하지 않습니다. 예제에 두 해결책을 제공합니다. 스케일 있는 gather(scaled gather)로 바꾸거나, 반복문(loop)으로 인덱스를 나누어 작은 unscaled gather 여러 개로 처리하세요.

  • 문서를 커널 작성자(kernel author)를 위한 하나의 학습 경로로 정리했습니다. 빠른 시작(Quick Start)은 설정과 도구(Setup and Tooling), 텐서와 수축(Tensor and Contraction), 커널 설계(Kernel Design), 커널 검증(Kernel Validation)을 안내하는 간단한 목차이며, 튜토리얼(tutorial) 자료는 관련 참고 장(reference chapter) 옆에 배치했습니다.

추가(Added)

  • DM·HBM 뷰(view) 양쪽에 pad, unpad를 추가했습니다. 타일(tile)로 표현할 수 없던 범위 재선언(extent re-declaration)으로, 같은 셀(cell)을 더 넓거나 좁은 범위로 선언합니다. 축 경계(axis boundary)의 패딩(padding)은 재선언이므로 허용하지만, 나눈 축(split axis)의 안쪽 자릿수(inner digit)에 패딩을 넣는 것은 허용하지 않습니다. 범위를 줄이는 것은 조용히 데이터를 버리는 방식이 아니라 tile의 역할입니다.
  • vector_reinterpret::<D2>()는 VE의 32비트 스트림(stream)을 비트 그대로 다른 스칼라(scalar)로 읽습니다. 1.0f32는 1이 아니라 0x3f80_0000이 됩니다. 하드웨어 비용이 없으므로 연결(chain)의 어디에나 놓을 수 있고, VectorTensor와 VectorTensorPair 양쪽에서 단계(stage), Way, 필터 문맥(filter context), stash 타입 상태(typestate)를 유지합니다. 시프트(shift)와 Fxp 클러스터(cluster)가 i32만 받으므로, f32의 비트 조작(bit manipulation)에 사용합니다.
  • 매핑 셀(mapping cell)을 공개했습니다. Cell은 위치(position)가 실제 인덱스(live index), 패딩 종류(padding kind), 범위 밖(out of bounds) 중 무엇을 담는지 나타내며, CellExt는 매핑(mapping)에서 이를 읽습니다.
  • 내장 테이블 조회 변환(baked table-lookup conversion) 네 가지가 모두 동작합니다. f4e2m1 → f8e4m3 또는 f8e5m2, f8e4m3 → bf16, f8e5m2 → f32입니다. 이전에는 네 개 중 두 개가 컴파일에 실패했습니다.
  • FetchCast에 i16 -> i32, f32 -> bf16을 추가했습니다.
  • 피연산자(operand)가 이미 누산기 너비(accumulator width)인 호스트 정답 계산(host answer key)을 작성할 수 있도록 Tensor::contraction_prewidened를 추가했습니다. Tensor::contraction은 계속 피연산자 너비(operand-width)의 입력을 받아 ContractionCast::Output으로 누산합니다.
  • 쉼표로 구분한 칩 ID(chip id) 목록인 FURIOSA_VISIBLE_CHIPS는 프로세스(process)가 획득(acquire)할 수 있는 칩(chip)을 제한합니다. 실행 두 개가 가장 낮은 빈 칩을 두고 경쟁하는 대신 서로 겹치지 않는 칩을 고정해서 사용할 수 있습니다. 설정하지 않거나 비워 두면 노출된 모든 칩이 후보(candidate)가 됩니다.

수정(Fixed)

  • 조건부 피연산자(conditional operand)의 슬롯(slot)이 작성 순서대로 적용됩니다. 원소(element)는 가드(guard)를 만족하는 첫 슬롯을 사용하므로, 끝에 놓은 TagGuard::all()은 해당 처리(pass)의 else 역할을 합니다. 소프트웨어 실행(software execution)은 이전에 일치하는 모든 슬롯을 차례로 적용해 장치(device)와 결과가 달랐습니다.
  • 지원하지 않는 형태(shape)는 컴파일러(compiler) 내부에서 패닉(panic)을 일으키는 대신 해당 커널(kernel)의 소스 범위(span)에 오류를 표시합니다. TagMode::AxisToggle 처리(pass), 그룹 비트(group bit)만으로 보호한 stash 읽기, VE 클러스터(cluster)의 수용량보다 많은 연산(op)을 연결한 경우가 해당합니다.
  • 호스트(host)에서 만든 타일 뷰(tiled view)가 NPU에서는 타일(tile) 0으로 도착하던 문제를 수정했습니다. tile이 오프셋(offset)을 뷰의 매핑(mapping)에만 기록하고 Npu 백엔드(backend)는 주소(address)를 읽어서, 모든 호스트 측 타일이 기본 텐서(base tensor)를 가리켰습니다. 이제 오프셋이 주소에 반영되며 런타임 값(run-time value)도 가능합니다. 토큰별 임베딩 조회(per-token embedding lookup)에 필요한 동작입니다. emulation에는 영향이 없었습니다.
  • HBM 뷰(view)의 타일(tile)이 축(axis)의 안쪽 자릿수(inner digit)를 지정해도 전체 축에 창(window)을 잡던 문제를 수정했습니다. m![H] 인수를 m![H % 120]으로 타일링하면 뷰에서 바깥쪽 반복(outer repetition)이 빠져, 지정한 자릿수 대신 H 전체를 덮는 창 하나를 읽었습니다. 이제 읽기와 to_hbm_view 쓰기 경로(write path) 모두 타일이 지정한 위치에 창을 둡니다.
  • HbmTensor::reshape가 유지해야 할 장치 할당(device allocation)을 해제하여, 반환한 핸들(handle)이 이미 해제된 HBM을 가리킬 수 있던 문제를 수정했습니다.
  • f4e2m1 또는 i4 타입의 커널 인수(kernel argument)가 텐서 업로드(tensor upload) 이전 EDF 적재(load) 중 size_in_bytes of f4e2m1 should not be used로 패닉(panic)을 일으키던 문제를 수정했습니다. 너비(width)를 비트(bit)로 전달하며, 4비트 텐서는 장치(device)에서 패킹된 크기(packed size)를 유지합니다.
  • i4와 i4의 수축(contraction)이 unsupported types (input: ..., rf: ...)로 EDF 컴파일에 실패하던 문제를 수정했습니다. TRF는 i4 가중치(weight)를 i5로 승격(promote)하여 보유하지만, 컴파일러(compiler)가 허용하는 적재(load)에서 이 승격이 빠져 모든 int4 가중치 수축이 장치(device)에 도달하지 못했습니다.
  • HBM 텐서(tensor)에 scatter한 다음 다시 읽는 커널(kernel)이 scatter 이전 내용을 읽던 문제를 수정했습니다. 읽기(read)가 scatter보다 먼저 스케줄링(scheduling)되고 있었습니다.
  • vector_reinterpret 뒤에 둔 stash 쓰기(write)가 조용히 분기 단계(branch stage)로 옮겨져 처리 입력(pass input)을 저장하던 문제를 수정했습니다. 이 때문에 음수 입력에서 |x| + |x|가 0.0이 되었습니다.
  • VectorTensorPair::vector_logic에 vISA 변환(translation)이 없어 Unknown primitive로 실패하던 문제를 수정했습니다.
  • concat 계층(layer)처럼 VRF 쓰기 포트(write port)가 없는 클러스터(cluster)에 피연산자(operand)를 쓰려 할 때, 거부하지 않고 다른 단계(stage)로 조용히 옮기던 문제를 수정했습니다.
  • bf16의 호스트 모델(host model)을 하드웨어에 맞췄습니다. RNGD는 f32, bf16의 비정규수(subnormal)를 지원하지 않고 NaN을 정규형(canonical form)으로 만드는데, 호스트는 일반 IEEE 동작을 사용했습니다. 이제 정답 계산(answer key)에 비정규수와 NaN 페이로드(payload)가 있어도 장치(device)와 비트 단위까지 일치합니다.

알려진 문제(Known issues)

  • 그룹 비트(group bit)만으로 보호한 stash 읽기(read)는 하향 변환(lowering)되지 않습니다. 캐시 읽기(cached read)에는 피연산자(operand)가 적용되는 원소(element)와, 읽을 슬라이스(slice)를 쓴 그룹(group)이라는 두 정보가 필요하며 컴파일러(compiler)는 이를 별도로 관리합니다. 그룹 형태 가드(group-shaped guard)는 zip의 읽기와 구분할 수 없습니다. 다른 비트도 제한하거나 가드를 제거하세요.
  • TagMode::AxisToggle은 하향 변환(lowering)되지 않습니다. 그룹 분할(group split)에는 지원되는 경로인 vector_intra_slice_unzip()을 사용하세요.
  • 패딩된 축(padded axis)이 분할(split)의 안쪽 자릿수(inner digit)인 타일(tile)은 DMA가 배치할 수 없습니다.
  • 안쪽 자릿수 타일(inner-digit tile)은 HBM 인수(argument)가 직접 이름을 지정한 축(axis)에서 지원합니다. 다른 축 아래에 중첩된(nested) 축 안으로 들어가는 타일은 여전히 컴파일 시점(compile time)에 거부합니다.

[v0.5.0]

변경(Changed)

호환성을 깨는 변경(breaking change)을 먼저 나열하고, 각각 대체하는 작성법을 함께 설명합니다.

  • 전송(transfer)은 더 이상 주소(address)를 받지 않습니다. to_hbm, to_dm을 주소 없이 호출하고, 주소가 중요할 때만 to_hbm_at, to_dm_at을 사용하세요. DM 텐서(tensor)는 DmTensor::from_addr 대신 DmTensor::new로 만듭니다. to_hbm이 생성하는 메모리의 배치(placement)는 런타임 할당기(runtime allocator)가 결정합니다.
  • 호스트 버퍼(host buffer)는 from_buf, into_buf 대신 from_vec, into_vec로 변환합니다.
  • Tensor::reshape는 소유 텐서(owned tensor)와 뷰(view) 모두에서 재구성(reshape) 대상 텐서를 소비합니다(consume). 크기 불일치(size mismatch)는 실행 시점(runtime)이 아니라 컴파일 시점(compile time)에 실패합니다.
  • 벡터 임시 저장(vector stash)을 두 번 읽으면 더 이상 컴파일되지 않습니다. 이전에는 관례(convention)였던 한 번 읽기 규칙(read-once rule)을 피연산자 타입(operand type)이 보장합니다.
  • furiosa-mapping의 replace_padding을 제거했습니다. 같은 결과를 얻으려면 padding(_, Top)을 사용하세요.
  • 조밀한 수축(dense contraction)은 더 이상 피연산자(operand)의 브로드캐스트(broadcast)를 실제로 생성(materialize)하지 않습니다. 호스트(host)에서 출력이 넓은 GEMM의 비용 대부분을 차지하던 부분입니다. 출력은 이전과 바이트 단위까지 동일합니다.
  • NPU 백엔드(backend)의 호스트→HBM, HBM→호스트 전송(transfer)은 준비용 복사(staging copy) 없이 DMA 힙(heap)을 거칩니다.
  • backend="npu"로 빌드한 바이너리(binary)는 컴파일된 커널(kernel)을 함께 보유하므로, 컴파일러(compiler)가 설치되지 않은 장비에서도 실행됩니다.
  • 포함된 장치 런타임(vendored device runtime)을 furiosa_kernel_run, furiosa_profiled_run이 런타임(runtime)을 가변 포인터(mutable pointer)로 받는 리비전(revision)으로 갱신했습니다.
  • vISA 스칼라 상수(scalar constant)는 하나의 공통 표현(shared representation) 대신 정수(integer) 또는 부동소수점(float)이라는 영역(domain)을 함께 보유합니다.
  • tracing-subscriber를 fmt, std, env-filter, json 기능(feature)과 함께 사용합니다.
  • 공개 산출물(published artifact)이 지원하는 호스트(host)는 x86_64-unknown-linux-gnu뿐입니다. README에 이를 명시하고 macOS 사용자는 컨테이너(container)를 사용하도록 안내합니다.

  • 매개변수(parameter) 전체를 덮는 HbmTensorViewMut를 통한 쓰기(write)가 호출자(caller)의 텐서(tensor)에 반영되지 않던 문제를 수정했습니다. 이제 원래 위치에 기록됩니다(in place).
  • Sequential 누산기(accumulator)를 사용하는 유효한 시간 축약기(Time Reducer) 접기(fold)가 누산 버퍼(accumulator buffer) 초과로 거부되던 문제를 수정했습니다. 이제 각 모드(mode)가 패딩(padding)하는 축(axis)만 한도(bound)에 반영하고, 오류에는 검사한 곱(product)을 명시합니다.
  • 컴파일러(compiler)가 변환하지 못하는 장치 호출(device call), 제네릭 #[device] 진입점(entrypoint), 평가하지 못하는 스칼라 형 변환(scalar cast)이 내부 컴파일러 오류(internal compiler error)로 나타나던 문제를 수정했습니다. 이제 구체적인 문제를 보고합니다.
  • 다른 모든 칩(chip)이 쉬고 있어도 칩 0이 사용 중이면 프로세스(process)를 시작하지 못하던 문제를 수정했습니다. 이제 호스트(host)가 노출한 칩 중 첫 번째 빈 NPU를 사용합니다.
  • 간접 DMA(indirect DMA)가 다차원(multidimensional) validlen을 거부하던 문제를 수정했습니다.
  • 단일 칩 장치(single-chip device)에서 DSL tactic 문맥(context)이 구체화(materialize)되지 않던 문제를 수정했습니다.
  • 스케줄러(scheduler)가 출처 추적 텐서(provenance tensor)를 정적으로 할당하여, 아무도 읽지 않는 메모리를 소비하던 문제를 수정했습니다.
  • 스칼라 편향값(scalar bias)의 DRAM→SRAM 전송(transfer)을 정렬된 단일 셀 끝부분(aligned single-cell tail)으로 준비(stage)합니다. DMA 엔진이 허용하는 형태입니다.
