쓰기 어댑터(Commit Adapter)

쓰기 어댑터(Commit Adapter)는 쓰기 엔진(Commit Engine)이 DM에 기록하기 전에 패킷 스트림(packet stream)에 원소별 변환(element-wise transformation)을 적용합니다. 텐서 유닛(Tensor Unit)의 출력 쪽에서 읽기 어댑터(Fetch Adapter)에 대응하는 역할을 합니다.

어댑터(adapter)의 각 단계는 앞 단계 텐서(tensor)에 전용 .commit_xxx(...) 메서드를 연결하여 구성합니다. 연결의 마지막에는 실제 DM 쓰기를 수행하는 .commit(...)이 옵니다. 잘라내기(Trimming)는 필수 첫 단계입니다. .commit_trim(...) 뒤에서만 .commit() / .commit_view()를 호출할 수 있으므로, 모든 쓰기는 먼저 잘라내기를 거칩니다. 이 과정에서 플릿 패딩(flit padding)을 제거합니다. 잘라내기 이후 형 변환(type casting)은 선택 사항이며 main 문맥에서만 가능합니다. 생성 모드(Generate Mode)는 memset이 즉시값으로 채우기 위해 내부적으로 사용하는 별도의 sub 문맥 경로이며, TuTensor에 연결하는 방식이 아닙니다.

  • 주 파이프라인(Main pipeline): 잘라내기(Trimming) → 형 변환(Type Casting)(선택적으로 ReLU를 결합) → .commit().
  • 보조 우회 경로(Sub bypass): 생성 모드(Generate Mode)가 memset을 위해 상수를 직접 씁니다. 앞 단계의 텐서 유닛(Tensor Unit) 스트림은 소비하지 않습니다.
연산(Operation) Main Sub
잘라내기(Trimming) ✅ ✅
형 변환(Type Casting)(선택적으로 ReLU 결합) ✅ ❌
생성 모드(Generate Mode, 내부 memset 경로) ❌ ✅

타입 시스템(type system)이 문맥(context)별 제약을 강제합니다. 각 단계의 메서드는 해당 문맥의 TuTensor에만 존재합니다.

잘라내기(Trimming)

텐서 유닛(Tensor Unit) 파이프라인의 스트림 패킷(stream packet)은 항상 32바이트 *플릿(flit)*입니다(수집 엔진(Collect Engine) 참고). 그러나 실제 유효 원소(valid element)가 용량보다 적어 나머지 끝부분이 패딩(padding)으로 채워질 수 있습니다. 플릿 전체를 그대로 쓰면 유효 영역 뒤의 DM 바이트까지 패딩값으로 덮어쓰게 됩니다.

잘라내기(trimming)는 각 플릿(flit)의 앞쪽 valid_size개 원소(element)만 DM에 쓰고, 뒤쪽 패딩(padding)은 버려 이 문제를 해결합니다. 컴파일러(compiler)가 출력 텐서 매핑(output tensor mapping)에서 valid_size를 도출하므로 사용자가 직접 설정하지 않습니다. D[valid_size]의 크기는 8, 16, 24, 32바이트 중 하나여야 합니다. 32바이트이면 잘라낼 부분이 없습니다. 잘라내기가 추가하는 지연(latency)은 거의 없습니다.

모든 쓰기에 제거할 패딩(padding)이 있는 것은 아니지만, 잘라내기(trimming)는 쓰기 어댑터(Commit Adapter)의 필수 첫 단계입니다. valid_size가 이미 32바이트이면 플릿(flit) 전체가 유효하므로 잘라내기는 아무 변화도 주지 않는 연산(no-op)입니다. .commit()은 .commit_trim(...) 뒤에서만 호출할 수 있으므로 잘라내기가 연결의 시작을 이루며, main의 형 변환(Type Casting)보다 먼저 실행됩니다.

rust
// 잘라내기(trim)는 쓰기 경로(commit path)의 필수 첫 단계이므로, 여기의 `D: MaterializableScalar`가 i5/i9 쓰기를 막습니다.
impl<
    'l,
    const T: Tu,
    P: CanApplyCommitTrim,
    D: MaterializableScalar,
    Chip: M,
    Cluster: M,
    Slice: M,
    Time: M,
    Packet: M,
    B: Backend,
> TuTensor<'l, T, P, D, Chip, Cluster, Slice, Time, Packet, B>
{
    /// 쓰기 어댑터(Commit Adapter)의 잘라내기(trimming) 단계를 실행합니다.
    ///
    /// 각 플릿(flit)의 끝쪽 패딩(trailing padding)을 버려 DM에 유효한 원소(valid element)만
    /// 저장합니다. `OutPacket`은 커널(kernel)이 약속하는 잘라내기 이후 배치(post-trim layout)입니다.
    /// 컴파일러(compiler)는 입력과 출력 매핑(mapping)에서 잘라낼 개수(trim count)를
    /// 도출합니다.
    #[primitive(TuTensor::commit_trim)]
    pub fn commit_trim<OutPacket: M>(self) -> CommitTrimTensor<'l, T, D, Chip, Cluster, Slice, Time, OutPacket, B> {
        verify_commit_trim::<D, Packet, OutPacket>();
        // `transpose(false)`는 타입 시스템(type system)을 맞추기 위한 자리 채움입니다. 실제 trim 하향 변환(lowering)은 백엔드 연결에서 처리합니다.
        CommitTrimTensor::new(self.device, self.inner.transpose(false))
    }
}

.commit_trim::<OutPacket>()는 잘라낸 뒤의 패킷(packet)을 선언합니다. 이어서 연결한 .commit(...)이 잘라낸 스트림(stream)을 실제로 DM에 씁니다. 두 단계는 완전히 분리되어 있습니다.

rust
axes![M = 4, K = 2, W = 8, N = 16, J = 64];

fn commit_trim_i8_padding<'l, const T: Tu>(
    input: CastTensor<'l, T, i8, m![1], m![1], m![1], m![M, K], m![W # 32]>,
) -> CommitTrimTensor<'l, T, i8, m![1], m![1], m![1], m![M, K], m![W]> {
    // 32개로 패딩된 i8 중 유효한 값은 8개입니다. OutPacket이 `# 32` 패딩(padding)을 제거합니다.
    input.commit_trim::<m![W]>()
}

fn commit_trim_f32_non_padding<'l, const T: Tu>(
    input: ContractTensor<'l, T, f32, m![1], m![1], m![1], m![M, K], m![W]>,
) -> CommitTrimTensor<'l, T, f32, m![1], m![1], m![1], m![M, K], m![W = 4]> {
    // f32 8개 중 유효한 값은 4개입니다. OutPacket이 `W`의 크기를 4로 바꿉니다.
    input.commit_trim::<m![W = 4]>()
}

fn commit_trim_bf16_with_transpose<'l, const T: Tu>(
    input: CastTensor<'l, T, bf16, m![1], m![1], m![1], m![M, K], m![N]>,
) -> CommitTrimTensor<'l, T, bf16, m![1], m![1], m![1], m![M, K], m![N = 8]> {
    // bf16 16개 중 유효한 값은 8개입니다. OutPacket이 `N`의 크기를 8로 바꿉니다.
    input.commit_trim::<m![N = 8]>()
}

fn commit_trim_i4_no_trim<'l, const T: Tu>(
    input: CastTensor<'l, T, i4, m![1], m![1], m![1], m![M, K], m![J]>,
) -> CommitTrimTensor<'l, T, i4, m![1], m![1], m![1], m![M, K], m![J]> {
    // 잘라내기(trimming) 없음: `OutPacket == Packet`.
    input.commit_trim::<m![J]>()
}

형 변환(Type Casting)

형 변환(type casting)은 쓰기 경로(commit path)의 f32 데이터를 bf16 형식으로 바꾸며, 같은 처리에서 ReLU 활성화(activation)를 결합할 수도 있습니다. 텐서 유닛(Tensor Unit) 파이프라인의 대부분의 타입 변환은 형 변환 엔진(Cast Engine)이 담당합니다. 쓰기 어댑터(Commit Adapter)의 형 변환은 main 문맥의 수축(contraction)과 sub 문맥의 벡터 엔진(Vector Engine) 작업을 병렬로 실행하는 특정 상황을 위해 존재합니다. 형 변환 엔진은 벡터 엔진 위에 놓여 있어 변환 중에 벡터 엔진을 점유합니다. main 문맥이 형 변환 엔진을 통해 f32 → bf16 변환을 하면 벡터 엔진이 사용 중이 되어 sub 문맥을 동시에 실행할 수 없습니다. 변환을 쓰기 어댑터로 보내면 벡터 엔진을 sub 문맥이 사용할 수 있습니다. 위 지원 표와 같이 sub 문맥 자체는 형 변환을 지원하지 않습니다.

commit_cast와 commit_cast_relu는 모드(mode)만 다른 하나의 변환이 아니라, 서로 다른 하드웨어 변환(hardware conversion)이므로 별도 메서드입니다. ReLU는 실행 시(runtime) 선택할 수 있는 독립 단계가 없고, 정밀도를 줄이는 형 변환(narrowing cast)에 결합된 형태로만 존재합니다.

rust
impl<'l, P: CanApplyCommitCast, D: MaterializableScalar, Chip: M, Cluster: M, Slice: M, Time: M, Packet: M, B: Backend>
    TuTensor<'l, { Tu::Main }, P, D, Chip, Cluster, Slice, Time, Packet, B>
{
    /// 쓰기 어댑터(Commit Adapter)의 형 변환(type-casting) 단계를 실행합니다.
    ///
    /// `f32` → `bf16` 형 변환(cast)을 쓰기 경로(commit path)에 결합하여,
    /// [형 변환 엔진(Cast Engine)](crate::engine::cast)을 sub 문맥 벡터 엔진(Vector Engine) 작업이
    /// 사용할 수 있게 둡니다. 이것이 유일한 변환인 이유는 [`CommitCast`](crate::prelude::CommitCast)를,
    /// ReLU를 결합한 변형(variant)은 [`commit_cast_relu`](Self::commit_cast_relu)를
    /// 참고하세요.
    ///
    /// main 문맥(context)에서만 사용할 수 있습니다.
    #[primitive(TuTensor::commit_cast)]
    pub fn commit_cast<OutD: Scalar>(
        self,
    ) -> CommitCastTensor<'l, { Tu::Main }, OutD, Chip, Cluster, Slice, Time, Packet, B>
    where
        D: CommitCast<OutD>,
    {
        verify_commit_cast::<Packet>();
        CommitCastTensor::new(self.device, self.inner.map(|v| v.cast()))
    }

    /// 같은 형 변환(cast)에 ReLU를 결합하여 음수를 0으로 제한(clamp)합니다.
    ///
    /// 두 변환은 별개의 하드웨어 변환(hardware conversion)이므로 인수(argument) 대신 별도 메서드(method)를
    /// 사용합니다. ReLU는 실행 시(runtime) 선택할 수 있는 독립 단계(standalone stage)가 없습니다.
    ///
    /// main 문맥(context)에서만 사용할 수 있습니다.
    #[primitive(TuTensor::commit_cast_relu)]
    pub fn commit_cast_relu<OutD: Scalar>(
        self,
    ) -> CommitCastTensor<'l, { Tu::Main }, OutD, Chip, Cluster, Slice, Time, Packet, B>
    where
        D: CommitCast<OutD>,
    {
        verify_commit_cast::<Packet>();
        CommitCastTensor::new(self.device, self.inner.map(|v| v.cast_relu()))
    }
}
rust
axes![N = 4, C = 3, H = 4, W = 8];

fn commit_cast_example<'l, const T: Tu>(
    input: ContractTensor<'l, T, f32, m![1], m![1], m![1], m![N, C, H], m![W]>,
) -> CommitCastTensor<'l, T, bf16, m![1], m![1], m![1], m![N, C, H], m![W]> {
    // f32를 bf16으로 형 변환(cast)합니다. 값을 보존하며 활성화(activation)는 없습니다. 실제 main
    // 쓰기(commit)에서는 먼저 `.commit_trim()`을, 뒤이어 `.commit(...)`을 실행합니다.
    // W = f32 원소 8개(32바이트)는 bf16 원소 8개(16바이트)로 유지됩니다.
    input.commit_cast::<bf16>()
}

fn commit_cast_relu_example<'l, const T: Tu>(
    input: ContractTensor<'l, T, f32, m![1], m![1], m![1], m![N, C, H], m![W]>,
) -> CommitCastTensor<'l, T, bf16, m![1], m![1], m![1], m![N, C, H], m![W]> {
    // f32 -> bf16 변환에 ReLU를 결합합니다. 음수는 0으로 제한(clamp)합니다.
    // e.g. [-5.0, -0.1, 0.0, 3.7] -> [0.0, 0.0, 0.0, 3.7]
    input.commit_cast_relu::<bf16>()
}

생성 모드(Generate Mode)

생성 모드(Generate Mode)는 DmTensorViewMut::memset(value, &mut device.sub)으로 DM 영역(region)을 상수(constant)로 채웁니다. 채우기는 sub 문맥(context)에서 실행하며, i32이면 0, bf16이면 const { bf16::from_f32(1.0) }처럼 텐서의 원소 타입(element type)에 맞는 값을 받습니다.

이 모드는 DM에서 읽지 않으며, 앞 단계의 텐서 유닛(Tensor Unit) 스트림(stream)도 소비하지 않습니다. 입력은 상수 value와 대상 위치(destination)뿐입니다. 나머지 텐서 유닛 파이프라인의 Fetch / Switch / Collect / Contraction / Vector / Cast / Transpose / Commit Adapter 단계를 모두 우회합니다.

장치 컴파일(device compilation)에서는 컴파일 시 상수(compile-time constant)인 값과 view_mut()로 얻은 전체 영역 뷰(whole-region view)가 필요합니다. 상수가 아닌 값이나 타일 부분 뷰(tiled sub-view)를 채우는 연산은 변환(translation) 단계에서 거부합니다. 지원하는 원소 타입(element type)은 i8, i16, i32, f32, bf16, f8e4m3, i4입니다. 바이트보다 작은 단위를 쓰는 영역(sub-byte region)은 바이트 경계에 정렬되어야 합니다. 장치 컴파일은 아직 f4e2m1 채우기를 지원하지 않습니다.
