수축 연산기(Contraction Engine)

읽기 도움말 · 번역자 설명

수축 연산기(Contraction Engine)의 흐름은 값을 맞춰 펼치기(broadcast) → 곱하기(multiply) → 더해 모으기(reduce)입니다. 아래 각 단계는 어떤 차원의 값을 한꺼번에 계산하고, 어떤 차원의 값을 여러 사이클(cycle)에 걸쳐 모으는지 구분합니다.

수축 연산기(Contraction Engine)는 행렬곱(matmul)과 합성곱(convolution)처럼 두 입력 텐서(tensor)를 사용하는 수축 연산을 수행합니다. 빠른 시작(Quick Start)의 내용을 떠올려 보세요.

  • 텐서 수축(tensor contraction)은 두 입력 텐서를 받아 공통된 축(axis), 즉 수축하는 축을 따라 값을 합칩니다. 내적(dot product), 행렬·벡터 곱(GEMV), 행렬·행렬 곱(GEMM)이 대표적인 예입니다.
  • 수축(contraction)은 브로드캐스트(Broadcast), 곱셈(Multiply), 축약(Reduce)의 세 단계로 나눌 수 있습니다.
  • 한 피연산자(operand)는 수집 엔진(Collect Engine)에서 스트림(stream)으로 들어오며, 다른 피연산자는 텐서 레지스터 파일(Tensor Register File, TRF)에 머뭅니다.
  • 수축(contraction)은 주 실행 문맥(main context)에서 실행합니다. TRF 준비는 .to_trf()를 통해 보조 실행 문맥(sub context)에서 수행합니다.

구조(Architecture)

작업은 네 개의 파이프라인 단계(pipeline stage)로 나뉩니다. 하나는 브로드캐스트(Broadcast)와 곱셈(Multiply)을, 나머지 세 개는 축약(Reduce)를 담당합니다. 각 단계는 서로 겹치지 않는 차원(dimension)을 처리합니다.

  • 외적 단계(Outer) (브로드캐스트와 곱셈, Broadcast and Multiply): 두 피연산자(operand)를 [Chip, Cluster, Slice, Lane, Time, Packet]이라는 같은 모양(shape)으로 브로드캐스트하고, 원소별(elementwise)로 곱해 하나의 곱 텐서를 만듭니다. Chip / Cluster / Slice는 그대로 통과합니다. Lane은 TRF와 후단 축약기(reducer)가 공유하는 공간 병렬성(spatial parallelism)의 인덱스입니다. Time과 Packet은 함께 패킷 스트림(packet stream)을 표현합니다. 내부의 세 단계가 순서대로 실행됩니다. 스트림 어댑터(Stream Adapter)는 스트리밍 피연산자를, TRF 시퀀서(TRF Sequencer)는 TRF 피연산자를 브로드캐스트합니다. 곱셈기(Multiplier)는 수축 출력 타입으로 확장한 뒤(i4/i8 -> i32, f8/bf16 -> f32) 원소별 곱셈을 수행합니다.
  • 패킷 축약기(Packet Reducer) (패킷 내부 축약, Reduce within Packet): 레인(lane)마다 하나씩 있는 병렬 트리(parallel tree)를 사용하여 Packet에 매핑된 수축 축(contracted axis)을 따라 값을 합칩니다.
  • 시간 축약기(Time Reducer) (시간에 걸친 축약, Reduce across Time): 매 사이클(cycle)의 결과를 공유 누산기(shared accumulator)에 누적합니다.
  • 레인 접기(Lane Folder) (레인 접기, Fold Lane): 버퍼(buffer)를 출력 스트림으로 내보내면서, 모드(mode)에 따라 Lane을 OutPacket이나 OutTime에 흡수합니다. 슬라이스(slice)나 칩(chip) 간 축약는 후단의 벡터 엔진(Vector Engine)이 담당합니다.

RNGD에서 외적 단계(Outer)는 Lane ≤ 8, Packet ≤ 64 B로 제한됩니다. 자세한 내용은 패킷 축약기(Packet Reducer)와 시간 축약기(Time Reducer)를 참고하세요.

예제: 배치 행렬곱(Batched MatMul)

빠른 시작(Quick Start)은 내적(dot product), GEMV, GEMM을 순서대로 설명합니다. 여기서는 배치 행렬곱(batched matmul)의 여러 변형에 대한 구조 참고 자료(architecture reference)와 실행 가능한 코드 조각들을 모아 둡니다. 처음부터 끝까지 따라가는 입문 과정은 빠른 시작을 이용하세요. 배치 행렬곱은 GEMM 앞에 배치 축(batch axis) V를 추가한 것으로, VMK, KN \rightarrow VMN으로 표현합니다. 서로 독립적인 V개의 (M × K) 입력 각각에 공유하는 (K × N) 가중치(weight)를 곱하여 (M × N) 결과를 만듭니다.

아래 세 변형은 어떤 축(axis)을 Time에 놓는지에 따라 커널(kernel)을 구분합니다. 나머지 축은 공간 병렬성(spatial parallelism)에 활용합니다. 모두 다음 축을 공유합니다.

rust
axes![V = 32, M = 32, N = 8, K = 32];   // V: 배치(batch), M×N: 출력(output), K: 수축(contraction)

K를 Time에 배치하기(K in Time)

수축 축(contraction axis) K를 Time에 놓습니다. M은 Cluster와 Slice에 나누어 배치하고, V도 나눕니다. V % 16은 Slice에, V / 16 = 2는 K와 함께 Time에 놓습니다. RNGD에서 V × M = 1024는 칩당 512개의 공간 셀(spatial cell)에 들어가지 않으므로 V의 바깥쪽 덩어리(outer chunk)는 반복해야 합니다. Packet은 1 # 32로 패딩(padding)되고, 패킷 축약기(Packet Reducer)의 공간 트리 대신 여러 사이클(cycle)에 걸쳐 순차적으로 축약합니다. 따라서 매 사이클 32개 곱셈기(multiplier) 중 하나만 유효한 일을 합니다. bf16의 곱셈·누산(MAC) 활용률은 1/32입니다. 성능이 좋지 않은 퇴화 커널(degenerate kernel)이며, 학습을 위한 비교 기준(baseline)으로만 제시합니다.

rust
axes![V = 32, M = 32, N = 8, K = 32];   // V: 배치(batch), M×N: 출력(output), K: 수축(contraction)

type Chip    = m![1];                   // 칩(chip) 하나
type Cluster = m![M / 16];              // M의 바깥쪽을 클러스터(cluster)에 분배합니다(M / 16 = 2).
type Slice   = m![M % 16, V % 16];      // 안쪽 M × 안쪽 V = 16 × 16 = 클러스터(cluster)당 슬라이스(slice) 256개
type Lane    = m![N];                   // N(출력 채널, output channel)을 하드웨어 레인(lane) 8개에 나눕니다.

/// K를 Time에 배치한 배치 행렬곱(batched matmul).
fn bmatmul_k_in_time<'l>(
    // 스트리밍 피연산자(streaming operand): 바깥쪽 V와 K를 Time에, 원소 하나를 Packet m![1]에 둡니다.
    input: CollectTensor<'l, { Tu::Main }, bf16, Chip, Cluster, Slice, m![V / 16, K], m![1 # 16]>,
    // TRF 피연산자(operand): N은 Lane에, K는 Element에 둡니다. 앞선 .to_trf() 호출이 TRF에 저장합니다.
    trf: &TrfTensor<bf16, Chip, Cluster, Slice, Lane, m![K]>,
    // 출력(output): (슬라이스, V 바깥쪽) 쌍마다 (M × N) f32 행렬 하나.
) -> ContractTensor<'l, { Tu::Main }, f32, Chip, Cluster, Slice, m![V / 16], m![N]> {
    input
         // Outer: Lane = m![N](trf에서 추론), OutTime = m![V / 16, K], OutPacket = m![1 # 32].
         // input: K 원소 하나를 모든 N 레인(lane)에 브로드캐스트(broadcast)합니다.
         // trf: 레인(lane)마다 K 원소 하나를 사용하며, 사이클(cycle)마다 K를 한 단계 진행합니다.
         .contract_outer::<m![V / 16, K], m![1 # 16], _, _, _>(trf)
         // 패킷 축약기(Packet Reducer): OutPacket = m![1]. 축약할 축이 없습니다.
         .contract_packet::<m![1]>()
         // 시간 축약기(Time Reducer): OutTime = m![V / 16]. K는 Time에 걸쳐 반복·누산하고, 바깥쪽 V는 유지합니다.
         .contract_time::<m![V / 16]>()
         // 레인 접기(Lane Folder): Lane을 OutPacket에 접습니다. Interleaved 모드는 사이클마다 레인 8개를 내보냅니다.
         .contract_lane::<m![V / 16], m![N]>(LaneMode::Interleaved)
}

이처럼 비효율적인 경우를 피하려면 K를 Packet에 두어 패킷 축약기(Packet Reducer)의 트리로 병렬 축약(parallel reduction)하고, 남는 축(surviving axis) V, M, N을 Cluster, Slice, Lane에 분산하여 공간 병렬성(spatial parallelism)을 최대한 활용하세요. 아래 두 전략은 이 원칙을 적용합니다. 설명을 단순하게 하려고 각 분류(class)에 축 하나씩을 놓지만, 실제 커널에서는 크기에 따라 한 축을 여러 분류에 나누어 배치할 수 있습니다.

M을 Time에 배치하기(M in Time)

배치(batch) V를 Cluster와 Slice에 분산하여 슬라이스(slice)마다 배치 원소 하나를 담당하게 합니다. M은 Time에, K는 Packet에 둡니다. 이 전략은 (1) 슬라이스 수가 배치를 모두 담당할 수 있고, (2) N이 Lane에 들어가며, (3) K가 Packet 하나에 들어갈 때 적용할 수 있습니다. K가 Packet보다 크면 K를 공간 차원(spatial dimension)인 Packet과 시간 차원(temporal dimension)인 Time에 나눕니다. 이렇게 하면 레인(lane) 전반의 곱셈·누산(MAC) 활용률을 극대화할 수 있습니다.

rust
axes![V = 32, M = 32, N = 8, K = 32];   // V: 배치(batch), M×N: 출력(output), K: 수축(contraction)

type Chip    = m![1];                   // 칩(chip) 하나
type Cluster = m![V / 16];              // V의 바깥쪽을 클러스터(cluster)에 분배합니다(V / 16 = 2).
type Slice   = m![V % 16 # 256];        // V의 안쪽을 슬라이스(slice)에 분배합니다(클러스터당 V % 16 = 16).
type Lane    = m![N];                   // N(출력 채널, output channel)을 하드웨어 레인(lane) 8개에 나눕니다(N = 8이면 모두 사용).

/// 배치 행렬곱(batched matmul): V개 슬라이스 × (M × K) · (K × N) → V × M × N.
fn bmatmul_m_in_time<'l>(
    // 스트리밍 피연산자(streaming operand): M은 Time에, K는 Packet에 둡니다.
    // 원소 타입(element type)은 i4, i8, f8, bf16입니다. 정수 출력은 i32로, 부동소수점 출력은 f32로 확장합니다.
    input: CollectTensor<'l, { Tu::Main }, bf16, Chip, Cluster, Slice, m![M, K / 16], m![K % 16]>,
    // TRF 피연산자(operand): N은 Lane에(레인당 출력 채널 하나), K는 Element에 둡니다.
    // 앞서 sub 문맥(context)에서 .to_trf()를 호출하여 TRF에 저장합니다.
    trf: &TrfTensor<bf16, Chip, Cluster, Slice, Lane, m![K]>,
    // 출력(output): 슬라이스(slice)마다 (M × N) f32 행렬 하나.
) -> ContractTensor<'l, { Tu::Main }, f32, Chip, Cluster, Slice, m![M], m![N]> {
    input
         // Outer: input과 trf를 브로드캐스트(broadcast)하고 원소별(elementwise)로 곱합니다.
         // Lane = m![N](trf에서 추론), OutTime = m![M], OutPacket = m![K].
         // input: K개 원소를 모든 N 레인(lane)에 브로드캐스트(broadcast)합니다.
         // trf: 레인(lane)마다 K개 원소를 사용하며, 모든 M 사이클(cycle)에 브로드캐스트(broadcast)합니다.
         .contract_outer::<m![M], m![K], _, _, _>(trf)
         // 패킷 축약기(Packet Reducer): OutPacket = m![1]. 축약 트리(reduction tree)로 K를 공간상에서 합칩니다.
         .contract_packet::<m![1]>()
         // 시간 축약기(Time Reducer): OutTime = m![M]. 축약할 축이 없습니다.
         .contract_time::<m![M]>()
         // 레인 접기(Lane Folder): Lane을 OutPacket에 접습니다. Interleaved 모드는 사이클마다 레인 8개를 내보냅니다.
         .contract_lane::<m![M], m![N]>(LaneMode::Interleaved)
}

V를 Time에 배치하기(V in Time)

배치(batch) V를 Time에, K를 Packet에 둡니다. M은 Cluster와 Slice에 나눕니다. 이 전략은 (1) 슬라이스(slice) 수가 M을 모두 담당할 수 있고(Cluster에 M / 16, Slice에 M % 16), (2) N이 Lane에 들어가며, (3) K가 Packet 하나에 들어갈 때 적용할 수 있습니다. 배치 추론(batched inference)처럼 배치가 가장 큰 비중을 차지하는 축(axis)일 때 유용합니다.

rust
axes![V = 32, M = 32, N = 8, K = 32];   // V: 배치(batch), M×N: 출력(output), K: 수축(contraction)

type Chip    = m![1];                   // 칩(chip) 하나
type Cluster = m![M / 16];              // M의 바깥쪽을 클러스터(cluster)에 분배합니다(M / 16 = 2).
type Slice   = m![M % 16 # 256];        // M의 안쪽을 슬라이스(slice)에 분배합니다(클러스터당 M % 16 = 16).
type Lane    = m![N];                   // N(출력 채널, output channel)을 하드웨어 레인(lane) 8개에 나눕니다.

/// V(배치, batch)를 Time에 배치한 배치 행렬곱(batched matmul).
fn bmatmul_v_in_time<'l>(
    // 스트리밍 피연산자(streaming operand): V는 Time에, K는 Packet에 둡니다.
    input: CollectTensor<'l, { Tu::Main }, bf16, Chip, Cluster, Slice, m![V, K / 16], m![K % 16]>,
    // TRF 피연산자(operand): N은 Lane에, K는 Element에 둡니다. 앞선 .to_trf() 호출이 TRF에 저장합니다.
    trf: &TrfTensor<bf16, Chip, Cluster, Slice, Lane, m![K]>,
    // 출력(output): 슬라이스(slice)마다 (V × N) f32 행렬 하나.
) -> ContractTensor<'l, { Tu::Main }, f32, Chip, Cluster, Slice, m![V], m![N]> {
    input
         // Outer: Lane = m![N](trf에서 추론), OutTime = m![V], OutPacket = m![K].
         // input: K개 원소를 모든 N 레인(lane)에 브로드캐스트(broadcast)합니다.
         // trf: 레인(lane)마다 K개 원소를 사용하며, 모든 V 사이클(cycle)에 브로드캐스트(broadcast)합니다.
         .contract_outer::<m![V], m![K], _, _, _>(trf)
         // 패킷 축약기(Packet Reducer): OutPacket = m![1]. 축약 트리(reduction tree)로 K를 공간상에서 합칩니다.
         .contract_packet::<m![1]>()
         // 시간 축약기(Time Reducer): OutTime = m![V]. 축약할 축이 없습니다.
         .contract_time::<m![V]>()
         // 레인 접기(Lane Folder): Lane을 OutPacket에 접습니다. Interleaved 모드는 사이클마다 레인 8개를 내보냅니다.
         .contract_lane::<m![V], m![N]>(LaneMode::Interleaved)
}
