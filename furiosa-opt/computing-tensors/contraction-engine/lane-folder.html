레인 접기(Lane Folder)

원문 대조 메모 · 번역자 설명

순차 모드(Sequential mode)의 앞 설명에서는 8개 단위 패딩(padding)을 다루지만, 성능 문단에는 패딩이 없다는 표현이 있습니다. 본문은 양쪽을 원문대로 옮겼습니다. 실제 동작을 판단할 때에는 출력 패킷 크기와 매핑 표현식(mapping expression)을 함께 확인하세요.

레인 접기(Lane Folder)는 수축 연산기(Contraction Engine)의 마지막 단계입니다. Lane의 8개 값을 OutPacket(Interleaved) 또는 OutTime(Sequential)으로 옮겨 Lane 차원(dimension)을 없앱니다. 값을 더하지는 않습니다. 이 단계는 레인 차원을 합산하여 축약(reduce)하는 대신 다른 축(axis)에 접어 넣습니다(fold).

인터페이스(Interface)

.contract_lane(mode)는 레인 접기(Lane Folder)를 호출합니다. 이 단계는 앞선 시간 축약기(Time Reducer)의 버퍼(buffer)를 8개 원소 너비의 출력 버스(output bus)로 사이클(cycle)마다 조금씩 비웁니다. LaneMode는 매 사이클의 플릿(flit)에 무엇을 담을지 선택합니다.

rust
impl<'l, D: ContractionAccumulator, Chip: M, Cluster: M, Slice: M, Lane: M, Time: M, Packet: M, B: Backend>
    ContractTimeTensor<'l, { Tu::Main }, D, Chip, Cluster, Slice, Lane, Time, Packet, B>
{
    /// `Lane` 차원(dimension)을 출력 스트림(output stream)에 접어 넣습니다(fold).
    /// `LaneMode::Interleaved`는 `Lane`을 `OutPacket`으로 옮기고,
    /// `LaneMode::Sequential`은 `Lane`을 `OutTime`으로 옮깁니다.
    ///
    /// main 문맥(context)에서만 사용할 수 있습니다.
    #[primitive(ContractTimeTensor::contract_lane)]
    pub fn contract_lane<OutTime: M, OutPacket: M>(
        self,
        mode: LaneMode,
    ) -> ContractTensor<'l, { Tu::Main }, D, Chip, Cluster, Slice, OutTime, OutPacket, B> {
        verify_contract_lane(ContractLaneInput {
            in_lane: Lane::to_value(),
            in_time: Time::to_value(),
            in_packet: Packet::to_value(),
            out_time: OutTime::to_value(),
            out_packet: OutPacket::to_value(),
            pre_reduce_time: self.pre_reduce_time,
            mode: mode.into(),
        });
        // 앞 단계들은 지연된 피연산자(deferred operand)의 타입만 바꿉니다. 여기서 이들의 결합 수축(fused contraction)을 수행한 뒤,
        // 레인 접기(lane-fold)에 따른 재배치(relayout)를 적용합니다.
        // `contraction_prewidened`는 매핑 분할(mapping carve)로 `out`을 검증합니다. 수축하는 기호(symbol) 하나가 공간 슬롯과
        // 축약 슬롯에 걸칠 수 있으므로 기호별 비교(symbol-wise comparison)는 올바르지 않습니다.
        let contraction = self.inner;
        let out = <m![{ Chip }, { Cluster }, { Slice }, { Lane }, { Time }, { Packet }]>::to_value();
        let reduced: Tensor<D, m![{ Chip }, { Cluster }, { Slice }, { Lane }, { Time }, { Packet }], B> =
            Tensor::from_inner(B::contraction_prewidened(
                &contraction.lhs,
                &contraction.rhs,
                &contraction.lhs_map,
                &contraction.rhs_map,
                &contraction.pre_reduce,
                &out,
            ));
        ContractTensor::new(self.device, reduced.transpose(false))
    }
}

아래의 최소 예제는 앞 단계 시간 축약기(Time Reducer)의 출력인 ContractTimeTensor를 받아 .contract_lane(...)만 호출합니다. 따라서 각 예제에서 레인 접기(Lane Folder)의 동작만 따로 볼 수 있습니다. 입력 Packet은 패킷 축약기(Packet Reducer)를 거친 뒤 남은 크기를 가지며, 레인(lane)당 원소 수는 {1, 2, 4, 8, 16, 32} 중 하나입니다.

교차 배치 모드(Interleaved)

Lane 차원(dimension)을 OutPacket에 접어 넣습니다. 매 사이클(cycle) 8개 레인(lane) 모두에서 같은 열 위치(column position)의 값을 하나씩 읽습니다. 레인당 하나, 플릿(flit)당 8개 값입니다. Lane은 OutPacket의 가장 안쪽 차원으로 구체화(materialize)됩니다.

text
OutTime   = [Time, Packet]
OutPacket = [Lane # 8]
rust
axes![N = 8, M = 4, P = 16];

/// Lane을 OutPacket에 접어 넣습니다(fold).
fn lane_interleaved<'l>(
    // 앞선 시간 축약기(Time Reducer)의 입력: Lane = m![N], Time = m![M], Packet = m![P].
    input: ContractTimeTensor<'l, { Tu::Main }, f32, m![1], m![1 # 2], m![1 # 256], m![N], m![M], m![P]>,
    // 출력(output): OutTime = m![M, P] = [Time, Packet], OutPacket = m![N] = [Lane].
) -> ContractTensor<'l, { Tu::Main }, f32, m![1], m![1 # 2], m![1 # 256], m![M, P], m![N]> {
    input.contract_lane::<m![M, P], m![N]>(LaneMode::Interleaved)
}

순차 모드(Sequential)

Lane 차원(dimension)을 OutTime에 접어 넣습니다. 매 사이클(cycle) 한 레인(lane)의 Packet에서 열 위치(column position) 8개의 값을 읽으므로 플릿(flit)당 값은 8개입니다. Lane은 연속된 사이클을 따라 순회합니다. 한 사이클의 너비가 원소 8개이므로 먼저 Packet을 버스 너비(bus width)인 8의 배수까지 패딩(padding)합니다. 그런 다음 레인당 PadPacket / 8개의 사이클과 사이클당 PadPacket % 8개의 원소로 나눕니다.

text
PadPacket = Packet # align_up(Packet::SIZE, 8)   (pad Packet up to the next multiple of 8)
OutTime   = [Time, Lane, PadPacket / 8]
OutPacket = [PadPacket % 8]

Packet::SIZE < 32일 때 [PadPacket / 8]::SIZE = ceil(Packet::SIZE / 8)은 패킷(packet)당 필요한 사이클(cycle) 수입니다. 예를 들어 Packet::SIZE = 4이면 1사이클, Packet::SIZE = 16이면 2사이클입니다.

rust
axes![N = 8, M = 4, P = 16];

/// Lane을 OutTime에 접어 넣습니다(fold).
fn lane_sequential<'l>(
    // 앞선 시간 축약기(Time Reducer)의 입력: Lane = m![N], Time = m![M], Packet = m![P].
    input: ContractTimeTensor<'l, { Tu::Main }, f32, m![1], m![1 # 2], m![1 # 256], m![N], m![M], m![P]>,
    // 출력(output): OutTime = m![M, N, P / 8] = [Time, Lane, Packet / 8], OutPacket = m![P % 8] = [Packet % 8].
) -> ContractTensor<'l, { Tu::Main }, f32, m![1], m![1 # 2], m![1 # 256], m![M, N, P / 8], m![P % 8]> {
    input.contract_lane::<m![M, N, P / 8], m![P % 8]>(LaneMode::Sequential)
}

제약(Constraints)

레인 접기(Lane Folder) 자체에는 별도의 제약이 없습니다. 여기서 선택한 LaneMode는 앞 단계 시간 축약기(Time Reducer)가 검사하는 슬롯 용량(slot capacity)의 한계를 결정합니다. 시간 축약기의 제약(Time Reducer Constraints)을 참고하세요.

성능(Performance)

Interleaved 모드(mode)에서는 Lane < 8일 때 처리량(throughput)이 Lane::SIZE / 8 비율로 줄어듭니다. 비활성 레인(inactive lane)에 해당하는 버스 위치(bus position)가 비기 때문입니다.

Sequential 모드(mode)에서 Packet::SIZE < 8이면 매 사이클(cycle) 전체 버스 너비(bus width)인 8개 대신 정확히 Packet::SIZE개 원소를 전달합니다. 예를 들어 패킷 축약기(Packet Reducer)가 bf16 패킷의 절반을 합쳐 Packet::SIZE = 4가 된 경우가 해당합니다. 사이클당 출력 너비는 작지만 패딩(padding)이 없고 버스 슬롯(bus slot)도 낭비하지 않습니다.

지연(latency)은 무시할 만큼 작습니다. 레인 접기(Lane Folder)는 레인별(per-lane) 출력을 재구성할 뿐이며, 버퍼(buffer)를 비우는 데 필요한 시간 외에 사이클(cycle)을 추가하지 않습니다.
