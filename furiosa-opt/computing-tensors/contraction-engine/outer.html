외적 단계(Outer)

외적 단계(Outer)는 두 피연산자(operand)를 같은 모양(shape)으로 브로드캐스트(broadcast)하고 원소별(elementwise)로 곱합니다.

이름 “Outer”는 선형대수(linear algebra)의 **외적(outer product)**에서 왔습니다. 길이가 n인 벡터 u와 길이가 m인 벡터 v에 대해 u v^T는 (u v^T)[i, j] = u[i] × v[j]인 n × m 행렬입니다. u를 길이 m의 열 축(column axis)으로, v를 길이 n의 행 축(row axis)으로 브로드캐스트(broadcast)한 뒤 원소별로 곱하면 이 행렬을 얻습니다. 외적 단계의 세 하위 단계(sub-stage)는 바로 이 의미(semantics)를 하드웨어로 구현한 것이며, 차례대로 실행합니다.

  • 스트림 어댑터(Stream Adapter)는 수집 엔진(Collect Engine)에서 오는 스트리밍 피연산자(streaming operand)를 처리하고 브로드캐스트(broadcast)합니다.
  • TRF 시퀀서(TRF Sequencer)는 TRF SRAM에서 오는 TRF 피연산자(operand)를 처리하고 브로드캐스트(broadcast)합니다.
  • 곱셈기(Multiplier)는 피연산자 타입(operand type)을 확장하고(i4 / i8 → i32, f8 / bf16 → f32), 정렬된 두 피연산자를 원소별(elementwise)로 곱합니다.

출력은 [Chip, Cluster, Slice, Lane, Time, Packet]이라는 결합 매핑(joint mapping)을 가진 하나의 곱 텐서(tensor)입니다. 이후 패킷 축약기(Packet Reducer)가 이를 더해 축약(reduce-add)합니다.

인터페이스(Interface)

CollectTensor의 .contract_outer(&trf)는 외적 단계(Outer)를 호출합니다.

rust
impl<
    'l,
    P: CanApplyContractOuter,
    D: Scalar + ContractionCast,
    Chip: M,
    Cluster: M,
    Slice: M,
    Time: M,
    Packet: M,
    B: Backend,
> TuTensor<'l, { Tu::Main }, P, D, Chip, Cluster, Slice, Time, Packet, B>
{
    /// 외적 단계(Outer)를 실행합니다. 아직 브로드캐스트하지 않고 누산기 타입(accumulator type)으로 확장한 두 피연산자와,
    /// [`super::ContractTimeTensor::contract_lane`]이 [`LazyContraction`]으로 결합하는 데 필요한 배치(layout)를 보관합니다.
    /// 실제 텐서를 생성하는 대체 경로나 백엔드별 분기는 없습니다. 모든 백엔드(backend)가 같은 방식으로 결합(fuse)합니다.
    ///
    /// impl 블록(block)은 [`ContractionCast`]로 한정하므로, 곱셈기(Multiplier)가 MAC을 제공하지 않는 원소 타입(element type)의
    /// `TuTensor`에는 이 메서드(method)가 존재하지 않습니다.
    ///
    /// main 문맥(context)에서만 사용할 수 있습니다.
    #[primitive(TuTensor::contract_outer)]
    pub fn contract_outer<OutTime: M, OutPacket: M, Lane: M, TrfElement: M, TrfD>(
        self,
        trf_tensor: &TrfTensor<TrfD, Chip, Cluster, Slice, Lane, TrfElement, B>,
    ) -> ContractOuterTensor<
        'l,
        { Tu::Main },
        <D as ContractionCast>::Output,
        D,
        Chip,
        Cluster,
        Slice,
        Lane,
        OutTime,
        OutPacket,
        B,
    >
    where
        D: Cast<<D as ContractionCast>::Output>,
        // 가중치(weight, TRF) 타입은 스트림(stream) 타입 `D`와 수축 연산기(contraction engine)가 허용하는 쌍을 이루어야 합니다.
        // 같은 타입이거나, 같은 계열(family) 안에서 정수 정밀도(integer precision)가 섞인 쌍이어야 합니다.
        // 허용하는 계열은 i4/i5 x i4/i5, i8/i9 x i8/i9입니다. 곱셈을 위해 두 피연산자(operand)를
        // 스트림의 누산기(accumulator) 타입으로 확장합니다.
        TrfD: Scalar + ContractionWeight<D> + Cast<<D as ContractionCast>::Output>,
    {
        type Out<D> = <D as ContractionCast>::Output;

        // 브로드캐스트 전치(broadcast transpose)를 생략해도 유효성 조건(validity contract)은 생략하지 않습니다. 그렇지 않으면 잘못된
        // 수축(contraction)이 이 검사를 통과한 뒤 훨씬 뒤쪽에서 패닉(panic)을 일으킬 수 있습니다.
        stream_adapter::verify_stream_adapter::<D, Lane, Time, Packet, OutTime, OutPacket>();
        trf_sequencer::verify_trf_sequencer::<TrfD, Lane, TrfElement, OutTime, OutPacket>();

        // 피연산자(operand)는 각자의 압축 배치(compact layout)를 유지합니다. lhs는 `[Chip, Cluster, Slice, Time, Packet]`
        // (`self.inner`), rhs는 `[Chip, Cluster, Slice, Lane, TrfElement]`(`trf_tensor`)입니다.
        // 원시 버퍼 백엔드(bare-buffer backend)는 여기서 스트라이드(stride)를 읽습니다. `MathStorage`는 축(axis)이
        // 저장소(storage) 안에 있으므로 이를 무시합니다.
        let lhs_map = <m![{ Chip }, { Cluster }, { Slice }, { Time }, { Packet }]>::to_value();
        let rhs_map = <m![{ Chip }, { Cluster }, { Slice }, { Lane }, { TrfElement }]>::to_value();
        let pre_reduce = <m![{ Chip }, { Cluster }, { Slice }, { Lane }, { OutTime }, { OutPacket }]>::to_value();

        // 각 피연산자(operand)를 미리 `Out<D>` 누산기(accumulator) 타입으로 확장합니다. 크기는 pre_reduce가 아니라
        // 각 피연산자 자체의 압축 크기(compact size)를 사용합니다. 이후 `contract_lane`의 접기(fold)는 모두 `Out<D>`에서 실행됩니다.
        // 원소마다 같은 `Cast::cast`를 사용하므로 예전의 셀별 확장(per-cell widen)과 결과가 정확히 같습니다. 다만 이전에 이 단계가 만들던
        // pre_reduce 모양의 브로드캐스트(broadcast)를 전혀 할당하지 않습니다.
        //
        let contraction = LazyContraction {
            lhs: self.inner.map(|v| -> Out<D> { v.cast() }).inner,
            rhs: trf_tensor.inner.map(|v| -> Out<D> { v.cast() }).inner,
            lhs_map,
            rhs_map,
            pre_reduce,
        };
        ContractOuterTensor::new(self.device, contraction)
    }
}

각 경로의 어댑터(adapter), 즉 스트리밍 경로의 스트림 어댑터(Stream Adapter)와 TRF 경로의 TRF 시퀀서(TRF Sequencer)를 거치면 두 경로는 같은 모양(shape)의 Lane / Time / Packet을 공급합니다. 곱셈기(Multiplier)는 정렬된 위치(position)끼리 원소별(elementwise)로 곱합니다.

스트리밍 피연산자(streaming operand)의 Time / Packet은 출력의 OutTime / OutPacket으로 매핑(mapping)됩니다. OutPacket은 패킹(Packing)으로 Time의 가장 안쪽 크기 1 또는 2인 인자(factor)를 흡수합니다. OutTime은 Time의 나머지 인자를 유지하며, 브로드캐스트(Broadcast)로 가장 안쪽 위치에 브로드캐스트 인자를 추가합니다. 브로드캐스트 인자는 TRF 피연산자의 Lane / Element에서 오거나(스트리밍 피연산자가 TRF 매핑에 맞춰 복제되는 경우), 입력과 TRF에는 없지만 OutTime / OutPacket에만 있는 출력 전용 축(purely-output axis)에서 옵니다. 예를 들어 einsum AB, BC -> ABCD의 D는 브로드캐스트됩니다.

TrfTensor의 모양(shape)은 [Chip, Cluster, Slice, Lane, Element]이며, Chip / Cluster / Slice / Lane은 공간상으로 병렬(spatially parallel)입니다. Chip / Cluster / Slice는 출력에 그대로 이어지고, Lane은 레인별 데이터를 하드웨어 레인(lane) 1~8개에 분할합니다. .to_trf()로 정한 레인별 배치(per-lane layout) Element는 TRF 시퀀서(TRF Sequencer)가 재구성하여 OutTime / OutPacket을 채웁니다.

스트림 어댑터(Stream Adapter)

스트림 어댑터(Stream Adapter)는 패킹(Packing)과 브로드캐스트(Broadcast)로 스트림의 Time / Packet을 계산 모양(computation shape)인 Lane / OutTime / OutPacket으로 바꿉니다. 컴파일러(compiler)는 사용자가 지정한 OutTime / OutPacket, TRF 피연산자(operand), 출력 전용 브로드캐스트 축(purely-output broadcast axis)에서 세 자유 변수(free variable) PackSize, LaneBroadcast, TimeBroadcast를 도출하여 다음 매핑(mapping)을 만듭니다.

text
Lane      = LaneBroadcast
OutTime   = [Time / PackSize, TimeBroadcast]
OutPacket = [Time % PackSize, Packet] # (64 / D::SIZE)

패킹(Packing)

수집 엔진(Collect Engine)은 32 B 플릿(flit)을 만들고, 외적 단계(Outer)는 PackSize × 32 B 패킷(packet)을 내보냅니다. RNGD에서는 32 또는 64 B입니다. 패킹(packing)은 연속된 플릿 PackSize ∈ {1, 2}개를 하나의 패킷으로 결합합니다.

text
PackTime   = [Time / PackSize]
PackPacket = [Time % PackSize, Packet] # (PackSize × 32 / D::SIZE)

PackSize는 OutPacket과 입력 Packet을 맞춰 정합니다. OutPacket이 Time의 가장 안쪽 크기 2인 인자(factor)를 흡수하면 PackSize = 2, 그렇지 않으면 PackSize = 1입니다. 같은 관계를 PackSize = OutPacket::SIZE * D::SIZE / 32로도 쓸 수 있습니다. 즉 사용자가 32 B 또는 64 B의 OutPacket을 선택하면, 패킹(packing)에 필요한 수집 플릿(collect-flit) 수가 따라 결정됩니다.

하드웨어는 내부적으로 항상 64 B 패킷(packet)을 처리합니다. PackSize = 1이면 쓰지 않는 32 B 절반에는 0이 들어가며, 이 값은 논리적 OutPacket 타입에는 포함되지 않습니다. 따라서 후단 단계인 패킷 축약기(Packet Reducer)와 레인 접기(Lane Folder)는 PackSize × 32 B의 실제 페이로드(payload)만 보며, 더미 사이클(dummy cycle)을 피할 수 있습니다. 레인 접기의 Sequential 설명을 참고하세요.

브로드캐스트(Broadcast)

패킹(packing) 후 스트림 어댑터(Stream Adapter)는 LaneBroadcast로 데이터를 공간 방향으로, TimeBroadcast로 시간 방향으로 브로드캐스트(broadcast)합니다. 이 공간 브로드캐스트는 TRF의 Lane 매핑(mapping)이며 값은 {1, 2, 4, 8} 중 하나입니다. TimeBroadcast는 입력 Time에 없는 TRF Element의 인자(factor)와, 입력·TRF 양쪽에 없으면서 OutTime에만 있는 출력 전용 축(purely-output axis)을 포함합니다. 같은 브로드캐스트 장치가 두 경우 모두에서 패킷(packet)을 복제합니다. 각 목적지는 같은 OutPacket을 받습니다.

text
Lane      = LaneBroadcast
OutTime   = [PackTime, TimeBroadcast]
OutPacket = PackPacket

TimeBroadcast 인자(factor)는 OutTime의 가장 안쪽(innermost) 위치에 놓입니다. 바깥쪽 PackTime 인자로 넘어가기 전에 같은 OutPacket을 이 인자들에 걸쳐 반복 전송합니다.

예제(Examples)

아래 예제는 두 연산을 모두 사용합니다. 패킹(Packing)은 Time의 가장 안쪽 크기 2인 인자 L을 Packet으로 흡수합니다(PackSize = 2). 레인 브로드캐스트(Lane Broadcast)는 만들어진 패킷을 N = 8개 레인(lane)에 분배하고, 시간 브로드캐스트(Time Broadcast)는 TRF에만 있는 B = 5 축(axis)에 걸쳐 스트리밍 데이터를 반복 배치합니다(tile).

rust
axes![M = 32, N = 8, K = 16, L = 2, B = 5];

fn stream_adapter_example<'l>(
    input: CollectTensor<'l, { Tu::Main }, bf16, m![1], m![1 # 2], m![1 # 256], m![M, L], m![K]>,
    trf: &TrfTensor<bf16, m![1], m![1 # 2], m![1 # 256], m![N], m![B, L, K]>,
) -> ContractOuterTensor<'l, { Tu::Main }, f32, bf16, m![1], m![1 # 2], m![1 # 256], m![N], m![M, B], m![L, K]> {
    // 패킹(Packing, PackSize = 2):
    //   L = 2(Time의 가장 안쪽)을 Packet으로 흡수합니다.
    //   PackTime = [M = 32], PackPacket = [L = 2, K = 16] = bf16 32개 = 64B.
    // 레인 브로드캐스트(Lane Broadcast): 모든 N = 8 레인에 같은 패킷을 보냅니다.
    // 시간 브로드캐스트(Time Broadcast): TRF에만 있는 B = 5를 OutTime의 가장 안쪽에 추가합니다.
    //   OutTime = [M, B = 5], OutPacket = [L = 2, K = 16].
    input.contract_outer::<m![M, B], m![L, K], _, _, _>(trf)
}

제약(Constraints)

  • RNGD에서는 OutPacket::SIZE * Storage::SIZE ∈ {32, 64}바이트입니다. 여기서 Storage는 확장 전 피연산자 데이터 타입(pre-widen operand dtype)입니다. 예를 들어 bf16은 2 B이며, 결과 텐서가 보유하는 확장된 f32 누산기(accumulator) 타입을 뜻하지 않습니다. PackSize = 1이면 32, PackSize = 2이면 64입니다. 사용자가 이 크기를 선택하면 패킹(packing)에 필요한 수집 플릿(collect-flit) 수가 따라 결정됩니다.
  • PackSize ∈ {1, 2}입니다(패킹(Packing) 참고).
  • Lane::SIZE ∈ {1, 2, 4, 8}.

성능(Performance)

PackSize는 곱셈·누산(MAC) 활용률(utilization)을 결정합니다. PackSize = 2는 64 B 전체를 채워 모든 MAC을 사용합니다. PackSize = 1은 32 B만 채우므로 0으로 패딩(padding)된 절반은 항상 0을 곱하게 되고, 실효 처리량(effective throughput)은 절반이 됩니다.

PackSize = 2는 패킷(Packet)당 2사이클(cycle)이 필요합니다. 32 B 플릿(flit) 두 개를 64 B 패킷 하나로 결합하기 때문입니다. 그래도 파이프라인 병목(bottleneck)은 되지 않습니다. 앞 단계가 최대 읽기 속도(full fetch rate)로 매 사이클 32 B 플릿 하나를 공급하므로, 스트림 어댑터(Stream Adapter)는 도착하는 플릿을 같은 속도로 소비하고 후단의 소비 속도에 맞춰 2사이클마다 패킷 하나를 내보냅니다.

시간 브로드캐스트(Time Broadcasting)는 읽기(fetch) 비용을 여러 번의 사용에 나누어 부담하게 합니다. 브로드캐스트 인자(factor)에 걸쳐 같은 스트리밍 패킷(packet)을 다시 읽지 않고 여러 사이클(cycle) 동안 재사용하므로, 이 인자들에 해당하는 대역폭(bandwidth) 비용이 없어집니다.

읽기(fetch)당 최대 32 B/사이클의 읽기 대역폭(fetch bandwidth)이 스트림 어댑터(Stream Adapter)의 전체 성능을 제한합니다. 활용률(utilization)을 높이려면 여러 슬라이스(slice)에 걸쳐 읽기 패턴(fetch pattern)을 교차 배치(interleave)하세요.

TRF 시퀀서(TRF Sequencer)

TRF 시퀀서(TRF Sequencer)는 TrfTensor를 읽고 Element를 패킷 축약기(Packet Reducer)에 보낼 OutTime / OutPacket으로 재구성(reshape)합니다. 레인(lane), 뱅크(bank), 행(row), 이중 버퍼링(double-buffering), 캐시(cache)를 포함한 TRF 저장 배치(storage layout)는 레지스터 파일(Register Files)을 참고하세요.

매핑(mapping)은 다음과 같습니다.

text
OutTime   = (sequencing over [Element / ReadSize] with broadcasts)
OutPacket = [PacketBroadcast, Element % ReadSize]

OutPacket은 매 사이클(cycle) TRF 읽기 한 번으로 채웁니다. 두 뱅크(bank)를 읽으면 레인(lane)당 640비트, 하나만 읽으면 320비트인 완전한 OutPacket 하나가 매 사이클 생성됩니다. 8개 레인을 합한 슬라이스(slice)당 바이트 수는 수축 연산기로 읽어 보내기(To Contraction Engine)를 참고하세요. 읽기는 Element의 가장 안쪽 연속 부분(innermost contiguous portion)을 가져오고, 이를 복제하여 64 B OutPacket을 채웁니다. 컴파일러(compiler)는 Element % ReadSize == OutPacket % ReadSize이면서 ReadSize * D::SIZE ≤ 64바이트인 가장 큰 ReadSize를 선택합니다. 넓은 ReadSize는 레인당 TRF 뱅크 두 개를 사용하고, 좁은 것은 하나만 사용합니다.

OutTime은 Element / ReadSize를 순회하고 필요한 경우 브로드캐스트(broadcast)하여 여러 사이클(cycle)에 걸쳐 채웁니다. TRF 시퀀서(TRF Sequencer)는 다른 모든 시퀀서(sequencer)와 같은 중첩 반복문 설정(nested-loop configuration)을 사용합니다.

예제(Examples)

이 예제에서는 64 B 읽기 한 번의 ReadSize가 Element 전체를 포함합니다. 따라서 Element / ReadSize는 크기 1의 단순한 값(trivial)이 되고, 시퀀서(sequencer)는 브로드캐스트(broadcast)만 반복합니다.

rust
axes![M = 32, N = 8, K = 32];

fn trf_sequencer_full_read<'l>(
    input: CollectTensor<'l, { Tu::Main }, bf16, m![1], m![1 # 2], m![1 # 256], m![M, K / 16], m![K % 16]>,
    trf: &TrfTensor<bf16, m![1], m![1 # 2], m![1 # 256], m![N], m![K]>,
) -> ContractOuterTensor<'l, { Tu::Main }, f32, bf16, m![1], m![1 # 2], m![1 # 256], m![N], m![M], m![K]> {
    // Element         = K
    // ReadSize        = 32
    // PacketBroadcast = 1
    // OutTime         = M      ([K / 32](= 1)을 순회하고, M을 브로드캐스트(broadcast))
    // OutPacket       = K      (= [1, K % 32])
    input.contract_outer::<m![M], m![K], _, _, _>(trf)
}

이 예제에서는 ReadSize가 Element의 일부만 포함합니다. 따라서 Element / ReadSize가 비자명(non-trivial)하며, 시퀀서(sequencer)는 브로드캐스트(broadcast)와 함께 Element의 바깥쪽 인자(outer factor)를 순회합니다.

rust
axes![M = 32, N = 8, K = 16, L = 2, O = 2];

fn trf_sequencer_partial_read<'l>(
    input: CollectTensor<'l, { Tu::Main }, bf16, m![1], m![1 # 2], m![1 # 256], m![O, M, L], m![K]>,
    trf: &TrfTensor<bf16, m![1], m![1 # 2], m![1 # 256], m![N], m![O, K]>,
) -> ContractOuterTensor<'l, { Tu::Main }, f32, bf16, m![1], m![1 # 2], m![1 # 256], m![N], m![O, M], m![L, K]> {
    // Element         = [O, K]
    // ReadSize        = 16
    // PacketBroadcast = L
    // OutTime         = [O, M]    ([O, K] / 16(= O)을 순회하고, M을 브로드캐스트(broadcast))
    // OutPacket       = [L, K]    (= [L, [O, K] % 16])
    input.contract_outer::<m![O, M], m![L, K], _, _, _>(trf)
}

제약(Constraints)

  • 하드웨어 차원(hardware dimension): Chip::SIZE, Cluster::SIZE, Slice::SIZE는 하드웨어 구성(configuration)과 일치해야 합니다. 공간 차원과 시간 차원(Spatial and Temporal Dimensions)을 참고하세요.
  • 주소 정렬(address alignment): Element % ReadSize가 64 B 전체를 포함하면 읽기가 레인(lane)마다 TRF 뱅크(bank) 두 개에 걸칩니다. 따라서 시퀀서(sequencer)의 기준 주소(base address)와 모든 스트라이드(stride)는 64 B 경계에 맞아야 합니다.

구조(Architecture)

여러 사이클(cycle)에 걸쳐 시퀀서(sequencer)는 다른 모든 시퀀서와 같은 중첩 반복문 설정(nested-loop configuration)으로 Element의 바깥쪽 인자(outer factor), 즉 Element / ReadSize를 순회합니다. 따라서 TrfTensor 하나의 내용을 모두 소비하기까지 Element / ReadSize개의 사이클을 진행합니다. PacketBroadcast 인자(factor)는 한 사이클 안에서 같은 행(row)을 복제합니다. 원래의 ReadSize를 넘어 64 B OutPacket을 채우면서도 추가 TRF 읽기 대역폭(read bandwidth)은 소비하지 않습니다.

성능(Performance)

처리량(throughput)은 레인(lane)당 매 사이클(cycle) 완전한 OutPacket 하나입니다. 두 뱅크(bank)를 읽을 때 레인당 640비트, 한 뱅크만 읽을 때 320비트입니다. 슬라이스(slice)당 총 바이트 수는 레지스터 파일: 수축 연산기로 읽어 보내기(Register Files: To Contraction Engine)를 참고하세요. TRF 읽기 캐시(read cache)와 뱅크 교대(bank alternation)는 브로드캐스트(broadcast) 재사용과 좁은 읽기(narrow read) 중에 동시에 진행하는 sub 문맥 저장(store)이 막히지 않게 돕습니다(레지스터 파일: 이중 버퍼링(Register Files: Double Buffering) 참고).

곱셈기(Multiplier)

곱셈기(Multiplier)는 스트림 어댑터(Stream Adapter)와 TRF 시퀀서(TRF Sequencer)가 보내는 정렬된 두 피연산자(operand)를 받습니다. 후단 누산기(accumulator)의 오버플로(overflow)를 방지하기 위해 각 입력 원소(element)를 수축 출력 타입(contraction output type)으로 확장하고, 원소별(elementwise)로 곱합니다. 출력은 [Chip, Cluster, Slice, Lane, Time, Packet]이라는 결합 매핑(joint mapping)의 단일 텐서(tensor)이며, 패킷 축약기(Packet Reducer)의 입력이 됩니다. 각 Time 사이클마다 모든 Lane이 곱셈 결과를 담은 완전한 packet을 병렬로 생성합니다.

피연산자 타입(Operand types)

곱셈기(Multiplier)가 허용하는 피연산자 쌍(operand pair)과 각 쌍을 확장하는 타입은 다음과 같습니다.

스트림(Stream, 활성값 activation) 가중치(Weight, TRF) 누산기(Accumulator)
i4 또는 i5 i4 또는 i5 i32
i8 또는 i9 i8 또는 i9 i32
f8e4m3 f8e4m3 f32
f8e5m2 f8e5m2 f32
bf16 bf16 f32

정수 피연산자(integer operand)는 원래 형태인 i4/i8이거나, 영점 빼기(Zero-Point Subtraction)로 생성한 준비용 형태(staging) i5/i9일 수 있습니다. 같은 계열(family) 안에서는 두 피연산자의 타입이 정확히 같지 않아도 됩니다. 그러나 계열을 넘나들거나(i4와 i8의 조합), 종류(kind)를 섞을 수는 없습니다(정수와 부동소수점의 조합). 부동소수점(float) 쌍은 타입이 정확히 같아야 합니다.

이 표에 없는 원소 타입(element type)의 수축(contraction)은 벡터 엔진(Vector Engine)에서 수행합니다. 먼저 원소별(elementwise)로 곱한 다음, i32 / f32로 계산하는 슬라이스 내부 축약(Intra-Slice Reduce)로 합칩니다.
