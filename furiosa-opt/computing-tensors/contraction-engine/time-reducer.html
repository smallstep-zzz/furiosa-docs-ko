시간 축약기(Time Reducer)

원문 대조 메모 · 번역자 설명

예제 코드와 주석에는 B / 16이 쓰이지만, 뒤의 누산기 설명에는 B / 4가 등장합니다. 두 표기는 원문부터 서로 다릅니다. 예제를 따라갈 때에는 실제 코드의 축(axis) 크기와 표현식을 함께 확인하세요.

시간 축약기(Time Reducer)는 *시간 누산기(temporal accumulator)*를 사용하여 패킷 축약기(Packet Reducer)의 [Lane, Packet] 출력을 Time에 걸쳐 OutTime으로 누적합니다.

인터페이스(Interface)

.contract_time::<OutTime>()은 시간 축약기(Time Reducer)를 호출합니다. OutTime은 Time의 차원(dimension) 중 남길 것들을 지정합니다. 나머지 차원은 합산되어 사라집니다.

rust
impl<'l, D: Scalar, Chip: M, Cluster: M, Slice: M, Lane: M, Time: M, Packet: M, B: Backend>
    ContractPacketTensor<'l, { Tu::Main }, D, Chip, Cluster, Slice, Lane, Time, Packet, B>
{
    /// 공유 누산 버퍼(accumulator buffer)를 통해 각 사이클(cycle)의 수축 결과를 `Time` 차원(dimension)에 걸쳐
    /// 누적하여 입력 `Time`을 `OutTime`으로 줄입니다. `Time`에 있지만
    /// `OutTime`에는 없는 축(axis)을 따라 합산 축약(reduce-add)합니다.
    ///
    /// main 문맥(context)에서만 사용할 수 있습니다.
    #[primitive(ContractPacketTensor::contract_time)]
    pub fn contract_time<OutTime: M>(
        self,
    ) -> ContractTimeTensor<'l, { Tu::Main }, D, Chip, Cluster, Slice, Lane, OutTime, Packet, B> {
        verify_contract_time(ContractTimeInput {
            in_time: Time::to_value(),
            out_time: OutTime::to_value(),
        });
        // 지연된 피연산자(deferred operand)를 아직 축약하지 않고 전달합니다. `contract_lane`의 결합 수축(fused contraction)이
        // 이 Time 축약도 수행합니다. 이 단계에서는 전달 객체(carrier)의 타입만 `OutTime`으로 바꿉니다.
        ContractTimeTensor::new(self.device, self.inner, Time::to_value())
    }
}

예를 들어 아래 커널(kernel)은 2차원 텐서(tensor)를 B 축으로 축약(reduce)하여 A만 남깁니다.

rust
axes![A = 2048, B = 32];

/// B를 따라 축약(reduce)하고 A를 남깁니다.
fn reduce_b<'l>(
    // 스트리밍 피연산자(streaming operand): Slice = m![A / 8](A 바깥쪽 덩어리 256개를 슬라이스에 분산).
    // Time = m![B / 16, A % 8]; Packet = m![B % 16].
    // B를 Packet(B % 16)과 Time(B / 16)에 나눕니다. 사이클(cycle)마다 부분합(partial sum)을 만듭니다.
    input: CollectTensor<'l, { Tu::Main }, bf16, m![1], m![1 # 2], m![A / 8], m![B / 16, A % 8], m![B % 16]>,
    // TRF 피연산자(operand): 슬라이스(slice)마다 레인(lane) 하나의 가중치(weight).
    trf: &TrfTensor<bf16, m![1], m![1 # 2], m![A / 8], m![1], m![B]>,
    // 출력(output): (슬라이스, A % 8) 셀(cell)마다 f32 하나.
) -> ContractTensor<'l, { Tu::Main }, f32, m![1], m![1 # 2], m![A / 8], m![A % 8], m![1 # 8]> {
    input
         // Outer: Lane = m![1], OutTime = m![B / 16, A % 8], OutPacket = m![B % 16].
         .contract_outer::<m![B / 16, A % 8], m![B % 16], _, _, _>(trf)
         // 패킷 축약기(Packet Reducer): OutPacket = m![1]. B % 16을 공간상에서 합칩니다.
         .contract_packet::<m![1]>()
         // 시간 축약기(Time Reducer): OutTime = m![A % 8]. 누산기(accumulator)는
         // Time::SIZE = (B / 16) × (A % 8) = 2 × 8 = 16개의 플릿(flit)을 받습니다. 바깥쪽 B / 16
         // 덩어리(chunk)를 A % 8로 인덱싱(indexing)하는 슬롯(slot) 8개에 누적합니다.
         .contract_time::<m![A % 8]>()
         // 레인 접기(Lane Folder): Lane을 OutPacket에 접습니다. Sequential 모드(Lane = m![1]).
         .contract_lane::<m![A % 8], m![1 # 8]>(LaneMode::Sequential)
}

구조(Architecture)

시간 축약기(Time Reducer)는 패킷 축약기(Packet Reducer)가 사이클(cycle)마다 생성하는 [Lane, Packet] 출력을 받습니다. 앞 단계에서 하드웨어는 공간상으로 병렬인 레인(lane)을 Lane::SIZE ≤ 8, 패킷을 Packet::SIZE ≤ 32로 제한합니다.

매 사이클(cycle), 시간 축약기(Time Reducer)는 [Lane, Packet] 공간 격자(spatial grid)를 Time에 걸쳐 OutTime으로 접어 모읍니다. OutTime은 Time의 부분집합(subset)이어야 하며, 남아 있는 차원(dimension)의 상대적 순서를 보존해야 합니다. 이 조건은 verify_contract_time이 강제합니다. Time에 있지만 OutTime에는 없는 차원은 합산되어 사라집니다. 그중 가장 바깥쪽 차원은 플릿(flit)을 순회합니다.

InnerTime은 Time의 안쪽 비축약 차원(inner non-reduce dimension), 즉 가장 바깥쪽 축약 차원보다 안쪽에 있으면서 OutTime에도 남는 차원을 뜻한다고 합시다. 위의 reduce_b에서는 Time = m![B / 4, A % 8], OutTime = m![A % 8]이므로 B / 4가 가장 바깥쪽 축약 차원입니다. 이 차원은 Time::SIZE = 2 × 8 = 16개의 플릿(flit)을 순회하며, InnerTime = m![A % 8]입니다.

누적(accumulation)에는 [Lane, Packet]을 담는 슬롯(slot)이 InnerTime::SIZE개 필요합니다. InnerTime 튜플(tuple)의 각 값마다 슬롯 하나를 둡니다. 같은 튜플을 가진 플릿(flit)은 같은 슬롯에 누적됩니다. reduce_b에서는 슬롯 8개가 B / 4 = 2회의 반복에 걸쳐 누적합니다. 플릿 15 이후 버퍼(buffer)에는 최종 축약 결과가 들어 있으며, 이를 레인 접기(Lane Folder) 단계에 전달합니다.

text
Time = m![B / 4, A % 8]
          ~~~~~  ~~~~~
        outer R  inner non-R (A % 8)

Flit sequence (B / 4 has values 0,1; A % 8 has values 0..7):

  flit #0:  B/4=0, A%8=0  ──→ ┌─────────────────┐
  flit #8:  B/4=1, A%8=0  ──→ │ slot 0 (A%8=0)  │  accumulates B for A%8=0
                              └─────────────────┘

  flit #1:  B/4=0, A%8=1  ──→ ┌─────────────────┐
  flit #9:  B/4=1, A%8=1  ──→ │ slot 1 (A%8=1)  │  accumulates B for A%8=1
                              └─────────────────┘
   ⋮

  flit #7:  B/4=0, A%8=7  ──→ ┌─────────────────┐
  flit #15: B/4=1, A%8=7  ──→ │ slot 7 (A%8=7)  │  accumulates B for A%8=7
                              └─────────────────┘

  8 non-reduce positions → 8 slots used

제약(Constraints)

InnerTime::SIZE가 슬롯 용량(slot capacity), 즉 버퍼(buffer)에 들어가는 슬롯 수를 넘지 않아야 매핑(mapping)이 버퍼에 들어갑니다.

슬롯 용량(slot capacity)은 버퍼(buffer)의 1,024개 셀(cell)과 후단 레인 접기(Lane Folder)의 LaneMode에 의해 정해집니다. 슬롯 하나는 [Lane, Packet] 덩어리(chunk)이며, 그 모양(shape)은 LaneMode가 결정합니다. 따라서 슬롯 수는 1,024를 덩어리당 셀 수로 나눈 값입니다.

LaneMode 덩어리 모양(Chunk shape) 덩어리당 셀 수(Cells per chunk) 슬롯 용량(Slot capacity)
Interleaved [Lane # 8, Packet] 8 × Packet::SIZE 128 / Packet::SIZE
Sequential [Lane, Packet # 32] Lane::SIZE × 32 32 / Lane::SIZE

reduce_b 뒤에 .contract_lane(LaneMode::Sequential)을 두고 Lane::SIZE = 1이면, 슬롯 용량(slot capacity)은 32이므로 InnerTime::SIZE = 8은 충분히 들어갑니다. InnerTime::SIZE가 용량을 넘으면 Time을 재구성하거나(예: B를 더 나누기), LaneMode를 바꾸어 처리량(throughput)과 슬롯 여유 사이의 균형을 조정해야 합니다.

성능(Performance)

입력 쪽 처리량(throughput)은 사이클(cycle)당 패킷(packet) 하나입니다. 입력 N개를 출력 하나로 축약하면 실효 출력률(effective output rate)은 입력률의 1 / N이 됩니다.

크기 N인 Time 차원(dimension)을 축약(reduction)할 때의 지연(latency)은 약 N사이클(cycle)입니다.
