읽기 어댑터(Fetch Adapter)

읽기 어댑터(Fetch Adapter)는 읽기 엔진(Fetch Engine)이 내보낸 패킷 스트림(packet stream)에 형 변환(type casting), 마스킹(masking), 테이블 조회(table lookup), 영점 빼기(zero-point subtraction) 같은 원소별 변환을 적용합니다. 이 처리는 교환 엔진(Switch Engine)이 슬라이스(slice) 사이로 데이터를 전달하기 전에 일어납니다. 읽기 엔진 자체는 이러한 변환을 수행하지 않습니다. 변환은 이 텐서 계산(Computing Tensors) 장에서 설명하는 별도의 단계로, 읽기 엔진과 교환 엔진 사이에 놓입니다. 커널 작성자는 FetchTensor에 단계별 메서드(method)를 직접 연결하며, 호출할 때마다 다음 단계로 진행합니다.

어댑터(adapter)에는 사용할 수 있는 단계(stage)가 세 개 있습니다. 모두 선택 사항이며, 하드웨어 파이프라인(hardware pipeline) 순서대로 스트림(stream)의 해당 메서드를 호출합니다. 어댑터 메서드를 하나도 호출하지 않고 FetchTensor를 교환 엔진(Switch Engine)이나 수집 엔진(Collect Engine)에 바로 전달해도 됩니다.

  • 테이블 조회(Table Lookup)는 하드웨어 조회 테이블(lookup table)로 값을 바꿉니다.
  • 형 변환(Type Casting)은 원소 타입(element type)을 변환합니다.
  • 영점 빼기(Zero-Point Subtraction)는 양자화 영점(quantization zero point)을 빼고, 정수 스트림을 수축 연산기(Contraction Engine)의 준비용 타입(staging type)으로 확장합니다. i4는 i5로, i8은 i9로 바뀝니다.

테이블 조회(Table Lookup)

테이블 조회(table lookup)는 읽기(fetch) 단계에서 하드웨어 가속 조회 테이블을 제공합니다. 각 입력값을 미리 설정한 테이블의 인덱스(index)로 해석하고, 입력값 대신 해당 테이블 항목(entry)을 출력합니다. Sigmoid와 GeLU 같은 비선형 활성화 함수(non-linear activation function), 또는 사용자 지정 인코딩 테이블(custom encoding table)을 쓰는 양자화(quantization) 방식처럼, 일반적인 산술 연산만으로 효율적으로 구현하기 어려운 연산에 유용합니다. 다음과 같은 용도로 사용할 수 있습니다.

  • 비선형 활성화(non-linear activation): 미리 계산한 조회 테이블(lookup table)로 Sigmoid, GeLU 등의 함수를 구현합니다.
  • 사용자 지정 형 변환(custom type casting): 변환 테이블(conversion table)로 MXFP4 / NVFP4 같은 특수 인코딩을 표준 형식으로 바꿉니다.

Sigmoid와 GeLU는 벡터 엔진(Vector Engine)에서도 직접 표현할 수 있습니다. 따라서 테이블 조회(table lookup)는 이 활성화 함수들을 구현하는 여러 방법 중 하나입니다.

rust
// 테이블 조회(table lookup)는 **main 문맥 전용(main-context-only)** 하드웨어 기능입니다. main Fetch Unit의
// 조회 테이블 레지스터(lookup-table register)만 상주 테이블을 가리킬 수 있으므로, 이 구현은
// `{ Tu::Main }`으로 고정됩니다. StoTrf 가중치 준비 경로가 사용하는 sub 문맥의 Fetch Unit에는
// 테이블 조회 레지스터가 없습니다. 따라서 압축 가중치(packed weight)의 디코딩은 main 문맥에서 읽으며 수행하고,
// 디코딩된 스트림을 DM에 기록해야 합니다. 그 뒤 변환만 수행하는 일반 StoTrf가 이를 TRF에 적재합니다.
impl<
    'l,
    P: CanApplyFetchTableLookup,
    D: MaterializableScalar,
    Chip: M,
    Cluster: M,
    Slice: M,
    Time: M,
    Packet: M,
    B: Backend,
> TuTensor<'l, { Tu::Main }, P, D, Chip, Cluster, Slice, Time, Packet, B>
{
    /// 읽기 어댑터(Fetch Adapter)의 테이블 조회(table-lookup) 단계를 실행합니다(main 문맥 전용).
    ///
    /// 각 입력값은 `TableLookupCast` 구현(impl)이 선택한 디코딩 테이블(decode table)의 인덱스가 됩니다.
    /// 런타임 인수(runtime argument)로 선택하지 않습니다. `f4e2m1`은 쌍 단위(paired) 4b->8b 테이블로
    /// 두 8비트 부동소수점(float) 타입 중 하나로 디코딩합니다(NVFP4 / MXFP4 가중치 경로). 각 8비트 부동소수점은
    /// 쌍 단위가 아닌(non-paired) 테이블로 `bf16`으로 디코딩합니다. 쌍 단위 디코딩 결과를 `f32`로 확장하려면
    /// [`fetch_cast`](Self::fetch_cast)를 연결하세요. 블록별 스케일(per-block scale)은
    /// 후단의 벡터 엔진(Vector Engine) 또는 수축 연산기(Contraction Engine)에서 적용합니다.
    /// 문서의 `computing-tensors/fetch-adapter.md` 장에서 “테이블 조회(Table Lookup)”를 참고하세요.
    ///
    /// main 문맥(context)에서만 사용할 수 있습니다. 조회 테이블(lookup table)은 main Fetch Unit의 레지스터에 있고
    /// sub 문맥에는 해당 레지스터가 없습니다. 디코딩한 가중치를 수축(contraction)에 쓰려면 여기서 디코딩한
    /// `f8e4m3` 스트림을 DM에 기록하고, 변환만 수행하는 일반 StoTrf로 그 DM 텐서를 TRF에 적재하세요.
    #[primitive(TuTensor::fetch_table_lookup)]
    pub fn fetch_table_lookup<OutD: Scalar>(
        self,
    ) -> FetchTableLookupTensor<'l, { Tu::Main }, OutD, Chip, Cluster, Slice, Time, Packet, B>
    where
        D: TableLookupCast<OutD>,
    {
        FetchTableLookupTensor::new(self.device, self.inner.map(|v| v.lookup()))
    }
}

디코딩 테이블(decode table)은 실행 시 인수(runtime argument)가 아니라 입력 스칼라 타입(input scalar type)의 TableLookupCast 트레이트(trait)로 선택합니다. fetch_cast가 입력 타입에 따라 변환을 선택하는 방식과 같습니다. 키 너비(key width)가 테이블을 결정하고, 요청한 출력 타입이 항목 인코딩(entry encoding)을 결정합니다.

입력(Input) 출력(Output)
f4e2m1 f8e4m3, f8e5m2
f8e4m3 bf16
f8e5m2 bf16

디코딩된 8비트 부동소수점(float)은 뒤이어 fetch_cast를 호출하여 f32로 확장하세요. NVFP4 / MXFP4의 블록별 스케일(per-block scale)은 후단의 벡터 엔진(Vector Engine)이나 수축 연산기(Contraction Engine)에서 적용합니다. 스케일은 의도적으로 테이블에 포함하지 않습니다. 테이블은 블록과 무관한 16개 항목의 정적 디코딩(static decode)으로 유지됩니다.

f4e2m1 디코딩(decode) 테이블은 컴파일 시 상수(compile-time constant)로 읽기 시퀀서(fetch sequencer) 설정에 포함됩니다. 따라서 이 단계의 데이터 입력은 f4e2m1 가중치 스트림(weight stream) 하나뿐이며, 호출할 때마다 테이블을 별도로 준비하지 않습니다. 16개 항목의 e2m1 디코딩은 블록과 무관하므로 블록별 스케일(per-block scale)을 포함하지 않습니다. 스케일까지 테이블에 넣으면 블록마다 다른 테이블이 필요해져 공통 정적 테이블을 공유할 수 없게 됩니다.

하드웨어 시퀀서(sequencer)는 바이트 경계에 맞춘 1바이트 또는 2바이트 키(key)를 순회하며, 4비트 니블(nibble)을 직접 읽지 않습니다. 따라서 4비트 키에는 쌍 단위(paired) 테이블이 필요합니다. f4e2m1 디코딩은 바이트로 인덱싱하는 256개 항목의 테이블로 수행합니다. 각 바이트는 니블 두 개를 담고, 한 번 조회하면 디코딩된 f8e4m3 값 두 개가 나옵니다. 즉 키 하나당 원소 두 개를 디코딩합니다. 이에 맞춰 f4e2m1 스칼라(scalar)는 니블 두 개를 담는 바이트로 모델링합니다. 다만 BITS = 4로 두어 읽기 매핑(fetch mapping)이 바이트가 아니라 원소의 개수를 계산하도록 합니다.

rust
axes![A = 8];

/// 하드웨어 테이블(hardware table)로 e2m1(NVFP4 / MXFP4) 가중치 스트림(weight stream)을 f8e4m3로 디코딩하고,
/// 이어지는 fetch_cast로 f32로 확장합니다.
fn fetch_decode_e2m1<'l, const T: Tu>(
    input: BeginTensor<'l, T, f4e2m1, m![1], m![1], m![1], m![1], m![A]>,
) -> FetchCastTensor<'l, T, f32, m![1], m![1], m![1], m![1], m![A]> {
    input
        .fetch::<m![1], m![A]>()
        .fetch_table_lookup::<f8e4m3>()
        .fetch_cast::<f32>()
}

형 변환(Type Casting)

fetch_cast::<OutD>()는 Time과 Packet 매핑(mapping)을 유지하면서 원소 타입(element type)을 D에서 OutD로 변환합니다. 형 변환(type casting)은 1~2사이클(cycle)의 지연(latency)을 추가합니다. fetch_cast는 타입 변환만 수행합니다. 영점 오프셋(zero-point offset)을 담기 위한 정수 확장(i4 → i5, i8 → i9)은 별도의 영점 빼기(Zero-Point Subtraction) 단계이므로, fetch_cast는 i5/i9를 만들지 않습니다.

rust
impl<
    'l,
    const T: Tu,
    P: CanApplyFetchCast,
    D: MaterializableScalar,
    Chip: M,
    Cluster: M,
    Slice: M,
    Time: M,
    Packet: M,
    B: Backend,
> TuTensor<'l, T, P, D, Chip, Cluster, Slice, Time, Packet, B>
{
    /// 읽기 어댑터(Fetch Adapter)의 형 변환(type-casting) 단계를 실행합니다.
    ///
    /// 스트림(stream)의 원소 타입(element type)을 `D`에서 `OutD`로 변환합니다. 매핑(mapping)의
    /// 모양(shape)은 유지합니다.
    #[primitive(TuTensor::fetch_cast)]
    pub fn fetch_cast<OutD: Scalar>(self) -> FetchCastTensor<'l, T, OutD, Chip, Cluster, Slice, Time, Packet, B>
    where
        D: FetchCast<OutD>,
    {
        FetchCastTensor::new(self.device, self.inner.map(|v| v.cast()))
    }
}

RNGD는 아래의 변환만 지원합니다. 모든 확장(widening)은 계산 너비(compute width)인 i32 / f32로 이어지며, 축소(narrowing)는 f32 → bf16만 가능합니다.

입력(Input) 출력(Output)
i4 i32
i8 i32
i16 i32
f8e4m3 f32
f8e5m2 f32
bf16 f32
f32 bf16

읽기 어댑터(Fetch Adapter)에는 8비트 부동소수점(float)을 bf16으로 바꾸는 형 변환도, f32를 8비트 부동소수점으로 바꾸는 형 변환도 없습니다. f8e4m3 스트림을 bf16으로 만들려면 쌍 단위가 아닌(non-paired) 테이블 조회(Table Lookup) 테이블로 디코딩하세요. 8비트 부동소수점으로 만들려면 파이프라인 후단의 형 변환 엔진(Cast Engine)에서 정밀도를 줄여야 합니다.

아래 예제는 원소(element) 8개의 i8 스트림을 읽고 i32로 형 변환(cast)합니다. 호출 전후로 Time과 Packet 매핑(mapping)은 유지됩니다.

rust
axes![A = 8];

/// 형 변환(type casting)을 적용해 읽습니다. 계산을 위해 i8 저장값을 i32로 변환합니다.
/// 입력(Input):   i8 [0, 1, 2, 3, 4, 5, 6, 7]
/// 출력(Output): i32 [0, 1, 2, 3, 4, 5, 6, 7]
fn fetch_with_type_cast<'l, const T: Tu>(
    input: BeginTensor<'l, T, i8, m![1], m![1], m![1], m![1], m![A]>,
) -> FetchCastTensor<'l, T, i32, m![1], m![1], m![1], m![1], m![A]> {
    input.fetch::<m![1], m![A]>().fetch_cast::<i32>()
}

형 변환(type casting)을 사용하면 read_size에 추가 제약이 생깁니다. 한 번 읽어서 변환한 출력은 32바이트 플릿(flit) 하나에 들어가야 합니다. 수집 엔진(Collect Engine)을 참고하세요.

  • 유효한 경우(Valid):
    • i4 -> i32, read_size = 8 (4 bytes): 8 × 4 = 32 B를 생성합니다.
    • i8 -> i32, read_size = 8 (8 bytes): 8 × 4 = 32 B를 생성합니다.
  • 유효하지 않은 경우(Invalid):
    • i4 -> i32, read_size = 16 (8 bytes): 16 × 4 = 64 B를 생성합니다.
    • i8 -> i32, read_size = 16 (16 bytes): 16 × 4 = 64 B를 생성합니다.

영점 빼기(Zero-Point Subtraction)

fetch_zero_point_sub::<OutD>(zero_point)는 각 원소(element)에서 양자화(quantization)의 zero_point를 빼고, 스트림을 수축 연산기(Contraction Engine)의 준비용 타입(staging type)으로 확장합니다. i4는 i5로, i8은 i9로 바뀝니다. i5/i9를 생성하는 단계는 이것뿐입니다.

rust
impl<
    'l,
    const T: Tu,
    P: CanApplyFetchZeroPointSub,
    D: MaterializableScalar,
    Chip: M,
    Cluster: M,
    Slice: M,
    Time: M,
    Packet: M,
    B: Backend,
> TuTensor<'l, T, P, D, Chip, Cluster, Slice, Time, Packet, B>
{
    /// 읽기 어댑터(Fetch Adapter)의 영점 빼기(zero-point-subtraction) 단계를 실행합니다.
    ///
    /// `zero_point`를 빼고 스트림(stream)을 `D`에서 수축 연산기(contraction engine)의 준비용
    /// 타입(staging type) `OutD`(`i4 -> i5`, `i8 -> i9`)로 확장합니다. i5/i9 스트림을 만드는 유일한
    /// 방법입니다. 결과는 `contract_outer`에만 전달할 수 있습니다. 이 타입은
    /// [`MaterializableScalar`]가 아니므로 쓰기(commit)나 다른 경로로의 전달(re-routing)은 컴파일
    /// 오류(error)가 됩니다. 매핑 모양(mapping shape)은 유지합니다.
    ///
    /// `zero_point`가 원본 타입(source type)의 범위를 벗어나면 패닉(panic)을 일으킵니다.
    /// 범위는 [`FetchZeroPointSub::ZERO_POINT_RANGE`]입니다. 범위 안의 영점(zero point)은
    /// 확장된 모든 잔차(widened residual)를 `OutD` 안에 유지하므로, 스트림 데이터와 무관한
    /// 이 검사 하나면 충분합니다.
    #[primitive(TuTensor::fetch_zero_point_sub)]
    pub fn fetch_zero_point_sub<OutD: Scalar>(
        self,
        zero_point: i32,
    ) -> FetchZeroPointSubTensor<'l, T, OutD, Chip, Cluster, Slice, Time, Packet, B>
    where
        D: FetchZeroPointSub<OutD>,
    {
        let zero_point_range = <D as FetchZeroPointSub<OutD>>::ZERO_POINT_RANGE;
        assert!(
            zero_point_range.contains(&zero_point),
            "zero_point {zero_point} is outside the source type's quantized range {zero_point_range:?}",
        );
        FetchZeroPointSubTensor::new(self.device, self.inner.map(|v| v.zero_point_sub(zero_point)))
    }
}

비트(bit)가 하나 더 필요한 이유

영점(zero point)을 빼면 zero_point를 중심으로 부호 없이 표현하던 양자화 값(quantized value)이 부호 있는 잔차(signed residual)로 바뀌며, 그 범위는 원래 입력 너비(width)에 들어가지 않을 수 있습니다. 대칭적인 부호 있는 입력(symmetric-signed input)에서 잔차는 같은 너비의 두 값의 차이입니다.

  • i4 잔차(residual): [-8, 7] - [-8, 7] = [-15, 15]이므로, i5의 범위 [-16, 15]가 필요합니다.
  • i8 잔차(residual): [-128, 127] - [-128, 127] = [-255, 255]이므로, i9의 범위 [-256, 255]가 필요합니다.

따라서 이 뺄셈(subtraction)은 입력보다 한 비트(bit) 더 넓은 결과를 만듭니다. 변환 과정은 실행 시(runtime) 이 조건을 검사합니다. zero_point나 입력이 범위를 벗어나 잔차(residual)가 i5/i9 범위 밖으로 나가면, 조용히 순환(wrap)시키지 않고 거부합니다.

수축 연산 전용 준비 타입(Contraction-Only Staging)

i5/i9 스트림은 교환 엔진(Switch Engine)과 수집 엔진(Collect Engine)을 통과할 수 있습니다. 그러나 그다음에 합법적으로 받을 수 있는 연산은 contract_outer뿐입니다. 이 연산은 피연산자 타입(Operand types)에 설명한 방식으로 가중치(weight)와 짝을 이룹니다. 이 스트림을 메모리에 쓰거나, 레지스터 파일(register file)에 저장하거나(to_trf/to_vrf), 전치(transpose)하거나, 다른 엔진으로 전달할 수는 없습니다.

이 제약은 실행 시 검사(runtime check)가 아니라 컴파일 시점(compile time)에 적용합니다. i5/i9 스트림을 contract_outer가 아닌 연산에 전달하면 컴파일 오류(compile error)가 발생합니다.
