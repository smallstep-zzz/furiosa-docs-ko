텐서 계산(Computing Tensors)

이 장에서는 유효한 텐서 유닛(Tensor Unit) 스트림이 벡터 엔진(Vector Engine)이나 수축 연산기(Contraction Engine)에 도달하는 과정을 설명합니다. 한 피연산자(operand)는 레지스터 파일(register file)에 머물고, 다른 피연산자는 스트림 형태로 연산기를 통과합니다. 텐서 레지스터 파일(Tensor Register File, TRF)은 수축 연산의 피연산자를, 벡터 레지스터 파일(Vector Register File, VRF)은 벡터 연산의 피연산자를 저장합니다. 이 장에서는 피연산자를 배치하고 스트림의 차원(dimension)을 유지하는 각 엔진의 동작을 살펴봅니다.

계산 경로(compute route) 선택

텐서 유닛(Tensor Unit)

텐서 유닛(Tensor Unit)은 칩 내부(on-chip)의 계산 파이프라인(compute pipeline)입니다. 데이터 메모리(DM)에서 텐서 데이터를 읽고, 10개 엔진을 거치며 변환한 다음 결과를 DM에 다시 씁니다.

각 텐서(tensor)는 사이클(cycle)마다 패킷(packet) 하나를 전달하는 스트림(stream) 형태로 파이프라인을 흐릅니다. 엔진은 이 스트림을 입력받아 새로운 스트림을 만들면서, 사이클 내부의 배치(layout)와 반복 순서(iteration order)를 바꿉니다. 수집 엔진(Collect Engine)은 입력 패킷을 32바이트 단위인 *플릿(flit)*으로 정규화(normalize)합니다. 그 뒤의 모든 엔진은 이 플릿을 처리합니다. 이후 파이프라인에는 수축(Contraction), 벡터(Vector), 형 변환(Cast), 전치(Transpose), 쓰기 어댑터(Commit Adapter), 쓰기(Commit) 단계가 있습니다. 자세한 내용은 수축 연산기(Contraction Engine), 벡터 엔진(Vector Engine), 형 변환 엔진(Cast Engine), 전치 엔진(Transpose Engine), 쓰기 어댑터(Commit Adapter), 쓰기 엔진(Commit Engine)에서 확인할 수 있습니다.

엔진(Engine) 기능(Function) 주요 제약(Key Constraint)
읽기(Fetch) DM의 데이터를 파이프라인(pipeline)으로 읽어 들입니다. 패킷(packet)은 8바이트 경계에 정렬되어야 합니다. 축 올리기(axis lifting)가 브로드캐스트(broadcast)를 Time의 축으로 대체하는 경우를 제외하면 Slice는 유지됩니다.
읽기 어댑터(Fetch Adapter) 읽은 뒤 원소별 변환(element-wise transform)을 수행합니다. 예: 테이블 조회(table lookup), 형 변환(cast). 선택 사항입니다. 생략하면 항등 변환(identity)으로 통과합니다.
교환(Switching) 슬라이스(slice) 사이에서 데이터를 이동합니다. 링 네트워크(ring network)를 사용하며 Slice가 바뀔 수 있습니다.
수집(Collect) 패킷(packet)을 32바이트 플릿(flit)으로 정규화합니다. 출력은 정확히 플릿(flit) 하나입니다.
수축(Contraction) 아인슈타인 합 표기(Einsum)로 표현하는 행렬곱(matmul), 합성곱(convolution), 어텐션(attention). 한 피연산자(operand)는 TRF에 상주하고, 다른 피연산자는 스트림(stream)으로 전달됩니다.
벡터(Vector) 원소별(elementwise) 연산, 두 입력을 사용하는 이항(binary) 연산, 축약(reduce) 연산. 입력은 i32/f32만 가능합니다.
형 변환(Cast) 묶음 처리(batching)를 동반한 정밀도 축소(precision lowering). 출력은 정확히 플릿(flit) 하나입니다.
전치(Transpose) 플릿(flit) 안에서 원소의 순서를 바꿉니다. 플릿(flit) 내부에서만 가능합니다.
쓰기 어댑터(Commit Adapter) 쓰기 전에 원소별 변환(element-wise transform)을 수행합니다. 예: 형 변환(cast), ReLU, 잘라내기(trim). 선택 사항입니다. .commit() 앞에 메서드를 연결합니다.
쓰기(Commit) 결과를 DM에 다시 씁니다. 플릿(flit) 경계에 맞추어 씁니다.

텐서 유닛(Tensor Unit) 내부의 각 텐서 스트림(tensor stream)에는 [Chip, Cluster, Slice, Time, Packet]이라는 다섯 차원(dimension)이 있으며, 두 부류로 나뉩니다. Chip, Cluster, Slice는 공간 차원(spatial dimension)입니다. 각 슬라이스(slice)가 독립된 파이프라인 인스턴스(pipeline instance)를 실행하고, 슬라이스는 클러스터(cluster)에, 클러스터는 칩(chip)에 속합니다. Time과 Packet은 각 슬라이스 내부의 스트림을 나타냅니다. 정의는 공간 차원과 시간 차원(Spatial and Temporal Dimensions)을 참고하세요. 위의 엔진들은 파이프라인을 따라 Time / Packet을 재구성합니다. 대부분의 엔진은 공간 차원을 유지합니다. 교환(Switch)은 슬라이스 간에 데이터를 이동합니다. 읽기(Fetch)의 축 올리기(axis lifting)는 Chip, Cluster, Slice에 따라 서로 다른 DM 읽기 오프셋(offset)을 부여하여 축(axis)을 Time에서 꺼냅니다. 벡터 슬라이스 간 축약기(Vector inter-slice reducer)는 클러스터 안의 256개 슬라이스의 값을 결합합니다.

수축 연산기(Contraction Engine)와 벡터 엔진(Vector Engine)은 각각 한 피연산자(operand)를 파이프라인 스트림에서 받고, 다른 피연산자는 슬라이스별 전용 레지스터 파일(register file)에서 받습니다. 텐서 레지스터 파일(Tensor Register File, TRF)은 수축 연산기에, 벡터 레지스터 파일(Vector Register File, VRF)은 벡터 엔진에 값을 공급합니다. 수집 엔진(Collect Engine)은 .to_trf()로 TRF에, .to_vrf()로 VRF에 씁니다. 두 파일을 함께 사용하는 전체 예제는 빠른 시작(Quick Start)을 참고하세요.

읽기(Fetch)는 DM에서 읽고, 쓰기(Commit)는 DM에 다시 씁니다. 이들의 구체적인 시퀀서(sequencer) 동작은 텐서 이동(Moving Tensors)에서 설명합니다.

실행 문맥(Execution Context)

스케줄러(scheduler)는 각 *실행 문맥(execution context)*을 독립적인 연산 스트림으로 취급합니다. 하드웨어는 다음 세 가지를 제공합니다.

  • **주 실행 문맥(Main)**은 커널(kernel)의 핵심 계산을 위해 텐서 유닛(Tensor Unit) 파이프라인을 구동합니다.
  • **보조 실행 문맥(Sub)**은 같은 파이프라인의 일부를 구동합니다. 일반적으로 main이 계산하는 동안 피연산자(operand)를 TRF / VRF에 미리 읽어 들입니다(prefetch).
  • DMA는 텐서 유닛(Tensor Unit) 외부의 DMA 엔진만 구동합니다.

다음 단계(stage)를 제외하면 모든 텐서 유닛(Tensor Unit) 단계는 두 문맥(context)에서 모두 사용할 수 있습니다. 각 행의 제약은 타입 시스템(type system)이 강제합니다.

단계(Stage) 문맥(Context)
contract_outer main
commit_cast, commit_cast_relu main
fetch_table_lookup main
memset sub

to_trf와 to_vrf는 두 문맥(context)에서 모두 사용할 수 있습니다. 두 메서드는 모두 sub 문맥을 통해 쓰므로, main 문맥에서 사용하는 형태는 sub 문맥을 인수(argument)로 받아 쓰기가 진행되는 동안 보유합니다.

문맥(context) 간 순서, 실행 겹침(overlap), 자원 충돌(resource conflict), 메모리 규칙에 따른 스케줄링(scheduling)은 스케줄(Schedule)에서 설명합니다.
