전치 엔진(Transpose Engine)

전치 엔진(Transpose Engine)은 Chip, Cluster, Slice 차원(dimension)은 그대로 두고 Time과 Packet 차원을 교환합니다.

인터페이스(Interface)

CollectTensor와 VectorFinalTensor는 모두 .transpose()를 제공합니다. VectorFinalTensor에서 호출하면 벡터 엔진(Vector Engine)의 출력을 전치 엔진으로 직접 전달합니다.

rust
// `D: MaterializableScalar`(해당 문서 참고)는 준비용 타입(staging) i5/i9를 전치(transpose) 대상에서 제외합니다.
impl<
    'l,
    const T: Tu,
    P: CanApplyTranspose,
    D: MaterializableScalar,
    Chip: M,
    Cluster: M,
    Slice: M,
    Time: M,
    Packet: M,
    B: Backend,
> TuTensor<'l, T, P, D, Chip, Cluster, Slice, Time, Packet, B>
{
    /// 전치 연산(transpose operation)을 수행합니다.
    #[primitive(TuTensor::transpose)]
    pub fn transpose<OutTime: M, OutPacket: M>(
        self,
    ) -> TransposeTensor<'l, T, D, Chip, Cluster, Slice, OutTime, OutPacket, B> {
        verify_transpose::<D, Time, Packet, OutTime, OutPacket>();
        TransposeTensor::new(self.device, self.inner.transpose(false))
    }
}

커널(kernel) 작성자는 출력 차원 배치(output dimension layout)인 OutTime과 OutPacket을 선택합니다. 컴파일러(compiler)는 매개변수(Parameters)에 나열된 하드웨어 제약(hardware constraint)에 맞는지 결과를 검증합니다.

아래 예제는 8×16 i8 행렬(matrix)을 전치(transpose)합니다. 너비가 16인 각 행(row)은 입력 패킷(packet) 두 개(D = 2)를 모아 만듭니다. 이 페이지의 나머지 설명에서도 같은 예제를 계속 사용합니다.

rust
axes![P = 256, B = 2, C = 8, D = 2, E = 8];

fn basic_transpose<'l, const T: Tu>(
    input: CollectTensor<'l, T, i8, m![1], m![1 # 2], m![P], m![B, C, D], m![E # 32]>,
) -> TransposeTensor<'l, T, i8, m![1], m![1 # 2], m![P], m![B, D, E], m![C # 32]> {
    input.transpose()
}

구조(Architecture)

아래에서는 인터페이스(Interface)의 예제로 전치(transpose)의 다섯 단계를 설명합니다.

매개변수(Parameters)

valid_size는 전치 엔진(Transpose Engine)이 32바이트 입력 버스(input bus)에서 사이클(cycle)마다 읽는 유효 원소(valid element)의 수입니다. 각 입력 플릿(flit)은 bit-width × valid_size 형태로 들어오며, 32바이트 중 나머지 바이트는 패딩(padding)으로 취급하여 풀기(Unpack) 단계에서 버립니다. 8비트와 16비트 원소는 두 배 입력 패킹(doubled input packing)을 선택하여 기본 8개 대신 플릿당 유효 원소 16개를 읽을 수 있습니다. 4비트와 32비트 원소는 두 배 패킹을 지원하지 않습니다. 데이터는 CollectTensor::transpose()로 Fetch → [Switch →] Collect → [Cast →] Transpose 경로를 거치거나, VectorFinalTensor::transpose()로 벡터 엔진(Vector Engine)에서 직접 옵니다. 수축 연산기(Contraction Engine)는 32b × 8만 출력합니다. 벡터 엔진과 읽기 엔진(Fetch Engine)은 아래 표의 모든 조합을 출력할 수 있습니다.

in_cols, in_rows, out_rows는 커널(kernel) 작성자가 선택한 OutTime, OutPacket에 의해 정해집니다. 네 값 모두 원소 크기(element size)에 따른 제약을 받습니다.

원소 크기(Element size) 단일 패킹의 valid_size(Single) 두 배 패킹의 valid_size(Doubled) 최대 in_rows(Max) 유효한 in_cols(Valid)
4비트(4-bit) 16 지원하지 않음(unsupported) 16 16, 32
8비트(8-bit) 8 16 8 8, 16, 32
16비트(16-bit) 8 16 4 8, 16, 32
32비트(32-bit) 8 지원하지 않음(unsupported) 2 8, 16, 32

계속 사용하는 예제는 i8이므로 valid_size = 8입니다. 컴파일러(compiler)는 다음 값을 도출합니다.

매개변수(Parameter) 값(Value) 설명(Notes)
in_cols 16 모은 패킷(packet) D = 2개 × valid_size = 8
in_rows 8 C::SIZE
out_rows 16 D·E(= in_cols, 전체 사용)
text
                 in_cols                  in_rows # F
           ┌─────────────────┐         ┌──────────────────┐
           │ 12 13 14 15 ... │         │ 3  7  11 15  ... │
 in_rows   │ 8  9  10 11 ... │  ────►  │ 2  6  10 14  ... │  out_rows

           └─────────────────┘         └──────────────────┘
                data_in                      data_out

풀기(Unpack)

각 32바이트 입력 패킷(packet)은 valid_size개의 유효 원소(valid element)를 담습니다. 풀기(Unpack) 단계는 플릿(flit)의 나머지를 패딩(padding)으로 버립니다. 8비트 또는 16비트 패킷에 기본 앞쪽 8개를 넘는 실제 원소(live element)가 있으면 컴파일러(compiler)는 두 배 패킹(doubled packing)을 선택합니다. 선택한 valid_size는 여전히 실제 값이 있는 앞부분(live prefix) 전체를 포함해야 하며, 나머지 레인(lane)은 모두 패딩이어야 합니다.

이 예제에서는 [C, D, E # 32] → [C, D, E]입니다.

예를 들어 i8 패킷(packet) [B=16 # 32]는 두 배 패킹(doubled packing)을 사용해 한 사이클(cycle)에 실제 원소(live element) 16개를 모두 제공합니다. 같은 의미의 단일 패킹(single-packed) 배치는 연속된 패킷 두 개에서 각각 8개 원소를 제공합니다. i4 패킷은 두 배 형태를 요청할 수 없습니다. 지원하는 valid_size가 16 하나뿐이기 때문입니다.

모으기(Gather)

입력 행렬(input matrix)의 한 행(row) 너비는 in_cols = packets_per_col × valid_size개 원소이며, 가장 안쪽 시간 단계(time step)에 해당하는 연속된 packets_per_col개 패킷(packet)으로 구성합니다. 모으기(Gather) 단계는 이 패킷들을 하나의 행으로 이어 붙입니다(concatenate). 그 바깥의 in_rows개 시간 단계를 쌓으면 [in_rows × in_cols] 입력 행렬이 됩니다. 풀기(Unpack)와 모으기는 모두 엔진이 입력을 읽는 동안 이루어지며, 별도의 버퍼(buffer)에 담아 두고 두 번 처리하는 과정이 아닙니다.

이 예제에서는 가장 안쪽 D = 2개 패킷(packet)이 각각 valid_size = 8개 원소를 제공해 너비 in_cols = 16인 행(row)을 만듭니다. 그 바깥의 C = 8개 시간 단계(time step)를 쌓으면 [8 × 16] 입력 행렬(input matrix)이 됩니다.

전치(Transpose)

행렬(matrix)을 전치(transpose)합니다. [in_rows × in_cols] → [in_cols × in_rows]입니다.

이 예제에서는 [C, D, E] → [D, E, C]입니다.

잘라내기(Trim)

일부 입력 패킷(packet)의 유효 원소(valid element)가 valid_size보다 적으면 전치한 행렬(transposed matrix)에 패딩된 행(padded row)이 생깁니다. 잘라내기(Trim) 단계는 그 행을 제거하여 [out_rows × in_rows]를 만듭니다. 여기서 out_rows ≤ in_cols입니다.

이 예제에서는 [D, E, C] → [D, E, C]입니다. 입력을 모두 사용하므로 잘라낼 행(row)이 없습니다. 실제로 잘라내기(Trim)가 행을 버리는 경우는 작은 행렬(Small Matrix) 예제를 참고하세요.

정렬 맞추기(Align)

전치한 행(transposed row)의 너비는 in_rows개 원소지만 DM 패킷(packet)은 32바이트여야 합니다. 정렬 맞추기(Align) 단계는 각 행을 32바이트 플릿(flit) 크기로 패딩(padding)하여 [out_rows × (in_rows # F)] 모양(shape)을 만듭니다. F는 D[F]가 32바이트가 되도록 선택합니다.

이 예제에서는 [D, E, C] → [D, E, C # 32]입니다.

지연(Latency)

참고(Note) 계산식은 먼저 성능(Performance) 절에서 확인하세요.

이 예제에서는 in_cols = 16 ≤ 16이므로 이중 버퍼링(double buffering)을 선택합니다. in_flits = 16, out_rows = 16, n = 2이므로 전체 지연(total latency)은 16 + 1 × max(16, 16) + 16 = 48사이클(cycle)입니다.

예제(Examples)

작은 행렬(Small Matrix)

이 예제는 out_rows < in_cols일 때 잘라내기(Trim) 단계가 패딩된 행(padded row)을 버리는 모습을 보여 줍니다.

rust
axes![P = 256, A = 4, B = 2];

fn small_transpose<'l, const T: Tu>(
    input: CollectTensor<'l, T, i8, m![1], m![1 # 2], m![P], m![A], m![B # 32]>,
) -> TransposeTensor<'l, T, i8, m![1], m![1 # 2], m![P], m![B], m![A # 32]> {
    input.transpose()
}

매개변수(Parameters):

매개변수(Parameter) 값(Value) 설명(Notes)
in_cols 8 B::SIZE = 2를 8까지 패딩(padding)
in_rows 4 A::SIZE
out_rows 2 B::SIZE

단계(Stages):

  • 풀기(Unpack): [A, B # 32] → [A, B # 8].
  • 모으기(Gather): [A, B # 8] → [A, B # 8]. packets_per_col = 1이므로 각 패킷(packet)이 이미 완전한 in_cols = 8 행(row)입니다.
  • 전치(Transpose): [A, B # 8] → [B # 8, A].
  • 잘라내기(Trim): [B # 8, A] → [B, A]. 패딩된 행(padded row) 6개를 제거합니다.
  • 정렬 맞추기(Align): [B, A] → [B, A # 32].

지연(latency): in_cols = 8 ≤ 16이므로 이중 버퍼링(double buffering)을 선택합니다. in_flits = 4, out_rows = 2, n = 1이므로 총 4 + 0 × max(4, 2) + 2 = 6사이클(cycle)입니다.

열이 많은 경우(Large Column)

이 예제는 in_cols > 16으로 만들어 단일 버퍼링(single buffering)을 사용하게 합니다. 입력과 출력을 겹쳐 실행할 수 없으므로 전체 사이클(total cycle) 수가 늘어납니다.

rust
axes![P = 256, B = 2, C = 8, D = 4, E = 8];

fn large_col_transpose<'l, const T: Tu>(
    input: CollectTensor<'l, T, i8, m![1], m![1 # 2], m![P], m![B, C, D], m![E # 32]>,
) -> TransposeTensor<'l, T, i8, m![1], m![1 # 2], m![P], m![B, D, E], m![C # 32]> {
    input.transpose()
}

매개변수(Parameters):

매개변수(Parameter) 값(Value) 설명(Notes)
in_cols 32 D::SIZE × E::SIZE
in_rows 8 C::SIZE
out_rows 32 D::SIZE × E::SIZE

단계(Stages):

  • 풀기(Unpack): [C, D, E # 32] → [C, D, E].
  • 모으기(Gather): 가장 안쪽 D = 4개 패킷(packet)이 각 in_cols = 32 행(row)을 만들고, C = 8개 시간 단계(time step)를 쌓아 [8 × 32] 입력 행렬(input matrix)을 만듭니다.
  • 전치(Transpose): [C, D, E] → [D, E, C].
  • 잘라내기(Trim): [D, E, C] → [D, E, C]. 제거하는 행(row)은 없습니다.
  • 정렬 맞추기(Align): [D, E, C] → [D, E, C # 32].

지연(latency): in_cols = 32 > 16이므로 단일 버퍼링(single buffering)을 선택합니다. in_flits = 32, out_rows = 32, n = 2(B)이므로 총 2 × (32 + 32) = 128사이클(cycle)입니다.

16비트 데이터 타입(16-bit Data Type)

이 예제는 bf16을 사용합니다. 원소(element)가 더 넓어 최대 in_rows는 절반인 4가 되고(8 대신 4), 32바이트 출력 플릿(output flit)의 원소 수는 16개로 줄어듭니다(i8에서는 32개).

rust
axes![P = 256, C = 8, D = 4, E = 8];

fn bf16_transpose<'l, const T: Tu>(
    input: CollectTensor<'l, T, bf16, m![1], m![1 # 2], m![P], m![C, D], m![E # 16]>,
) -> TransposeTensor<'l, T, bf16, m![1], m![1 # 2], m![P], m![C, E], m![D # 16]> {
    input.transpose()
}

매개변수(Parameters):

매개변수(Parameter) 값(Value) 설명(Notes)
in_cols 8 E::SIZE
in_rows 4 D::SIZE
out_rows 8 E::SIZE

단계(Stages):

  • 풀기(Unpack): [D, E # 16] → [D, E].
  • 모으기(Gather): [D, E] → [D, E]. packets_per_col = 1이므로 각 패킷(packet)이 이미 완전한 in_cols = 8 행(row)입니다.
  • 전치(Transpose): [D, E] → [E, D].
  • 잘라내기(Trim): [E, D] → [E, D]. 제거하는 행(row)은 없습니다.
  • 정렬 맞추기(Align): [E, D] → [E, D # 16].

지연(latency): in_cols = 8 ≤ 16이므로 이중 버퍼링(double buffering)을 선택합니다. in_flits = 4, out_rows = 8, n = 8(C)이므로 총 4 + 7 × max(4, 8) + 8 = 68사이클(cycle)입니다.

4비트 데이터 타입(4-bit Data Type)

이 예제는 i4를 사용합니다. valid_size = 16이므로 사이클당 원소 수(per-cycle element count)가 두 배가 되고, 최대 in_rows는 16으로 늘어납니다(16 × 4비트 = 8바이트). 32바이트 플릿(flit)은 원소 64개를 담습니다.

rust
axes![P = 256, B = 4, C = 16, E = 16];

fn i4_transpose<'l, const T: Tu>(
    input: CollectTensor<'l, T, i4, m![1], m![1 # 2], m![P], m![B, C], m![E # 64]>,
) -> TransposeTensor<'l, T, i4, m![1], m![1 # 2], m![P], m![B, E], m![C # 64]> {
    input.transpose()
}

매개변수(Parameters):

매개변수(Parameter) 값(Value) 설명(Notes)
in_cols 16 E::SIZE
in_rows 16 C::SIZE
out_rows 16 E::SIZE

단계(Stages):

  • 풀기(Unpack): [C, E # 64] → [C, E].
  • 모으기(Gather): [C, E] → [C, E]. packets_per_col = 1이므로 각 패킷(packet)이 이미 완전한 in_cols = 16 행(row)입니다.
  • 전치(Transpose): [C, E] → [E, C].
  • 잘라내기(Trim): [E, C] → [E, C]. 제거하는 행(row)은 없습니다.
  • 정렬 맞추기(Align): [E, C] → [E, C # 64].

지연(latency): in_cols = 16 ≤ 16이므로 이중 버퍼링(double buffering)을 선택합니다. in_flits = 16, out_rows = 16, n = 4(B)이므로 총 16 + 3 × max(16, 16) + 16 = 80사이클(cycle)입니다.

32비트 데이터 타입(32-bit Data Type)

이 예제는 수축 연산기(Contraction Engine)가 출력하는 두 32비트 형식(format) 중 하나인 f32를 사용합니다. 출력은 32b × 8이며 f32 또는 i32입니다. 원소(element)가 더 넓어 최대 in_rows는 2가 되고(2 × 4바이트 = 8바이트), 32바이트 플릿(flit)은 원소 8개를 담습니다.

rust
axes![P = 256, B = 4, D = 2, E = 8];

fn f32_transpose<'l, const T: Tu>(
    input: CollectTensor<'l, T, f32, m![1], m![1 # 2], m![P], m![B, D], m![E # 8]>,
) -> TransposeTensor<'l, T, f32, m![1], m![1 # 2], m![P], m![B, E], m![D # 8]> {
    input.transpose()
}

매개변수(Parameters):

매개변수(Parameter) 값(Value) 설명(Notes)
in_cols 8 E::SIZE
in_rows 2 D::SIZE
out_rows 8 E::SIZE

단계(Stages):

  • 풀기(Unpack): [D, E # 8] → [D, E].
  • 모으기(Gather): [D, E] → [D, E]. packets_per_col = 1이므로 각 패킷(packet)이 이미 완전한 in_cols = 8 행(row)입니다.
  • 전치(Transpose): [D, E] → [E, D].
  • 잘라내기(Trim): [E, D] → [E, D]. 제거하는 행(row)은 없습니다.
  • 정렬 맞추기(Align): [E, D] → [E, D # 8].

지연(latency): in_cols = 8 ≤ 16이므로 이중 버퍼링(double buffering)을 선택합니다. in_flits = 2, out_rows = 8, n = 4(B)이므로 총 2 + 3 × max(2, 8) + 8 = 34사이클(cycle)입니다.

성능(Performance)

하나의 버스트(burst)는 n = OutTime::SIZE / out_rows번의 전치 반복(transpose iteration)을 실행합니다. 각 반복은 입력 플릿(input flit) in_flits = in_rows × (in_cols / valid_size)개와 출력 플릿(output flit) out_rows개를 이동합니다.

버퍼링 모드(Buffering Modes)

전치 엔진(Transpose Engine)에는 각각 열(column) 16개를 담는 내부 버퍼(internal buffer)가 두 개 있습니다. in_cols ≤ 16이면 컴파일러(compiler)가 이중 버퍼링(double buffering)을, 아니면 단일 버퍼링(single buffering)을 선택합니다. 이중 버퍼링은 입력과 출력을 겹쳐 전체 사이클(cycle) 수를 줄이고, 단일 버퍼링은 두 단계를 차례대로 실행합니다.

단일 버퍼링 지연(Single Buffering Latency)

전체 버스트 지연(total burst latency)은 n × (in_flits + out_rows)입니다. 두 버퍼(buffer)를 함께 사용하므로 각 반복(iteration)에서 입력 시간과 출력 시간이 더해집니다.

이중 버퍼링 지연(Double Buffering Latency)

전체 버스트 지연(total burst latency)은 in_flits + (n - 1) × max(in_flits, out_rows) + out_rows이며, 다음 세 단계로 나뉩니다.

  • 입력만 수행하는 단계(Input-only phase) (in_flits사이클): 첫 번째 버퍼(buffer)를 채웁니다.
  • 입출력이 겹치는 단계(Overlap phase) ((n - 1) × max(in_flits, out_rows)사이클): 한 버퍼(buffer)가 입력을 받는 동안 다른 버퍼는 동시에 출력합니다. 따라서 느린 쪽이 각 반복(iteration)의 속도를 결정합니다.
  • 출력만 수행하는 단계(Output-only phase) (out_rows사이클): 마지막 버퍼(buffer)를 비웁니다.
