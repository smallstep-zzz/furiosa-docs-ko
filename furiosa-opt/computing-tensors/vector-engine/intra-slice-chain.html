슬라이스 내부 체인(Intra-Slice Chain)

읽기 도움말 · 번역자 설명

스태시(stash)는 계산 중인 값을 잠시 저장해 뒤의 연산에서 한 번 읽는 슬롯(slot)입니다. 한 번 저장·한 번 읽기가 기본 규칙이며, 사용하면 컴파일러(compiler)가 슬라이스(slice)마다 VRF 1 KiB를 예약합니다. 미리 적재한 VRF 피연산자(operand)와 공간을 공유한다는 점을 먼저 기억하면 아래 설명을 읽기 쉽습니다.

슬라이스 내부 체인(Intra-Slice Chain)은 각 슬라이스(slice)의 데이터를 독립적으로 처리하며, 원소별 연산(elementwise operation)·이항 연산(binary operation)·슬라이스 내부 축약(reduction)을 수행합니다. 활성화(activation)나 정규화(normalization)처럼 수축 연산 뒤의 처리를 담당합니다. 예를 들어 \operatorname{sigmoid}(XW + b)를 계산할 때 XW는 수축 연산기(Contraction Engine)에서, 덧셈과 sigmoid 활성화는 슬라이스 내부 체인에서 실행합니다.

인터페이스(Interface)

아래 예제는 고정소수점 편향(fixed-point bias)을 더하고, 부동소수점 경로(float path)에서 sigmoid를 실행한 뒤(4-way로 줄였다가 다시 확장), 마지막으로 ReLU 클리핑(clip)을 적용합니다. 계산식은 output[a, b] = \max(\operatorname{sigmoid}(input[a, b] + 100), 0)입니다.

rust
axes![A = 512, B = 2];

fn staged_pipeline<'l, const T: Tu>(
    input: CollectTensor<'l, T, i32, m![1], m![B], m![A / 2], m![1], m![A % 2 # 8]>,
) -> VectorFinalTensor<'l, T, i32, m![1], m![B], m![A / 2], m![1], m![A % 2 # 8]> {
    input
    .vector_init()
    .vector_intra_slice_tag(TagMode::Zero)
    // input + 100
    .vector_fxp(FxpBinaryOp::AddFxp, 100)
    // i32 → f32(고정소수점(fixed-point), int_width = 31)
    .vector_fxp_to_fp(31)
    // 부동소수점 경로(float path)를 위해 Way8 → Way4로 바꿉니다.
    .vector_narrow_trim::<m![A % 2 # 4]>()
    // sigmoid(input + 100)
    .vector_fp_unary(FpUnaryOp::Sigmoid)
    // Way4 → Way8
    .vector_widen_pad::<m![A % 2 # 8]>()
    // f32 → i32
    .vector_fp_to_fxp(31)
    // max(sigmoid(input + 100), 0)
    .vector_clip(ClipBinaryOpI32::Max, 0)
    .vector_final()
}

진입 후 체인(chain)은 아래 파이프라인 단계(pipeline stage)를 정해진 순서로 통과합니다. 소프트웨어는 필요한 단계만 연결하고 나머지는 건너뜁니다. 위 예제에서도 Logic·FpDiv·Filter를 건너뜁니다. 각 행은 체인 내 위치(#), 단계 이름(Stage), 해당 단계를 실행하는 API 메서드(Method), 실행 폭(Way: 사이클당 원소 8개 또는 4개), 피연산자(operand)를 받는지 여부(Operand)를 나타냅니다. 자료형 시스템(type system)이 컴파일 시점에 모든 단계 전환을 검사하므로, 앞선 체인이 호환되는 상태에 도달한 뒤에만 해당 메서드를 호출할 수 있습니다. 단계별 설명은 아래 단계(Stages)를 참고하세요.

vector_reinterpret()는 의도적으로 표에서 제외했습니다. 특정 단계(stage)를 차지하지 않으며 어느 두 단계 사이에도 놓을 수 있기 때문입니다(재해석(Reinterpret) 참고).

각 단계(stage)는 8-way(사이클당 원소 8개) 또는 4-way(사이클당 원소 4개)로 실행됩니다. 부동소수점 연산부(floating-point cluster)는 다른 체인에 비해 ALU 처리량이 절반이므로 4-way로 동작하여 이를 맞춥니다. 따라서 부동소수점 경로를 사용하는 체인은 8-way로 진입한 후 부동소수점 단계 앞에서 Narrow(vector_narrow_split 또는 vector_narrow_trim)를 호출하고, 뒤에서 Widen(vector_widen_concat 또는 vector_widen_pad)을 호출하여 8-way로 돌아옵니다. 위 예제도 vector_narrow_trim, vector_fp_unary(Sigmoid), vector_widen_pad 순서로 정확히 이 과정을 수행합니다.

체인(chain)은 예제처럼 vector_final()로 종료하거나, vector_inter_slice_reduce()로 슬라이스 간 축약기(Inter-Slice Reducer)에 넘깁니다. 두 종료 경로 모두 8-way가 필요하므로, 현재 4-way 단계에 있다면 먼저 Widen을 거쳐야 합니다.

피연산자(Operands)

이항 연산(binary op)과 삼항 연산(ternary op)에는 두 종류의 슬롯(slot)이 있습니다. **스트림(stream)**은 체인을 따라 흐르는 현재 텐서, 즉 메서드 체인의 self로서 체인이 결정합니다. 하나 또는 두 개의 **피연산자(operand)**는 추가 입력입니다. 각 피연산자는 세 가지 출처 중 하나에서 가져옵니다.

출처(Source) 예(Example) 설명(Description)
상수(Constant) 100, 2.5f32 모든 원소에 브로드캐스트(broadcast)하는 스칼라(scalar)
VRF 텐서(VRF tensor) &vrf_tensor 벡터 엔진(Vector Engine)에 들어가기 전에 .to_vrf()로 미리 적재합니다.
임시 보관 값(Stash) Stash 앞선 체인 단계의 스냅샷(snapshot)으로, 아래에서 설명합니다.

삼항 연산(ternary op)인 FmaF는 (operand0, operand1) 쌍을 받습니다.

VRF 피연산자(operand)는 인덱서(indexer)가 슬라이스(slice)별로 읽으며, 다음 세 규칙을 따라야 합니다.

첫째, 피연산자의 Chip·Cluster·Slice는 스트림(stream)의 것과 같아야 합니다. 슬라이스(slice) s의 연산은 슬라이스 s가 가진 값을 읽으므로, 피연산자의 분할(partition)이 다르면 다른 슬라이스의 데이터를 조용히 읽는 대신 컴파일 오류가 납니다. 두 표현이 같은 슬라이스들을 가리킨다면 VrfTensor::reshape로 피연산자를 스트림의 분할에 맞춰 다시 표현할 수 있습니다. 예를 들어 이름 없는 m![256] 아래 복제된 피연산자를, 이름 있는 축으로 분할된 스트림에 제공하는 경우입니다.

둘째, 한 번의 접근(access), 즉 Packet(8-way에서는 레인 8개, 4-way에서는 4개)이 인덱서(indexer)의 한 단계이며 읽기 방식은 두 가지뿐입니다. **브로드캐스트(broadcast)**는 한 주소의 값을 모든 레인(lane)에 공급하고, **연속 읽기(contiguous)**는 연속된 Element 셀을 Packet개 읽습니다. 따라서 패킷의 축(axis)들은 피연산자의 가장 안쪽에 연속적으로 놓여 있거나, 피연산자에 아예 없어야 합니다. 피연산자의 바깥쪽 축을 따라 이동하는 패킷이나, 한 번의 접근 안에서 브로드캐스트 레인과 실제 데이터를 읽는 레인을 섞는 패킷은 표현할 인코딩(encoding)이 없어 거부됩니다.

셋째, 축(axis) 불일치는 방향에 따라 의미가 다릅니다. 피연산자(operand)에만 있고 스트림(stream)에는 없는 축은 해당 셀을 읽을 일이 없으므로 the stream leaves operand axes unmatched 오류로 거부됩니다. 반대로 스트림에만 있고 피연산자에는 없는 축은 브로드캐스트(broadcast)로 처리됩니다. 이렇게 하나의 피연산자를 스트림의 모든 행에 공급합니다.

같은 연산 메서드(op method)도 인수(argument)의 자료형에 따라 서로 다른 출처의 값을 가져옵니다.

rust
.vector_fxp(FxpBinaryOp::AddFxp, 100)         // 상수(constant)에서 피연산자를 가져옵니다.
.vector_fxp(FxpBinaryOp::MulInt, &vrf)        // VRF 텐서(tensor)에서 피연산자를 가져옵니다.
.vector_clip(ClipBinaryOpI32::Max, Stash)     // 앞서 설정한 임시 보관 값(stash)에서 피연산자를 가져옵니다.

Stash는 vector_stash()가 현재 텐서(tensor)를 스냅샷(snapshot)으로 보관한 값입니다. 뒤의 이항·삼항 연산은 Stash 피연산자(operand)로 이 값을 다시 읽습니다. 대표적인 용도는 max(f(x), x)와 같은 잔차(residual) 또는 건너뛰기 연결(skip connection)로, 중간 단계를 지나도 원래 x가 남아 있어야 하는 경우입니다. 별도의 피연산자 출처로 보이지만 실제 저장소는 VRF입니다. 현재 텐서의 일부를 VRF에 저장하고 그곳에서 다시 읽습니다. 텐서 유닛(Tensor Unit) 호출에서 stash를 사용하면, 실제 보관한 데이터양과 관계없이 컴파일러(compiler)는 슬라이스(slice)당 VRF 1,024 B를 보수적으로 예약합니다. 같은 호출에서 미리 적재한 VRF 텐서를 우변(RHS) 피연산자로 읽는다면 이 예약량을 고려해야 합니다. stash와 RHS가 8 KiB VRF를 공유하므로 RHS에는 슬라이스당 최대 7 KiB만 남습니다. vector_stash()는 Stashable 단계(Branch, Logic, Fxp, Narrow, Fp, FpDiv, Clip)에서 호출할 수 있습니다. 스냅샷은 텐서 유닛 호출이 끝날 때까지 유효하며, 이후 Stash를 받는 이항·삼항 연산에 전달됩니다. 슬롯(slot)은 한 번만 쓸 수 있어 두 번째 vector_stash()는 컴파일 오류입니다. 또한 자료형이 지정되므로 f32 stash는 f32 연산에만 전달할 수 있습니다. 저장과 읽기 사이에 형 변환이나 재해석(reinterpret)을 했다면 먼저 원래 자료형으로 되돌려야 합니다. 읽기도 한 번만 가능합니다. 읽으면 슬롯이 Occupied 상태를 벗어나므로 두 번째 Stash 읽기는 컴파일 오류입니다. 여러 번 읽어야 할 값은 stash가 아니라 반복 읽기가 가능한 VRF에 넣고 &vrf로 전달하세요. 매핑(mapping)은 현재 텐서를 따르므로 Narrow 전에 보관한 stash도 Widen 뒤에서 사용할 수 있습니다. 위의 일곱 단계는 VRF 쓰기 포트(write port)를 가진 일곱 체인 단계입니다. Widen의 출력에서는 피연산자 레지스터에 쓸 수 없으므로 목록에 포함되지 않습니다. 따라서 4-way 영역에서 계산한 값을 stash에 넣으려면 먼저 폭을 늘린 뒤 Clip 연산에서 보관하여 쓰기와 읽기를 모두 8-way 쪽에서 수행합니다. 쌍 모드(Pair Mode)에서는 stash를 사용할 수 없습니다. 또한 IntraFirst 경로로 슬라이스 간 축약기에 전환하면 stash가 사라지므로 vector_inter_slice_reduce() 전에 보관한 값은 이후 사용할 수 없습니다.

그다음 **인수 모드(argument mode)**가 스트림(stream)과 피연산자(operand)를 어느 슬롯(slot)에 놓을지 정합니다. 같은 연산으로 stream + operand 또는 operand - stream 등을 계산할 수 있는 이유입니다. 예를 들어 BinaryArgMode::Mode10은 두 슬롯을 바꾸므로 SubFxp가 operand - stream을 계산합니다.

rust
.vector_fxp_with_mode(FxpBinaryOp::SubFxp, BinaryArgMode::Mode10, 7)  // 7 - stream을 계산합니다.

BinaryArgMode는 이항 연산(binary op)의 두 슬롯(slot)에 스트림(stream)과 피연산자(operand)를 어떻게 넣을지 정합니다. 단항 연산(unary op)에는 모드가 없으며 항상 op(stream)으로 실행됩니다.

BinaryArgMode 슬롯(Slots) 계산(Computation)

Mode01 stream / operand op(stream, operand)(기본값, default)
Mode10 operand / stream op(operand, stream)
Mode11 operand / operand op(operand, operand)

Mode002 stream / stream / operand1 op(stream, stream, operand1)
Mode102 operand0 / stream / operand1 op(operand0, stream, operand1)

Mode021 stream / operand1 / operand0 op(stream, operand1, operand0)
Mode120 operand0 / operand1 / stream op(operand0, operand1, stream)

쌍 모드(Pair Mode)

쌍 모드(pair mode)는 원소를 교차 배치된(interleaved) 두 그룹으로 나눈 텐서에 체인을 실행하여, 두 그룹 사이의 관계를 계산합니다. 대응 원소의 덧셈이나 서로 다른 배율 적용(asymmetric scale)이 예입니다. 크기 2인 그룹 구분 축(grouping axis)을 가진 수집된 텐서(collected tensor)에, vector_init() 바로 뒤에서 vector_intra_slice_unzip()을 호출하여 진입합니다. vector_intra_slice_unzip()으로 체인을 시작하면 뒤에서 필터(Filter) 단계를 사용할 수 없습니다. 내부적으로 vector_intra_slice_unzip()은 각 원소의 그룹 축 위치로부터 GroupId를 구하고, TagMode 대신 분기 유닛(branch unit)의 개수 증가기(count augmenter)를 제어합니다. 체인을 시작할 때의 태그(tag)는 바뀌지 않습니다. 따라서 그룹 분할에는 이 경로를 사용해야 하며 TagMode::AxisToggle은 지원되는 방법이 아닙니다.

처리 흐름은 네 단계입니다.

  1. vector_intra_slice_unzip()이 입력을 두 개의 병렬 스트림(stream), 즉 그룹 0과 그룹 1로 분리합니다.
  2. 체인(chain)이 두 그룹을 보조를 맞춰 함께 진행시킵니다. 이것이 **쌍 상태(paired phase)**입니다.
  3. _zip 연산이 두 스트림(stream)을 다시 하나로 결합합니다. 이것이 **병합 상태(merged phase)**입니다.
  4. 병합된 스트림(stream)은 일반 체인처럼 vector_final()까지 계속 진행합니다.

쌍 상태(paired phase)의 단계는 두 종류로 나뉩니다.

  • **공통 단계(common stages)**인 vector_fxp_to_fp, vector_narrow_split, vector_widen_concat, vector_fp_to_fxp는 두 그룹에 동일하게 작용합니다. 쌍 상태에서는 vector_narrow_trim과 vector_widen_pad를 사용할 수 없으므로 _split·_concat 버전을 사용하세요.
  • **그룹별 연산(per-group ops)**은 각 그룹에 인수(argument)를 하나씩 받습니다.
    • 이항·삼항 연산(binary/ternary op)인 vector_fxp, vector_fp_binary, vector_fp_ternary, vector_clip 등은 어느 한쪽에 ()를 주어 그 그룹을 건너뛰거나, 양쪽에 서로 다른 피연산자(operand)를 줄 수 있습니다.
    • 단항 연산(unary op)인 vector_fp_unary는 예외입니다. (op, group0_apply, group1_apply) 플래그(flag)를 받으며, false인 그룹은 건너뜁니다.

쌍 모드(pair mode)는 연산에 따라 BinaryArgMode를 다르게 해석합니다. 그룹별 연산(vector_fxp_with_mode, vector_fp_binary_with_mode 등)은 각 그룹 안에서 모드를 독립적으로 적용합니다. 0은 해당 그룹의 스트림(stream), 1은 해당 그룹의 피연산자(operand)입니다. 반면 _zip 연산(vector_fxp_zip_with_mode 등)은 두 슬롯(slot)을 두 그룹의 스트림으로 해석합니다. 0은 그룹 0의 스트림이고 1은 그룹 1의 스트림입니다.

_zip BinaryArgMode 슬롯(Slots) 계산(Computation)
Mode00 group0 / group0 op(group0, group0)
Mode01 group0 / group1 op(group0, group1)(기본값, default)
Mode10 group1 / group0 op(group1, group0)
Mode11 group1 / group1 op(group1, group1)

쌍 모드(pair mode)의 제약 조건:

  • 쌍 모드(pair mode)의 전체 구간, 즉 쌍 상태(paired)와 병합 상태(merged) 모두에서 stash()와 filter()를 사용할 수 없습니다.
  • vector_intra_slice_reduce() 역시 _zip 이전과 이후를 포함한 쌍 모드(pair mode) 전체에서 사용할 수 없습니다. 축약기(reducer)가 그룹 조건(group condition)을 받지 않기 때문입니다.
  • _zip 이전인 쌍 상태(paired phase)에서는 그룹별 텐서(per-group tensor)에 vector_inter_slice_reduce()가 없으므로 슬라이스 간 축약기(inter-slice reducer)로 전환할 수 없습니다. _zip 이후의 병합 상태(merged phase)에서는 결과가 다시 Commitable이 되므로, 현재 단계가 전환을 지원한다면 vector_inter_slice_reduce()를 호출할 수 있습니다.
  • 두 그룹은 ALU 사용량을 공유합니다. 어느 한 그룹에서 사용한 ALU는 두 그룹 모두에서 이미 사용한 것으로 계산합니다.

단계(Stages)

한 단계(stage) 안에서 각 ALU는 텐서 유닛(Tensor Unit) 호출당 최대 한 번만 실행됩니다. 이는 여러 연산자가 단계 내부의 ALU 풀(pool)을 공유하는 Logic·Fxp·Fp·Clip에서 주로 중요합니다. 예를 들어 tanh와 sqrt가 모두 FpFpu ALU를 사용하므로 tanh(sqrt(x))를 한 번의 텐서 유닛 호출에 넣을 수 없습니다.

태그(Tag)

태그(Tag) 단계는 체인의 진입점이며, 플릿(flit) 안의 각 32비트 원소에 4비트 Tag(0~15)를 부여합니다. 뒤 단계들은 이를 조건부 연산(conditional operation)에 사용합니다. 비트 3(최상위 비트, MSB)은 GroupId이며, Filter와 쌍 모드(pair mode)가 원소를 그룹 0·그룹 1로 나눌 때 사용합니다. 비트 0~2는 비교 결과를 담는 범용 플래그 비트(flag bit)입니다.

TagMode는 각 원소의 4비트를 계산하는 방식을 선택합니다. 현재 사용할 수 있는 것은 Zero와 Comparison뿐입니다. 마지막 열에 표시한 것처럼 AxisToggle은 선언되어 있지만 컴파일할 수 없습니다. ValidCount와 Vrf는 두 실행 경로 모두에서 작동하기 전까지 열거형(enum) 자체에서 제외되어 있습니다.

TagMode 각 태그 비트(tag bit)를 채우는 방식 상태(Status)
Zero 네 비트가 모두 0입니다. 모든 원소의 tag = 0입니다. 사용 가능(Works)
Comparison([cmp0, cmp1, cmp2, cmp3]) 각 원소 x에서 cmp_i(x)가 참일 때에만 비트 i = 1입니다. 각 cmp_i는 비교할 경계값(boundary)을 가진 Cmp<D>이며, 스트림의 스칼라 자료형(scalar type)을 따라 경계값도 검사됩니다. 지원 종류는 Equal, Less, Greater, LessUnsigned, GreaterUnsigned, True, False입니다. 두 *Unsigned 비교는 원시 비트 패턴(raw bit pattern)을 비교합니다. 사용 가능(Works)
AxisToggle { axis } axis를 따라 비트 3(GroupId) = axis_index % 2가 됩니다. 비트 0~2는 0을 유지합니다. 컴파일 불가(not compilable). 호스트(host)에서는 실행되지만, 하위 수준 변환(lowering) 시 커널 컴파일 오류로 거부됩니다. 이 그룹 구성을 얻으려면 지원되는 방법인 vector_intra_slice_unzip()을 사용하세요.

예를 들어 i32 데이터와 Comparison([Cmp::Less(0), Cmp::Equal(5), Cmp::Greater(100), Cmp::True])를 사용하면, 원소 x = 7의 비트는 최하위 비트(LSB)부터 0/0/0/1이므로 태그(tag)는 0b1000 = 8입니다.

태그(tag)를 부여한 뒤의 이항·삼항 연산(binary/ternary op)은 태그에 따라 피연산자(operand)를 선택하여, 원소마다 다른 값을 사용하게 할 수 있습니다. 규칙은 간단합니다. 조건이 없으면 피연산자를 그대로 쓰고, 조건이 있으면 Branched를 통해 그 값이 들어갈 하드웨어 슬롯(slot)의 종류를 지정합니다. furiosa-opt-examples의 ve_elementwise_branched는 조건부 즉시값(immediate) 뒤에 무조건 레지스터 파일 읽기(rf read)를 두어 이 방식을 실제로 컴파일하는 커널입니다. ve_branch_bit_order는 즉시값 세 개와 조건부 stash 읽기를 추가합니다. 이 문서에서는 예제를 다시 써 두는 대신 원본을 읽어 사용하므로, API가 바뀌면 오래된 설명이 남는 대신 예제 검증에서 문제가 드러납니다.

TagGuard에는 모든 경우를 허용하는 TagGuard::all(), 한 그룹을 선택하는 TagGuard::group(id), 또는 [BitReq; 4] 패턴을 검사하는 matches·not_matches가 있습니다. 패턴은 최하위 비트(LSB)부터 태그 비트마다 BitReq 하나씩 씁니다. One은 비트가 1이어야 함을, Zero는 0이어야 함을, Ignore는 상관없음을 뜻합니다. 조건은 태그 모드(tag mode)가 그 비트를 어떤 방식으로 채웠든 비트의 값 자체에 적용됩니다.

한 처리 단계(pass)에는 피연산자 슬롯(operand slot)이 네 개 있습니다. 즉시값 레지스터(immediate register) 세 개와, VRF 레지스터 또는 stash를 읽는 레지스터 파일 포트(register-file port) 하나입니다. 조건부 피연산자는 어느 종류의 슬롯을 사용할지 지정합니다. 즉시값에는 Branched::imm, 포트에는 Branched::rf를 쓰며, 이후 허용되는 작업만 제공하는 빌더(builder)를 받습니다. imm은 세 번, rf는 마지막에 한 번만 호출할 수 있습니다. 네 번째 imm이나 rf 뒤의 imm은 컴파일되지 않습니다.

커널(kernel)이 구체적으로 어느 즉시값 레지스터를 쓸지는 선택하지 않습니다. imm은 다음 슬롯을 차지하며, 실제 물리 레지스터(physical register) 배정은 명령 생성(command generation)이 결정합니다. 유지되는 것은 **호출 순서(call order)**입니다. 슬롯은 채워진 순서대로 하드웨어에 전달되며, 그 순서가 조건 일치 우선순위(match priority)입니다. 따라서 각 원소는 조건을 만족하는 첫 슬롯을 사용하고, 무조건 슬롯(unconditional slot)은 그 처리의 else에 해당하므로 뒤에 다른 슬롯을 둘 수 없습니다.

두 종류의 조건(guard)은 즉시 거부됩니다. 한 처리 단계(pass)의 슬롯은 네 개뿐인데, 이런 조건을 가진 슬롯은 자리를 차지하면서도 아무 효과가 없기 때문입니다. 어느 실행 ID도 만족하지 않는 TagGuard::not_matches([Ignore, Ignore, Ignore, Ignore]), 그리고 무조건 슬롯 뒤에 놓인 모든 슬롯이 해당합니다. TagGuard::matches([Ignore, Ignore, Ignore, Ignore])는 허용되며 같은 조건을 더 짧게 쓴 TagGuard::all()로 저장됩니다.

배치(layout)를 구성하여 반환하는 도우미(helper)는 일반 함수이므로, 커널 라이브러리(kernel library)는 자주 사용하는 조합을 감쌀 수 있습니다. 다만 operand 모듈에서 자세히 설명하는 두 가지는 할 수 없습니다. 첫째, 새로운 피연산자 자료형(operand type)을 만들 수 없습니다. 피연산자는 stash에 미치는 영향을 자료형으로 보증하므로 관련 트레이트(trait)가 외부 확장에 닫혀 있습니다. 둘째, 조건에 따라 슬롯을 채울지 말지 결정할 수 없습니다. 차지한 슬롯 수가 빌더(builder)의 자료형에 포함되어 if의 두 분기 자료형이 달라지기 때문입니다. 슬롯 수 대신 데이터(payload)나 조건(guard)을 바꾸거나, 연산 전체를 분기로 감싸세요.

논리 연산부(Logic Cluster)

논리 연산부(Logic Cluster)는 i32 또는 f32에 비트 단위 연산(bitwise operation)을 수행합니다. 8-way로 실행됩니다.

이 단계는 다섯 ALU 종류(LogicAnd, LogicOr, LogicXor, LogicLshift, LogicRshift)를 제공하며, 각 ALU는 텐서 유닛(Tensor Unit) 호출당 한 번씩 실행할 수 있습니다. 같은 ALU 종류를 공유하는 연산자(operator)들은 하나의 호출로 융합(fuse)할 수 없습니다.

BitAnd LogicAnd 비트 AND(bitwise and)
BitOr LogicOr 비트 OR(bitwise or)
BitXor LogicXor 비트 XOR(bitwise xor)
LeftShift LogicLshift 논리 왼쪽 시프트(logical left shift)
LogicRightShift LogicRshift 논리 오른쪽 시프트(logical right shift)
ArithRightShift LogicRshift 산술 오른쪽 시프트(arithmetic right shift)

f32 연산(operation):

BitAnd LogicAnd 부동소수점 비트 패턴에 대한 비트 AND(bitwise and)

고정소수점 연산부(Fxp Cluster)

고정소수점 연산부(Fxp Cluster)는 i32의 정수(integer) 및 고정소수점(fixed-point) 산술 연산을 수행합니다. 8-way로 실행됩니다.

이 단계는 네 ALU 종류(FxpAdd, FxpLshift, FxpMul, FxpRshift)를 제공하며, 각 ALU는 텐서 유닛(Tensor Unit) 호출당 한 번씩 실행할 수 있습니다. 같은 종류를 공유하는 연산자(operator)들은 하나의 호출로 융합(fuse)할 수 없습니다.

연산(Op) ALU 설명(Note)
AddFxp FxpAdd 오버플로 시 순환하는 덧셈(wrapping add)
AddFxpSat FxpAdd 포화 덧셈(saturating add)
SubFxp FxpAdd 오버플로 시 순환하는 뺄셈(wrapping subtract)
SubFxpSat FxpAdd 포화 뺄셈(saturating subtract)
LeftShift FxpLshift 논리 왼쪽 시프트(logical left shift)
LeftShiftSat FxpLshift 포화 왼쪽 시프트(saturating left shift)
MulFxp FxpMul 고정소수점 곱셈(fixed-point multiply)
MulInt FxpMul 정수 곱셈(integer multiply)
LogicRightShift FxpRshift 논리 오른쪽 시프트(logical right shift)
ArithRightShift FxpRshift 산술 오른쪽 시프트(arithmetic right shift)

ALU를 한 번만 쓸 수 있다는 규칙에 따라, 예를 들어 둘 다 FxpAdd를 사용하는 두 연산은 거부됩니다.

// 패닉(PANICS): "FxpAdd is already in use"
input

    .vector_intra_slice_tag(TagMode::Zero)
    .vector_fxp(FxpBinaryOp::AddFxp, 10)    // FxpAdd를 사용합니다.
    .vector_fxp(FxpBinaryOp::MulInt, 2)     // FxpMul을 사용합니다. ✓
    .vector_fxp(FxpBinaryOp::SubFxp, 5)     // FxpAdd를 다시 사용합니다. ✗
    .vector_final()

고정소수점에서 부동소수점으로 변환(FxpToFp Conversion)

FxpToFp 변환(conversion) 단계는 i32를 f32로 바꿉니다. int_width 매개변수(parameter)는 변환에 사용할 정수부 비트 폭(integer bit width)을 지정합니다. int_width = 31은 일반적인 i32 ↔ f32 변환입니다.

메서드(Method) 효과(Effect)
vector_fxp_to_fp(int_width) i32 스트림(stream)을 f32로 변환합니다.

폭 줄이기(Narrow)

Narrow 단계는 8-way를 4-way로 바꿉니다. 8-way 패킷(packet)은 활성 원소 8개(Packet = m![... # 8])를, 4-way 패킷은 4개(Packet = m![... # 4])를 담습니다. 폭을 줄이면 부동소수점 및 축약 경로(float/reduce path)의 처리량(throughput)이 절반이 되므로, 같은 논리적 텐서 형태(logical tensor shape)를 처리하는 데 패킷 수 또는 텐서 유닛(Tensor Unit) 호출 수가 두 배 필요합니다.

메서드(Method) 사용 조건(Use When) 효과(Effect)
vector_narrow_split() 앞뒤 절반에 모두 실제 데이터가 있을 때 8-way 플릿(flit) 하나를 앞쪽 4개와 뒤쪽 4개의 패킷(packet)으로 나누고 Time·Packet을 갱신합니다.
vector_narrow_trim() 뒤쪽 원소 4개가 이미 패딩(padding)이거나 필요 없는 값일 때 앞쪽 원소 4개만 유지합니다.

형태 변환의 의미(shape semantics):

rust
axes![A = 512, B = 2, S = 64];

fn vector_narrow_split_semantics<'l, const T: Tu>(
    input: VectorBranchTensor<'l, T, i32, m![1], m![B], m![S / 4 # 256], m![S % 4], m![A % 8], Fresh, { stage::VeOrder::IntraFirst }>,
) -> VectorNarrowTensor<'l, T, i32, m![1], m![B], m![S / 4 # 256], m![S % 4, A / 4 % 2], m![A % 4], Fresh, { stage::VeOrder::IntraFirst }>
{
    input.vector_narrow_split::<m![S % 4, A / 4 % 2], m![A % 4]>()
    // 형태 변환(shape semantics): [T], [P] -> [T, P / 2], [P % 4]
}

fn vector_narrow_trim_semantics<'l, const T: Tu>(
    input: VectorBranchTensor<'l, T, f32, m![1], m![B], m![A / 2], m![1], m![A % 2 # 8], Fresh, { stage::VeOrder::IntraFirst }>,

{
    input.vector_narrow_trim::<m![A % 2 # 4]>()
    // 형태 변환(shape semantics): [T], [P] -> [T], [P = 4]
}

부동소수점 연산부(Float Cluster)

부동소수점 연산부(Float Cluster)는 f32에 단항·이항·삼항 부동소수점 연산(unary/binary/ternary floating-point operation)을 제공합니다. 4-way로 실행되므로 입력은 이미 Narrow를 거쳐야 합니다.

독립적인 ALU 다섯 개(FpFma, FpFpu, FpExp, FpMul0, FpMul1)를 제공하며, 각 ALU는 텐서 유닛(Tensor Unit) 호출당 한 번 실행할 수 있습니다. ALU 배치 계획(planning)이 가장 중요한 단계입니다.

단항 연산(unary ops):

연산(Op) ALU 설명(Note)
Exp FpExp 지수함수(exponential)
NegExp FpExp 음의 지수함수(negative exponential)
Sqrt FpFpu 제곱근(square root)
Tanh FpFpu 쌍곡탄젠트(hyperbolic tangent)
Sigmoid FpFpu 시그모이드(sigmoid)
Erf FpFpu 오차 함수(error function)
Log FpFpu 자연로그(natural logarithm)
Sin FpFpu 사인(sine)
Cos FpFpu 코사인(cosine)

이항 연산(binary ops):

연산(Op) ALU 설명(Note)
AddF FpFma 부동소수점 덧셈(floating-point add)
SubF FpFma 부동소수점 뺄셈(floating-point subtract)
MulF(FpMulAlu::Mul0) FpMul0 곱셈(multiply)
MulF(FpMulAlu::Mul1) FpMul1 곱셈(multiply)
MulF(FpMulAlu::Fma) FpFma 곱셈(multiply)
DivF FpFpu Fp 단계 내부의 나눗셈(division)

삼항 연산(ternary ops):

연산(Op) ALU 설명(Note)
FmaF FpFma 융합 곱셈-덧셈(fused multiply-add)

예를 들어 exp(sqrt(((x + 1) * 2) * 3))는 다음과 같이 계산합니다.

  • FpFma(FpBinaryOp::AddF)로 x1 = x + 1을 계산합니다.
  • FpMul0(FpBinaryOp::MulF(FpMulAlu::Mul0))으로 x2 = x1 * 2를 계산합니다.
  • FpMul1(FpBinaryOp::MulF(FpMulAlu::Mul1))으로 x3 = x2 * 3를 계산합니다.
  • FpFpu(FpUnaryOp::Sqrt)로 x4 = sqrt(x3)를 계산합니다.
  • FpExp(FpUnaryOp::Exp)로 x5 = exp(x4)를 계산합니다.

슬라이스 내부 축약(IntraSliceReduce)

IntraSliceReduce 단계는 슬라이스(slice) 하나 안의 축(axis)을 축약하며 4-way로 실행됩니다. 전용 누산기 트리 ALU(accumulator-tree ALU)를 사용하므로 사용자가 선택할 ALU는 노출하지 않습니다.

자료형(Data Type) 지원 연산(Supported Ops)
i32 AddSat, Max, Min
f32 Add, Max, Min

자세한 내용은 슬라이스 내부 축약(Intra-Slice Reduce)을 참고하세요.

부동소수점 나눗셈(FpDiv)

FpDiv 단계는 부동소수점 나눗셈(floating-point division)을 수행하며 4-way로 실행됩니다. 전용 부동소수점 나눗셈기(divider)를 사용하므로 사용자가 선택할 ALU는 노출하지 않습니다.

연산(Op) 설명(Note)
FpDivBinaryOp::DivF 전용 부동소수점 나눗셈(floating-point division)

폭 늘리기(Widen)

Widen 단계는 4-way에서 8-way로 돌아갑니다. 이후 단계(FpToFxp, Clip, Filter, Output)는 다시 원소 8개짜리 패킷(packet)을 받습니다.

메서드(Method) 사용 조건(Use When) 효과(Effect)
vector_widen_concat() 앞서 수행한 vector_narrow_split()을 되돌릴 때 4-way 패킷(packet) 두 개를 8-way 플릿(flit) 하나로 다시 합칩니다.
vector_widen_pad() 앞서 수행한 vector_narrow_trim()을 되돌릴 때 4-way 패킷(packet)에 유효하지 않은 채움 값(invalid filler)을 더해 원소 8개로 패딩(padding)합니다.

형태 변환의 의미(shape semantics):

rust
axes![A = 512, B = 2, S = 64, R = 8];

fn vector_widen_concat_semantics<'l, const T: Tu>(
    input: VectorIntraSliceReduceTensor<'l, T, i32, m![1], m![B], m![S / 4 # 256], m![A / 4 % 2], m![A % 4], Fresh, { stage::VeOrder::IntraFirst }>,
) -> VectorWidenTensor<'l, T, i32, m![1], m![B], m![S / 4 # 256], m![1], m![A % 8], Fresh, { stage::VeOrder::IntraFirst }>
{
    input.vector_widen_concat::<m![1], m![A % 8]>()
    // 형태 변환(shape semantics): [T, P / 2], [P % 4] -> [T], [P]
}

fn vector_widen_pad_semantics<'l, const T: Tu>(
    input: VectorFpTensor<'l, T, f32, m![1], m![B], m![A / 2], m![1], m![A % 2 # 4], Fresh, { stage::VeOrder::IntraFirst }>,
) -> VectorWidenTensor<'l, T, f32, m![1], m![B], m![A / 2], m![1], m![A % 2 # 8], Fresh, { stage::VeOrder::IntraFirst }>
{
    input.vector_widen_pad::<m![A % 2 # 8]>()
    // 형태 변환(shape semantics): [T], [P] -> [T], [P # 8]
}

부동소수점에서 고정소수점으로 변환(FpToFxp Conversion)

FpToFxp 변환(conversion) 단계는 f32를 i32로 되돌립니다. int_width 매개변수(parameter)는 정수부 비트 폭(integer bit width)을 지정합니다.

메서드(Method) 효과(Effect)
vector_fp_to_fxp(int_width) f32 스트림(stream)을 i32로 되돌립니다.

범위 제한 연산부(Clip Cluster)

범위 제한 연산부(Clip Cluster)는 범위 제한(clamping)과 비교(comparison) 연산을 수행합니다. 8-way로 실행됩니다.

이 단계는 세 ALU 종류(ClipAdd, ClipMax, ClipMin)를 제공하며, 각 ALU는 텐서 유닛(Tensor Unit) 호출당 한 번 실행할 수 있습니다.

i32 연산(operation):

연산(Op) ALU 설명(Note)
Min ClipMin 최솟값(minimum)
Max ClipMax 최댓값(maximum)
AbsMin ClipMin 절댓값 기준 최솟값(absolute minimum)
AbsMax ClipMax 절댓값 기준 최댓값(absolute maximum)
AddFxp ClipAdd 오버플로 시 순환하는 덧셈(wrapping add)
AddFxpSat ClipAdd 포화 덧셈(saturating add)

f32 연산(operation):

연산(Op) ALU 설명(Note)
Min ClipMin 최솟값(minimum)
Max ClipMax 최댓값(maximum)
AbsMin ClipMin 절댓값 기준 최솟값(absolute minimum)
AbsMax ClipMax 절댓값 기준 최댓값(absolute maximum)
Add ClipAdd 부동소수점 덧셈(floating-point add)

필터(Filter)

필터(Filter) 단계는 TagGuard에서 얻은 실행 마스크(execution mask)를 적용하여 출력 플릿(flit)을 걸러 냅니다. 일반적으로 각 원소 Tag의 GroupId 최상위 비트(MSB)를 조건으로 사용합니다. 8-way와 Standalone 컨텍스트(context)에서만 사용할 수 있습니다. 소스의 impl은 CanTransitionTo<Filter>를 만족하는 모든 단계의 VectorTensor에 정의되어 있으며, 여기에는 모든 슬라이스 내부 단계와 InterSliceReduce가 포함됩니다.

출력(Output)

출력(Output) 단계는 벡터 엔진(Vector Engine) 파이프라인을 종료합니다. 결과는 형 변환 엔진(Cast Engine), 전치 엔진(Transpose Engine), 또는 저장 엔진(Commit Engine)으로 이어질 수 있습니다.

재해석(Reinterpret)

vector_reinterpret::<D2>()는 비트를 바꾸지 않고 스트림(stream)을 다른 32비트 스칼라 자료형(scalar type)으로 읽습니다. 따라서 1.0f32는 1이 아니라 0x3f80_0000이 됩니다. 모든 원소가 32비트이고 각 연산부(cluster)는 실행할 연산에서 피연산자 자료형을 정하므로, 재해석은 명령(instruction)을 내보내지 않고 ALU도 차지하지 않으며 현재 단계와 처리 폭(way)을 유지합니다. 따라서 같은 연산부의 두 연산 사이를 포함해 체인 어디에서든 몇 번이든 사용할 수 있습니다.

재해석(reinterpret)의 한 가지 용도는 비트 연산으로 f32의 abs 구하기처럼 부동소수점 값에 비트 연산(bitwise operation)을 적용하는 것입니다. 수치 자체를 보존하는 변환에는 FxpToFp·FpToFxp를 사용하세요.

메서드(Method) 효과(Effect)
vector_reinterpret::<i32>() f32 스트림(stream)의 비트를 i32로 읽습니다.
vector_reinterpret::<f32>() i32 스트림(stream)의 비트를 f32로 읽습니다.

stash는 저장 시점의 스트림 스칼라 자료형(scalar type)을 따르므로, 재해석(reinterpret)은 뒤따르는 vector_stash()가 무엇을 저장할지도 결정합니다. 다른 스칼라 자료형으로 읽을 값은 먼저 재해석하고 그다음 보관해야 합니다. 저장한 것과 다른 스칼라 자료형으로 읽으려 하면 컴파일되지 않습니다.

예제(Examples)

i32 파이프라인(Pipeline)

분기(branching) 후 상수를 더하는 최소한의 i32 체인(chain)입니다. Fxp 단계는 8-way로 실행되므로 폭 줄이기(narrow)나 늘리기(widen)가 필요하지 않습니다.

rust
axes![A = 2048, B = 2];

fn add_constant<'l, const T: Tu>(
    input: CollectTensor<'l, T, i32, m![1], m![B], m![A / 8], m![1], m![A % 8]>,
) -> VectorFinalTensor<'l, T, i32, m![1], m![B], m![A / 8], m![1], m![A % 8]> {
    input
        .vector_init()
        .vector_intra_slice_tag(TagMode::Zero)
        .vector_fxp(FxpBinaryOp::AddFxp, 100)
        .vector_final()
}

f32 파이프라인(Pipeline)

vector_narrow_trim()은 부동소수점 연산(float operation) 전에 텐서를 8-way에서 4-way로 바꾸는 Narrow 단계입니다. vector_widen_pad()는 연산 후 8-way로 되돌리는 Widen 단계입니다.

rust
axes![A = 512, B = 2];

fn sigmoid<'l, const T: Tu>(
    input: CollectTensor<'l, T, f32, m![1], m![B], m![A / 2], m![1], m![A % 2 # 8]>,
) -> VectorFinalTensor<'l, T, f32, m![1], m![B], m![A / 2], m![1], m![A % 2 # 8]> {
    input
        .vector_init()
        .vector_intra_slice_tag(TagMode::Zero)
        .vector_narrow_trim::<m![A % 2 # 4]>() // 폭 줄이기(Narrow): Way8 -> Way4
        .vector_fp_unary(FpUnaryOp::Sigmoid)
        .vector_widen_pad::<m![A % 2 # 8]>() // 폭 늘리기(Widen): Way4 -> Way8
        .vector_final()
}

비트 연산으로 f32의 절댓값(Abs) 구하기

부호 비트(sign bit)를 0으로 만들면 부동소수점 ALU 없이 |x|를 얻습니다. 필요한 연산 한 번에 대해서만 스트림을 i32로 읽으므로 마스크(mask)는 일반 i32 리터럴(literal)입니다. 두 번의 재해석(reinterpret)에는 비용이 없어, 정확히 LogicAnd 하나만 사용합니다.

rust
axes![A = 512, B = 2];

fn abs<'l, const T: Tu>(
    input: CollectTensor<'l, T, f32, m![1], m![B], m![A / 2], m![1], m![A % 2 # 8]>,
) -> VectorFinalTensor<'l, T, f32, m![1], m![B], m![A / 2], m![1], m![A % 2 # 8]> {
    input
        .vector_init()
        .vector_intra_slice_tag(TagMode::Zero)
        .vector_reinterpret::<i32>() // 비트를 i32로 읽습니다.
        .vector_logic(LogicBinaryOpI32::BitAnd, 0x7fff_ffff) // 부호 비트(sign bit)를 지웁니다.
        .vector_reinterpret::<f32>() // 원래 자료형으로 돌아갑니다.
        .vector_final()
}

단일 스트림 인수 모드(Single-Stream Argument Mode)

BinaryArgMode::Mode10은 스트림(stream)과 피연산자(operand)의 위치를 바꾸므로, SubFxp는 기본값인 stream - operand 대신 operand - stream(여기서는 7 - x)을 계산합니다.

rust
axes![A = 2048, B = 2];

fn bias_minus_x<'l, const T: Tu>(
    input: CollectTensor<'l, T, i32, m![1], m![B], m![A / 8], m![1], m![A % 8]>,
) -> VectorFinalTensor<'l, T, i32, m![1], m![B], m![A / 8], m![1], m![A % 8]> {
    input
        .vector_init()
        .vector_intra_slice_tag(TagMode::Zero)
        .vector_fxp_with_mode(FxpBinaryOp::SubFxp, BinaryArgMode::Mode10, 7) // 7 - x를 계산합니다.
        .vector_final()
}

VRF 피연산자(Operand)

미리 적재한 VRF 데이터를 피연산자(operand)로 사용합니다.

axes![A = 2048, B = 2, N = 256];

fn vrf_add<'l, const T: Tu>(
    input: CollectTensor<'l, T, i32, m![1], m![B], m![A / 8], m![N], m![A % 8]>,

부동소수점 전용 경로에서 임시 보관(Stash on the Fp-Only Path)

앞선 단계에서 임시 보관(stash)한 값을 나중의 Clip 연산에서 사용합니다. 다음은 max(2 * x, x)를 구현합니다.

rust
axes![A = 512, B = 2];

fn residual_max<'l, const T: Tu>(
    input: CollectTensor<'l, T, f32, m![1], m![B], m![A / 2], m![1], m![A % 2 # 8]>,
) -> VectorFinalTensor<'l, T, f32, m![1], m![B], m![A / 2], m![1], m![A % 2 # 8]> {
    input
        .vector_init()                                        // 벡터 엔진(VE)에 진입합니다.
        .vector_intra_slice_tag(TagMode::Zero) // 슬라이스 내부 경로(intra-slice path)를 시작합니다.
        .vector_stash()                                       // 원래 x를 보관합니다.
        .vector_narrow_trim::<m![A % 2 # 4]>()                  // Way4로 폭을 줄입니다.
        .vector_fp_binary(FpBinaryOp::MulF(FpMulAlu::Mul0), 2.0f32) // 2 * x를 계산합니다.
        .vector_widen_pad::<m![A % 2 # 8]>()                   // Way8로 폭을 다시 늘립니다.
        .vector_clip(ClipBinaryOpF32::Max, Stash)             // max(2 * x, x)
        .vector_final()
}

고정소수점 전용 경로에서 임시 보관(Stash on the Fxp-Only Path)

앞선 단계에서 임시 보관(stash)한 값을 나중의 Clip 연산에서 사용합니다. 다음은 max(x + bias, x)를 구현합니다.

rust
axes![A = 2048, B = 2];

fn stash_at_fxp<'l, const T: Tu>(
    input: CollectTensor<'l, T, i32, m![1], m![B], m![A / 8], m![1], m![A % 8]>,
) -> VectorFinalTensor<'l, T, i32, m![1], m![B], m![A / 8], m![1], m![A % 8]> {
    input
        .vector_init()                                      // 벡터 엔진(VE)에 진입합니다.
        .vector_intra_slice_tag(TagMode::Zero) // 슬라이스 내부 경로(intra-slice path)를 시작합니다.
        .vector_stash()                                     // 원래 x를 보관합니다.
        .vector_fxp(FxpBinaryOp::AddFxp, 100)               // x + bias를 계산합니다.
        .vector_clip(ClipBinaryOpI32::Max, Stash)           // max(x + bias, x)를 계산합니다.
        .vector_final()
}

폭 줄이기·늘리기 전후의 임시 보관(Stash Across Narrow and Widen)

폭을 줄이기 전에 보관(stash)하고, 폭을 늘린 뒤 사용합니다. 다음은 max(sigmoid(x), x)를 계산합니다.

rust
axes![A = 512, B = 2];

fn stash_across_narrow_widen<'l, const T: Tu>(
    input: CollectTensor<'l, T, f32, m![1], m![B], m![A / 2], m![1], m![A % 2 # 8]>,
) -> VectorFinalTensor<'l, T, f32, m![1], m![B], m![A / 2], m![1], m![A % 2 # 8]> {
    input
        .vector_init()                                     // 벡터 엔진(VE)에 진입합니다.
        .vector_intra_slice_tag(TagMode::Zero) // 슬라이스 내부 경로(intra-slice path)를 시작합니다.
        .vector_stash()                                    // x를 보관합니다(Way8).
        .vector_narrow_trim::<m![A % 2 # 4]>()               // Way4로 폭을 줄입니다.
        .vector_fp_unary(FpUnaryOp::Sigmoid)               // Way4에서 sigmoid(x)를 계산합니다.
        .vector_widen_pad::<m![A % 2 # 8]>()                // Way8로 폭을 다시 늘립니다.
        .vector_clip(ClipBinaryOpF32::Max, Stash)          // max(sigmoid(x), x)를 계산합니다.
        .vector_final()
}

쌍 덧셈(Pair Add)

교차 배치된(interleaved) 두 그룹을 정수 덧셈(integer add)으로 결합(zip)합니다.

rust
axes![A = 2048, B = 2, I = 2];

fn pair_add<'l, const T: Tu>(
    input: CollectTensor<'l, T, i32, m![1], m![B], m![A / 8], m![I], m![A % 8]>,
) -> VectorFinalTensor<'l, T, i32, m![1], m![B], m![A / 8], m![1], m![A % 8]> {
    input
        .vector_init()
        .vector_intra_slice_unzip::<I, m![1]>()
        .vector_clip_zip(ClipBinaryOpI32::AddFxp)
        .vector_final()
}

쌍의 한쪽만 전처리하기(Pair Per-Side Preprocessing)

결합(zip)하기 전에 그룹 0에만 배율을 적용하는 비대칭 전처리(asymmetric preprocessing)입니다.

rust
axes![A = 2048, B = 2, I = 2];

fn pair_preprocess_one_side<'l, const T: Tu>(
    input: CollectTensor<'l, T, i32, m![1], m![B], m![A / 8], m![I], m![A % 8]>,
) -> VectorFinalTensor<'l, T, i32, m![1], m![B], m![A / 8], m![1], m![A % 8]> {
    input
        .vector_init()
        .vector_intra_slice_unzip::<I, m![1]>()
        .vector_fxp(FxpBinaryOp::MulInt, 10, ())   // 그룹 0에만 적용합니다.
        .vector_clip_zip(ClipBinaryOpI32::AddFxp)
        .vector_final()
}

결합을 포함한 쌍 부동소수점 파이프라인(Pair Float Pipeline with Zip)

두 그룹 모두 부동소수점 경로(float path)를 통과합니다(narrow -> fp -> zip -> widen).

rust
axes![A = 512, B = 2, I = 2];

fn pair_fp_mul_zip<'l, const T: Tu>(
    input: CollectTensor<'l, T, f32, m![1], m![B], m![A / 2], m![I], m![A % 2 # 8]>,
) -> VectorFinalTensor<'l, T, f32, m![1], m![B], m![A / 2], m![1], m![A % 2 # 8]> {
    input
        .vector_init()
        .vector_intra_slice_unzip::<I, m![1]>()
        .vector_narrow_split::<m![1 # 2], m![A % 2 # 4]>()        // 두 그룹 모두: Way8 -> Way4
        .vector_fp_zip(FpBinaryOp::MulF(FpMulAlu::Mul0))   // group0 * group1(Way4)
        .vector_widen_concat::<m![1], m![A % 2 # 8]>()           // Way4 -> Way8
        .vector_final()
}

쌍의 그룹별 전처리(Pair Per-Group Preprocessing)

결합(zip) 전에 각 그룹에 서로 다른 연산을 적용합니다.

rust
axes![A = 512, B = 2, I = 2];

fn pair_asymmetric_preprocess<'l, const T: Tu>(
    input: CollectTensor<'l, T, f32, m![1], m![B], m![A / 2], m![I], m![A % 2 # 8]>,
) -> VectorFinalTensor<'l, T, f32, m![1], m![B], m![A / 2], m![1], m![A % 2 # 8]> {
    input
        .vector_init()
        .vector_intra_slice_unzip::<I, m![1]>()
        .vector_narrow_split::<m![1 # 2], m![A % 2 # 4]>()
        .vector_fp_unary(FpUnaryOp::Exp, true, false)         // 그룹 0: exp(x), 그룹 1: 건너뜀
        .vector_fp_zip(FpBinaryOp::MulF(FpMulAlu::Mul0))   // exp(group0) * group1
        .vector_widen_concat::<m![1], m![A % 2 # 8]>()
        .vector_final()
}

쌍 결합 인수 모드(Pair Zip Argument Mode)

BinaryArgMode::Mode10은 결합(zip)할 때 두 그룹의 스트림(stream)을 바꿉니다.

rust
axes![A = 512, B = 2, I = 2];

fn pair_sub_reverse<'l, const T: Tu>(
    input: CollectTensor<'l, T, f32, m![1], m![B], m![A / 2], m![I], m![A % 2 # 8]>,
) -> VectorFinalTensor<'l, T, f32, m![1], m![B], m![A / 2], m![1], m![A % 2 # 8]> {
    input
        .vector_init()
        .vector_intra_slice_unzip::<I, m![1]>()
        .vector_narrow_split::<m![1 # 2], m![A % 2 # 4]>()
        .vector_fp_zip_with_mode(FpBinaryOp::SubF, BinaryArgMode::Mode10) // group1 - group0을 계산합니다.
        .vector_widen_concat::<m![1], m![A % 2 # 8]>()
        .vector_final()
}

성능(Performance)

Logic·Fxp·Clip 연산부(cluster)는 최대 8-way, 즉 사이클(cycle)당 원소 8개의 처리량(throughput)을 냅니다. Float 연산부는 4-way로 실행되며, 부동소수점 경로 앞뒤의 Narrow/Widen으로 인해 실제 유효 처리량은 절반이 됩니다.

지연 시간(latency)은 사용한 ALU 하나당 1사이클씩 추가됩니다. 여러 ALU에 걸친 연산은 각 지연 시간이 누적됩니다. 예를 들어 exp(sqrt(x))에는 sqrt의 FpFpu와 exp의 FpExp를 합쳐 2사이클이 추가됩니다.
