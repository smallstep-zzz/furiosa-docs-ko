슬라이스 내부 축약(Intra-Slice Reduce)

슬라이스 내부 체인(Intra-Slice Chain)의 IntraSliceReduce 단계는 각 슬라이스(slice)의 Time과 Packet에 놓인 차원(dimension)을 축약합니다. Chip·Cluster·Slice는 바뀌지 않습니다. 한 클러스터(cluster)의 슬라이스 256개에 걸쳐 축약하는 다른 경우는 슬라이스 간 축약기(Inter-Slice Reducer)가 담당합니다.

예제(Examples)

축약(reduce) 호출의 주요 매개변수(parameter)는 다음과 같습니다.

  • REDUCE_LABEL: 축약할 축(axis)입니다. 축약은 Time과 Packet에서 이 축을 가진 모든 인자(factor)를 제거하므로, 해당 인자들은 출력 형태(shape)인 OutTime·OutPacket에 남아 있으면 안 됩니다. 예를 들어 R을 Time의 R / 4와 Packet의 R % 4로 나누었다면 REDUCE_LABEL = R 지정으로 둘 다 제거됩니다.
  • op: 축약 연산(reduce operation)입니다. IntraSliceReduceOpI32는 AddSat·Max·Min을, IntraSliceReduceOpF32는 Add·Max·Min을 제공합니다.
  • OutTime, OutPacket: 축약(reduction) 후 출력의 Time과 Packet 형태(shape)입니다. 입력의 Time·Packet에서 모든 REDUCE_LABEL 인자(factor)를 제거한 형태와 일치해야 합니다.

이 호출은 쌍 모드(Pair Mode)에서는 사용할 수 없습니다. 아래 예제에서 각 매개변수(parameter) 조합을 살펴봅니다.

Time에서 축약하기(Reduction)

R이 Time에만 있으므로, 이 단계는 여러 시간 단계(time step)에 걸쳐 값을 누산합니다. 포화 덧셈(saturating addition)으로 output[a] = \sum_{r \in R} input[a, r]을 계산합니다.

rust
axes![A = 512, R = 16];

// R이 Time에 있으므로 시간 방향 누산(temporal accumulation)을 수행합니다. Packet은 축약 대상이 아닙니다.
fn reduce_time<'l, const T: Tu>(
    input: VectorBranchTensor<'l, T, i32, m![1], m![1 # 2], m![A / 2], m![R], m![A % 2 # 8], Fresh, { stage::VeOrder::IntraFirst }>,
) -> VectorIntraSliceReduceTensor<'l, T, i32, m![1], m![1 # 2], m![A / 2], m![1], m![A % 2 # 4], Fresh, { stage::VeOrder::IntraFirst }>
{
    input
        .vector_narrow_trim::<m![A % 2 # 4]>()       // 8-way → 4-way
        // Time에서 R이 제거됩니다.
        .vector_intra_slice_reduce::<R, m![1], m![A % 2 # 4]>(
            IntraSliceReduceOpI32::AddSat,
        )
}

Packet에서 축약하기(Reduction)

R이 Packet에만 있으므로, 하드웨어는 각 플릿(flit) 안에서 4방향 트리 축약(4-way tree reduce)을 수행하고 시간 방향 누산(temporal accumulation)은 건너뜁니다. output[a] = \sum_{r \in R} input[a, r]을 계산합니다.

rust
axes![A = 512, R = 4];

// R이 Packet에 있으므로 플릿(flit) 안에서 트리 축약(tree reduce)을 수행합니다.
fn reduce_packet<'l, const T: Tu>(
    input: VectorBranchTensor<'l, T, f32, m![1], m![1 # 2], m![A / 2], m![A % 2], m![R # 8], Fresh, { stage::VeOrder::IntraFirst }>,
) -> VectorIntraSliceReduceTensor<'l, T, f32, m![1], m![1 # 2], m![A / 2], m![A % 2], m![1 # 4], Fresh, { stage::VeOrder::IntraFirst }>
{
    input
        .vector_narrow_trim::<m![R]>()             // 8-way → 4-way
        // Packet에서 R이 제거됩니다.
        .vector_intra_slice_reduce::<R, m![A % 2], m![1 # 4]>(
            IntraSliceReduceOpF32::Add,
        )
}

두 차원에서 함께 축약하기(Reduction)

R을 Packet과 Time에 나누어 배치합니다. Packet의 R % 4는 각 플릿(flit) 안에서 트리 축약(tree reduce)을 수행하고, Time의 R / 4는 여러 시간 단계(time step)에 걸쳐 누산합니다. output[a] = \max_{r \in R} input[a, r]을 계산합니다.

rust
axes![A = 256, R = 16];

// Packet의 R % 4: 공간 방향 트리 축약(spatial tree reduce)
// Time의 R / 4: 시간 방향 누산(temporal accumulation)
fn reduce_time_packet<'l, const T: Tu>(
    input: VectorBranchTensor<'l, T, f32, m![1], m![1 # 2], m![A], m![R / 4], m![R % 4 # 8], Fresh, { stage::VeOrder::IntraFirst }>,
) -> VectorIntraSliceReduceTensor<'l, T, f32, m![1], m![1 # 2], m![A], m![1], m![1 # 4], Fresh, { stage::VeOrder::IntraFirst }>
{
    input
        .vector_narrow_trim::<m![R % 4]>()            // 8-way → 4-way
        // Time과 Packet 모두에서 R이 제거됩니다.
        .vector_intra_slice_reduce::<R, m![1], m![1 # 4]>(
            IntraSliceReduceOpF32::Max,
        )
}

슬라이스별 축약(Per-Slice Reduction)

R의 일부가 Slice·Time·Packet에 각각 놓여 있지만, 슬라이스 내부 축약기(intra-slice reducer)는 Time·Packet 부분만 축약하므로 R의 Slice 부분은 출력에 남습니다. 여기서는 R = 13을 배치(layout)에 맞게 32까지 패딩(padding)한 뒤(R # 32), R을 슬라이스(slice) 4개에 나눕니다. 각 슬라이스에는 R의 위치가 8개씩 있습니다. 실제 원소는 위치 0~12에만 있으므로, 그 경계를 걸치는 슬라이스(위치 8~15: 실제 값 5개 다음에 패딩 3개)가 경계 슬라이스(boundary slice)이며 그 뒤의 슬라이스는 전부 패딩입니다. VCG는 각 슬라이스의 축약 개수를 정해 실제 원소만 축약하게 합니다. 정확한 매핑(mapping)은 유효 개수 생성기(Valid Count Generator)를 참고하세요.

rust
axes![R = 13];

// R을 세 차원에 나눕니다: Slice(8개씩 묶은 그룹), Time(그룹 내부의 쌍), Packet(원소 4개).
fn reduce_slice_time_packet<'l, const T: Tu>(
    input: VectorBranchTensor<'l, T, i32, m![1], m![1 # 2], m![R # 32 / 8 # 256], m![R # 32 / 4 % 2], m![R # 32 % 4 # 8], Fresh, { stage::VeOrder::IntraFirst }>,
) -> VectorIntraSliceReduceTensor<'l, T, i32, m![1], m![1 # 2], m![R # 32 / 8 # 256], m![1], m![1 # 4], Fresh, { stage::VeOrder::IntraFirst }>
{
    input
        .vector_narrow_trim::<m![R # 32 % 4]>()       // 8-way → 4-way
        // Time과 Packet에서 R이 제거됩니다(각 슬라이스 내부에서 누산).
        .vector_intra_slice_reduce::<R, m![1], m![1 # 4]>(
            IntraSliceReduceOpI32::Min,
        )
}

구조(Architecture)

이 단계는 Time 축(axis)과 Packet 축에 각각 별도의 처리 장치를 사용합니다.

Time에서 축약하기(Reduction)

이 단계는 슬롯(slot) 용량이 8인 시간 방향 누산기(temporal accumulator) 모델을 사용합니다. 따라서 InnerTime::SIZE ≤ 8이어야 합니다.

위의 reduce_time에서는 Time = m![R], OutTime = m![1]이므로 R이 가장 바깥쪽 축약 차원(reduce dimension)이고 InnerTime = m![1]입니다(InnerTime::SIZE = 1). 슬롯(slot) 하나가 모든 R 값을 누산하여 출력을 만듭니다.

InnerTime::SIZE가 8보다 크면 API가 호출을 거부합니다. 다음이 그 예입니다.

rust
fn invalid_too_many_slots<'l, const T: Tu>(
    input: VectorBranchTensor<'l, T, i32, m![1], m![1 # 2], m![A / 3 # 256], m![R, A % 3, B % 4], m![B / 4 # 8], Fresh, { stage::VeOrder::IntraFirst }>,
) -> VectorIntraSliceReduceTensor<'l, T, i32, m![1], m![1 # 2], m![A / 3 # 256], m![A % 3, B % 4], m![B / 4], Fresh, { stage::VeOrder::IntraFirst }>
{
    input
        .vector_narrow_trim::<m![B / 4]>()
        // Time      = m![R, A % 3, B % 4]
        // OutTime   = m![A % 3, B % 4]
        // InnerTime = m![A % 3, B % 4], InnerTime::SIZE = 3 × 4 = 12 > 8
        .vector_intra_slice_reduce::<R, m![A % 3, B % 4], m![B / 4]>(
            IntraSliceReduceOpI32::AddSat,
        )
    // 거부됨: 누산기 슬롯(accumulator slot)이 12개 필요하지만 사용 가능한 슬롯은 8개뿐입니다.
}

Packet에서 축약하기(Reduction)

플릿(flit) 하나의 Packet 원소 4개는 다음 두 경로 중 하나로 처리됩니다.

  • OutPacket = Packet: 원소들이 축약되지 않고 그대로 통과합니다. 사이클(cycle)당 출력 4개이며, 각각 Time에 걸쳐 독립적으로 누산됩니다.
  • OutPacket = m![1 # 4]: 원소들이 2단계 트리(tree) op(op(a, b), op(c, d))를 거쳐 값 하나로 합쳐집니다. 사이클(cycle)당 출력 1개와 패딩(padding) 위치 3개가 나옵니다.

축약 축(reduce axis)을 하드웨어 차원(dimension)에 맞게 패딩(padding)하면, 패딩 위치에는 임의의 데이터가 들어 있으므로 축약에서 제외해야 합니다. 이를 처리하는 방법은 두 가지입니다.

  • 유효 개수 생성기(VCG, Valid Count Generator): 해당 축 배치(axis placement)를 지원한다면 우선적으로 사용할 방법입니다. 컴파일러(compiler)가 매핑(mapping)으로부터 VCG를 자동 설정하고, VCG는 각 플릿(flit)에 valid_count를 표시하여 패딩 원소를 자동으로 제외합니다. Slice·Time·Packet에 축을 배치하는 모든 형태가 지원되는 것은 아닙니다. 자세한 내용은 유효 개수 생성기를 참고하세요.

  • 항등원으로 패딩하기(identity-element padding): 데이터가 슬라이스 내부 체인(Intra-Slice Chain)에 도달하기 전에 패딩 위치를 해당 축약 연산의 항등원(identity element)으로 채웁니다. 이 문서는 사용 가능한 공개 마스킹 연산(masking operation)을 설명하지 않습니다. 축약에 앞서 항등원을 생성한다는 사실이 검증된 경로를 사용하세요.

    연산(Operation) 항등원(Identity Element)
    AddSat / Add 0 / 0.0
    Max i32::MIN / f32::NEG_INFINITY
    Min i32::MAX / f32::INFINITY

    이 방법은 축약 연산(reduce operation) 앞에 되돌릴 수 없는 변환(non-invertible transformation)이 없을 때만 적용할 수 있습니다. 예를 들어 exp(x) + exp(y) + ...처럼 지수함수의 합을 계산할 때는 exp(p) = 0(덧셈의 항등원)을 만족하는 값 p가 없습니다. 따라서 항등원 패딩(identity padding)을 적용할 수 없습니다.

성능(Performance)

트리 축약(tree reduce)이 슬라이스 내부 체인(Intra-Slice Chain) 안에서 완전히 파이프라인화되어 있으므로, 플릿(flit)당 추가 비용 없이 사이클(cycle)당 플릿 하나의 처리량(throughput)을 유지합니다.

지연 시간(latency)에는 첫 출력까지 n 플릿 사이클의 대기가 추가됩니다. n은 축약 축(reduce axis)의 시간 단계(time step) 수입니다. 한 축약 그룹의 입력 플릿을 모두 누산한 다음에야 결과를 내보낼 수 있기 때문입니다. 여러 엔진으로 구성된 파이프라인(pipeline)에서는 이 누산 지연 때문에 첫 플릿을 기다리는 뒷단 엔진이 멈춥니다.
