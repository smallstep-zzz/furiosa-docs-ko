유효 개수 생성기(Valid Count Generator)

읽기 도움말 · 번역자 설명

유효 개수 생성기(Valid Count Generator, VCG)는 입력 플릿(flit)에서 실제 데이터가 몇 개인지 셉니다. 아래 R을 Packet에 놓는 예제에서 VCG는 입력의 R # 8을 기준으로 셉니다. 이후 vector_narrow_trim을 거친 연산은 R # 4를 사용하므로, 두 표기는 처리 시점이 다릅니다.

슬라이스 내부 축약(Intra-Slice Reduce) 단계는 REDUCE_LABEL로 지정한 축(axis, 예: R)의 Time·Packet 인자(factor)를 축약하고, Slice 인자는 출력에 남깁니다. 하드웨어 차원(dimension)에 맞추려면 이 축에 패딩(padding)이 필요한 경우가 많습니다. 추가된 패딩 위치에는 임의의 데이터가 있으므로 축약에서 제외해야 합니다.

유효 개수 생성기(VCG, Valid Count Generator)가 이 문제를 해결합니다. 사용자가 매핑(mapping)에서 R을 부분 표현식(sub-expression)으로 나누어 Slice·Time·Packet에 배치하면, 컴파일러(compiler)는 VCG를 설정하여 원소 8개짜리 플릿(flit)마다 실제 데이터 개수인 valid_size를 표시하게 합니다. Time 또는 Slice의 각 부분 표현식은 시간 필터(time filter)에 배정된 시퀀서 카운터(sequencer counter)로 대응됩니다. Packet의 각 부분 표현식은 패킷 클리퍼(packet clipper)를 제어합니다.

이 문서에서 대문자로 시작하는 Slice·Time·Packet은 매핑 차원(mapping dimension)을 뜻합니다. 소문자 slice와 time step은 실행 중의 개별 슬라이스와 시간 단계를 뜻합니다.

VCG가 동작하려면 매핑(mapping)에서 R을 정해진 형태로 표현해야 합니다. 먼저 R을 하드웨어에 정렬된 크기까지 패딩(padding)하며, 일반적인 설명에서는 이를 R # PADDED_SIZE로 씁니다. 실제 예제에서는 R # 16, R # 48처럼 구체적인 패딩 크기를 사용합니다. 각 부분 표현식(sub-expression)은 R # PADDED_SIZE의 인자(factor)로, R # PADDED_SIZE / n % m 형태입니다. 여기서 스트라이드(stride)는 n, 모듈로(modulo)는 m입니다. / n과 % m의 의미는 스트라이드와 모듈로(Stride and Modulo)를 참고하세요. 각 부분 표현식은 하드웨어 차원 하나에 배정합니다. 예를 들어 R = 43을 R # 48로 패딩하여 세 차원 모두에 다음과 같이 나눌 수 있습니다.

text
Slice:  R # 48 / 8       (stride 8, 6 positions)
Time:   R # 48 / 2 % 4   (stride 2, 4 positions)
Packet: R # 48 % 2       (stride 1, 2 positions)

구조(Architecture)

VCG는 플릿(flit)마다 valid_size(s, t) ∈ {0, 1, ..., 8}을 부여합니다. s는 모든 Slice 부분 표현식(sub-expression)에서 플릿의 위치를 정수로 나타낸 슬라이스 ID이며, t는 시간 단계(time step)입니다. 플릿의 앞쪽 valid_size개 원소가 실제 데이터이고 나머지는 패딩(padding)입니다.

rust
struct VcgConfig {
    time_filters:   [TimeFilterConfig; 3], // Time 및/또는 Slice에 놓인 R의 부분 표현식(sub-expression)을 처리합니다.
    packet_clipper: PacketClipperConfig,   // Packet에 놓인 R의 부분 표현식(sub-expression)을 처리합니다.
}

impl VcgConfig {
    fn valid_size(&self, s: u64, t: u64) -> u32 {
        if self.time_filters.iter().all(|tf| tf.valid(s, t)) {
            self.packet_clipper.valid_size(t)
        } else {
            0
        }
    }
}

모든 타이머(timer)가 플릿(flit) (s, t)를 유효하다고 판단하면, 패킷 클리퍼(packet clipper)가 플릿 안의 실제 데이터 개수를 결정합니다. 타이머 하나라도 무효라고 판단하면 패킷 클리퍼의 결과와 관계없이 플릿의 모든 원소를 제외합니다. 두 구성 요소인 TimeFilterConfig와 PacketClipperConfig는 아래에서 설명합니다.

시간 필터(Time Filter)

시간 필터(time filter)는 각 슬라이스(slice) s에서 시간 단계(time step) t마다 유효한 R 데이터가 있는지 판단합니다. 아래에서는 가장 단순한 경우부터 복잡도를 늘리며 fn valid()를 단계적으로 구성합니다. R의 부분 표현식(sub-expression)이 Time이나 Slice에 없으면 slice_mask = 0, slice_thres = 1로 시간 필터를 비활성화합니다. 모든 s에서 s & 0 = 0 < 1이 되어 Less 분기로 들어가므로 fn valid()가 항상 true를 반환합니다. slice_thres = 1은 관례적인 선택일 뿐이며, 0보다 큰 값이면 무엇이든 같은 결과가 됩니다.

rust
struct TimeFilterConfig {
    // t로부터 R의 인덱스(index)를 복원하는 방식입니다.
    sequencer: Sequencer,

    // 슬라이스 분류(slice classification): `R in Slice and Time`, `R in Time and Slice` 참고.
    slice_mask:  u32,
    slice_thres: u32,
    time_thres:  u32,
    mode:        TimeFilterMode, // SliceMajor | TimeMajor
}

impl TimeFilterConfig {
    /// 플릿(flit) (s, t)에 유효한 R 데이터가 있으면 true를 반환합니다.
    fn valid(&self, s: u64, t: u64) -> bool {
        let idx = self.sequencer.index(t);
        match ((s & self.slice_mask).cmp(&self.slice_thres), self.mode) {
            (Less,    _)          => true,
            (Greater, SliceMajor) => false,
            _                     => idx < self.time_thres as u64,
        }
    }
}

R이 Time 전체를 차지하는 경우

가장 단순한 경우에는 다른 축(axis) 없이 R이 Time 전체를 차지합니다. 각 시간 단계(time step) t가 R의 인덱스 하나에 직접 대응하며, t < R::SIZE이면 유효합니다.

rust
// 컴파일러(compiler)는 대략 다음 설정을 생성합니다.
TimeFilterConfig {
    sequencer:   [R # PADDED_SIZE -> size PADDED_SIZE : stride 1],  // idx = t
    slice_mask:  0,           // 슬라이스 분할(slice partitioning)이 없습니다.
    slice_thres: 0,           // 0 cmp 0 = Equal이므로 `idx < time_thres` 검사로 이어집니다.
    time_thres:  R::SIZE,     // idx < R::SIZE이면 유효합니다.
    mode:        SliceMajor,  // Equal 분기만 사용하므로 임의의 값을 써도 됩니다.
}
rust
axes![A = 8, R = 12, X = 128];

fn reduce_time_only<'l, const T: Tu>(
    input: VectorBranchTensor<'l, T, i32, m![1], m![1 # 2], m![X, A / 4], m![R # 16], m![A % 4 # 8], Fresh, { stage::VeOrder::IntraFirst }>,
) -> VectorIntraSliceReduceTensor<'l, T, i32, m![1], m![1 # 2], m![X, A / 4], m![1], m![A % 4], Fresh, { stage::VeOrder::IntraFirst }>
{
    input
        .vector_narrow_trim::<m![A % 4]>()
        //   Slice     = m![X, A / 4]
        //   Time      = m![R # 16]     (단계 < R::SIZE인 경우 유효)
        //   Packet    = m![A % 4]
        //   OutTime   = m![1]          (Time에서 R이 제거됨)
        //   OutPacket = m![A % 4]
        .vector_intra_slice_reduce::<R, m![1], m![A % 4]>(
            IntraSliceReduceOpI32::AddSat,
        )
}

위 예제에서 시퀀서(sequencer)는 size 16 : stride 1로 R # 16을 한 번 순회하므로 모든 시간 단계(time step)에서 idx = t입니다. time_thres = R::SIZE = 12이므로 처음 12단계(t = 0..11)는 유효하고 나머지 4단계(t = 12..15)는 제외됩니다. 따라서 슬라이스 내부 축약(intra-slice reduce)은 각 슬라이스의 실제 R 원소 12개만 정확히 합칩니다.

R이 Time의 일부를 차지하는 경우

VCG는 R이 다른 축(axis)과 Time을 공유하고 여러 부분 표현식(sub-expression)으로 나타나는 매핑(mapping)도 지원하며, 그 순서는 자유롭습니다. 시간 필터(time filter)는 시퀀서(Sequencer)로 t를 부분 표현식별 카운터(counter)로 분해합니다. R에 배정된 카운터들의 값과 스트라이드의 곱인 value × stride를 합하면 해당 시간 단계에서 R의 인덱스를 나타내는 idx를 얻습니다.

다음 예제는 R = 10을 R # 12로 패딩(padding)하고, Time 안에서 R의 두 부분 표현식(sub-expression) 사이에 A를 놓습니다.

rust
axes![A = 3, B = 4, R = 10, X = 64];

// R = 10을 R # 12로 패딩하고 (size 3, stride 4) × (size 4, stride 1)로 나눕니다.
// 시간 필터는 (R # 12 / 4 값) * 4 + (R # 12 % 4 값) * 1을 합하여 A와 무관하게 R 인덱스를 복원합니다.
fn reduce_time_reordered<'l, const T: Tu>(
    input: VectorBranchTensor<'l, T, i32, m![1], m![1 # 2], m![X # 256], m![R # 12 / 4, A, R # 12 % 4], m![B # 8], Fresh, { stage::VeOrder::IntraFirst }>,
) -> VectorIntraSliceReduceTensor<'l, T, i32, m![1], m![1 # 2], m![X # 256], m![A], m![B], Fresh, { stage::VeOrder::IntraFirst }>
{
    input
        .vector_narrow_trim::<m![B]>()
        //   Slice     = m![X # 256]
        //   Time      = m![R # 12 / 4, A, R # 12 % 4]
        //   Packet    = m![B]
        //   OutTime   = m![A]    (R은 제거되고 A는 남음)
        //   OutPacket = m![B]
        .vector_intra_slice_reduce::<R, m![A], m![B]>(
            IntraSliceReduceOpI32::AddSat,
        )
}

컴파일러(compiler)는 이 배치(placement)의 시간 필터(time filter)를 다음과 같이 설정합니다.

rust
TimeFilterConfig {
    sequencer:   [R # 12 / 4 -> size 3 : stride 4,   // 시간 필터(time filter)에 배정됩니다.
                  A          -> size 3 : stride 0,   // 배정하지 않습니다(A의 OutTime).
                  R # 12 % 4 -> size 4 : stride 1],  // 시간 필터(time filter)에 배정됩니다.
    slice_mask:  0,           // 슬라이스 분할(slice partitioning)이 없습니다(R이 Time에만 있음).
    slice_thres: 0,           // 모든 슬라이스(slice)가 `idx < time_thres` 분기로 들어갑니다.
    time_thres:  R::SIZE,     // 10
    mode:        SliceMajor,  // Equal 분기만 사용하므로 임의의 값을 써도 됩니다.
}

A 항목은 스트라이드(stride)가 0이어서 idx에 전혀 기여하지 않습니다. 따라서 Time에서 A의 위치는 유효성(validity)에 영향을 주지 않습니다. 나머지 두 항목은 (R # 12 / 4 value) × 4 + (R # 12 % 4 value)(각 value는 해당 부분 표현식의 값)으로 R을 복원합니다.

예를 들어 다음과 같습니다.

  • t = 13일 때 시퀀서(sequencer) 상태는 (R # 12 / 4, A, R # 12 % 4) = (1, 0, 1)이고, idx = 1 × 4 + 0 + 1 × 1 = 5입니다. idx < 10이므로 유효합니다.
  • t = 27일 때 시퀀서(sequencer) 상태는 (2, 0, 3)이고, idx = 2 × 4 + 0 + 3 × 1 = 11입니다. idx ≥ 10이므로 무효입니다. R에 추가된 패딩(padding) 위치 두 개 중 하나에 해당합니다.

R을 Slice와 Time에 배치하기

SliceMajor 모드는 Slice와 Time 양쪽에 여러 R 부분 표현식(sub-expression)을 허용하며, Slice 쪽이 Time 쪽보다 상위(major), 즉 더 큰 스트라이드(stride)를 갖습니다. Slice 안에서는 부분 표현식을 스트라이드 내림차순(major 다음 minor)으로 놓아야 합니다. 또한 각 크기와 스트라이드가 2의 거듭제곱이어야 그 비트가 slice_mask에서 연속된 구간을 차지합니다. Time 안의 부분 표현식 순서는 자유롭습니다.

rust
axes![R = 11, X = 64];

fn reduce_slice_time_slicemajor<'l, const T: Tu>(
    input: VectorBranchTensor<'l, T, i32, m![1], m![1 # 2], m![R # 16 / 8, X, R # 16 / 4 % 2], m![R # 16 % 2, R # 16 / 2 % 2], m![1 # 8], Fresh, { stage::VeOrder::IntraFirst }>,
) -> VectorIntraSliceReduceTensor<'l, T, i32, m![1], m![1 # 2], m![R # 16 / 8, X, R # 16 / 4 % 2], m![1], m![1 # 4], Fresh, { stage::VeOrder::IntraFirst }>
{
    input
        .vector_narrow_trim::<m![1 # 4]>()
        //   Slice     = m![R # 16 / 8, X, R # 16 / 4 % 2]   (상위 R 부분 표현식, R 스트라이드 내림차순 필수)
        //   Time      = m![R # 16 % 2, R # 16 / 2 % 2]      (하위 R 부분 표현식, 순서는 자유)
        //   Packet    = m![1 # 4]
        //   OutTime   = m![1]          (R이 제거됨)
        //   OutPacket = m![1 # 4]
        .vector_intra_slice_reduce::<R, m![1], m![1 # 4]>(
            IntraSliceReduceOpI32::Min,
        )
}

이 예제는 R = 11을 R # 16으로 패딩(padding)한 뒤, 다음 부분 표현식(sub-expression)으로 Slice와 Time에 나누어 배치합니다.

차원(Dimension) 부분 표현식(Sub-expression) 스트라이드(Stride)
Slice R # 16 / 8 8
Slice R # 16 / 4 % 2 4
Time R # 16 % 2 1
Time R # 16 / 2 % 2 2

이 예제는 슬라이스 그룹(slice group) 4개로 나뉩니다. Slice가 R에 기여하는 값 0·4·8·12마다 하나씩이며, 각 슬라이스에서는 시간 반복(time iteration)을 4번 수행합니다. 배치(layout)는 세 경우로 나뉩니다. 슬라이스 2개는 전부 유효하고, 1개는 일부만 유효하며, 1개는 전부 무효입니다.

Slice가 R에 기여하는 값(contribution) 반복(iteration)에 따른 R 값 유효한 시간 단계(valid time steps)
0 0, 2, 1, 3 4(모두 < R::SIZE)
4 4, 6, 5, 7 4(모두 < R::SIZE)
8 8, 10, 9, 11 3(R = 11은 무효)
12 12, 14, 13, 15 0(모두 ≥ R::SIZE)

컴파일러(compiler)는 아래 시간 필터 설정(time filter config)을 생성합니다.

rust
TimeFilterConfig {
    sequencer:   [R # 16 % 2     -> size 2 : stride 1,
                  R # 16 / 2 % 2 -> size 2 : stride 2],
    slice_mask:  0b1000001,  // 비트 0(R # 16 / 4 % 2)과 비트 6(R # 16 / 8)이 R에 기여하는 값을 담습니다.
    slice_thres: 64,         // 경계의 R 기여 값(= 8)을 표현하는 마스킹된 ID(masked id)입니다.
    time_thres:  3,          // = R::SIZE - 경계값 = 11 - 8
    mode:        SliceMajor,
}

각 필드(field)는 유효성 판단(validity decision)의 한 부분을 표현합니다.

  • sequencer는 Time의 각 부분 표현식(sub-expression)과 그 R 스트라이드(stride)를 기록합니다. 따라서 복원한 idx는 각 시간 단계(time step) t에서 Time이 R에 기여하는 값과 같습니다. 이 예제에서는 t가 [0, 4)를 순회할 때 idx가 {0, 1, 2, 3}의 값을 가집니다.
  • slice_mask는 슬라이스 ID(slice id)에서 Slice가 R에 기여하는 값을 담은 비트만 추출합니다. 이 예제에서는 비트 0이 R # 16 / 4 % 2, 비트 6이 R # 16 / 8을 담으므로 slice_mask = 0b1000001입니다.
  • slice_thres는 일부만 유효한 슬라이스(partial slice)의 R 기여 값을 slice_mask 안의 비트 패턴(bit pattern)으로 표현한 것입니다. 위 표에서 부분 유효 슬라이스의 R 기여 값은 8입니다. 비트 6을 켜고(R # 16 / 8 = 1), 비트 0을 끄면(R # 16 / 4 % 2 = 0) 이를 표현할 수 있습니다. 따라서 slice_thres = 64입니다.
  • time_thres는 R::SIZE에서 부분 유효 슬라이스(partial slice)의 R 기여 값을 뺀 것입니다. 이 예제에서는 time_thres = 11 - 8 = 3입니다.

fn valid는 모든 플릿(flit)에 대해 올바른 유효성(validity)을 반환합니다. 이를 확인하려면 R의 인덱스를 r = r_slice + idx로 분해합니다. 여기서 r_slice는 Slice가 R에 기여하는 값(s & slice_mask로 표현됨), idx는 Time이 기여하는 값입니다. 슬라이스 비교의 세 경우를 살펴보겠습니다.

  • (s & slice_mask) < slice_thres이면 모든 시간 단계(time step)가 유효합니다. r_slice가 부분 유효 슬라이스의 기여 값보다 최소 한 슬라이스 간격만큼 작으므로, 모든 idx에서 r = r_slice + idx < R::SIZE입니다.
  • (s & slice_mask) = slice_thres이면 idx < time_thres일 때에만 시간 단계(time step)가 유효합니다. 이 경우는 부분 유효 슬라이스(partial slice)이며, time_thres의 정의에 따라 r_slice = R::SIZE - time_thres입니다. 따라서 r = r_slice + idx < R::SIZE의 조건은 정확히 idx < time_thres입니다.
  • (s & slice_mask) > slice_thres이면 유효한 시간 단계(time step)가 없습니다. r_slice가 부분 유효 슬라이스의 기여 값보다 최소 한 슬라이스 간격만큼 크므로 r_slice ≥ R::SIZE이기 때문입니다.

R을 Time과 Slice에 배치하기

TimeMajor 모드는 SliceMajor와 상위·하위(major/minor) 관계를 뒤집은 형태입니다. Time의 부분 표현식(sub-expression)이 큰 스트라이드(stride)를, Slice의 부분 표현식이 작은 스트라이드를 가집니다. Slice·Time 내부의 순서 규칙과 Slice 부분 표현식의 크기·스트라이드가 2의 거듭제곱이어야 한다는 조건은 SliceMajor와 같습니다.

TimeMajor에는 이 규칙들 외에 제약 하나가 더 있습니다. PADDED_SIZE는 slice_span × time_span으로 분해되며, slice_span과 time_span은 각각 Slice와 Time에 있는 R 부분 표현식(sub-expression) 크기의 곱입니다. TimeMajor는 PADDED_SIZE - R::SIZE ≤ slice_span을 요구합니다. 즉, R에 추가되는 패딩(padding) 위치가 최대 slice_span개여야 합니다. 이 제약은 필수이며, 이를 어긴 배치는 VCG가 지원하지 않습니다(R을 Time과 Slice에 배치하기 참고).

rust
axes![R = 13, X = 64];

fn reduce_time_slice_timemajor<'l, const T: Tu>(
    input: VectorBranchTensor<'l, T, i32, m![1], m![1 # 2], m![R # 16 / 2 % 2, X, R # 16 % 2], m![R # 16 / 4 % 2, R # 16 / 8], m![1 # 8], Fresh, { stage::VeOrder::IntraFirst }>,
) -> VectorIntraSliceReduceTensor<'l, T, i32, m![1], m![1 # 2], m![R # 16 / 2 % 2, X, R # 16 % 2], m![1], m![1 # 4], Fresh, { stage::VeOrder::IntraFirst }>
{
    input
        .vector_narrow_trim::<m![1 # 4]>()
        //   Slice     = m![R # 16 / 2 % 2, X, R # 16 % 2]
        //   Time      = m![R # 16 / 4 % 2, R # 16 / 8]
        //   Packet    = m![1 # 4]
        //   OutTime   = m![1]          (R이 제거됨)
        //   OutPacket = m![1 # 4]
        .vector_intra_slice_reduce::<R, m![1], m![1 # 4]>(
            IntraSliceReduceOpI32::AddSat,
        )
}

이 예제는 R = 13을 R # 16으로 패딩(padding)한 뒤, 다음 부분 표현식(sub-expression)으로 Slice와 Time에 나누어 배치합니다.

차원(Dimension) 부분 표현식(Sub-expression) 스트라이드(Stride)
Time R # 16 / 4 % 2 4
Time R # 16 / 8 8
Slice R # 16 / 2 % 2 2
Slice R # 16 % 2 1

이 부분 표현식(sub-expression)들에서는 slice_span = 4, time_span = 4이고 추가 패딩(padding)은 PADDED_SIZE - R::SIZE = 3이므로 3 ≤ 4 조건을 만족합니다. 슬라이스(slice) 4개는 Slice가 R에 기여하는 값 0·1·2·3으로 구분되며, 각각 시간 반복(time iteration) 4번 동안 R 값 4개를 순회합니다. 배치(layout)는 두 경우로 나뉩니다. 슬라이스 1개는 전부 유효하고, 나머지 3개는 각각 반복 한 번을 제외하여 일부만 유효합니다.

Slice가 R에 기여하는 값(contribution) 반복(iteration)에 따른 R 값 유효한 시간 단계(valid time steps)
0 0, 8, 4, 12 4(모두 < R::SIZE)
1 1, 9, 5, 13 3(R = 13은 무효)
2 2, 10, 6, 14 3(R = 14는 무효)
3 3, 11, 7, 15 3(R = 15는 무효)

컴파일러(compiler)는 아래 시간 필터 설정(time filter config)을 생성합니다.

rust
TimeFilterConfig {
    sequencer:   [R # 16 / 4 % 2 -> size 2 : stride 1,    // 1 = 4 / slice_span
                  R # 16 / 8     -> size 2 : stride 2],   // 2 = 8 / slice_span
    slice_mask:  0b1000001,  // 비트 0(R # 16 % 2)과 비트 6(R # 16 / 2 % 2)이 R에 기여하는 값을 담습니다.
    slice_thres: 1,          // r_slice = 1을 표현하는 마스킹된 ID(masked id)입니다.
    time_thres:  3,          // = time_span - 1(부분 유효 슬라이스는 패딩된 마지막 반복을 제외함)
    mode:        TimeMajor,
}

이 설정(config)은 SliceMajor와 비교해 세 필드(field)가 다릅니다. slice_mask는 같은 방식을 따릅니다.

  • sequencer: 먼저 Time의 각 부분 표현식(sub-expression) 스트라이드(stride)를 slice_span으로 나눕니다. 이 예제에서는 스트라이드 4와 8이 1과 2가 됩니다.
  • slice_thres: 부분 유효 슬라이스(partial slice)의 r_slice = slice_span - (PADDED_SIZE - R::SIZE)를 표현합니다. 이 예제의 목표 값은 4 - 3 = 1입니다. 비트 0을 켜고(R # 16 % 2 = 1), 비트 6을 끄면(R # 16 / 2 % 2 = 0) 표현할 수 있어 slice_thres = 1입니다.
  • time_thres: 항상 time_span - 1입니다. 이 예제에서는 time_thres = 3입니다.

fn valid는 모든 플릿(flit)에 대해 올바른 유효성(validity)을 반환합니다. 확인하려면 R의 인덱스를 r = idx * slice_span + r_slice로 분해합니다. r_slice는 s & slice_mask에서 복원한 해당 슬라이스의 R 기여 값입니다. 슬라이스 비교의 두 경우를 살펴보겠습니다.

  • (s & slice_mask) < slice_thres이면 모든 시간 단계(time step)가 유효합니다. r_slice < slice_span - (PADDED_SIZE - R::SIZE)이므로 모든 idx에 대해 r ≤ (time_span - 1) * slice_span + r_slice < R::SIZE입니다.
  • (s & slice_mask) ≥ slice_thres이면 idx < time_thres = time_span - 1일 때에만 시간 단계(time step)가 유효합니다. 이 슬라이스는 r_slice ≥ slice_span - (PADDED_SIZE - R::SIZE)입니다. idx ≤ time_span - 2이면 r ≤ (time_span - 2) * slice_span + (slice_span - 1) < (time_span - 1) * slice_span ≤ R::SIZE입니다. idx = time_span - 1이면 r ≥ (time_span - 1) * slice_span + slice_span - (PADDED_SIZE - R::SIZE) = R::SIZE입니다.

SliceMajor와 달리 TimeMajor에는 전부 무효인 경우(all invalid)가 없습니다. 패딩 제약(padding constraint) PADDED_SIZE - R::SIZE ≤ slice_span이 추가 패딩을 충분히 제한하여, 완전히 무효가 되는 슬라이스가 없도록 하기 때문입니다.

패킷 클리퍼(Packet Clipper)

패킷 클리퍼(packet clipper)는 각 플릿(flit)의 valid_size(t)를 계산합니다. 이 값은 슬라이스 s가 아닌 시간 t에만 의존하므로, 같은 시간 단계(time step)의 모든 슬라이스가 같은 개수를 받습니다. 이러한 슬라이스 독립성(slice-independence) 때문에 VCG가 표현할 수 있는 배치(placement)에 제약이 생깁니다. 아래에서는 fn valid_size()를 단계적으로 구성합니다. R의 부분 표현식(sub-expression)이 Packet에 없으면 빈 시퀀서(sequencer)와 axis_size = packet_span = 8을 설정해 패킷 클리퍼를 비활성화합니다. 그러면 fn valid_size()는 항상 플릿 전체 크기인 8을 반환합니다.

rust
struct PacketClipperConfig {
    sequencer:   Sequencer,
    axis_size:   u32, // R::SIZE
    packet_span: u32, // 플릿(flit) 하나에 들어가는 R 위치의 수입니다.
}

impl PacketClipperConfig {
    /// 시간 단계(time step) t의 플릿(flit)에 있는 유효 원소 개수(valid element count)를 반환합니다.
    fn valid_size(&self, t: u64) -> u32 {
        let idx = self.sequencer.index(t);
        (self.axis_size - idx).clamp(0, self.packet_span)
    }
}

패킷 클리퍼(packet clipper)는 Packet = m![R # PADDED_SIZE % packet_span # 8]을 요구합니다. 다른 축(axis)이 R과 Packet을 공유하거나 R이 Packet 안에서 여러 부분 표현식(sub-expression)으로 나뉘면, fn valid_size()가 전제하는 연속된 앞부분(contiguous-prefix) 성질이 깨집니다(표현할 수 없는 패턴(Inexpressible Patterns) 참고).

R이 Packet 전체를 차지하는 경우

가장 단순한 경우에는 R이 플릿(flit) 하나에 들어갑니다(R::SIZE ≤ 8). 따라서 시간 단계(time step)나 슬라이스(slice)에 관계없이 모든 플릿의 valid_size = R::SIZE가 같습니다.

rust
axes![A = 8, R = 3, X = 64];

fn reduce_packet_only<'l, const T: Tu>(
    input: VectorBranchTensor<'l, T, f32, m![1], m![1 # 2], m![X, A / 2], m![1], m![R # 8], Fresh, { stage::VeOrder::IntraFirst }>,
) -> VectorIntraSliceReduceTensor<'l, T, f32, m![1], m![1 # 2], m![X, A / 2], m![1], m![1 # 4], Fresh, { stage::VeOrder::IntraFirst }>
{
    input
        .vector_narrow_trim::<m![R # 4]>()
        //   Slice     = m![X, A / 2]
        //   Time      = m![1]
        //   Packet    = m![R # 4]
        //   OutTime   = m![1]
        //   OutPacket = m![1 # 4]  (Packet에서 R이 제거됨)
        .vector_intra_slice_reduce::<R, m![1], m![1 # 4]>(
            IntraSliceReduceOpF32::Add,
        )
}

위 예제는 R = 3을 R # 8로 패딩(padding)하고, 하나의 부분 표현식(sub-expression)으로 Packet에 전부 배치합니다. 컴파일러(compiler)는 패킷 클리퍼(packet clipper)를 다음과 같이 설정합니다.

rust
PacketClipperConfig {
    sequencer:   [],   // 비어 있음: 플릿(flit) 하나가 R 전체를 담습니다.
    axis_size:   3,    // R::SIZE
    packet_span: 8,    // R이 플릿(flit)의 8개 위치 안에 들어갑니다.
}

모든 플릿(flit)의 valid_size = clamp(3 - 0, 0, 8) = 3입니다. 시간 단계(time step)와 슬라이스(slice)에 관계없이 일정합니다.

R을 Time과 Packet에 배치하기

VCG는 Time과 Packet 양쪽에 부분 표현식(sub-expression)을 가진 R도 지원합니다.

rust
axes![A = 8, R = 10, X = 64];

fn reduce_time_packet<'l, const T: Tu>(
    input: VectorBranchTensor<'l, T, f32, m![1], m![1 # 2], m![X, A / 2], m![R # 16 / 4], m![R # 16 % 4 # 8], Fresh, { stage::VeOrder::IntraFirst }>,
) -> VectorIntraSliceReduceTensor<'l, T, f32, m![1], m![1 # 2], m![X, A / 2], m![1], m![1 # 4], Fresh, { stage::VeOrder::IntraFirst }>
{
    input
        .vector_narrow_trim::<m![R # 16 % 4]>()
        //   Slice     = m![X, A / 2]
        //   Time      = m![R # 16 / 4]
        //   Packet    = m![R # 16 % 4 # 8]
        //   OutTime   = m![1]          (R이 제거됨)
        //   OutPacket = m![1 # 4]
        .vector_intra_slice_reduce::<R, m![1], m![1 # 4]>(
            IntraSliceReduceOpF32::Add,
        )
}

위 예제는 R = 10을 R # 16으로 패딩(padding)한 뒤 Time과 Packet에 나누어 배치합니다.

차원(Dimension) 부분 표현식(Sub-expression) 스트라이드(Stride)
Time R # 16 / 4 4
Packet R # 16 % 4 # 8 1

컴파일러(compiler)는 패킷 클리퍼(packet clipper)를 다음과 같이 설정합니다.

rust
PacketClipperConfig {
    sequencer:   [R # 16 / 4 -> size 4 : stride 4],
    axis_size:   10,   // R::SIZE
    packet_span: 4,    // 플릿(flit)당 R 위치 4개입니다(플릿의 뒤쪽 4개 위치는 항상 패딩).
}

이 설정(config)에서 시퀀서(sequencer)는 R 인덱스에 대한 Time의 기여 값 idx(t)를 복원합니다(R이 Time의 일부를 차지하는 경우 참고). 전체 axis_size = 10개 원소 중 Time이 idx(t)개를 처리했다면 axis_size - idx(t)개가 남습니다. 패킷 클리퍼(packet clipper)는 남은 원소를 최대 packet_span = 4개까지 플릿(flit)에 넣습니다. 따라서 fn valid_size(t) = clamp(10 - idx(t), 0, 4)입니다. 플릿 뒤쪽 4개 위치는 항상 패딩(padding)이고, R::SIZE가 packet_span의 배수가 아니면 마지막 플릿의 유효 개수는 일부만 채워집니다.

text
  flit 0: idx =  0  →  clamp(10 -  0, 0, 4) = 4  [████    ]
  flit 1: idx =  4  →  clamp(10 -  4, 0, 4) = 4  [████    ]
  flit 2: idx =  8  →  clamp(10 -  8, 0, 4) = 2  [██      ]
  flit 3: idx = 12  →  clamp(10 - 12, 0, 4) = 0  [        ]

전체 구성 결합하기(Putting It All Together)

앞에서는 R의 부분 표현식(sub-expression)을 한두 차원에 배치한 경우를 살펴봤습니다. 실제 슬라이스 내부 축약(Intra-Slice Reduce)은 하나의 REDUCE_LABEL(R) 외에 패딩된 비축약 축(non-reduce axis)도 함께 처리하며, VCG가 이들을 모두 추적합니다. R이든 다른 축이든 패딩된 축마다 시간 필터 슬롯(time filter slot)을 하나 사용하고, R의 Packet 부분은 패킷 클리퍼(packet clipper)가 담당합니다. 아래 예제는 각 차원(dimension)의 역할을 명확히 볼 수 있도록 축 하나에서 세 개까지 차례로 늘립니다.

원래 형태(shape)는 [H, C, W] = [5, 5, 19]입니다. 각 축(axis)은 배치 위치에 따라 slice/time/packet 부분으로 나뉩니다.

축(Axis) 패딩 후(Padded) Slice Time Packet
H # 8 H # 8 / 2(크기 4) H # 8 % 2(크기 2) -
C # 8 C # 8 / 2(크기 4) C # 8 % 2(크기 2) -
W # 24 - W # 24 / 8(크기 3) W # 24 % 8(크기 8)

다음 설명에서는 간결하게 Ho·Co·Wo와 Hi·Ci·Wi라는 약어를 사용합니다. *o는 표의 각 행에서 왼쪽 인자(factor), 즉 H·C의 slice 부분과 W의 time 부분입니다. *i는 그 바로 오른쪽 인자입니다.

1단계: W=19만 사용(패킷 클리퍼, 시간 필터 없음)

우선 H와 C는 제외하고 생각합니다. 시간 필터(time filter) 0과 1을 비활성화합니다(slice_mask=0, slice_thres=1). 각 슬라이스(slice)는 플릿(flit) 3개를 처리하고(Wo의 크기 3), 패킷 클리퍼(packet clipper)는 다음 톱니 모양 패턴(sawtooth)을 만듭니다.

text
valid_size: 8, 8, 3
              ^     ^
            full   19 - 16 = 3 (partial)

시간 필터(time filter)가 없으므로 모든 슬라이스(slice)가 정확히 같은 패턴을 받습니다.

text
All slices, all flits:
flit 0: ████████  (valid_size=8)
flit 1: ████████  (valid_size=8)
flit 2: ███       (valid_size=3)

2단계: C=5 추가(패킷 클리퍼 + 시간 필터 0)

이제 C축 타이머(timer), 즉 시간 필터(time filter) 0을 켭니다. C=5는 Co(slice, 크기 4) × Ci(time, 크기 2)로 나뉩니다. C 시간 필터의 설정은 slice_mask=0b0011(slice_id에서 Co 추출), slice_thres=2, time_thres=1, SliceMajor입니다.

이제 각 슬라이스(slice)는 Ci 크기 2 × Wo 크기 3에 해당하는 플릿(flit) 6개를 처리합니다. C 시간 필터(time filter)는 Co 값에 따라 슬라이스를 분류합니다.

Co 그룹(Group) 효과(Effect)
0 경계 아래(below, < 2) 플릿(flit) 6개 모두 패킷 클리퍼(packet clipper)의 패턴을 그대로 따릅니다.
1 경계 아래(below, < 2) 동일(same)
2 경계(boundary, = 2) Ci=0이면 유효하고 Ci=1이면 무효입니다.
3 경계 위(above, > 2) 플릿(flit) 6개 모두 valid_size = 0입니다.

슬라이스(slice)별 결과입니다. 플릿(flit) 6개 = Ci 크기 2 × Wo 크기 3입니다.

text
Co=0:  [8,8,3, 8,8,3]   (both Ci steps valid)
Co=1:  [8,8,3, 8,8,3]   (same)
Co=2:  [8,8,3, 0,0,0]   (Ci=0 valid, Ci=1 invalid)
Co=3:  [0,0,0, 0,0,0]   (all invalid)

타이머(timer)의 효과를 살펴보세요. 일부 슬라이스(slice)는 전부 0이 되고, 경계 슬라이스(boundary slice)는 뒤쪽 절반이 제외됩니다. 그러나 유효한 플릿(flit) 안에서는 패킷 클리퍼(packet clipper)의 [8,8,3] 패턴이 그대로 유지됩니다.

3단계: H=5 추가(패킷 클리퍼 + 시간 필터 0 + 시간 필터 1)

이제 H축 타이머(timer), 즉 시간 필터(time filter) 1을 켭니다. H=5는 Ho(slice, 크기 4) × Hi(time, 크기 2)로 나뉩니다. H 시간 필터의 설정은 slice_mask=0b1100(slice_id에서 Ho 추출), slice_thres=0b1000, time_thres=1, SliceMajor입니다.

슬라이스 ID(slice id)는 두 slice 인자(factor)를 slice_id = Ho * 4 + Co로 표현하며, 슬라이스는 총 16개입니다. 이제 각 슬라이스가 Hi 크기 2 × Ci 크기 2 × Wo 크기 3에 해당하는 플릿(flit) 12개를 처리합니다.

구성 요소(Component) 축(Axis) 추적 대상(Tracks) 설정(Config)
패킷 클리퍼(packet clipper) W=19 플릿(flit)별 R 개수 axis_size=19, packet_span=8, 시퀀서(sequencer) = [Wo -> size 3 : stride 8]
시간 필터(time filter) 0 C=5 슬라이스(slice)별 Co 유효성(validity) slice_mask=0b0011, slice_thres=2, time_thres=1, SliceMajor
시간 필터(time filter) 1 H=5 슬라이스(slice)별 Ho 유효성(validity) slice_mask=0b1100, slice_thres=0b1000, time_thres=1, SliceMajor

H 시간 필터(time filter)는 Ho로 슬라이스를 분류합니다. C 시간 필터가 Co로 분류할 때와 같은 논리입니다.

Ho 그룹(Group) 효과(Effect)
0 경계 아래(below) 통과(open)
1 경계 아래(below) 통과(open)
2 경계(boundary) Hi=0이면 통과(open), Hi=1이면 차단(closed)
3 경계 위(above) 차단(closed)

두 시간 필터(time filter)가 모두 true를 반환하면 최종 valid_size는 패킷 클리퍼(packet clipper)의 개수입니다. 어느 하나라도 false이면 0입니다.

아래 전체 히트맵(heatmap)은 슬라이스(slice) 16개를 열로(Ho별 그룹), 플릿(flit) 12개를 행으로((Hi, Ci)별 그룹) 나타냅니다. 오른쪽 주석(H:, C:)은 각 행에서 타이머(timer)의 상태를 표시합니다. v는 유효(valid), >는 경계(boundary), x는 무효(invalid)입니다. 먼저 주석을 보고 어느 행×열 구간이 모두 0인지(타이머 하나라도 x), 어느 구간에 데이터가 있는지 예상해 보세요. 그런 다음 셀에서 패킷 차원(packet dimension)의 [8, 8, 3] 톱니 패턴(sawtooth)을 확인합니다.

표현할 수 없는 패턴(Inexpressible Patterns)

다음 배치(placement)는 VCG로 표현할 수 없습니다. 각 절에서 해당 배치와 이유를 설명합니다.

Slice 안의 R 순서가 잘못된 경우

R이 Slice에 여러 부분 표현식(sub-expression)으로 들어가면, 바깥쪽 부분 표현식의 스트라이드(stride)가 안쪽보다 커야 합니다. 이 순서를 뒤집으면 슬라이스별 R 인덱스 범위가 단조적(monotonic)이지 않게 되어 slice_thres 하나로 표현할 수 없습니다.

rust
axes![R = 13, X = 32];

// 지원하지 않음: Slice에서 안쪽 부분 표현식(/ 2 % 4, stride 2)을 상위 부분(/ 8, stride 8) 바깥에 놓았습니다.
// 슬라이스 유효성(validity)이 단조롭지 않습니다(S5가 부분 유효인데 뒤의 S6은 유효). VCG로 표현할 수 없습니다.
fn reduce_wrong_ordering<'l, const T: Tu>(
    input: VectorBranchTensor<'l, T, i32, m![1], m![1 # 2], m![X, R # 16 / 2 % 4, R # 16 / 8], m![R # 16 % 2], m![1 # 8], Fresh, { stage::VeOrder::IntraFirst }>,
) -> VectorIntraSliceReduceTensor<'l, T, i32, m![1], m![1 # 2], m![X, R # 16 / 2 % 4, R # 16 / 8], m![1], m![1 # 4], Fresh, { stage::VeOrder::IntraFirst }>
{
    input
        .vector_narrow_trim::<m![1 # 4]>()
        //   Slice     = m![X, R # 16 / 2 % 4, R # 16 / 8]
        //   Time      = m![R # 16 % 2]
        //   Packet    = m![1 # 8]
        //   OutTime   = m![1]          (R이 제거됨)
        //   OutPacket = m![1 # 4]
        .vector_intra_slice_reduce::<R, m![1], m![1 # 4]>(
            IntraSliceReduceOpI32::Min,
        )
}

Slice와 Time의 R 인자가 교차하는 경우(Interleaved)

R의 부분 표현식(sub-expression)을 나눌 때 두 Time 인자(factor) 사이에 Slice 인자가 끼면, 슬라이스(slice)마다 필요한 유효 시간 단계(valid time step)의 수가 달라집니다. slice_thres 하나로는 이 차이를 표현할 수 없습니다.

rust
axes![R = 13, X = 64];

// 지원하지 않음: Time-Slice-Time으로 교차 배치(interleave)했습니다.
// 슬라이스마다 필요한 유효 단계 수가 다릅니다(예: S2는 3/4, S3는 2/4). 임계값 하나로 표현할 수 없습니다.
fn reduce_wrong_interleave<'l, const T: Tu>(
    input: VectorBranchTensor<'l, T, i32, m![1], m![1 # 2], m![X, R # 16 / 2 % 4], m![R # 16 / 8, R # 16 % 2], m![1 # 8], Fresh, { stage::VeOrder::IntraFirst }>,
) -> VectorIntraSliceReduceTensor<'l, T, i32, m![1], m![1 # 2], m![X, R # 16 / 2 % 4], m![1], m![1 # 4], Fresh, { stage::VeOrder::IntraFirst }>
{
    input
        .vector_narrow_trim::<m![1 # 4]>()
        //   Slice     = m![X, R # 16 / 2 % 4]
        //   Time      = m![R # 16 / 8, R # 16 % 2]
        //   Packet    = m![1 # 8]
        //   OutTime   = m![1]          (R이 제거됨)
        //   OutPacket = m![1 # 4]
        .vector_intra_slice_reduce::<R, m![1], m![1 # 4]>(
            IntraSliceReduceOpI32::Min,
        )
}

Slice와 Time의 R을 지나치게 패딩한 경우(Over-padded)

TimeMajor 모드는 PADDED_SIZE - R::SIZE ≤ slice_span을 요구합니다. R에 추가로 패딩(padding)할 수 있는 위치는 최대 slice_span개입니다.

아래 예제는 R = 14, Slice = m![X, R # 20 % 4](slice_span = 4), Time = m![A, R # 20 / 4], A = 3입니다. 따라서 R # 20 / 4의 time_span = 5이지만 Time::SIZE = A × time_span = 15입니다. 제약 대상은 Time::SIZE가 아닌 time_span입니다. A처럼 Time의 비(非)R 축(axis)은 R 인덱스를 바꾸지 않고 반복하므로 이 제약에 영향을 주지 않습니다. 올바른 패딩(padding)은 R # 16입니다(16 - 14 = 2 ≤ slice_span = 4). 이때 time_span = 4입니다. R # 20을 쓰면 R이 과도하게 패딩되어 time_span = 5가 되어 실제 데이터가 전혀 없는 Time 반복이 하나 추가됩니다. slice_thres 아래의 슬라이스(slice contribution = 0)에서는 R # 20 / 4 = 4일 때 시퀀서(sequencer)가 복원한 idx가 4 × 4 = 16에 도달합니다. 그러면 R 인덱스가 16 ≥ R::SIZE가 되어, 도달해서는 안 되는 패딩에 접근합니다. CPU 엔진은 이 경우를 정확히 검출합니다. 과도하게 패딩한 배치(layout)를 축약하면 오래된 도달 불가능한 R 인덱스로 실행하는 대신 out x residue must factor the operand 패닉(panic)이 발생합니다.

rust
axes![A = 3, R = 14, X = 64];

fn reduce_time_major_wrong<'l, const T: Tu>(
    input: VectorBranchTensor<'l, T, i32, m![1], m![1 # 2], m![X, R # 20 % 4], m![A, R # 20 / 4], m![1 # 8], Fresh, { stage::VeOrder::IntraFirst }>,
) -> VectorIntraSliceReduceTensor<'l, T, i32, m![1], m![1 # 2], m![X, R # 20 % 4], m![A], m![1 # 4], Fresh, { stage::VeOrder::IntraFirst }>
{
    input
        .vector_narrow_trim::<m![1 # 4]>()
        //   Slice     = m![X, R # 20 % 4]
        //   Time      = m![A, R # 20 / 4]   (A는 R이 아닌 축이며, R # 20 / 4의 time_span = 5)
        //   Packet    = m![1 # 8]
        //   OutTime   = m![A]              (R은 제거되고 A는 남음)
        //   OutPacket = m![1 # 4]
        // 지원하지 않음: R # 20은 과도한 패딩입니다(20 - 14 = 6 > slice_span = 4).
        // time_span = 5 > 4. 경계 아래 그룹의 슬라이스에 R # 20 / 4 = 4(R = 16 패딩)인 시간 단계가 포함됩니다.
        .vector_intra_slice_reduce::<R, m![A], m![1 # 4]>(
            IntraSliceReduceOpI32::AddSat,
        )
}

Packet 안의 R 형태가 복잡한 경우

패킷 클리퍼(packet clipper)는 Packet = m![R # PADDED_SIZE % packet_span # 8]을 요구합니다. 다른 형태는 fn valid_size()가 전제하는 연속된 앞부분(contiguous-prefix) 성질을 깨뜨립니다.

첫 예제는 R의 상위 부분(major part)을 Packet에 놓습니다. 즉, R # 24 % 8 대신 R # 24 / 8 형태입니다. 따라서 앞부분(prefix)이 R의 다음 연속 구간을 담지 않고 서로 다른 R 스트라이드(stride)의 위치들을 섞어 담습니다.

rust
axes![A = 8, R = 19, X = 64];

fn reduce_wrong_packet_outer<'l, const T: Tu>(
    input: VectorBranchTensor<'l, T, f32, m![1], m![1 # 2], m![X, A / 2], m![R # 24 % 8], m![R # 24 / 8 # 8], Fresh, { stage::VeOrder::IntraFirst }>,
) -> VectorIntraSliceReduceTensor<'l, T, f32, m![1], m![1 # 2], m![X, A / 2], m![1], m![1 # 4], Fresh, { stage::VeOrder::IntraFirst }>
{
    input
        .vector_narrow_trim::<m![R # 24 / 8 # 4]>()
        //   Slice     = m![X, A / 2]
        //   Time      = m![R # 24 % 8]
        //   Packet    = m![R # 24 / 8 # 8]   (지원하지 않음: R의 상위 부분이 Packet에 있음)
        //   OutTime   = m![1]          (R이 제거됨)
        //   OutPacket = m![1 # 4]
        .vector_intra_slice_reduce::<R, m![1], m![1 # 4]>(
            IntraSliceReduceOpF32::Add,
        )
}

두 번째 예제는 R과 다른 축(axis) A가 Packet을 공유합니다. 따라서 앞부분 기준 개수(prefix-based count)가 패딩(padding)으로 간주하는 위치에 A의 원소들이 놓입니다.

rust
axes![A = 4, R = 19, X = 256];

fn reduce_wrong_mixed_packet<'l, const T: Tu>(
    input: VectorBranchTensor<'l, T, f32, m![1], m![1 # 2], m![X], m![R # 24 / 2], m![R # 24 % 2, A], Fresh, { stage::VeOrder::IntraFirst }>,
) -> VectorIntraSliceReduceTensor<'l, T, f32, m![1], m![1 # 2], m![X], m![1], m![A], Fresh, { stage::VeOrder::IntraFirst }>
{
    input
        .vector_narrow_split::<m![R # 24], m![A]>()
        //   벡터 초기화(Vector Init) 시점:
        //   Slice     = m![X]
        //   Time      = m![R # 24 / 2]
        //   Packet    = m![R # 24 % 2, A]   (지원하지 않음: A가 R과 Packet을 공유함)
        //   OutTime   = m![1]          (R이 제거되며, A도 앞부분 기준 valid_size에 의해 별도 알림 없이 제외됨)
        //   OutPacket = m![A]
        .vector_intra_slice_reduce::<R, m![1], m![A]>(
            IntraSliceReduceOpF32::Add,
        )
}

R을 Slice와 Packet에 배치한 경우

R을 Slice와 Packet에 나눕니다. 이를 표현할 수 없는 이유를 보려면, R = 2045를 R # 2048로 패딩(padding)하고 Slice = m![R # 2048 / 8](슬라이스 256개), Packet = m![R # 2048 % 8](원소 8개짜리 플릿)로 나눈 경우를 생각해 보세요. 유일한 시간 단계(time step) t = 0에서 fn valid_size는 모든 슬라이스에 대해 clamp(2045 - 0, 0, 8) = 8을 계산합니다. 그러나 슬라이스 255의 플릿(flit)은 R 인덱스 2040~2047을 담고 있으며, 그중 실제 데이터는 다섯 개뿐입니다.

t = 0, slice = 255일 때:

플릿 위치(flit position) 0 1 2 3 4 5 6 7
R 인덱스(index) 2040 2041 2042 2043 2044 2045 2046 2047
유효 여부(valid?) 유효(yes) 유효(yes) 유효(yes) 유효(yes) 유효(yes) [pad] [pad] [pad]

슬라이스(slice) 0~254에는 valid_size = 8이 맞지만, 슬라이스 255에는 valid_size = 5가 필요합니다. fn valid_size(t)는 같은 t에 대해 값 하나만 반환할 수 있으므로, 이 모두를 만족하는 단일 설정(config)은 없습니다.

단, R::SIZE % packet_span = 0이어서 모든 패킷(packet)이 꽉 차 있거나 완전히 비어 있는 특수한 경우는 Slice만 사용하는 문제로 단순화되므로 지원됩니다.

rust
axes![R = 2045];

// 지원하지 않음: R = 2045를 Slice(/ 8, 슬라이스 256개)와 Packet(% 8)에 나누어 배치했습니다.
// 슬라이스 0~254에는 valid_size = 8, 255에는 valid_size = 5가 필요합니다. fn valid_size(t)는 슬라이스별로 달라질 수 없습니다.
fn reduce_wrong_slice_packet<'l, const T: Tu>(
    input: VectorBranchTensor<'l, T, i32, m![1], m![1 # 2], m![R # 2048 / 8], m![1], m![R # 2048 % 8], Fresh, { stage::VeOrder::IntraFirst }>,
) -> VectorIntraSliceReduceTensor<'l, T, i32, m![1], m![1 # 2], m![R # 2048 / 8], m![1], m![1 # 4], Fresh, { stage::VeOrder::IntraFirst }>
{
    input
        .vector_narrow_trim::<m![R # 2048 % 4]>()
        //   Slice     = m![R # 2048 / 8]
        //   Time      = m![1]
        //   Packet    = m![R # 2048 % 8]
        //   OutTime   = m![1]          (R이 제거됨)
        //   OutPacket = m![1 # 4]

}

유효성 추적(validity tracking)이 필요한 패딩된 축(axis)은 각각 시간 필터(time filter) 또는 패킷 클리퍼(packet clipper)를 하나 사용합니다. 한 번의 호출에서 추적할 수 있는 축은 최대 4개입니다(패킷 클리퍼 1개 + 시간 필터 3개). 패딩되지 않은 축은 슬롯(slot)이 필요 없습니다. slice_mask=0, slice_thres=1로 시간 필터를 끄면 항상 true를 반환합니다.

슬라이스 내부 축약(intra-slice reduce)은 REDUCE_LABEL을 하나만 받습니다. 따라서 “여러 축(multi-axis)”은 축약 축 R 하나에 패딩된 비축약 축(non-reduce axis)이 추가된다는 뜻이며, 여러 축약을 동시에 수행한다는 뜻은 아닙니다.

뒷단의 4-Way 연산(Downstream 4-Way Operations)

VCG는 폭을 줄이기(narrowing) 전에 8-way 플릿(flit)마다 valid_size를 생성합니다. 뒷단의 Narrow 단계는 각 8-way 플릿을 4-way 절반들로 나누며, 어떤 narrow 연산을 적용하느냐에 따라 valid_size를 양쪽에 나누는 방식이 결정됩니다.

연산(Operation) 입력(Input) 출력(Output) 유효 개수 변환(Valid Count Transformation)
vector_narrow_split 8-way 플릿(flit, valid_size = v) 4-way 플릿(flit) 두 개 아래쪽(low): min(v, 4), 위쪽(high): max(v - 4, 0)
vector_narrow_trim 8-way 플릿(flit, valid_size = v) 4-way 플릿(flit) 한 개 min(v, 4)
vector_widen_concat 4-way 플릿(flit) 두 개(v_low, v_high) 8-way 플릿(flit) v_low + v_high
vector_widen_pad 4-way 플릿(flit) 8-way 플릿(flit) 변경 없음(unchanged)

vector_narrow_split과 vector_widen_concat은 앞부분(prefix) 성질을 유지합니다. vector_narrow_trim을 사용하려면 매핑(mapping)이 v <= 4를 정적으로(static) 보장해야 합니다. 위쪽 원소 4개가 유효할 수 있다면 이를 잘라 내는 것은 데이터 손실입니다.
