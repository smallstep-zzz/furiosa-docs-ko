사례 연구: 실행 중 루프 본문 건너뛰기(Skip Loop Bodies at Runtime)

커널(kernel)은 실행 시점의 스칼라(runtime scalar)를 사용하여, 상한이 정적으로 정해진 작업(statically bounded workload) 중 필요한 부분만 실행할 수 있습니다. 호스트(host)가 HbmScalar<T>에 값을 저장하면 커널은 to_spm으로 SPM에 읽어 들이고, 일반적인 if로 건너뛸 수 있는 연산을 감쌉니다. 텐서 형태(tensor shape)와 루프의 최대 반복 횟수(maximum trip count)는 여전히 컴파일 시간 상수(compile-time constant)입니다.

이 패턴(pattern)은 MoE 전문가 블록(expert block), 가변 길이 배치(variable-length batch), 그 밖에 최대 작업량은 알려져 있고 실행 시점에 유효 개수(runtime valid count)가 정해지는 커널에 적합합니다.

정적 루프에 조건 걸기(Guard a Static Loop)

다음은 테스트된 커널(kernel)로, 처음 active_experts개 그룹을 복사하고 나머지 출력 그룹은 0으로 유지합니다.

rust
axes![Slice = 64, Group = 4, Width = 8];
type Chip = m![1];
type Cluster = m![1];
/// 정적 `Group` 상한(static bound)을 가진 조건부 벡터 가져오기·저장(guarded vector fetch/commit)으로 요청한 전문가 그룹(expert group)을 복사합니다.
#[device(chip = 1, pe = 1)]
pub fn bounded_dynamic_expert_loop(
    device: &mut Device,
    input: &HbmTensor<i32, Chip, m![Slice, Group, Width]>,
    active_experts: &HbmScalar<usize>,
) -> HbmTensor<i32, Chip, m![Slice, Group, Width]> {
    let input = input.to_dm::<Cluster, m![Slice], m![Group, Width]>(&mut device.tdma);
    let mut output = DmTensor::<i32, Chip, Cluster, m![Slice], m![Group, Width]>::new();
    output.view_mut().memset(0, &mut device.sub);

    let active_experts = active_experts.to_spm(&mut device.tdma);
    for group in 0..Group::SIZE {
        if group < active_experts {
            let source = input.view().tile::<m![Group], 1, m![1 # { Group::SIZE }, Width]>(group);
            let target = output
                .view_mut()
                .tile::<m![Group], 1, m![1 #{!} { Group::SIZE }, Width]>(group);
            device
                .main
                .begin(source)
                .fetch::<m![1], m![Width]>()
                .collect::<m![1], m![Width]>()
                .commit_trim::<m![Width]>()
                .commit_view(target);
        }
    }

    output.to_hbm(&mut device.tdma)
}

루프(loop)의 상한은 항상 정적인 Group::SIZE입니다. 각 반복은 usize 반복 변수(induction variable)를 HBM에서 읽은 usize 값과 비교합니다. active_experts가 0이면 모든 본문(body)을 건너뛰고, Group::SIZE보다 크면 모든 본문을 실행합니다. 예제에서 루프 전에 하는 것처럼, 건너뛴 반복이 남길 출력 영역(output region)에 정해진 값이 필요하면 미리 초기화하세요.

같은 조건(guard)으로 텐서 유닛(Tensor Unit) 연산도 감쌀 수 있습니다. 테스트된 MoE 예제에서 가져온 다음 코드는 전문가 인덱스(expert index)가 실행 시점 개수(runtime count)보다 작을 때만 해당 전문가의 수축(contraction) 연산을 실행합니다.

rust
axes![Slice = 64, Expert = 4, MatmulOut = 8, MatmulRed = 16];
type Chip = m![1];
type Cluster = m![1];
/// 요청한 전문가(expert)에 대해 행렬곱(matmul)을 실행하고 나머지 전문가는 0으로 유지합니다.
/// 모든 `Expert` 반복(iteration)을 스케줄(schedule)에 넣고 각 본문(body)을 실행 시점 조건(runtime guard)으로 제어합니다.
#[device(chip = 1, pe = 1)]
pub fn bounded_dynamic_matmul(
    device: &mut Device,
    activation: &HbmTensor<bf16, Chip, m![Slice, MatmulRed]>,
    weight: &HbmTensor<bf16, Chip, m![Slice, Expert, MatmulOut, MatmulRed]>,
    active_experts: &HbmScalar<usize>,
) -> HbmTensor<f32, Chip, m![Slice, Expert, MatmulOut]> {
    let activation: DmTensor<bf16, Chip, Cluster, m![Slice], m![MatmulRed]> = activation.to_dm(&mut device.tdma);
    let weight: DmTensor<bf16, Chip, Cluster, m![Slice], m![Expert, MatmulOut, MatmulRed]> =
        weight.to_dm(&mut device.tdma);
    let mut output: DmTensor<f32, Chip, Cluster, m![Slice], m![Expert, MatmulOut]> = DmTensor::new();
    output.view_mut().memset(0.0, &mut device.sub);

    let active_experts = active_experts.to_spm(&mut device.tdma);
    for expert in 0..Expert::SIZE {
        if expert < active_experts {
            let weight_group = weight
                .view()
                .tile::<m![Expert], 1, m![1 # { Expert::SIZE }, MatmulOut, MatmulRed]>(expert);
            let weight_trf: TrfTensor<bf16, Chip, Cluster, m![Slice], m![MatmulOut], m![MatmulRed]> = device
                .sub
                .begin(weight_group)
                .fetch::<m![MatmulOut], m![MatmulRed]>()
                .collect::<m![MatmulOut], m![MatmulRed]>()
                .to_trf();

            device
                .main
                .begin(activation.view())
                .fetch::<m![1], m![MatmulRed]>()
                .collect::<m![1], m![MatmulRed]>()
                .contract_outer::<m![1], m![MatmulRed], _, _, _>(&weight_trf)
                .contract_packet::<m![1]>()
                .contract_time::<m![1]>()
                .contract_lane::<m![1], m![MatmulOut]>(LaneMode::Interleaved)
                .commit_trim::<m![MatmulOut]>()
                .commit_view(
                    output
                        .view_mut()
                        .tile::<m![Expert], 1, m![1 #{!} { Expert::SIZE }, MatmulOut]>(expert),
                );
        }
    }
    output.to_hbm(&mut device.tdma)
}

실행 시점 스칼라 전달·갱신(Pass and Update a Runtime Scalar)

실행 컨텍스트(launch context)의 PDMA 큐(queue)를 통해 스칼라(scalar)를 만든 뒤, 다른 커널 인수(kernel argument)처럼 전달합니다.

rust
let mut active = HbmScalar::<usize>::from_host(0, &mut device.pdma).await?;

HbmScalar::from_host(3, &mut device.pdma).output(&mut active).await?;
launch(scalar_consumer, (&mut device, &active)).await?;

from_host는 각 칩(chip)의 로컬 HBM에 스칼라(scalar) 하나를 할당하고 모든 복사본에 같은 값을 씁니다. write는 이 할당(allocation)을 다음 실행(launch)에서 재사용합니다. 커널 내부의 to_spm(&mut device.tdma)는 이 값을 SPM 스칼라로 옮겨 장치 스칼라 표현식(device scalar expression)에서 사용할 수 있게 합니다.

HbmScalar는 bool, i32, u32, i64, u64, usize를 지원합니다. 단순한 켜기·끄기 조건(on/off guard)에는 bool, 루프 상한(loop bound)과 텐서 인덱스(tensor index)에는 usize를 사용하세요. 현재 컴파일러(compiler)는 64비트 Rust 프런트엔드 대상(frontend target)에서만 실행 시점 usize 스칼라를 허용하며, 부호 없는 64비트 값(unsigned 64-bit value)으로 저장합니다.

실행 시점 루프 상한 대신 if 사용하기

값을 반환하지 않는 문장 블록(statement block)을 포함하여 실행 시점 if 문(runtime if statement)을 지원합니다. 장치 함수(device function)에서는 일반적인 break 문과 실행 시점 루프 상한(runtime loop bound)을 지원하지 않습니다. 정적인 최대 반복 루프에 실행 시점 조건(guard)을 붙여 작성하세요.

rust
for expert in 0..Expert::SIZE {
    if expert < active_experts {
        run_expert(expert);
    }
}

다음 형태는 지원하지 않습니다.

text
for expert in 0..active_experts {
    run_expert(expert);
}

for expert in 0..Expert::SIZE {
    if expert >= active_experts {
        break;
    }
    run_expert(expert);
}

지원되는 형태는 정적인 최대 반복 횟수(static maximum)를 스케줄(schedule)에 반영합니다. 조건이 거짓이면 조건으로 감싼 텐서 유닛(Tensor Unit) 또는 DMA 연산은 실행되지 않지만, 조건을 평가하고 바깥 루프를 진행하는 실행 비용(runtime cost)은 여전히 듭니다.

작은 최대 반복 횟수는 펼치기(Unroll a Small Maximum)

최대 반복 횟수(maximum trip count)가 작은 컴파일 시간 상수(compile-time constant)이면 #[unroll]을 적용할 수 있습니다.

rust
axes![Slice = 64, Group = 4, Width = 8];
type Chip = m![1];
type Cluster = m![1];
/// 정적 `Group` 루프(loop)를 펼친 뒤(unroll) 요청한 전문가 그룹(expert group)을 복사합니다.
#[device(chip = 1, pe = 1)]
pub fn unrolled_bounded_dynamic_expert_loop(
    device: &mut Device,
    input: &HbmTensor<i32, Chip, m![Slice, Group, Width]>,
    active_experts: &HbmScalar<usize>,
) -> HbmTensor<i32, Chip, m![Slice, Group, Width]> {
    let input = input.to_dm::<Cluster, m![Slice], m![Group, Width]>(&mut device.tdma);
    let mut output = DmTensor::<i32, Chip, Cluster, m![Slice], m![Group, Width]>::new();
    output.view_mut().memset(0, &mut device.sub);

    let active_experts = active_experts.to_spm(&mut device.tdma);
    #[unroll]
    for group in 0..Group::SIZE {
        if group < active_experts {
            let source = input.view().tile::<m![Group], 1, m![1 # { Group::SIZE }, Width]>(group);
            let target = output
                .view_mut()
                .tile::<m![Group], 1, m![1 #{!} { Group::SIZE }, Width]>(group);
            device
                .main
                .begin(source)
                .fetch::<m![1], m![Width]>()
                .collect::<m![1], m![Width]>()
                .commit_trim::<m![Width]>()
                .commit_view(target);
        }
    }

    output.to_hbm(&mut device.tdma)
}

Group::SIZE = 4이면 #[unroll]은 루프를 조건이 포함된 본문(guarded body)의 복사본 네 개로 바꿉니다. 결과는 다음처럼 동작합니다.

text
if 0 < active_experts { run_group(0); }
if 1 < active_experts { run_group(1); }
if 2 < active_experts { run_group(2); }
if 3 < active_experts { run_group(3); }

active_experts는 여전히 실행 시점(runtime)에 읽습니다. 루프 펼치기(unrolling)는 루프 제어를 없애고 스케줄러(scheduler)가 서로 다른 그룹의 연산을 함께 고려하게 하지만, 네 번의 실행 시점 조건 검사는 제거하지 않습니다.

범위(range)는 0에서 시작하여 0이 아닌 컴파일 시간 상수(compile-time constant)에서 끝나야 합니다. 중첩 루프(nested loop)에서는 펼칠 각 수준에 #[unroll]을 추가하세요.

컴파일러(compiler)는 “작은” 루프의 기준값(threshold)을 정해 두지 않습니다. 생성 코드가 정적 상한(static bound)에 비례해 커지므로, 그룹 4개짜리 루프는 적절한 후보지만 전문가(expert) 1,024개짜리 루프는 보통 펼치지 않는 편이 좋습니다. 득실(trade-off)이 분명하지 않으면 두 형태를 비교하세요. 일반적인 스케줄링 득실은 루프 펼치기(Unroll a loop)를 참고하세요.
