매핑 표현식(Mapping Expressions)

매핑 표현식(mapping expression)은 매핑(mapping)을 표현하는 Rust 타입(type)입니다. 먼저 해당 위치의 Cell을 읽고, 그다음 Index의 항(term), 패딩 종류(padding kind), 범위 밖(out-of-bounds) 결과를 이용해 접근을 디버깅(debugging)하세요. 이 절에서는 그러한 결과를 만드는 생성자(constructor)와 지원 동작을 정의합니다.

축 크기(Axis Sizes)

axes! 매크로(macro)는 축 식별자(axis identifier)와 크기를 선언합니다. 이 절 전체에서는 다음 선언을 사용합니다.

rust
axes![A = 8, B = 512];

위치에 대한 결과(Position Results)

m![H, W] 같은 매핑 표현식(mapping expression)은 각 물리적 위치(physical position)를 Cell에 대응시킵니다. 내부 항(term)을 읽기 전에 먼저 결과 종류를 확인하세요.

rust
axes![A = 8];
type E = m![A];
assert_eq!(E::map(0), i![A: 0]);

Cell::Index는 구조적으로 유효한 위치(live)를 나타내는 결과입니다. 매핑 항(mapping term)을 유지하며, Index::finalize()는 그 항의 스칼라 좌표(scalar coordinate)를 검증하고 모듈로 범위 초과(modulo overshoot)가 있으면 오류를 반환할 수 있습니다. 패딩(padding)과 범위 밖(out-of-bounds) 위치에는 유효한 항이 없습니다. Cell::Index(Index::new())는 축 항(axis term)이 없어도 유효한 결과이며, Cell::Padding이나 Cell::OutOfBounds와 구별됩니다. 따라서 빈 Index가 유효하지 않은 위치를 뜻하는 일은 없습니다. i! 매크로(macro)는 쓰인 순서대로 할당(assignment)을 결합하며, 합성 매핑(composed mapping)에서는 이것이 주 차원에서 부 차원으로 가는 순서(major-to-minor)입니다. 패딩에 대한 Cell::combine은 교환법칙이 성립하지 않으므로(non-commutative), 그 순서를 바꾸려는 의도가 있을 때만 할당의 순서를 바꾸세요.

M 생성자 규칙(Constructor Rules)

모든 매핑 표현식(mapping expression)은 버퍼 크기(buffer size)와 위치 매핑(position mapping)을 제공하는 M 트레이트(trait)를 구현합니다.

rust
// `furiosa_opt_std::prelude` 내부...
pub trait M: Debug + Clone {
    /// 주어진 형상(shape)에 대해 계산한 크기(size).
    const SIZE: usize;

    /// 매핑 표현식 타입(mapping expression type)을 값(value)으로 변환.
    fn to_value() -> Mapping;

    /// 버퍼 인덱스(buffer index)를 물리적 셀 결과(physical cell result)로 변환.
    fn map(i: usize) -> Cell;
}

/// 유효한 텐서 인덱스(live tensor index): 축 식별자(axis identifier)에서 좌푯값(coordinate value)으로의 사상(map).
pub struct Index { /* ... */ }

/// 유효 위치(live), 패딩된 위치(padded), 범위 밖 위치(out-of-range)의 결과.
pub enum Cell { Index(Index), Padding(PaddingKind), OutOfBounds }

/// 종류가 구분된 셀(classified cell)을 생성.
/// `i![A: 2, B: 3]`은 A = 2, B = 3인 유효한 `Cell::Index`를 생성하며,
/// 유효하지 않은 부분(non-live contribution)은 `Cell::Padding` 또는 `Cell::OutOfBounds`로 유지됨.
macro_rules! i {
    /* ... */
}

호스트 텐서 사용법(Host Tensor Usage)

M 트레이트(trait)를 기반으로 하는 가장 단순한 구체 타입(concrete type)은 HostTensor<D, E>입니다. 원소 타입(element type)이 D인 호스트 메모리 버퍼(host memory buffer)이며, 표현(representation)은 매핑(mapping) E가 완전히 결정합니다. E는 버퍼 크기(E::SIZE)와 버퍼 위치를 셀(cell)에 대응시키는 관계(E::map)를 모두 결정합니다. HostTensor<bf16, m![A, B]>에는 bf16 데이터 원소 4,096개가 들어갑니다. 호스트 텐서에서 E::map이 반환한 각 Cell::Index(index)는 그 물리적 위치에 저장된 구조적 Index를 나타냅니다. 이를 텐서 인덱스(tensor index)로 취급하기 전에 Index::finalize()를 호출해 스칼라 좌표(scalar coordinate)를 검증하세요. 범위를 초과하면 이 단계에서 실패할 수 있습니다. Cell::OutOfBounds는 읽기의 경우 CellExt::finalize(PaddingKind::Top)으로, 쓰기의 경우 CellExt::finalize(PaddingKind::Bottom)으로 변환하세요. *담고 있다(holds)*의 형식적 정의(formal definition)는 텐서 의미론(Tensor Semantics)에 있습니다.

HbmTensor, DmTensor 같은 장치 텐서(device tensor)는 여러 매핑 표현식(mapping expression)에 걸친 더 복잡한 표현(representation)을 가집니다. 자세한 내용은 공간 차원과 시간 차원(Spatial and Temporal Dimensions)을 참고하세요.

생성자(Constructors)

HostTensor<D, E>의 E를 비롯한 매핑 표현식(mapping expression)은 작은 생성자(constructor)들을 합성해 만듭니다. 각 생성자는 더 단순한 매핑(mapping)을 변환하거나 결합합니다. 이 표현식들은 산술 연산자와 비슷한 /, %, 패딩(padding)을 위한 #를 사용해 텐서 인덱스(tensor index)와 선형 버퍼 인덱스(linear buffer index)의 대응 관계를 간결하게 정의합니다.

기호(Symbol)

기호(symbol)는 대문자 한 글자이며, 크기는 형상(shape) 선언에서 가져옵니다. 매핑(mapping) m![A]는 버퍼 인덱스(buffer index) 8개를 해당 축(axis)의 텐서 인덱스(tensor index)에 선형으로 대응시킵니다.

rust
type E = m![A]; // Symbol<Ident::A, 8>

fn test_symbol() {
    assert_eq!(E::map(0), i![A: 0]);
    assert_eq!(E::map(1), i![A: 1]);
    assert_eq!(E::map(2), i![A: 2]);
    for i in 0..E::SIZE {
        assert_eq!(E::map(i), i![A: i]);
    }
    assert_eq!(E::map(E::SIZE), Cell::OutOfBounds);
}
rust
impl<S: AxisName> M for Symbol<S> {
    const SIZE: usize = S::SIZE;

    fn to_value() -> Mapping {
        Mapping::Symbol {
            symbol: S::NAME,
            size: S::SIZE,
        }
    }

    fn map(i: usize) -> Cell {
        if i >= S::SIZE {
            return Cell::OutOfBounds;
        }
        Cell::Index({
            let mut index = Index::new();
            index.add_term(
                Term {
                    inner: Atom::Symbol {
                        symbol: S::NAME,
                        size: S::SIZE,
                    },
                    stride: 1,
                    modulo: S::SIZE,
                },
                i,
            );
            index
        })
    }
}

참고(Note) 모든 기호(symbol) A에서 인덱스(index) 0인 i![A: 0]은 빈 텐서 인덱스(tensor index) i![]와 동등합니다.

쌍(Pair)

쌍 매핑(pair mapping) m![A, B]는 형상(shape)이 \\{A=8, B=512\\}인 2차원 텐서(tensor)를 원소 4,096개짜리 버퍼(buffer)에 저장합니다. Pair<L, R>은 두 공간의 데카르트 곱(Cartesian product)을 선형 버퍼(linear buffer)에 대응시키며, L은 주 차원(major dimension), R은 부 차원(minor dimension)입니다. 크기는 L::SIZE * R::SIZE이며, 내림 나눗셈(floor division)과 나머지(modulo)로 인덱스(index)를 분해합니다. 주 차원 L의 결과가 패딩(padding)이면 부 차원 R의 결과를 보기 전에 그 패딩 종류가 우선합니다. 유효한 결합(live combination)이 불가능하면 범위 밖(out-of-bounds) 결과가 전파됩니다. m![A, B, C, D]는 Pair<A, Pair<B, Pair<C, D>>>로 확장되며 오른쪽 결합(right-associative)입니다.

rust
type E = m![A, B]; // Pair<m![A], m![B]>

fn test_pair() {
    // 처음 원소 512개는 A=0, 다음 512개는 A=1을 담음
    assert_eq!(E::map(0),   i![A: 0, B: 0]);
    assert_eq!(E::map(511), i![A: 0, B: 511]);
    assert_eq!(E::map(512), i![A: 1, B: 0]);
    assert_eq!(E::map(519), i![A: 1, B: 7]); // 519 == 512 * 1 + 7
    for i in 0..E::SIZE {
        assert_eq!(E::map(i), i![A: i / <m![B]>::SIZE, B: i % <m![B]>::SIZE]);
    }
    assert_eq!(E::map(E::SIZE), Cell::OutOfBounds);
}
rust
impl<L, R> M for Pair<L, R>
where
    L: M,
    R: M,
{
    const SIZE: usize = L::SIZE * R::SIZE;

    fn to_value() -> Mapping {
        Mapping::Pair {
            left: RBox::new(L::to_value()),
            right: RBox::new(R::to_value()),
        }
    }

    fn map(i: usize) -> Cell {
        if i >= Self::SIZE {
            return Cell::OutOfBounds;
        }
        let l = L::map(i / R::SIZE);
        let r = R::map(i % R::SIZE);
        match l {
            Cell::OutOfBounds => Cell::OutOfBounds,
            Cell::Padding(kind) => Cell::Padding(kind),
            Cell::Index(mut left) => match r {
                Cell::Index(right) => {
                    left.add(right);
                    Cell::Index(left)
                }
                Cell::Padding(kind) => Cell::Padding(kind),
                Cell::OutOfBounds => Cell::OutOfBounds,
            },
        }
    }
}

항등(Identity)

항등 매핑(identity mapping) m![1]은 버퍼 인덱스(buffer index) 0을 빈 텐서 인덱스(tensor index) i![]에 대응시키는 단일 원소 버퍼(buffer)를 만듭니다. 이는 Pair의 항등원(identity element)이므로 m![1, A]와 m![A, 1]은 모두 m![A]와 동등합니다. 더 일반적으로 브로드캐스트 매핑(broadcast mapping)은 크기 미만의 모든 위치에서 동일한 유효한 빈 값 Cell::Index(Index::new())를 반환하고, 그 크기 이상의 위치에서는 Cell::OutOfBounds를 반환합니다.

rust
type E = m![1]; // 항등(Identity)

fn test_identity() {
    assert_eq!(E::map(0), i![]);
    assert_eq!(E::map(1), Cell::OutOfBounds);
}
rust
/// 항등 매핑(identity mapping, 크기 1의 브로드캐스트(broadcast)); `m![1]`로 쓰는 단위원(unit).
pub type Identity = Broadcast<1>;

패딩(Padding)

패딩(padding)은 사용하지 않는 버퍼 공간(buffer space)을 더해 데이터를 하드웨어 요구 사항에 맞게 정렬(alignment)합니다. 예를 들어 DMA 엔진(engine)은 행(row)의 시작이 64바이트 경계(boundary)에 놓이도록 요구합니다. axes![C = 13, D = 61]일 때 m![C, D]는 61이 64로 나누어떨어지지 않으므로 행이 정렬되지 않습니다. m![C, D # 64]는 행마다 원소 3개를 추가하여 각 행을 64바이트 경계에 맞춥니다.

rust
axes![C = 13, D = 61];

type E = m![C, D # 64]; // Pair<m![C], Padding<m![D], 64>>

fn test_padding() {
    assert_eq!(E::map(0),  i![C: 0, D: 0]);
    assert_eq!(E::map(60), i![C: 0, D: 60]);
    assert_eq!(E::map(61), Cell::Padding(PaddingKind::Top));
    assert_eq!(E::map(62), Cell::Padding(PaddingKind::Top));
    assert_eq!(E::map(63), Cell::Padding(PaddingKind::Top));
    assert_eq!(E::map(64), i![C: 1, D: 0]);
}
rust
impl<L, F, const KIND: PaddingKind> M for Padding<L, F, KIND>
where
    L: M,
    F: Count,
{
    const SIZE: usize = F::SIZE;

    fn to_value() -> Mapping {
        Mapping::Padding {
            inner: RBox::new(L::to_value()),
            padding: F::SIZE,
            kind: KIND,
        }
    }

    fn map(i: usize) -> Cell {
        if i >= F::SIZE {
            Cell::OutOfBounds
        } else if i >= L::SIZE {
            Cell::Padding(KIND)
        } else {
            L::map(i)
        }
    }
}

패딩(padding)된 위치는 개수뿐 아니라 그 내용도 타입(type)에 포함됩니다. 다음 세 종류를 추적합니다.

  • m![A # m] 또는 m![A #{*} m]은 크기 m까지 최상위 패딩(top padding)을 적용합니다. 이 위치들은 접근 가능하지만 어떤 값이 들어 있는지는 정해져 있지 않습니다. 원시 DM 텐서(raw DM tensor)가 이 속성을 가집니다. #는 축약 표기이고, #{*}는 종류를 명시적으로 적은 표기입니다.
  • m![A #{0} m]은 크기 m까지 0 패딩(zero-filled padding)을 적용합니다. 이 위치들은 접근 가능하며 0이 들어 있다는 사실이 알려져 있습니다. 매핑(mapping)은 이 값의 속성을 기록할 뿐, 표현식(expression) 자체가 값을 채우는 작업을 수행하지는 않습니다.
  • m![A #{!} m]은 크기 m까지 최하위 패딩(bottom padding)을 적용합니다. 읽기는 허용되며 임의의 값이 반환되지만, 쓰기는 금지됩니다. 이는 컴파일러(compiler)가 쓰기 작업 중에 보존해야 할 위치를 모델링합니다.

#의 기본 종류는 최상위(top)입니다. Rust 타입 수준(type level)에서는 Padding<L, SIZE, KIND>에 PaddingKind 상수 제네릭(const generic)을 두어 이를 표현합니다. Padding<L, N>은 KIND = PaddingKind::Top이고, Padding<L, N, { PaddingKind::Zero }>는 0으로 채워진 변형이며, Padding<L, N, { PaddingKind::Bottom }>는 읽을 수 있지만 쓸 수 없습니다.

Cell::Padding(kind)는 패딩 범위(padded extent) 안이지만 내부 매핑(inner mapping) 밖에 있는 위치를 나타냅니다. kind는 Top, Zero, Bottom 중 하나이며, 패딩 범위를 넘어선 위치는 여전히 Cell::OutOfBounds입니다. Cell 결과의 전체 정의는 위치에 대한 결과(Position Results)에 있습니다.

크기 조정(Resize)

크기 조정(resize)은 새 크기 이상의 인덱스(index)를 잘라 내고 그 범위 바깥의 원소를 제외하여 매핑(mapping)의 논리적 크기(logical size)를 줄입니다. 버퍼(buffer)를 확장하는 패딩(padding)과 달리 논리적 뷰(logical view)를 축소합니다. m![D = 2]는 D축(axis)의 처음 원소 2개만 취해 D = 0, D = 1 인덱스를 만듭니다.

rust
axes![C = 2, D = 3];
type E = m![C, D = 2]; // Pair<m![C], Resize<m![D], 2>>

fn test_resize() {
    assert_eq!(E::map(0), i![C: 0, D: 0]);
    assert_eq!(E::map(1), i![C: 0, D: 1]);
    assert_eq!(E::map(2), i![C: 1, D: 0]);
    assert_eq!(E::map(3), i![C: 1, D: 1]);
    assert_eq!(E::map(4), Cell::OutOfBounds);
}
rust
impl<L, F> M for Resize<L, F>
where
    L: M,
    F: Count,
{
    const SIZE: usize = F::SIZE;

    fn to_value() -> Mapping {
        Mapping::Resize {
            inner: RBox::new(L::to_value()),
            resize: F::SIZE,
        }
    }

    fn map(i: usize) -> Cell {
        if i < F::SIZE { L::map(i) } else { Cell::OutOfBounds }
    }
}

타일링(Tiling)

타일링(tiling)은 인덱스를 지정한 뷰(indexed view)로 구현됩니다. tile은 매핑 분할(mapping split)을 검증한 뒤 데이터를 복사하지 않고 메타데이터 뷰(metadata view)를 만듭니다. 범용 뷰 API(generic view API)는 TensorView::tile<I, E2, LEN>(start)입니다. I는 타일(tile)의 위치를 정하는 매핑(mapping), E2는 요청한 뷰 매핑(view mapping), LEN은 타일 안에 있는 I 셀(cell)의 개수, start는 I를 따른 논리적 시작 좌표(logical starting coordinate)입니다.

rust
let tensor = HbmTensor::<bf16, m![1], m![A, B]>::new();
let view = tensor.view(); // HbmTensorView::<'_, bf16, m![1], m![A, B]>
let tile01 = view.tile::<m![B], 2, m![A, B = 2 # 512]>(0); // HbmTensorView::<'_, bf16, m![1], m![A, B = 2 # 512]>
let tile23 = view.tile::<m![B], 2, m![A, B = 2 # 512]>(2); // HbmTensorView::<'_, bf16, m![1], m![A, B = 2 # 512]>

HBM 예제는 I = m![B], LEN = 2, E2 = m![A, B = 2 # 512]를 사용합니다. B = 2 # 512 매핑(mapping)은 셀(cell) 512개짜리 물리적 범위(physical extent) 안에 유효한 B 위치 두 개를 뷰(view)에 제공합니다. 이 점유 범위(footprint)를 유지하지 않으면 분할이 원본 매핑과의 검증을 통과하지 못합니다. start = 0, start = 2는 논리적 B 좌표(coordinate)이므로 두 뷰는 각각 0..2, 2..4 범위를 다룹니다. 이는 시작 위치이며, 별도의 타일 번호(tile-number) API가 아닙니다.

읽기 뷰(read view)는 타일(tile) 밖의 셀(cell)을 PaddingKind::Top으로 채웁니다. 변경 가능한 뷰(mutable view)는 쓰기가 타일 밖으로 벗어나지 않도록 그 위치에 PaddingKind::Bottom을 요구합니다. HBM과 DM은 메모리 계층별(tier-specific) 타일 래퍼(wrapper)를 제공하며, TRF·VRF·DPE는 범용 뷰(generic view)를 사용합니다. HostTensor에는 뷰/타일 API가 없습니다.

스트라이드와 모듈로(Stride and Modulo)

스트라이드(stride, /)와 모듈로(modulo, %)는 한 차원(dimension)을 바깥쪽 블록 인덱스(block index)와 안쪽 블록 내 위치(position within block)의 두 차원으로 분해합니다. 원소 512개인 B축(axis)을 각 64개씩 담은 블록 여덟 개로 나눈다고 생각해 보세요. m![B / 64, B % 64]는 8 × 64 격자(grid)를 만들며, 첫 차원은 어느 블록인지를, 두 번째 차원은 그 블록 안의 위치를 선택합니다.

rust
type D1 = m![B / 64]; // 크기가 8인 스트라이드(stride)
type D2 = m![B % 64]; // 크기가 64인 모듈로(modulo)

type E = m![B / 64, B % 64]; // `m![B]`와 동등

fn test_stride_modulo() {
    assert_eq!(E::map(130), i![B / 64: 2, B % 64: 2]); // 블록(block) 2, 위치(position) 2: B = 64*2 + 2 = 130
    assert_eq!(E::map(130), <m![B]>::map(130));               // 평탄한(flat) m![B]와 같은 결과

    for i in 0..8 {
        assert_eq!(D1::map(i), i![B / 64: i]);
    }
    assert_eq!(D1::map(8), Cell::OutOfBounds);

    for j in 0..64 {
        assert_eq!(D2::map(j), i![B % 64: j]);
    }
    assert_eq!(D2::map(64), Cell::OutOfBounds);

    for i in 0..8 {
        for j in 0..64 {
            assert_eq!(
                E::map(64 * i + j),
                <m![B]>::map(64 * i + j),
            );
        }
    }
    assert_eq!(E::map(512), Cell::OutOfBounds);
}
rust
impl<L, F> M for Stride<L, F>
where
    L: M,
    F: Count,
{
    const SIZE: usize = {
        assert!(L::SIZE % F::SIZE == 0, "Stride size must divide the original size");
        L::SIZE / F::SIZE
    };

    fn to_value() -> Mapping {
        Mapping::Stride {
            inner: RBox::new(L::to_value()),
            stride: F::SIZE,
        }
    }

    fn map(i: usize) -> Cell {
        if i < Self::SIZE {
            L::map(i * F::SIZE)
        } else {
            Cell::OutOfBounds
        }
    }
}

impl<L, F> M for Modulo<L, F>
where
    L: M,
    F: Count,
{
    const SIZE: usize = {
        assert!(L::SIZE % F::SIZE == 0, "Modulo size must divide the original size");
        F::SIZE
    };

    fn to_value() -> Mapping {
        Mapping::Modulo {
            inner: RBox::new(L::to_value()),
            modulo: F::SIZE,
        }
    }

    fn map(i: usize) -> Cell {
        if i < Self::SIZE {
            L::map(i % L::SIZE)
        } else {
            Cell::OutOfBounds
        }
    }
}

스트라이드(stride)와 모듈로(modulo) 매핑(mapping)은 표로 표현할 수 있습니다. B::SIZE = 16일 때 m![B / 4, B % 4]를 생각해 보세요. 다음 표는 버퍼 인덱스(buffer index)의 배치를 보여 줍니다. 각 행(row)은 B / 4인 스트라이드 축(stride axis)의 특정 인덱스에, 각 열(column)은 B % 4인 모듈로 축(modulo axis)의 인덱스에 대응합니다.

i![B % 4: 0] i![B % 4: 1] i![B % 4: 2] i![B % 4: 3]
i![B / 4: 0] i![B: 0] i![B: 1] i![B: 2] i![B: 3]
i![B / 4: 1] i![B: 4] i![B: 5] i![B: 6] i![B: 7]
i![B / 4: 2] i![B: 8] i![B: 9] i![B: 10] i![B: 11]
i![B / 4: 3] i![B: 12] i![B: 13] i![B: 14] i![B: 15]

모듈로(modulo)는 버퍼 크기(buffer size)를 다루는 방식에서 크기 조정(resize)과 다릅니다.

  • 크기 조정(resize)은 새 크기 이상의 인덱스(index)를 잘라 내 버퍼(buffer)를 줄입니다.
  • 모듈로(modulo)는 원래 버퍼 크기(buffer size)를 유지하면서 같은 크기의 블록(block)으로 나눕니다.

이 연산들을 중첩(nesting)하면 더 복잡하게 분해할 수 있습니다. 다음 예제는 B를 세 차원(dimension)으로 나누며, 버퍼(buffer)의 비트 배치(bit arrangement)가 텐서 인덱스(tensor index)의 비트 배치와 달라집니다.

rust
// B의 비트(bits): 6 - 8,  0 - 4,          5
// 값(values):    0 - 7, 0 - 31,      0 - 1
type E = m![B / 64, B % 32, B / 32 % 2];

fn test_nested_stride() {
    assert_eq!(E::map(67), i![B: 97]); // 67 = 64*1 + 2*1 + 1 (i=1,j=1,k=1) → B = 64*1 + 1 + 32*1 = 97
    // B=97의 왕복 변환(round-trip) 확인: 97/64=1, 97%32=1, (97/32)%2=1
    assert_eq!(97 / 64, 1);
    assert_eq!(97 % 32, 1);
    assert_eq!((97 / 32) % 2, 1);

    // 버퍼 인덱스(buffer index): 64 * i + 2 * j + k (i = 블록, j = 블록 내 위치, k = 하위 블록)
    // 텐서 인덱스(tensor index) B: 64 * i + j + 32 * k (비트 위치를 재배열)
    for i in 0..8 {
        for j in 0..32 {
            for k in 0..2 {
                assert_eq!(
                    E::map(64 * i + 2 * j + k),
                    i![B: 64 * i + j + 32 * k],
                );
            }
        }
    }
    assert_eq!(E::map(512), Cell::OutOfBounds);
}

이러한 비트 재배열(bit rearrangement)은 뱅크 인터리빙(bank interleaving)이나 캐시 효율(cache efficiency)을 위해 주소 비트(address bit)의 순서를 바꾸는 하드웨어 표현(representation)에 자연스럽게 대응합니다. 이진수로 보면 버퍼(buffer)의 001_00001_1이 B = 001_1_00001로 바뀝니다. 버퍼는 비트를 [8:6]_[5:1]_[0]으로 묶지만, B는 [8:6]_[5]_[4:0]으로 묶습니다.

타일링(tiling)은 개별 원소 대신 블록(block)에 적용할 수도 있습니다. 다음 예제는 m![B / 32]로 블록 단위 타일링을 수행하여 서로 겹치는 타일(tile)을 만듭니다.

rust
let tensor = HbmTensor::<bf16, m![1], m![A, B]>::new();
for i in 0..15 {
    let tile = tensor.view().tile::<m![B / 32], 2, m![A, B / 32 = 2 # 16, B % 32]>(i);
}

B = 512이면 B / 32 차원(dimension)에는 0–15로 번호를 붙인 블록(block) 16개가 있습니다. 각 타일(tile)은 인덱스(index) i에서 시작하는 연속 블록 두 개를 취합니다. 타일 0은 {0, 1}, 타일 1은 {1, 2}를 포함하며, 이런 식으로 타일 14는 {14, 15}를 포함합니다. 이웃한 두 타일이 블록 하나를 공유하므로 타일들이 서로 겹칩니다.

타일 매핑(tile mapping) B / 32 = 2는 각 타일(tile)이 정확히 블록(block) 두 개를 포함하므로 블록 차원(dimension)의 크기를 2로 줄입니다. 블록 하나로 타일링(tiling)하면 이 차원의 값이 하나뿐이므로 B / 32 = 1은 항등(identity) m![1]로 단순화됩니다.

이스케이프(Escape)

매핑(mapping)이 복잡하다면 타입 별칭(type alias)을 정의하고 { ... }로 참조하세요. L = m![A], R = m![B]를 따로 정의한 뒤 m![{ L }, { R }]로 결합하면 m![A, B]와 같은 결과가 나옵니다.

rust
type L = m![A];
type R = m![B];
type E = m![{ L }, { R }]; // `m![A, B]`와 동등

fn test_escape() {
    for i in 0..E::SIZE {
        assert_eq!(E::map(i), <m![A, B]>::map(i));
    }
}

이 이스케이프 문법(escape syntax)을 이용하면 복잡한 매핑(mapping)을 이름이 있고 재사용 가능한 구성 요소(component)로 나눌 수 있습니다.

동등한 매핑(Equivalent Mappings)

서로 다른 생성자(constructor) 조합이 같은 위치 동작(position behavior)을 만들 수 있습니다. 이 동작상의 관계(behavioral relation)는 Rust 매핑 값(mapping value)의 구조적 동일성(structural equality)과는 구별됩니다. 매핑 E1과 E2는 다음 조건을 만족하면 *동등(equivalent)*합니다.

  • E1::SIZE == E2::SIZE이며,
  • 모든 i에서 E1::map(i) == E2::map(i)입니다.

동등 관계(equivalence relation)는 반사성(reflexivity), 대칭성(symmetry), 추이성(transitivity)을 가집니다. 아래 항등식(identity)은 유용한 동작 관계를 설명합니다. 정규화(normalization)가 모든 동등한 입력에 대해 유일한 구조적 대표(structural representative)를 만든다고 주장하는 것은 아닙니다.

테스트로 확인된 정규화(normalization) 동작의 범위는 더 좁습니다. 두 번 적용해도 결과가 바뀌지 않는 멱등성(idempotence)이 있고, 생성된 매핑 집합(mapping corpus)은 테스트한 위치(position)·패딩(padding) 동작을 보존하며, 정규화된 매핑은 매핑 표현(representation)을 거쳐 왕복 변환(round-trip)할 수 있습니다. 이 테스트들이 동등성을 증명하거나, 표현의 유일성을 보장하거나, 모든 경우의 의미 보존(semantic preservation)을 입증하는 것은 아닙니다. 다음 항등식은 흔히 쓰이는 동등 관계를 나타냅니다.

  • 쌍의 항등원(Identity of pairs): 모든 E에서 E는 m![{ E }, 1], m![1, { E }] 모두와 동등합니다.
  • 스트라이드·모듈로 분해(Stride-modulo decomposition): 크기 E::SIZE가 n으로 나누어떨어지는 모든 E에서, E와 m![{ E } / n, { E } % n]은 동등합니다.
  • 쌍의 사영(Pair projection): 모든 A, B에서 m![[{ A }, { B }] / B::SIZE]는 m![A]와, m![[{ A }, { B }] % B::SIZE]는 m![B]와 동등합니다.
  • 쌍의 결합법칙(Associativity of pairs): 모든 E1, E2, E3에서 m![{ E1 }, { E2 }, { E3 }], m![[{ E1 }, { E2 }], { E3 }], m![{ E1 }, [{ E2 }, { E3 }]]는 동등합니다.
  • 멱등 연산(Idempotent operations): 모든 E에서 E는 m![{ E } / 1], m![{ E } # E::SIZE], m![{ E } = E::SIZE]와 동등합니다.
  • 1에 대한 모듈로(Modulo by 1): 모든 E에서 m![E % 1]은 항등 매핑(identity mapping) m![1]과 동등합니다.
