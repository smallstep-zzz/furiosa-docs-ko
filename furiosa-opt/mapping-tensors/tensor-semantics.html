텐서 의미론(Tensor Semantics)

텐서(tensor)는 HBM, 칩 내부 DM(on-chip DM), 파이프라인 스트림(pipeline stream)에 존재하며 연산(operation)을 통해 변환됩니다. 이 장에서는 그 수학적 의미를 정의합니다. 텐서 변수가 수학적 텐서(mathematical tensor)를 *담는다(hold)*는 뜻과, 연산이 수학적 함수(mathematical function)를 *명세한다(specify)*는 뜻을 설명합니다. 이 정의들을 이용하면 vISA 프로그램을 텐서 수준(tensor level)에서 판단할 수 있습니다. 어떤 매핑(mapping)이나 메모리 계층(memory tier)을 사용하는지와 무관하게 출력이 올바른 수학적 텐서를 담으면 해당 함수는 올바릅니다.

텐서가 값을 담는다는 의미(Tensor Holding Semantics)

각 차원(dimension)의 매핑(mapping)이 생성한 부분 인덱스(partial index)들을 더해 텐서 인덱스(tensor index)를 만들었을 때, 각 원소가 그 인덱스에 해당하는 수학적 텐서(mathematical tensor) T의 값을 저장한다면 텐서 변수는 T를 *담는다(holds)*고 합니다.

HostTensor<D, E>는 가장 단순한 경우입니다. 하나의 매핑(mapping) E가 버퍼 위치(buffer position)와 텐서 인덱스(tensor index)의 대응 관계를 완전히 결정합니다. 예를 들어 A = 8, B = 512인 HostTensor<bf16, m![A, B]>는 bf16 원소 4,096개를 A-major, B-minor 순서로 저장합니다. 다음 조건을 만족하면 텐서(tensor) T를 담습니다.

  • E::map(i) = Cell::Index(ti)인 모든 버퍼 인덱스(buffer index) i에 대해,
  • i번째 원소가 ti에서의 T 값을 저장합니다.

HbmTensor<D, Chip, Element>는 하나의 매핑(mapping)을 둘로 나누어 이 개념을 확장합니다. Chip은 칩 인덱스(chip index)를 부분 텐서 인덱스(partial tensor index)에 대응시키고, Element는 칩별 원소 인덱스(element index)를 나머지 부분 인덱스에 대응시킵니다. 둘은 서로 겹치지 않는 축(axis)의 부분집합을 담당하므로, 두 인덱스를 더하면 전체 텐서 인덱스가 됩니다. 다음 조건을 만족하면 T를 담습니다.

  • Chip::map(i) = Cell::Index(ti)이고 Element::map(j) = Cell::Index(tj)인 모든 칩 인덱스(chip index) i와 원소 인덱스(element index) j에 대해,
  • i번째 칩(chip)의 j번째 원소가 ti + tj 인덱스(index)의 T 값을 저장합니다.

나머지 모든 텐서 타입(tensor type)도 더 많은 차원(dimension)에 같은 규칙을 적용합니다. 각 원소는 모든 매핑 매개변수(mapping parameter)가 반환한 부분 인덱스(partial index)의 합에 해당하는 T 값을 저장합니다.

선형 결합 의미론(Linear Combination Semantics)

선형 결합 표현식(linear combination expression) $(e1:n1, ..., ed:nd)은 지정한 스트라이드(stride)로 여러 차원(dimension)을 결합합니다. 크기는 size_S($(e1:n1, ..., ed:nd)) = 1 + sum_k((size_S(ek) - 1) * nk)입니다. 매핑(mapping) S, $(e1:n1, ..., ed:nd) |- si ~ ti는 모든 k에서 S, ek |- sik ~ tik가 성립하고 si = sum_k(sik * nk), ti = sum_k(tik * nk)를 만족하는 si1...sid, ti1...tid가 존재할 때 유효합니다.

선형 결합(linear combination)은 외부 합(outer sum)도 표현할 수 있습니다. e1 * e2는 $(e1 : size_S(e2), e2 : 1)과 동등합니다. 축 순서 변경(axis reordering)이 중요하다면 외부 합이 더 적합합니다. e1 * e2를 e2 * e1로 바꿔도 스트라이드(stride)를 수동으로 갱신할 필요가 없기 때문입니다.

슬라이딩 연산(sliding operation)은 서로 겹치는 데이터 블록(data block)에 접근합니다. 형상(shape)이 \\{N=5, F=3\\}인 텐서(tensor)를 원소 9개짜리 버퍼(buffer)로 표현한다고 생각해 보세요. 각 행(row)은 원소 세 개짜리 조각(slice)이며, 한 번에 원소 하나만큼씩 이동합니다. N, F의 텐서 원소는 버퍼 인덱스(buffer index) N + 2F에 대응합니다.

\\begin{array}{c|ccc} & F=0 & F=1 & F=2 \\\\ \\hline N=0 & 0 & 2 & 4 \\\\ N=1 & 1 & 3 & 5 \\\\ N=2 & 2 & 4 & 6 \\\\ N=3 & 3 & 5 & 7 \\\\ N=4 & 4 & 6 & 8 \\\\ \\end{array}

이 슬라이딩 패턴(sliding pattern)에서는 하나의 공간 인덱스(space index)가 여러 텐서 인덱스(tensor index)에 대응할 수 있습니다. 예를 들어 공간 인덱스 4는 {4_N}, {2_N, 1_F}, {2_F}에 동시에 대응합니다. 이는 (S, e).maps(si, ti)가 일대일(one-to-one) 관계가 아님을 보여 줍니다. 선형 결합(linear combination)은 N에 스트라이드(stride) 1, F에 스트라이드 2를 사용하므로 크기는 1 + (5-1)*1 + (3-1)*2 = 9가 됩니다.

함수 명세(Function Specification)

함수를 명세(specification)한다는 것은 입력을 기준으로 출력에 어떤 값이 담기는지를 선언하는 것입니다. 예를 들어 함수 elementwise_add는 다음과 같은 의미에서 수학적 연산(mathematical operation) f(T_1, T_2) = T_1 + T_2를 명세합니다.

  • 모든 텐서(tensor) T_1, T_2에 대해,
  • lhs가 T_1을 담고 rhs가 T_2를 담으면,
  • 반환값(return value)은 T_1 + T_2를 담습니다.
rust
axes![A = 8, B = 512];

// 이 시그니처(signature)는 수학적 동작 규칙(mathematical contract)을 명세하며, 엔진 파이프라인(engine pipeline)의
// 구현은 텐서 계산(Computing Tensors) 장에 제시되어 있음.
fn elementwise_add(
    lhs: &HbmTensor<bf16, m![A], m![B]>,
    rhs: &HbmTensor<bf16, m![A], m![B]>,
) -> HbmTensor<bf16, m![A], m![B]> {
    // 구현은 의도적으로 생략함. 이 예제는 함수의
    // 텐서 수준 동작 규칙(tensor-level contract)만 설명함.
}

*수학적 텐서 이동(mathematical tensor move)*은 f(T) = T를 명세합니다. 표현(representation)과 무관하게 출력이 입력과 동일한 수학적 텐서를 담는다는 뜻입니다. .to_dm()은 수학적 텐서 이동입니다. 예를 들어 .to_dm()은 다음 의미에서 f(T) = T를 명세합니다.

  • hbm이 T를 담으면,
  • 반환값(return value)은 T를 담습니다.
rust
axes![A = 8, B = 512];

fn hbm_to_dm(
    device: &mut Device,
    hbm: &HbmTensor<bf16, m![A], m![B]>,
) -> DmTensor<bf16, m![A], m![1], m![B / 2], m![B % 2]> {
    hbm.to_dm(&mut device.tdma)
}
