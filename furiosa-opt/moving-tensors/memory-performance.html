메모리 성능(Memory Performance)

읽기 도움말 · 번역자 설명

대역폭(bandwidth)은 일정 시간에 옮길 수 있는 데이터 양입니다. 아래 수치는 원문이 제시한 조건을 그대로 옮겼습니다. 예를 들어 정렬(alignment)과 뱅크(bank) 배치가 달라지면 같은 데이터 양이어도 실제 처리 속도가 달라집니다.

메모리 성능(memory performance)은 커널 처리량(kernel throughput)을 제한하는 주요 원인입니다. 계산 매핑(compute mapping)을 바꾸기 전에 조건을 고정한 스케줄(schedule)을 비교하세요. Fetch·Commit·DMA 엔진(engine)은 Packet 크기와 접근 순서(access ordering)처럼 성능 결과에 직접 연결되는 API 선택지를 제공합니다. 이 절에서는 그 선택 뒤에 있는 하드웨어 제약(hardware constraint)과 측정 처리량(measured throughput)에 미치는 영향을 설명합니다.

각 메모리 종류(memory type)의 칩(chip)당 최대 대역폭(peak bandwidth)은 다음과 같습니다.

메모리(Memory) 최대 대역폭(Peak Bandwidth)
DM 칩(chip)당 2 TB/s
HBM 칩(chip)당 1.5 TB/s

이 최대치에 도달하려면 특정 접근 패턴(access pattern)이 필요합니다. 다음 표는 어기면 처리량(throughput)이 떨어지는 규칙들을 정리한 것이며, 아래 절에서는 각 메모리 종류(memory type)와 요인을 자세히 설명합니다.

메모리(Memory) 문제(Issue) 규칙(Rule) 비용(Penalty)
DM 뱅크 기아(Bank starvation) 같은 뱅크(bank)에 연속 64회 미만 접근 NoC 타임아웃(timeout) → 하드웨어 초기화(reset)
DM DMN 인터리빙(interleaving) 클러스터(cluster)당 두 DMN을 번갈아 접근 대역폭(bandwidth) 50% 손실
DM 슬라이스 인터리빙(Slice interleaving) DMN당 슬라이스(slice) 32개에 분산 명령 큐 경합(Command queue contention)
HBM 정렬(Alignment) 256바이트에 정렬된 접근(aligned access) 비정렬 읽기(unaligned read): 2× 비용. 비정렬 쓰기(unaligned write): 약 50× 비용(RMW)
HBM 뱅크 충돌(Bank conflicts) 같은 뱅크(bank)에서 행 전환(row switch) 방지 성능 30–40배 저하
HBM 채널 인터리빙(Channel interleaving) 채널(channel) 32개에 분산 병렬성(parallelism) 감소

먼저 표를 바탕으로 정렬(alignment), 인터리빙(interleaving), 패킷 크기(packet size)를 고르고, 상세 절에서 뱅크 기아(bank starvation)나 HBM 충돌(conflict)을 진단하세요. 규칙 표(rule table)는 후보 매핑(candidate mapping)의 제한 자원(limiting resource)을 식별하고, DM·SPM·HBM 절은 그 자원을 설명합니다.

데이터 메모리(Data Memory, DM)

데이터 메모리(Data Memory, DM)는 칩(chip)당 256MB이며, 클러스터(cluster)·데이터 메모리 네트워크(Data Memory Network, DMN)·슬라이스(slice)·뱅크(bank)의 계층 구조(hierarchy)로 구성됩니다. 다음 표는 이 구조(geometry)를 요약합니다.

단위(Unit) 개수(Count)
클러스터(Clusters) 칩(Chip)당 2개
데이터 메모리 네트워크(Data Memory Networks, DMNs) 클러스터(Cluster)당 8개
슬라이스(Slices) DMN당 32개
뱅크(Banks) 슬라이스(Slice)당 16개
행(Rows) 뱅크(Bank)당 4096개
바이트(Bytes) 행(Row)당 8바이트

클러스터(cluster)는 교환 엔진(Switch Engine)을 통해 데이터를 교환할 수 있습니다. 자세한 내용은 해당 절을 참고하세요. 아래 하위 절에서는 이 구조가 대역폭(bandwidth)과 뱅크 접근 제약(bank access constraint)을 어떻게 결정하는지 설명합니다.

슬라이스 내부의 뱅크 구조(Bank Structure in a Slice)

각 슬라이스(slice)는 전용 주소 공간(dedicated address space)을 갖는 512KB SRAM을 제공합니다. 메모리는 8바이트 데이터 폭(data width)의 병렬 뱅크(parallel bank) 16개로 구성되어 총 128 B/cycle의 데이터 접근 속도를 냅니다. 개별 뱅크에 대한 접근은 직렬화(serialize)되지만, 주소 공간은 연속된 128바이트를 16개 뱅크에 8바이트씩 분산해 병렬 접근(parallel access)이 가능하게 합니다. 다음 비트 매핑(bit mapping)이 이 분배를 정의합니다.

비트 번호(Bit #) 구성 요소(Component)
0–2 바이트(Byte)
3–6 뱅크(Bank)
7–18 행(Row)

연속 주소(consecutive address)가 서로 다른 뱅크(bank)에 대응하므로, 순차 순회(sequential scan)에서 병렬 접근(parallel access)이 가능합니다.

DMN과 슬라이스 인터리빙(DMN and Slice Interleaving)

각 DMN의 대역폭(bandwidth)은 128 B/cycle뿐이며, 슬라이스(slice) 32개가 데이터 경로(data path)를 공유합니다. 표준 256바이트 전송 단위(transfer unit)는 DMN마다 두 사이클(cycle)이 필요하므로, 연속적인 처리량(throughput)을 유지하려면 두 DMN의 접근을 파이프라인(pipeline)으로 겹쳐야 합니다.

사이클(cycle) DMN #0 DMN #1
0 읽기(read) #0 (1/2) (유휴(idle))
1 읽기(read) #0 (2/2) 읽기(read) #1 (1/2)
2 읽기(read) #2 (1/2) 읽기(read) #1 (2/2)
3 읽기(read) #2 (2/2) 읽기(read) #3 (1/2)
... ... ...
2n-1 읽기(read) #2n-2 (2/2) 읽기(read) #2n-1 (1/2)
2n (유휴(idle)) 읽기(read) #2n-1 (2/2)

참고(Note) 명령 큐(command queue) 덕분에 이론적으로는 인터리빙(interleaving) 없이 어느 정도 버스트 접근(burst access)이 가능하지만, DMA 스트림(stream)을 만들 때는 항상 여러 DMN에 걸쳐 인터리빙하세요. 이것이 가장 자연스러운 방식입니다.

슬라이스(slice)는 DMA·Fetch·Commit 엔진(engine)이 공유하므로, 각 DMN 안의 슬라이스 32개에 요청(request)을 분산하면 경합(contention)이 줄어듭니다. 데이터 메모리 라우터(Data Memory Router)는 각 DMN 안에서 슬라이스들을 링 토폴로지(ring topology)로 연결합니다. 연결은 slice0_in → slice31_out, slice32_in → slice63_out입니다. 각 데이터 메모리 슬라이스(Data Memory Slice)는 대기 중인 DMA 요청을 위한 항목(entry) 두 개짜리 명령 큐(command queue)를 가집니다. 요청을 M개 슬라이스에 분산하면 우선순위(priority)로 개별 슬라이스가 지연되어도 슬라이스당 필요한 처리량(throughput)은 1/M로 줄어듭니다. n사이클(cycle)마다 DMN을 인터리빙하면 최대치인 256 B/cycle을 채울 수 있습니다.

뱅크 기아(Bank Starvation)

뱅크 기아(bank starvation)는 높은 우선순위(priority)의 엔진(engine)이 DM 뱅크(bank)를 계속 점유하여 DMA 엔진이 무기한 기다리는 현상입니다. 64회 접근 규칙(access rule)은 이를 방지합니다. 이 규칙을 어기면 칩 내부 네트워크(Network-on-Chip, NoC) 타임아웃(timeout)과 클러스터(cluster) 전체 초기화(reset)가 발생해 모든 계산 상태(computation state)가 사라집니다.

각 DM 뱅크(bank)는 공유 자원(shared resource)입니다. 높은 우선순위(priority)의 엔진(engine)이 계속 접근하면 낮은 우선순위의 요청자(requester)가 무기한 차단되며, 이는 우선순위 역전(priority inversion)의 한 형태입니다. DM 컨트롤러(controller)는 다음 순서로 요청의 우선순위를 정합니다.

  • main 컨텍스트(main-context) 읽기 엔진(Fetch Engine)
  • main 컨텍스트(main-context) 쓰기 엔진(Commit Engine)
  • sub 컨텍스트(sub-context) 읽기 엔진(Fetch Engine)
  • sub 컨텍스트(sub-context) 쓰기 엔진(Commit Engine)
  • DMA 엔진(DMA Engine)

정상 동작에서는 계산 엔진(computation engine)이 데이터에 우선 접근해야 하므로, DMA는 모든 메모리 엔진(memory engine) 중 우선순위(priority)가 가장 낮습니다. 높은 우선순위의 엔진은 같은 뱅크(bank)를 계속 사용할 수 있고, 큐(queue)에 들어간 DMA 요청(request)은 그 엔진들이 뱅크를 놓을 때까지 기다립니다. 텐서 DMA(Tensor DMA)는 NoC 허브(hub)를 통해 DRAM·DMN과 통신하며, 각 포트(port, DMA·DRAM·DMN)는 4,096사이클(cycle) 안에 요청에 응답해야 합니다. 응답 없이 4,096사이클이 지나면 NoC 프로토콜(protocol)은 해당 트랜잭션(transaction)을 더 이상 진행되지 않는 것으로 판단하고 예외 상태(exception state)에 들어갑니다. 이는 교착 상태(deadlock)와 무기한 멈춘 트랜잭션을 감지하는 안전 장치입니다. 타임아웃(timeout)이 발생했을 때 하드웨어에는 상태를 유지하며 복구하는 방법(graceful recovery)이 없습니다. 유일한 복구 방법은 클러스터 도메인(cluster domain) 전체를 초기화(reset)하는 것이므로 모든 계산 상태를 잃고 완전한 재초기화(reinitialization)가 필요합니다.

한계는 같은 뱅크(bank)에 대한 연속 접근 64회입니다. DMA가 활성(active)인 동안 Fetch와 Commit은 같은 뱅크를 64회 이상 연속 점유하면 안 됩니다. 왜 64일까요? 제약식은 (TDMA_IO_BYTE / DMN_IO_BYTE) * Max_Consecutive_Access * DMN_SIZE < 4096이고, TDMA_IO_BYTE = 256, DMN_IO_BYTE = 128, DMN_SIZE = 32를 대입하면 Max_Consecutive_Access < 64가 됩니다. 이 조건은 최악의 경우에도 NoC 타임아웃(timeout) 전에 DMA 요청(request)이 완료되도록 보장합니다.

예를 들어 DMA 엔진(DMA Engine)이 뱅크(bank) 0과 나머지 15개 뱅크에 요청(request)을 보냈는데, main 컨텍스트(main-context)의 읽기 엔진(Fetch Engine)이 뱅크 0에 계속 요청한다고 해 보겠습니다. DMA 요청은 멈춰 기다리며(stall), 이 상태가 4,096사이클(cycle)을 넘으면 NoC 타임아웃(timeout)이 하드웨어 초기화(reset)를 강제합니다.

컨텍스트 점유(context occupancy), 64회 접근 규칙(access rule), main/sub 뱅크 경합(bank contention)은 스케줄링: 자원과 뱅크 경합(Resource and bank contention)을 참고하세요. 어떤 연산(operation)이 병렬로 실행되는지 보여 주고 실제 컨텍스트 배정(context assignment)을 확인하는 시각화 도구(visualization utility)는 스케줄 뷰어(Schedule Viewer)를 참고하세요.

고대역폭 메모리(High-Bandwidth Memory, HBM)

HBM은 칩(chip)당 48GB를 저장하고 총 1.5 TB/s의 대역폭(aggregate bandwidth)을 제공하지만, 이 최대치에 도달하려면 256바이트에 정렬된 접근(aligned access)과 32개 채널(channel) 전체에 걸친 인터리빙(interleaving)이 필요합니다. 정렬되지 않은 쓰기(misaligned write)와 뱅크 충돌(bank conflict)은 처리량(throughput)을 30–50배까지 떨어뜨릴 수 있습니다. 다음 표는 HBM 구조(geometry)를 요약합니다.

단위(Unit) 개수(Count)
스택(Stacks) 칩(Chip)당 2개
채널(Channels) 스택(Stack)당 16개
슬라이스(Slices) 채널(Channel)당 3개
뱅크 그룹(Bank Groups) 슬라이스(Slice)당 4개
뱅크(Banks) 뱅크 그룹(Bank Group)당 4개
행(Rows) 뱅크(Bank)당 16K개
바이트(Bytes) 행(Row)당 2K바이트

최대 대역폭(Peak Bandwidth)

DMA 엔진(DMA Engine) 하나의 처리 용량(capacity) 256GB/s를 모두 사용하려면 여러 채널(channel)에 접근을 인터리빙(interleaving)해야 합니다. HBM은 스택(stack)과 채널을 병렬로 동작시켜 칩(chip)당 최대 1.5TB/s를 제공합니다. 채널 컨트롤러(channel controller)는 0.75GHz에서 64B/cycle을 전송하므로,1 채널당 48GB/s(0.75GHz x 64B/cycle), 칩당 1.5TB/s(48GB/s x 32채널)가 됩니다. 기본 전송 단위(transfer unit)는 256바이트이며, 채널당 클록 사이클(clock cycle) 네 번이 필요합니다.

1 채널 컨트롤러(channel controller)의 동작 주파수(frequency)는 0.75GHz이지만, 사이클(cycle)마다 버스트(burst) 전송을 여덟 번 수행하므로 유효 주파수(effective frequency)는 0.75×8=6GHz입니다.

최대 대역폭(peak bandwidth)은 접근 패턴(access pattern)에 민감합니다. 정렬 불일치(misalignment), 뱅크 충돌(bank conflict), 자원 공유(resource sharing)는 각각 처리량(throughput)을 크게 떨어뜨릴 수 있습니다. 각 채널 컨트롤러(channel controller)는 항목(entry) 64개짜리 명령 큐(command queue)로 접근을 인터리빙(interleaving)하여 비용을 최소화하지만, 병적인 경우(pathological case)에는 여전히 큰 성능 저하가 생깁니다. 다음 절들은 성능 저하의 원인과 피하는 방법을 설명합니다.

칩 내부 주소 공간(Address Space in a Chip)

HBM 주소 공간(address space)은 연속 접근을 병렬화하는 데 최적화된 비선형 비트 매핑(non-linear bit mapping)을 사용합니다. 이 설계는 병렬성(parallelism)을 최대화하고 부가 비용(overhead)을 최소화합니다.

비트 번호(Bit #) 주 구성 요소(Main Component) 추가 구성 요소(Additional Components)
0–7 바이트(Byte)
8 스택(Stack)
9–12 채널(Channel)
13 뱅크 그룹(Bank Group) 채널(Channel)
14–16 바이트(Byte) 채널(Channel)
17–18 뱅크(Bank) 채널(Channel)
19 뱅크 그룹(Bank Group) 채널(Channel)
20 슬라이스(Slice) 채널(Channel)
21–33 행(Row) 채널(Channel, 21–28)
34 슬라이스(Slice) 행(Row)
35 행(Row)

각 구성 요소(component)의 비트 배정(bit assignment)은 물리적 메모리 구조(physical memory geometry)에 대응합니다. 예를 들어 바이트 요소(byte component)는 행(row)당 2K(2^11)바이트를 표현하기 위해 11비트(비트 0–7, 14–16)를 사용합니다. 예외는 세 가지입니다.

  • 슬라이스 표현(Slice representation): 슬라이스(slice)는 세 개뿐이지만 두 비트(20, 34)로 표현합니다.
  • 연속 주소 공간(Contiguous address space): 행 요소(row component)가 비트 34에 영향을 주어 비트 34와 35가 동시에 1이 되지 않게 합니다. 이를 통해 연속된 48GB 주소 공간(address space)을 보장합니다.
  • 채널 XOR 매핑(Channel XOR mapping): 채널 요소(channel component)는 비트 9–12와 13–28을 XOR한 결과입니다. 예를 들어 채널의 첫 번째 비트는 비트 9·13·21·25를 XOR한 값입니다.

이 비트 순서(bit ordering)는 순차 접근(sequential access)을 스택(stack)·채널(channel)·뱅크 그룹(bank group)·뱅크(bank)에 동시에 분산하여 여러 메모리 자원(memory resource)을 병렬로 계속 활용하게 합니다.

정렬되지 않은 접근(Misaligned Access)

정렬되지 않은 접근(misaligned access)은 HBM 성능을 크게 떨어뜨립니다. 256바이트 경계(boundary)를 넘는 읽기는 전송(transfer) 두 번이 필요해 비용이 2배가 되고, 정렬되지 않은 쓰기는 읽기·수정·쓰기(Read-Modify-Write, RMW)가 필요해 비용이 약 50배가 됩니다. 최소 접근 단위(access unit) 256바이트는 비트 0–7, 즉 최하위 비트(LSB) 여덟 개로 정의되므로, 데이터가 이 경계를 가로지르면 해당 비용이 발생합니다.

  • 정렬되지 않은 읽기(Unaligned Read): 256바이트 경계(boundary)를 가로지르는 읽기 요청(read request)은 NoC 전송(transfer) 두 번이 필요하므로 대역폭(bandwidth)이 사실상 절반이 됩니다.
  • 정렬되지 않은 쓰기 또는 부분 쓰기(Unaligned or Partial Write): DMA 패킷(packet)이 내부적으로 256바이트 트랜잭션(transaction)으로 분할되기 때문에 정렬되지 않은 쓰기가 생깁니다. 패킷 크기가 256바이트에 맞지 않으면 마지막에 남는 트랜잭션은 RMW가 필요합니다. 예를 들어 2,800바이트 패킷은 256바이트 요청(request) 열 개와 240바이트 요청 하나로 나뉩니다. RMW는 256바이트 단위 전체를 읽고 요청한 바이트만 갱신한 다음 전체 단위를 다시 씁니다. RMW 때문에 쓰기가 정렬된 쓰기(aligned write)보다 약 50배 느려질 수 있습니다.

뱅크 충돌(Bank Conflict)

HBM 뱅크(bank)는 한 번에 행(row) 하나를 열어 둡니다. 같은 뱅크에서 다른 행으로 전환하려면 현재 행을 닫고 새 행을 열어야 합니다. 이 과정은 40–50 ns(1.5 GHz에서 60–75사이클(cycle))의 지연(latency)을 추가하며, 이미 열린 행에 접근하는 것보다 30–40배 느립니다. 같은 뱅크의 서로 다른 행을 연속해서 접근할 때마다 이 비용이 발생합니다. 처음에는 모든 행이 닫혀 있으므로, 어느 행이든 첫 접근에서는 행을 여는 비용(open-row cost)을 지불합니다.

채널 인터리빙(channel interleaving)은 뱅크 충돌(bank conflict)을 완화합니다. 32개 채널(channel) 전체에 접근을 분산하면 부하(load)가 나뉘고 충돌이 줄어듭니다. 비트 8–12, 즉 그다음 다섯 하위 비트(LSB)는 독립적인 스택(stack)과 채널을 나타냅니다. 이 비트들을 주소(address)의 낮은 쪽에 두면 이웃한 접근 사이의 간섭(interference)을 막을 수 있으며, 이는 연속 연산(contiguous operation)의 병렬화에 매우 중요합니다. 채널 요소(channel component)는 비트 9–28에 걸쳐 있으므로 비연속 연산(non-contiguous operation)도 자연스러운 채널 인터리빙의 이득을 보는 경우가 많습니다. 하지만 스택 요소(stack component)는 비트 8에만 대응하므로, 완전한 스택 인터리빙을 하려면 프로그래머가 두 스택을 번갈아 접근하도록 명시적으로 보장해야 합니다.

컨트롤러(controller)는 명령 인터리빙(command interleaving)으로 행 전환 지연(row-switch latency)을 가립니다. 각 채널(channel) 내부에서 컨트롤러는 뱅크(bank) 사이의 명령을 자동으로 인터리빙하여, 어떤 뱅크가 행을 전환하는 동안 다른 뱅크에서는 유효한 전송(transfer)을 수행하게 합니다. 컨트롤러는 명령 큐(command queue)로 뱅크 상태(bank state)를 관리합니다. 이미 열린 행(row)을 대상으로 하는 명령에 우선권을 주는 FR-FCFS(First Ready-First Come First Served) 스케줄링(scheduling)을 사용합니다.

이처럼 정교한 스케줄링(scheduling)이 있어도 같은 뱅크(bank)에서 행(row)을 계속 전환하는 접근 패턴(access pattern)은 성능을 크게 떨어뜨립니다. 컴파일러(compiler)와 프로그래머는 코드를 생성할 때 행 전환 비용(row-switch cost)을 추산해야 합니다.

열 간 지연(Column-to-Column Delay)

tCCD(열 간 지연, Column-to-Column Delay)는 같은 채널(channel)에서 연속된 읽기 또는 쓰기 명령(command) 사이에 필요한 최소 시간이며, 최대 명령 발행률(command issue rate)을 결정합니다. 대부분의 접근 패턴(access pattern)에서는 tCCD가 병목(bottleneck)이 되기 전에 뱅크 충돌(bank conflict)이나 채널 인터리빙(channel interleaving)이 더 큰 영향을 줍니다. 제조사 사양(vendor specification)은 DRAM 스택 층(stack layer)과 공유 자원(shared resource)에 접근할 때의 아날로그 제약(analog constraint)을 기준으로 tCCD를 정합니다.

tCCD 값은 연속된 명령(command)이 어떤 메모리 자원(memory resource)을 대상으로 하는지에 따라 달라집니다.

명령 간 관계(Command Relation) tCCD(사이클(cycles), 1.5GHz 기준) 상대 성능(Relative Performance) 비용 발생 이유(Reason for Penalty)
같은 슬라이스(slice), 다른 뱅크 그룹(bank group) 2 1 뱅크 그룹(bank group)의 이상적인 인터리빙(interleaving)
다른 슬라이스(slice) 3 2/3 데이터 경로 전환(Data path switching)
같은 슬라이스(slice), 같은 뱅크 그룹(bank group) 4 1/2 뱅크(bank) 네 개가 입출력 버퍼(I/O buffer)를 공유

슬라이스(slice) 하나 안에서 뱅크 그룹(bank group)을 인터리빙(interleaving)하면 1.5GHz에서 tCCD = 2사이클(cycle)이 됩니다. 그러면 0.75GHz의 매 사이클마다 새 64B 명령(command)을 발행할 수 있어 채널(channel)의 전체 속도를 사용할 수 있습니다. tCCD가 2보다 크면 명령 발행률(command rate)과 채널 활용률(channel utilization)이 낮아집니다.

뱅크 충돌(bank conflict)에 비하면 tCCD에 따른 성능 저하(degradation)는 덜 심합니다. 최악의 패턴(pattern)은 뱅크 충돌과 함께 발생해 tCCD의 영향이 부차적이 되거나, 채널 인터리빙(channel interleaving)에 가려지기 때문입니다.

  • 다른 슬라이스(slice, tCCD = 3): 슬라이스 ID(slice ID)는 비트 20, 행(row)은 비트 21에 대응합니다. 따라서 여러 슬라이스를 인터리빙(interleaving)하면 뱅크 충돌(bank conflict)도 동시에 일어날 가능성이 큽니다.
  • 같은 슬라이스(slice), 같은 뱅크 그룹(bank group, tCCD = 4): 이 패턴(pattern)은 비트 13, 19, 20, 34를 제외한 비트 8-35를 인터리빙(interleaving)합니다. 비트 29-35는 뱅크 충돌(bank conflict)에, 비트 8-28은 채널 인터리빙(channel interleaving)에 관련됩니다.
