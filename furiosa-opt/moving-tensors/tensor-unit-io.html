사례 연구: 텐서 유닛 입출력(Case Study: Tensor Unit I/O)

이 전체 과정 텐서 유닛 입출력(end-to-end Tensor Unit I/O) 패턴은 Fetch와 Commit을 사용해 텐서(tensor)를 DM을 거쳐 이동시키며 모든 논리 인덱스(logical index)를 보존합니다. 여러 이동 단계를 결합한 패턴(composed movement pattern)이므로, Fetch Engine·Commit Engine 각각의 참조 페이지와 구분됩니다.

대표적인 공개 예제(canonical public case)는 fetch_commit_simple입니다. 매핑(mapping)이 [A, B]인 i8 HBM 텐서(tensor)를 입력받고, 텐서 유닛(Tensor Unit)에서 값의 타입 폭을 i32로 넓힌 뒤 매핑이 [B, A]인 HBM 텐서를 반환합니다. 마지막 to_hbm DMA 호출이 출력 HBM 매핑을 선택하므로, 이 테스트는 HBM→DM, Fetch, Collect, Commit, DM→HBM으로 이어지는 파이프라인(pipeline) 전체를 검증합니다. 이 예제는 스트리밍 중의 순열 변환(streaming permutation)을 주장하지 않습니다. 공개 예제의 [A, B]→[B, A] 재배치(relayout)는 마지막 DMA 경계에서 일어납니다. 장치 소스(device source)는 아래에 포함되어 있습니다.

rust
#![expect(clippy::type_complexity)]

use furiosa_opt_std::prelude::*;

axes![A = 4096, B = 8];

type Chip = m![1];
type Cluster = m![1 # 2];

#[device(chip = 1)]
pub fn fetch_commit_simple(
    device: &mut Device,
    input: &HbmTensor<i8, m![1], m![A, B]>,
) -> HbmTensor<i32, m![1], m![B, A]> {
    // Element의 가장 안쪽 축(axis)은 원본의 가장 안쪽 축(B, 스트라이드(stride) 1)과 같아야 함. 그래야
    // DMA 꼬리(tail)가 B축 전체(8 × i8 = 8바이트)를 포함하여 min_align = 8을 만족함.
    let input_dm = input.to_dm::<Cluster, m![A / 16], m![A / 8 % 2, A % 8, B]>(&mut device.tdma);

    let fetch_and_commit_tensor: DmTensor<i32, Chip, Cluster, m![A / 16], m![A / 8 % 2, A % 8, B]> = device
        .main
        .begin(input_dm.view())
        .fetch::<m![A / 8 % 2], m![A % 8, B]>()
        .fetch_cast::<i32>()
        .collect::<m![A / 8 % 2, A % 8], m![B]>()
        .commit_trim::<m![B]>()
        .commit();

    fetch_and_commit_tensor.to_hbm(&mut device.tdma)
}

호스트 기준 계산(host oracle)과 테스트는 examples의 테스트 타깃(test target)에 포함되어 있습니다.

rust
use furiosa_opt_examples::fetch_commit::fetch_commit_simple;
use furiosa_opt_std::prelude::*;

#[tokio::test]
async fn test_fetch_commit_simple_host() -> eyre::Result<()> {
    use furiosa_opt_examples::fetch_commit::{A, B};

    let mut device = Device::new(fetch_commit_simple.topology())?;

    // 형상(shape)이 (A=4096)(B=8)인 입력 텐서(tensor)를 생성.
    let input = HostTensor::<i8, m![A, B]>::from_vec((0..32768).map(|x| x as i8).collect::<Vec<_>>())
        .to_hbm::<m![1], m![A, B]>(&mut device.pdma)
        .await?;

    // 장치 함수(device function)를 호출.
    let output = launch(fetch_commit_simple, (&mut device, &input)).await?;

    let mut expected = vec![0i32; 4096 * 8];
    let mut idx = 0;
    for b in 0..8 {
        for a in 0..4096 {
            expected[idx] = ((a * 8 + b) as i8) as i32;
            idx += 1;
        }
    }

    assert_eq!(
        output.to_host::<m![B, A]>(&mut device.pdma).await?.into_inner(),
        Tensor::<_, m![B, A], CurrentBackend>::from_vec(expected)
    );

    Ok(())
}

cargo furiosa-opt test --test fetch_commit_tests를 실행하면 대표 예제(canonical case)를 실행할 수 있습니다. 호스트 기준 계산(host oracle)은 모든 output[b, a] 값을 타입 폭을 넓힌 input[a, b] 값과 비교합니다. 스트리밍 경로(streaming path)는 입력 DM, Fetch, Cast, Collect, Commit, 출력 DM 순서이며, DM 배치(layout)는 원래의 [A, B]를 유지합니다. 여기서 사용하는 API는 읽기 엔진(Fetch Engine), 수집 엔진(Collect Engine), 쓰기 엔진(Commit Engine)에서 설명합니다.
