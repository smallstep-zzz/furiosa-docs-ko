커널 설계(Kernel Design)

첫 벡터 커널(First Vector Kernel)

상수 덧셈(Constant Addition)

목표(Goal)

벡터(vector)의 모든 원소에 대해 \text{out}[i] = \text{in}[i] + 1을 계산합니다. 이 패턴은 잔차 덧셈(residual addition)과 편향 덧셈(bias addition)에 활용됩니다.

데이터 이동(Data Movement)

벡터(vector)를 HBM에서 DM으로 옮기고, 각 DM 슬라이스(slice)의 데이터를 Fetch, Collect, 벡터 엔진(Vector Engine), Commit을 거쳐 스트리밍(streaming)한 다음, 결과를 DM에서 HBM으로 되돌려 보냅니다.

장치 소스(Device Source)

이 커널(kernel)은 칩(chip) 하나에서 두 클러스터(cluster) 중 하나를 사용하며, 그 클러스터의 슬라이스(slice) 256개를 모두 사용합니다. 각 슬라이스는 i32 값 여덟 개를 받습니다. TagMode::Zero는 벡터 엔진(Vector Engine)을 매 사이클(cycle) 실행하게 합니다. to_dm은 벡터(vector)를 슬라이스에 나누어 배치하고, begin → fetch → collect → vector_init → vector_intra_slice_tag → vector_fxp → vector_final → commit으로 이어지는 호출은 각 슬라이스를 한 번의 처리(pass)로 계산합니다.

장치 소스(device source): src/kernel/constant_add_kernel.rs.

rust
use furiosa_opt_std::prelude::*;

axes![A = 2048];

pub type Chip = m![1];
pub type Cluster = m![1 # 2];
pub type Slice = m![A / 8 # 256];

#[device(chip = 1)]
pub fn constant_add_kernel(device: &mut Device, input: &HbmTensor<i32, Chip, m![A]>) -> HbmTensor<i32, Chip, m![A]> {
    // HBM → DM: 원소 2048개를 슬라이스(slice) 256개에 분배(슬라이스당 원소 8개)
    let dm = input.to_dm::<Cluster, Slice, m![A % 8]>(&mut device.tdma);

    let result = device
        .main
        .begin(dm.view())
        // Fetch: DM에서 원소 8개짜리 패킷(packet)을 파이프라인(pipeline)으로 스트리밍
        .fetch::<m![1], m![A % 8]>()
        // Collect: 스트림(stream)을 32바이트 플릿(flit, 8 × i32)으로 정규화
        .collect::<m![1], m![A % 8]>()
        // 벡터 엔진(Vector Engine): 파이프라인(pipeline)에 진입하고 조건 없이 실행하도록 설정
        .vector_init()
        .vector_intra_slice_tag(TagMode::Zero)
        // 모든 원소에 스칼라(scalar) 상수 1을 더함
        .vector_fxp(FxpBinaryOp::AddFxp, 1)
        // VE를 나와 커밋(commit): 패킷(packet)을 커밋 폭에 맞게 줄인 뒤
        // 결과를 DM에 다시 기록
        .vector_final()
        .commit_trim::<m![A % 8]>()
        .commit::<m![A % 8]>();

    // DM → HBM
    result.to_hbm(&mut device.tdma)
}

호스트 프로그램과 기준 계산(Host Program and Oracle)

호스트 프로그램(host program)은 입력을 만들고 HBM에 업로드한 뒤 장치 함수(device function)를 실행하며, 테스트에서 결과를 호스트 측 수식과 비교합니다.

기본 템플릿(base-template)의 호스트 프로그램과 기준 계산(host oracle): src/constant_add.rs.

rust
use furiosa_opt_std::prelude::*;
use {{ crate_name }}::kernel::constant_add_kernel::{A, constant_add_kernel};
use rand::SeedableRng;
use rand::rngs::SmallRng;

#[tokio::main]
async fn main() -> eyre::Result<()> {
    let mut device = Device::new(constant_add_kernel.topology())?;
    let mut rng = SmallRng::seed_from_u64(42);
    let input = HostTensor::<i32, m![A]>::rand(&mut rng);
    let in_hbm = input.to_hbm(&mut device.pdma).await?;
    let _out_hbm = launch(constant_add_kernel, (&mut device, &in_hbm)).await?;
    println!("Constant Add: kernel ran");

    Ok(())
}

#[cfg(test)]
mod tests {
    use super::*;

    #[tokio::test]
    async fn matches_reference() -> eyre::Result<()> {
        let mut device = Device::new(constant_add_kernel.topology())?;

        let mut rng = SmallRng::seed_from_u64(42);
        let input = HostTensor::<i32, m![A]>::rand(&mut rng);
        let in_hbm = input.to_hbm(&mut device.pdma).await?;

        // 기준 계산(reference): out[i] = in[i] + 1.
        let in_buf: Vec<i32> = input.into_vec();
        let expected: Vec<i32> = in_buf.iter().map(|&x| x.wrapping_add(1)).collect();

        let out_hbm = launch(constant_add_kernel, (&mut device, &in_hbm)).await?;

        let actual: Vec<i32> = out_hbm.to_host::<m![A]>(&mut device.pdma).await?.into_vec();
        for (i, (&e, &a)) in expected.iter().zip(&actual).enumerate() {
            assert_eq!(e, a, "constant_add mismatch at i={i}: expected {e}, actual {a}");
        }

        Ok(())
    }
}

이 패턴의 매핑과 메모리(Pattern-Specific Mapping and Memory)

TCP 하드웨어는 네 단계의 중첩된 계층(level)으로 구성됩니다.

계층(Level) 개수(Count, RNGD) 역할(Role)
Chip 시스템에 따라 다름 HBM을 포함하는 최상위 유닛(unit).
Cluster 칩(chip)당 두 개 슬라이스(slice) 256개의 묶음.
Slice 클러스터(cluster)당 256개 텐서 유닛(Tensor Unit) 하나.
Lane 슬라이스(slice)당 여덟 개 수축 엔진(Contraction Engine)의 곱셈·누산(MAC) 배열에서 한 행(row).

텐서 타입(tensor type)은 원소 타입(element type)과 각 논리 축(logical axis)이 이 계층에 어떻게 분산되는지를 표현합니다. 예를 들어 DmTensor<bf16, m![1], m![1 # 2], m![A / 8 # 256], m![A % 8]>는 bf16 벡터(vector)의 A축을 슬라이스(slice) 256개에 나누고, 각 슬라이스에 원소 여덟 개를 배치한다는 뜻입니다. A의 각 원소는 어느 한 슬라이스 안의 명확한 위치 하나를 차지합니다.

매핑 연산자(mapping operator)는 축(axis)을 어디에 배치하는지 나타냅니다.

  • /는 스트라이드(stride)를 기준으로 축(axis)을 나눕니다.
  • %는 유닛 내부(in-unit)의 개수를 지정합니다.
  • #는 매핑(mapping)을 하드웨어 유닛(unit)의 개수에 맞게 패딩(padding)합니다.
  • =는 뷰(view)가 기존 항(term)에서 다루는 범위를 줄입니다. 타일(tile)은 이 방식으로 텐서(tensor)의 일부를 선택합니다.

%와 =는 모두 축(axis)의 범위를 좁히지만 작용 방식이 다릅니다. %는 새로운 안쪽 항(inner term)을 만듭니다. m![B / 2048, B % 2048]에서 첫 항은 B를 원소 2048개짜리 블록(block) 단위로 세고, 두 번째 항은 블록 하나 안의 위치를 셉니다. =는 항 자체를 바꾸지 않고 뷰(view)가 읽는 범위를 줄입니다. 따라서 m![B / 2048 = 1 # 2]는 두 블록 중 하나를 선택하고, # 2는 선택된 범위가 아닌 전체 축의 스트라이드(stride)를 유지합니다. 타일을 사용하는 커널(kernel)은 m![B / 2048 = 1 # 2, B % 2048]처럼 둘을 함께 써서 블록 하나를 선택하고 그 안의 모든 위치를 다룹니다. 일반 규칙은 타일링(Tiling)을 참고하세요.

텐서 유닛 텐서(Tensor Unit tensor)는 파이프라인 반복(pipeline iteration)을 나타내는 Time과 한 반복 안의 원소를 나타내는 Packet도 사용합니다. 텐서 유닛 파이프라인은 Fetch → Switch → Collect → Contraction → Vector → Cast → Transpose → Commit 순서입니다. 대부분의 단계는 슬라이스(slice) 내부에서 독립적으로 동작하지만, 교환 엔진(Switch Engine)은 슬라이스들을 서로 연결합니다.

종류(Type) 위치(Location) 용량(Capacity, RNGD) 역할(Role)
HbmTensor 패키지 내부(On-package) 48 GB, 1.5 TB/s 가중치(weight)와 활성값(activation)의 장기 저장.
DmTensor 칩 내부 SRAM(On-chip SRAM) 총 256 MB, 슬라이스(slice)당 512 KB 주 작업 메모리(working memory).
SpmTensor 칩 내부 스크래치패드(On-chip scratchpad) PE당 4 KB, 클러스터(cluster)당 PE 네 개 gather 인덱스(index)처럼 크기가 작고 다시 읽는 값을 임시로 저장.
TrfTensor 칩 내부 SRAM(On-chip SRAM) 레인(lane)당 8 KB, 슬라이스(slice)당 레인 여덟 개 수축 엔진(Contraction Engine)의 레지스터 파일(register file).
VrfTensor 칩 내부 SRAM(On-chip SRAM) 슬라이스(slice)당 8 KB 벡터 엔진(Vector Engine)의 피연산자 레지스터 파일(operand register file).

to_spm으로 DmTensor를 스크래치패드(scratchpad)로 옮기고, to_dm으로 되돌릴 수 있습니다. SPM gather는 인덱스(index)를 SpmTensor에서 직접 가져옵니다. 이러한 선택들이 상수 덧셈(constant-add) 패턴의 구체적인 구현을 결정합니다. 전체 매핑 모델(mapping model)은 텐서 매핑(Mapping Tensors), 메모리 이동은 텐서 이동(Moving Tensors), 파이프라인 API(pipeline API)는 텐서 계산(Computing Tensors)을 참고하세요.

고정된 벡터 피연산자(Stationary Vector Operand)

원소별 곱셈(Elementwise Multiplication)

목표(Goal)

\text{out}[i] = \text{lhs}[i] \times \text{rhs}[i]를 계산합니다. 이 패턴은 게이트 스케일링(gate scaling), GLU, 어텐션 스케일링(attention scaling)에 활용됩니다.

매핑과 데이터 이동(Mapping and Data Movement)

sub 컨텍스트(context)는 rhs를 VRF에 미리 적재하고, main 컨텍스트는 lhs를 스트리밍(streaming)하면서 벡터 엔진(Vector Engine)의 매 사이클(cycle)마다 VRF를 읽습니다. 두 DM 영역은 겹치면 안 됩니다.

모든 장치 커널(device kernel)에는 서로 다른 하드웨어 자원을 사용하는 device.main과 device.sub 실행 컨텍스트(execution context)가 있습니다. main은 주 계산을 수행하고, sub는 주로 피연산자(operand)를 미리 가져옵니다(prefetch). main은 필요한 데이터를 sub가 아직 만들지 않았다면 기다리며, 두 컨텍스트는 평면적으로 주소가 지정되는 칩 내부 SRAM(flat on-chip SRAM)을 공유합니다.

DM 주소(address)를 생략하면 자동 배치를 사용합니다. 알고리즘이 명시적으로 겹치지 않는 주소를 필요로 할 때만 _at API를 사용하세요. Tu 상수 제네릭(const generic)은 텐서(tensor)가 { Tu::Main }과 { Tu::Sub } 중 어디로 흐르는지를 나타냅니다. sub 컨텍스트(context)는 Fetch, Collect, .to_vrf()를 거쳐 rhs_dm을 적재합니다. 그동안 main은 고정된 VRF 피연산자(stationary operand)를 사용하는 MulInt에 lhs_dm을 스트리밍(streaming)합니다. 자원 의존성(resource dependency)이 허용하면 두 컨텍스트는 동시에 실행됩니다.

장치 소스(Device Source)

장치 소스(device source): src/kernel/elementwise_mul_kernel.rs.

rust
use furiosa_opt_std::prelude::*;

axes![A = 2048];

pub type Chip = m![1];
pub type Cluster = m![1 # 2];
pub type Slice = m![A / 8 # 256];

#[device(chip = 1)]
pub fn elementwise_mul_kernel(
    device: &mut Device,
    lhs: &HbmTensor<i32, Chip, m![A]>,
    rhs: &HbmTensor<i32, Chip, m![A]>,
) -> HbmTensor<i32, Chip, m![A]> {
    // 두 피연산자(operand)를 HBM에서 DM으로 이동(DM 위치는 자동 지정).
    let lhs_dm = lhs.to_dm::<Cluster, Slice, m![A % 8]>(&mut device.tdma);
    let rhs_dm = rhs.to_dm::<Cluster, Slice, m![A % 8]>(&mut device.tdma);

    // Sub 컨텍스트(context): rhs를 VRF에 적재(아래 main 컨텍스트와 동시에 실행).
    // VRF에는 벡터 엔진(Vector Engine)이 매 사이클(cycle) 읽는 슬라이스(slice)별 피연산자가 들어 있음.
    let rhs_vrf: VrfTensor<i32, Chip, Cluster, Slice, m![A % 8]> = device
        .sub
        .begin(rhs_dm.view())
        .fetch::<m![1], m![A % 8]>()
        .collect::<m![A % 8 / 8], m![A % 8 % 8]>()
        .to_vrf();

    // Main 컨텍스트(context): lhs의 각 원소에 VRF에서 대응하는 rhs 원소를 곱함
    let result = device
        .main
        .begin(lhs_dm.view())
        .fetch::<m![1], m![A % 8]>()
        .collect::<m![1], m![A % 8]>()
        .vector_init()
        .vector_intra_slice_tag(TagMode::Zero)
        // 각 슬라이스(slice)는 lhs 원소 8개에 VRF에서 대응하는 rhs 원소 8개를 곱함
        .vector_fxp(FxpBinaryOp::MulInt, &rhs_vrf)
        .vector_final()
        .commit_trim::<m![A % 8]>()
        .commit::<m![A % 8]>();

    result.to_hbm(&mut device.tdma)
}

호스트 프로그램과 기준 계산(Host Program and Oracle)

기본 템플릿(base-template)의 호스트 프로그램과 기준 계산(host oracle): src/elementwise_mul.rs.

rust
use furiosa_opt_std::prelude::*;
use {{ crate_name }}::kernel::elementwise_mul_kernel::{A, elementwise_mul_kernel};
use rand::SeedableRng;
use rand::rngs::SmallRng;

#[tokio::main]
async fn main() -> eyre::Result<()> {
    let mut device = Device::new(elementwise_mul_kernel.topology())?;
    let mut rng = SmallRng::seed_from_u64(42);

    let _out_hbm = launch(elementwise_mul_kernel, (&mut device, &lhs_hbm, &rhs_hbm)).await?;
    println!("Elementwise Mul: kernel ran");

    Ok(())
}

        let rhs = HostTensor::<i32, m![A]>::rand(&mut rng);

        let lhs_hbm = lhs.to_hbm(&mut device.pdma).await?;
        let rhs_hbm = rhs.to_hbm(&mut device.pdma).await?;

        // 기준 계산(reference): out[i] = lhs[i] * rhs[i].
        let lhs_buf: Vec<i32> = lhs.into_vec();
        let rhs_buf: Vec<i32> = rhs.into_vec();
        let expected: Vec<i32> = lhs_buf.iter().zip(&rhs_buf).map(|(&a, &b)| a.wrapping_mul(b)).collect();

        let out_hbm = launch(elementwise_mul_kernel, (&mut device, &lhs_hbm, &rhs_hbm)).await?;

        let actual: Vec<i32> = out_hbm.to_host::<m![A]>(&mut device.pdma).await?.into_vec();
        for (i, (&e, &a)) in expected.iter().zip(&actual).enumerate() {
            assert_eq!(e, a, "elementwise_mul mismatch at i={i}: expected {e}, actual {a}");
        }

        Ok(())
    }
}

수축 패턴(Contraction Patterns)

내적(Dot Product)

목표(Goal)

\sum_i x_i y_i를 계산합니다. 이 패턴은 어텐션 점수(attention score)와 유사도(similarity)에 활용됩니다.

매핑과 데이터 이동(Mapping and Data Movement)

한 피연산자(operand)는 파이프라인(pipeline)을 따라 흐르고, 다른 피연산자는 sub 컨텍스트(context)가 TRF에 저장합니다. sub 컨텍스트는 Fetch, Collect, .to_trf()를 거쳐 이 피연산자를 적재합니다.

.contract_outer()는 32바이트 플릿(flit) 두 개씩을 묶어 64바이트 패킷(packet)으로 만들고, TRF에 고정되어 있는 피연산자(stationary operand)를 읽습니다. 플릿을 묶는 작업은 스트림 어댑터(Stream Adapter)가, 고정 피연산자 읽기는 TRF 시퀀서(TRF Sequencer)가 수행합니다. 두 피연산자는 레인(lane)별 곱셈기(multiplier)에 들어갑니다. .contract_packet()은 하드웨어 축약 트리(reduction tree)를 통해 곱셈 결과를 공간적으로 축약합니다. .contract_time::<m![1]>()은 시간에 걸쳐 값을 누산(accumulate)해 슬라이스(slice)당 스칼라(scalar) 하나를 만듭니다. .contract_lane()은 레인들을 합치며, Lane = m![1]이면 이 과정은 단순합니다. .cast()는 f32 누산기(accumulator) 값을 bf16으로 변환합니다.

수축(contraction)은 많은 항에 대해 곱셈·누산(multiply-and-accumulate)을 수행하므로 더 넓은 타입(widened type)이 필요합니다. 수축은 i4·i8을 i32로, fp8·bf16을 f32로 확장합니다. .align()과 .contract()의 타입 표기(annotation)가 이 확장 타입을 선택합니다.

장치 소스(Device Source)

장치 소스(device source): src/kernel/dot_product_kernel.rs.

rust
use furiosa_opt_std::prelude::*;

axes![A = 2048];

pub type Chip = m![1];
pub type Cluster = m![1 # 2];
pub type Slice = m![1 # 256]; // 활성 슬라이스(slice) 1개; m![A / 8 # 256]이면 256개 전체에 분배
pub type Time = m![1]; // 시간 반복(temporal iteration) 없음
pub type Lane = m![1]; // 레인 병렬 처리(lane parallelism) 없음

#[device(chip = 1)]
pub fn dot_product_kernel(
    device: &mut Device,
    lhs: &HbmTensor<bf16, Chip, m![A]>,
    rhs: &HbmTensor<bf16, Chip, m![A]>,
) -> HbmTensor<bf16, Chip, m![1]> {
    // HBM → DM
    let lhs: DmTensor<bf16, Chip, Cluster, Slice, m![A]> = lhs.to_dm(&mut device.tdma);
    let rhs: DmTensor<bf16, Chip, Cluster, Slice, m![A]> = rhs.to_dm(&mut device.tdma);

    // Sub 컨텍스트(context): rhs를 TRF에 적재
    let rhs: TrfTensor<bf16, Chip, Cluster, Slice, Lane, m![A]> = device
        .sub
        .begin(rhs.view())
        .fetch::<Time, m![A]>()
        .collect::<m![{ Time }, A / 16], m![A % 16]>()
        .to_trf();

    // Main 컨텍스트(context): lhs를 수축 엔진(Contraction Engine)으로 스트리밍하고 A축을 축약(reduce)
    let result: DmTensor<bf16, Chip, Cluster, Slice, m![1 # 8]> = device
        .main
        .begin(lhs.view())
        .fetch::<Time, m![A]>()
        .collect::<m![A / 16], m![A % 16]>()
        // 연속된 32바이트 플릿(flit)을 둘씩 묶어 64바이트 패킷(packet)을 만들고 시간 단계 수를 절반으로 줄임(A/16 → A/32)
        .contract_outer::<m![A / 32], m![A % 32], _, _, _>(&rhs)
        .contract_packet::<m![1]>()
        .contract_time::<m![1]>()
        .contract_lane::<m![1], m![1 # 8]>(LaneMode::Interleaved)
        .cast::<bf16, m![1 # 16]>() // f32 누산기(accumulator) 출력을 bf16으로 다시 변환(cast)
        .commit_trim::<m![1 # 8]>()
        .commit();

    // DM → HBM
    result.to_hbm(&mut device.tdma)
}

GEMV

목표(Goal)

y_i = \sum_j A_{ij} x_j를 계산합니다. 이 패턴은 LLM 디코딩(decode)에 활용됩니다.

매핑과 데이터 이동(Mapping and Data Movement)

출력 차원(output dimension) I를 슬라이스(slice)에 걸쳐 매핑(mapping)하여 각 슬라이스가 한 행(row)을 계산하게 합니다. 벡터(vector) x 전체를 브로드캐스트(broadcast)하여 모든 슬라이스가 자신의 행과 수축(contraction)할 수 있게 합니다. 내적(dot product)과 달리 행들은 서로 독립적이지만, 모든 행에 동일한 전체 벡터 피연산자(operand)가 필요합니다.

장치 소스(Device Source)

장치 소스(device source): src/kernel/gemv_kernel.rs.

rust
use furiosa_opt_std::prelude::*;

axes![I = 256, J = 2048];

pub type Chip = m![1];
pub type Cluster = m![1 # 2];
pub type Slice = m![I]; // 출력 차원(output dimension)을 슬라이스(slice)에 걸쳐 분배
pub type Time = m![J / 32]; // 축약 차원(reduction dimension)의 시간 반복(temporal iteration)
pub type Packet = m![J % 32]; // 축약 차원(reduction dimension)의 패킷 크기(packet size)
pub type Lane = m![1];

#[device(chip = 1)]
pub fn gemv_kernel(
    device: &mut Device,
    matrix: &HbmTensor<bf16, Chip, m![I, J]>,
    vector: &HbmTensor<bf16, Chip, m![J]>,
) -> HbmTensor<bf16, Chip, m![I]> {
    // 데이터를 HBM에서 DM으로 이동
    let matrix: DmTensor<bf16, Chip, Cluster, Slice, m![J]> = matrix.to_dm(&mut device.tdma);
    let vector: DmTensor<bf16, Chip, Cluster, Slice, m![J]> = vector.to_dm(&mut device.tdma);

    // 벡터(vector)를 TRF에 적재
    let vector_trf: TrfTensor<bf16, Chip, Cluster, Slice, Lane, m![J]> = device
        .sub
        .begin(vector.view())
        .fetch::<m![1], m![J]>()
        // 수집 엔진(Collect Engine): 32바이트 플릿(flit)으로 나눔.
        .collect::<m![J / 16], m![J % 16]>()
        .to_trf();

    // GEMV 계산: 행렬(matrix) × 벡터(vector)
    // 핵심 차이: `I`는 슬라이스(slice)에 매핑되어 유지되고, `J`는 축약(reduce)됨
    let result: DmTensor<bf16, Chip, Cluster, Slice, m![1 # 4]> = device
        .main
        .begin(matrix.view())
        .fetch::<m![J / 16], m![J % 16]>()
        .collect::<m![J / 16], m![J % 16]>()
        .contract_outer::<Time, Packet, _, _, _>(&vector_trf)
        .contract_packet::<m![1]>()
        .contract_time::<m![1]>()
        .contract_lane::<m![1], m![1 # 8]>(LaneMode::Interleaved)
        .cast::<bf16, m![1 # 16]>()
        .commit_trim::<m![1 # 4]>()
        .commit();

    // 결과를 HBM으로 전송
    result.to_hbm(&mut device.tdma)
}

GEMM

목표(Goal)

C_{ij} = \sum_k A_{ik} B_{kj}를 계산합니다. A는 J에 걸쳐, B는 I에 걸쳐 브로드캐스트(broadcast)됩니다.

매핑과 데이터 이동(Mapping and Data Movement)

두 출력 차원(output dimension)을 type Slice = m![I / 32, J / 32]로 매핑(mapping)하여 각 슬라이스(slice)가 16 × 16 출력 타일(output tile)을 계산하게 합니다. 교환 엔진(Switch Engine)이 각 B 타일을 대응하는 슬라이스로 전달하므로, 각 슬라이스는 자신의 출력 타일에 해당하는 J 부분만 받습니다. .contract_packet::<m![1]>()은 K축을 공간적으로 축약(reduce)합니다. .contract_time::<m![I]>()은 I를 유지하면서 시간에 걸쳐 누산(accumulate)합니다. .contract_lane::<m![I], m![J # 8]>(LaneMode::Interleaved)는 출력 패킷(output packet)에 I와 J를 유지합니다.

장치 소스(Device Source)

장치 소스(device source): src/kernel/gemm_kernel.rs.

rust
use furiosa_opt_std::prelude::*;

axes![I = 512, J = 512, K = 64];

pub type Chip = m![1];
pub type Cluster = m![1 # 2];
// 출력 차원(output dimension) `I`와 `J`를 슬라이스(slice)에 걸쳐 분배
pub type Slice = m![I / 32, J / 32]; // 각 슬라이스(slice)가 16 × 16 출력 타일(output tile)을 처리
pub type Lane = m![J % 8];

#[device(chip = 1)]
pub fn gemm_kernel(
    device: &mut Device,
    a: &HbmTensor<bf16, Chip, m![I, K]>,
    b: &HbmTensor<bf16, Chip, m![J, K]>,
) -> HbmTensor<bf16, Chip, m![I, J]> {
    // 데이터를 HBM에서 DM으로 이동
    let a: DmTensor<bf16, Chip, Cluster, Slice, m![I % 32, K]> = a.to_dm(&mut device.tdma);
    let b: DmTensor<bf16, Chip, Cluster, Slice, m![J % 32, K]> = b.to_dm(&mut device.tdma);

    // 행렬(matrix) B를 TRF에 적재
    // 교환 엔진(Switch Engine)이 B를 슬라이스(slice) 256개에 분배
    // 각 슬라이스(slice)는 `K` 차원(dimension) 전체와 자신의 (16 × 16) 출력 타일(output tile)에 해당하는 부분만 받음
    // 분배의 자세한 내용은 교환 엔진(Switch Engine) 토폴로지(topology) 참고
    let b_trf: TrfTensor<bf16, Chip, Cluster, Slice, Lane, m![J / 8 % 4, K]> = device
        .sub
        .begin(b.view())
        .fetch::<m![J % 8, J / 8 % 4], m![K]>()
        .collect::<m![J % 8, J / 8 % 4, K / 16], m![K % 16]>()
        .to_trf();

    // GEMM 계산: A × B
    // 교환 엔진(Switch Engine)이 (`I / 32`, `J / 32`)에 맞는 슬라이스(slice) 분배를 보장
    // 수축(contraction)은 `K`축을 축약(reduce)하고 `I`와 `J`는 유지
    let result: DmTensor<bf16, Chip, Cluster, Slice, m![I % 32, J % 32]> = device
        .main
        .begin(a.view())
        .fetch::<m![I % 32, J / 8 % 4], m![K]>()
        .collect::<m![I % 32, J / 8 % 4, K / 16], m![K % 16]>()
        .contract_outer::<m![I % 32, J / 8 % 4, K / 32], m![K % 32], _, _, _>(&b_trf)
        .contract_packet::<m![1]>()
        .contract_time::<m![I % 32, J / 8 % 4]>()
        .contract_lane::<m![I % 32, J / 8 % 4], m![J % 8]>(LaneMode::Interleaved)
        .cast::<bf16, m![J % 8 # 16]>()
        .commit_trim::<m![J % 8]>()
        .commit();

    // 결과를 HBM으로 전송
    result.to_hbm(&mut device.tdma)
}

블록 GEMM(Blocked GEMM)은 칩 내부 DM 용량을 초과하는 행렬(matrix)을 처리하도록 GEMM에 타일링(tiling)을 추가한 것입니다. K에 대한 시간 분할(temporal partitioning)과 여러 칩(chip)에 걸친 I·J의 공간 분할(spatial partitioning)을 다룹니다. 플래시 어텐션(Flash Attention)은 트랜스포머 어텐션 헤드(transformer attention head)에서 GEMM, 벡터 엔진(Vector Engine)의 소프트맥스(softmax), main/sub 프리페치(prefetch)를 결합합니다.
