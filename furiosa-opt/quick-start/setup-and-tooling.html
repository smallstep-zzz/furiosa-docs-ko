설정과 도구(Setup and Tooling)

설치와 첫 프로그램

이 장에서는 설치부터 첫 프로젝트 실행까지의 명령 순서를 다룹니다. 커널(kernel) 패턴을 읽기 전에 먼저 실행해 보세요.

호스트 요구 사항(Host Requirements)

호스트(host)는 Ubuntu 22.04 이상에서 실행하는 x86_64-unknown-linux-gnu 환경이어야 합니다. 배포되는 바이너리(binary)는 GLIBC_2.34를 요구하지만 Ubuntu 20.04에는 2.31이 포함되어 있기 때문입니다. macOS나 arm64에서는 모든 작업을 linux/amd64 컨테이너(container) 안에서 실행하세요.

bash
sudo apt install build-essential libclang-dev   # 모든 빌드(build)에 필요
sudo apt install gcc-aarch64-linux-gnu          # NPU 빌드(build)에만 필요(cargo furiosa-opt)

아래 도구 모음(toolchain)에는 이 의존성이 포함되어 있지 않으므로 먼저 설치하세요. rustc는 시스템의 cc로 호스트 바이너리(host binary)를 링크(link)하고, furiosa-opt-std의 빌드 스크립트(build script)는 libclang.so를 불러옵니다.

시작 템플릿(Starter) 설치와 실행

Furiosa 최적화 도구(optimizer)는 rustc 드라이버(driver)이며, ABI가 지정된 nightly 버전에 고정되어 있습니다. 도구 모음(toolchain)과 호스트 도구를 설치하고 표준 시작 템플릿(starter)을 만든 다음, CPU에서 실행하고 커널(kernel)을 컴파일하세요.

bash
rustup toolchain install nightly-2026-05-01
cargo +nightly-2026-05-01 install cargo-binstall
cargo +nightly-2026-05-01 binstall cargo-furiosa-opt
cargo install cargo-generate
cargo generate furiosa-ai/furiosa-opt base-template
cd base-template
cargo run --release --bin gemm
cargo furiosa-opt compile

생성된 프로젝트의 rust-toolchain.toml도 같은 채널(channel)을 지정합니다. Cargo는 해당 디렉터리에서 이 버전을 자동으로 활성화합니다.

일반 cargo 명령은 CPU용으로 빌드(build)하고 실행합니다. cargo furiosa-opt는 NPU용으로 빌드하며 커널(kernel)을 미리 컴파일합니다.

NPU 요구 사항(NPU Requirements)

NPU 빌드(build)에는 Furiosa SDK와 실제 NPU도 필요합니다. 실행 요청은 SDK 커널 드라이버(kernel driver)와 PE 런타임(runtime)을 거쳐 전달됩니다. 여기에는 furiosa-driver-rngd, furiosa-smi 및 관련 구성 요소가 포함됩니다. SDK 문서를 참고하세요.

CPU 빌드(build)에는 SDK가 필요하지 않으며, NPU 의존성 없이 호스트(host)에서 실행됩니다.

생성된 프로젝트(The Generated Project)

위 명령 순서는 base-template 시작 템플릿(starter)의 프로젝트 골격을 생성합니다. 이 템플릿은 표준 실행 예제이며, 지속적 통합(continuous integration, CI)에서도 임의의 이름으로 최신 소스를 생성한 뒤 CPU에서 테스트합니다. 생성된 템플릿을 수정하기 전에 텐서와 수축(Tensor and Contraction), 커널 검증(Kernel Validation)을 읽으세요. 에이전트(agent)가 변경을 구현한다면 Kernel Authoring Skill을 사용하세요.

템플릿 구성(Template Layout)

생성된 Cargo.toml에는 [package.metadata.furiosa-opt]가 선언되어 있으며, 이 설정은 해당 패키지(package)를 커널 컴파일 대상으로 표시합니다. src/kernel/에는 각 #[device] 함수가 들어 있고, src/kernel/mod.rs에서 이 커널 모듈(kernel module)을 다시 내보냅니다(re-export). src/*.rs 파일은 launch(kernel, ...)를 호출하는 호스트 바이너리(host binary)이며, 호스트 기준 계산(host oracle) 테스트도 포함합니다. 각 호스트 바이너리는 Cargo.toml에 path = "src/<name>.rs"를 지정한 명시적인 [[bin]] 항목을 가집니다. 컴파일러 플러그인(compiler plugin)은 src/에 루트를 둔 cargo 타깃(target)을 탐색하므로, 호스트 바이너리를 src/bin/, examples/, tests/로 옮기지 마세요.

text
base-template/
├── Cargo.toml
├── rust-toolchain.toml
└── src/
    ├── lib.rs
    ├── kernel/
    │   ├── mod.rs
    │   └── <name>_kernel.rs
    └── <name>.rs

커널 추가하기(Add a Kernel)

  1. #[device(...)] pub fn <name>_kernel(...) 함수를 담은 src/kernel/<name>_kernel.rs를 추가합니다.
  2. src/kernel/mod.rs에서 이를 다시 내보냅니다(re-export).
  3. 호스트 프로그램(host program), 호스트 기준 계산(host oracle), launch(<name>_kernel, ...) 호출을 담은 src/<name>.rs를 추가합니다.
  4. Cargo.toml에서 호스트 프로그램(host program)을 [[bin]] 타깃(target)으로 등록합니다.
  5. 커널 최적화 도구(Kernel Optimizer)의 명령어 참조에 따라 커널(kernel)을 실행합니다.

개발 도구(Development Tools)

Furiosa IR Optimizer는 Furiosa SDK 컴파일러를 보완합니다. 프로그래머가 vISA를 직접 작성하거나 다른 컴파일러로 생성할 때 세밀한 제어 기능을 제공합니다.

커널 최적화 도구(Kernel Optimizer)

CLI 문법과 컴파일 동작은 커널 최적화 도구(Kernel Optimizer) 참조에서 다룹니다.

언어 서버(Language Server)

furiosa-rust-analyzer-proxy는 표준 Rust IDE 기능을 제공하면서 Furiosa 매핑 표현식(mapping expression)을 읽기 쉽게 보여 줍니다. Stride<Symbol<A>, 8>처럼 긴 매핑 타입(mapping type)을 m![A / 8] 형태로 표시합니다. 설치와 설정은 언어 서버(Language Server) 도구 참조를 확인하세요.

스케줄 뷰어(Schedule Viewer)

스케줄 뷰어(Schedule Viewer)는 실행 타임라인(execution timeline)을 시각화해 성능 병목(performance bottleneck)을 찾도록 도와줍니다. furiosa-opt로 스케줄 JSON 파일을 내보낸 뒤 furiosa-schedule-viewer로 여세요.

설치와 사용법은 스케줄 뷰어(Schedule Viewer) 도구 참조를 확인하세요.
