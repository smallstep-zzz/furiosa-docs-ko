furiosa-opt-rt

컴파일된 #[device] 함수를 Furiosa NPU에서 실행합니다. furiosa-opt-std가 대신 호출해 주며, 직접 만든 호스트 코드(host code)에서 이미지(image)를 실행하려면 이 런타임을 직접 사용할 수 있습니다.

rust
use furiosa_opt_rt::{Argument, Device, Pinned, Result, Topology, memory::Kind, registry};
use std::sync::Arc;

async fn run(entry: &registry::Entry) -> Result<()> {
    let device = Arc::new(Device::new(Topology { chips: 1, pes: 8 })?);
    let mut buffer = device.alloc(Kind::Dram, 4096)?;
    let mut host = Pinned::zeroed(4096)?;
    device.write([(host.slice(..), buffer.slice_mut(..)?)]).await?;
    // 안전성(SAFETY): 엔트리(entry)는 컴파일러가 생성한 해당 함수의 이미지(image)를 보유합니다.
    let function = unsafe { registry::load(entry, &device, None) }.await?;
    function.launch([Argument::from(buffer.slice_mut(..)?)])?.await?;
    device.read([(buffer.slice(..)?, host.slice_mut(..))]).await
}

보장 사항(Guarantees)

  • 제출된 작업(submitted work)은 끝까지 실행됩니다. 실행(launch)이나 전송(transfer)의 퓨처(future)를 버리거나(drop) 잊어버려도(forget) 취소되지 않습니다. 장치(device)가 응답할 때까지 해당 메모리를 계속 보유합니다.
  • 충돌하는 작업(conflicting work)은 기다리거나 거부되며, 경쟁 상태(race)를 일으키지 않습니다. 다른 작업이 보유한 바이트(bytes)가 필요한 실행(launch)은 Error::Busy로 실패합니다. 전송(transfer)은 자신이 사용할 바이트에 대해 앞서 접수된 작업이 끝나기를 기다립니다. 실행은 호출 시 접수되고, 전송은 처음 폴링(polling)될 때 접수됩니다. 한 장치의 실행들은 제출 순서(submission order)를 따릅니다.
  • 장치 실패(device failure)는 지속됩니다(sticky). 제출된 작업이 장치에서 실패하면 장치는 이후의 모든 작업을 같은 오류로 거부하며, 실패한 작업이 쓸 수 있었던 모든 할당 영역(allocation)은 Error::Poisoned 상태가 됩니다. 실패 응답(answer)만으로 장치 코드가 실행되었는지 알 수 없으므로, 거부된 실행도 이 규칙에 포함됩니다. Error::Busy처럼 제출 전에 거부된 작업은 장치 상태를 바꾸지 않습니다.
  • 실행(launch)은 호스트(host)에서 메모리를 할당하지 않습니다. 모델 한 단계(step)는 각각 수 마이크로초짜리 실행 수백 번으로 이루어지므로, 실행당 런타임 비용(runtime cost)이 지연 시간(latency)의 하한을 결정합니다.

계층(Layers)

각 계층(layer)은 이웃한 계층과만 통신하며, 같은 이름은 호스트(host)와 펌웨어(firmware)에서 같은 뜻으로 쓰입니다.

계층(Layer) 규약(Contract) 호스트(Host) 펌웨어(Firmware)
프로그램(Program) #[device] 함수(fn), launch(f, args) furiosa-opt-std
이미지(Image) 컴파일러 이미지(compiler image), 레지스트리 엔트리(registry entry) furiosa-opt-abi
런타임(Runtime) Device, Buffer, Pinned, Function 이 크레이트(crate)
애플리케이션(Application) 호출(call)과 그 응답(answer) Device Server
메일박스(Mailbox) 각 응답(answer)을 해당 호출(call)과 연결합니다. Mailbox Mailbox
메시지(Message) Request, Answer, 태그가 붙은 옵션(tagged options) furiosa-opt-ipc furiosa-opt-ipc
프레임(Frame) 헤더(header)와 워드(word), 해당 리비전(revision) furiosa-opt-ipc furiosa-opt-ipc
링크(Link) 링(ring)과 도어벨(doorbell) Link Link
장치 ABI(Device ABI) 실행 파일(executable), 부트로더(bootloader), 링 배치(ring layout) furiosa-opt-abi furiosa-opt-abi

펌웨어(firmware)는 미리 빌드한 이미지(prebuilt image)로 이 크레이트(crate)에 내장되어 배포됩니다. 서명된 부트로더(signed bootloader)가 각 PE 클러스터(cluster)에서 이를 검증하고 시작합니다.

커널 드라이버(Kernel driver)

장치에 매핑된 고정 메모리(pinned memory)의 전송(transfer)과 장치 코드가 요청하는 DMA에는, 펌웨어(firmware)용 PDMA 채널(channel)을 예약하는 커널 드라이버(kernel driver)가 필요합니다. 이 기능을 지원하지 않는 드라이버에서도 장치를 열 수는 있습니다. 이 경우 모든 호스트 전송(host transfer)은 드라이버 자체 채널을 사용하고, 펌웨어 DMA가 필요한 실행(launch)은 Error::Unsupported로 실패합니다.
