튜닝(Tuning)

튜닝(tuning)은 통제된 실험(controlled experiment)입니다. 정확성(correctness)을 유지하고 기준선(baseline)을 기록한 뒤, 지원되는 조정 요소(lever) 하나를 바꿉니다. 같은 스케줄 지표(schedule metric)를 비교한 다음 변경을 유지할지 결정합니다.

실험 조건 통제하기(Control the experiment)

모든 후보(candidate)에 대해 다음 순서를 따릅니다.

  1. 자료형 검사(type-checking) 경로를 실행하여 매핑(mapping)과 형태(shape)의 제약을 검증합니다.
  2. 관련 경계 사례(boundary case)를 포함하여 호스트 정답 기준(host oracle)과 비교하는 CPU 테스트를 실행합니다.
  3. 기준선(baseline)을 컴파일하고 스케줄 전체 완료 시간(schedule makespan)을 기록합니다.
  4. 릴리스(release), 형태(shape), 자료형(data type), 매핑(mapping)을 고정한 상태에서 조정 요소(lever) 하나를 바꿉니다.
  5. 같은 검사를 다시 실행하고 후보 스케줄(candidate schedule)을 덤프합니다.
  6. 정확성 검사(correctness check)를 계속 통과하고 측정 지표(metric)도 좋아졌을 때만 변경을 유지합니다. 그렇지 않으면 기준선(baseline)으로 되돌립니다.

이 장의 주요 정적 지표(static metric)는 스케줄 전체 완료 시간(schedule makespan)입니다. 재현 가능한 스케줄 비교나 별도로 기록한 장치 측정 근거(device evidence) 없이 처리량(throughput) 또는 사이클(cycle)이 개선되었다고 보고하지 마세요.

조정 요소 하나 선택하기(Choose one lever)

진단(diagnosis)에서 대상 의존성(dependency)이나 자원(resource)을 특정한 뒤 조정 요소(lever)를 고릅니다.

  • 현재 자원(resource)이 병목(bottleneck)이면 실행 엔진 경로(execution-engine path)를 바꿉니다.
  • 스케줄(schedule)에서 피할 수 있는 직렬 작업(serial work)이나 형태에 맞지 않는 축약(reduction)이 드러나면 타일(tile) 또는 분할 형태(split shape)를 바꿉니다.
  • 제한 구간(limiting interval)이 데이터 이동(movement)이나 주소 의존성(address dependency)에 있다면 매핑(mapping), 패딩(padding), 전송 경계(transfer boundary)를 바꿉니다.

이 선택들은 텐서 이동(Moving Tensors), 텐서 연산(Computing Tensors), 텐서 매핑(Mapping Tensors)에서 정의합니다.

루프 펼치기(Unroll a loop)

#[unroll]을 사용하면 작은 정적 루프(static loop)의 모든 반복을 스케줄러(scheduler)에 드러낼 수 있습니다.

rust
#[unroll]
for group in 0..Group::SIZE {
    consume(group);
}

커널 크레이트(kernel crate)에는 #![feature(proc_macro_hygiene, stmt_expr_attributes)]가 필요합니다. 루프(loop)는 0에서 시작하고 최소 한 번 실행되며, 끝값이 컴파일 시간 상수(compile-time constant)여야 합니다. #[unroll]은 그 반복 횟수 전체를 펼칩니다. 소스 수준의 부분 펼치기 계수(partial-unroll factor)나 고정된 최대 반복 횟수 제한은 없습니다. 실제로 생성 IR과 코드 크기가 반복 횟수에 비례해 늘어나므로 작은 루프에 사용하세요.

본문(body) 안의 실행 시점 if(runtime if)는 지원되며, 펼친 각 반복에 복사됩니다. 0..valid_len처럼 실행 시점에 정해지는 루프 끝값(runtime loop end)은 컴파일러가 만들어야 할 본문 복사본 수를 정할 수 없어 펼치기 전에 거부됩니다. 루프는 장치 진입점(device entry point) 안이나 그곳에서 호출하는 도우미 함수(helper)에 둘 수 있습니다. 중첩 루프(nested loop)는 자동으로 펼쳐지지 않으므로 모든 수준을 펼치려면 각 루프에 #[unroll]을 붙이세요. 자체 상수 끝값을 가진 중첩 루프는 지원됩니다. 그러나 for j in 0..i처럼 바깥 루프의 카운터(counter)에 의존하는 끝값은 실행 시점 끝값입니다. 현재 루프 구성이 펼치기보다 먼저 수행되므로, 바깥 루프에 #[unroll]이 있어도 거부됩니다.

컴파일러(compiler)는 #[unroll] 적용 후 남은 루프(loop)가 있는지 확인합니다. 커널 전체에 루프가 하나도 남지 않아야 레지스터 파일 재사용(register-file reuse)이 활성화됩니다. 일부만 펼쳐도 그 반복들이 스케줄링(scheduling)에 드러나지만, 바깥 루프나 중첩 루프가 하나라도 남으면 루프 없는 경우의 최적화(loop-free optimization)는 활성화되지 않습니다.

이중 버퍼링(Double buffering)

이중 버퍼링(double buffering)은 SubContext에서 다음 가중치 그룹(weight group)을 준비하는 작업과 MainContext에서 현재 그룹을 수축(contraction)하는 작업을 겹칠 수 있습니다. 스케줄러(scheduler)가 두 연산을 같은 스케줄링 단위(scheduling unit)에서 볼 수 있어야 이러한 겹침(overlap)을 고려합니다. 수동으로 2단계 루프를 구성하거나 #[unroll]을 사용하여 이 기회를 만드세요.

이 비교는 가중치 그룹(weight group) 20개를 사용하며, 모든 경우에 같은 스케줄 구간(schedule window)을 봅니다.

루프 형태(Loop form) 스케줄링 단위당 보이는 그룹 수(Groups visible per scheduling unit) 반복 간 실행 겹침(Cross-iteration overlap) 전체 완료 시간(Makespan)
일반적인 펼치지 않은 루프(rolled loop) 1 없음(No) 19,106사이클(cycles)
수동 2단계 소프트웨어 파이프라인(software pipeline) 2 있음(Yes) 15,477사이클(cycles)
전체 펼치기(full unrolling) 20 있음(Yes) 15,086사이클(cycles)

StoTrf는 가중치 그룹(weight group)을 텐서 레지스터 파일(TRF, Tensor Register File)에 준비합니다. TRF의 두 절반에 그룹을 하나씩 놓을 수 있지만, 두 절반은 뱅크(bank)를 공유합니다. 용량과 주소 모드(address mode)는 레지스터 파일: 이중 버퍼링(Register Files: Double Buffering)을 참고하세요. 실제 겹침(overlap)은 스케줄 뷰어(Schedule Viewer)로 확인합니다.

파란 상자는 StoTrf, 주황 상자는 수축(contraction), 초록 띠는 측정된 실행 겹침(overlap)을 나타냅니다.

일반적인 펼치지 않은 루프(rolled loop): 19,106사이클

스케줄러(scheduler)는 펼치지 않은 루프(rolled loop)의 본문에 대해 스케줄(schedule) 하나를 만들고 이를 매 반복에서 되풀이합니다. 따라서 Contraction(i)와 StoTrf(i + 1)은 겹쳐 실행할 수 없습니다.

rust
use furiosa_opt_std::prelude::*;

type Chip = m![1];
type Cluster = m![Tok / 8 % 2];
type Slice = m![Tok % 8 # 256];

/// 펼치지 않은 루프(rolled loop)의 각 반복(iteration)에서 가중치 그룹(weight group) 하나를 준비하고 수축(contraction) 연산을 수행합니다.
#[device(chip = 1)]
pub fn rolled(
    device: &mut Device,
    activation: &HbmTensor<bf16, Chip, m![Tok, Red]>,
    weight: &HbmTensor<bf16, Chip, m![Group, Out, Red]>,
) -> HbmTensor<bf16, Chip, m![Tok, Group, Out]> {
    let activation: DmTensor<bf16, Chip, Cluster, Slice, m![Red]> = activation.to_dm(&mut device.tdma);
    let weight: DmTensor<bf16, Chip, Cluster, Slice, m![Group, Out, Red]> = weight.to_dm(&mut device.tdma);
    let mut output: DmTensor<bf16, Chip, Cluster, Slice, m![Group, Out]> = DmTensor::new();

    for g in 0..Group::SIZE {
        let weight_group = weight.view().tile::<m![Group], 1, m![1 # 20, Out, Red]>(g);
        let weight_trf: TrfTensor<bf16, Chip, Cluster, Slice, m![Out], m![Red]> = device
            .sub
            .begin(weight_group)
            .fetch::<m![Out, Red / 16], m![Red % 16]>()
            .collect::<m![Out, Red / 16], m![Red % 16]>()
            .to_trf();

        device
            .main
            .begin(activation.view())
            .fetch::<m![Red / 16], m![Red % 16]>()
            .collect::<m![Red / 16], m![Red % 16]>()
            .contract_outer::<m![Red / 32], m![Red % 32], _, _, _>(&weight_trf)
            .contract_packet::<m![1]>()
            .contract_time::<m![1]>()
            .contract_lane::<m![1], m![Out]>(LaneMode::Interleaved)
            .cast::<bf16, m![Out # 16]>()
            .commit_trim::<m![Out]>()
            .commit_view(output.view_mut().tile::<m![Group], 1, m![1 #{!} 20, Out]>(g));
    }

    let mut result = HbmTensor::<bf16, Chip, m![Tok, Group, Out]>::new();
    output.view().to_hbm_view(&mut device.tdma, result.view_mut());
    result
}

수동 2단계 소프트웨어 파이프라인(software pipeline): 15,477사이클

수동 파이프라인(manual pipeline)은 한 루프 본문(loop body)에 두 그룹을 놓습니다. 이로써 스케줄러(scheduler)가 Contraction(first)와 StoTrf(second)를 함께 고려할 수 있습니다.

rust
use furiosa_opt_std::prelude::*;

type Chip = m![1];
type Cluster = m![Tok / 8 % 2];
type Slice = m![Tok % 8 # 256];

/// 반복(iteration)마다 가중치 그룹(weight group) 두 개를 드러내 소프트웨어 파이프라이닝(software pipelining)을 가능하게 합니다.
#[device(chip = 1)]
pub fn software_pipelined(
    device: &mut Device,
    activation: &HbmTensor<bf16, Chip, m![Tok, Red]>,
    weight: &HbmTensor<bf16, Chip, m![Group, Out, Red]>,
) -> HbmTensor<bf16, Chip, m![Tok, Group, Out]> {
    let activation: DmTensor<bf16, Chip, Cluster, Slice, m![Red]> = activation.to_dm(&mut device.tdma);
    let weight: DmTensor<bf16, Chip, Cluster, Slice, m![Group, Out, Red]> = weight.to_dm(&mut device.tdma);
    let mut output: DmTensor<bf16, Chip, Cluster, Slice, m![Group, Out]> = DmTensor::new();

    for pair in 0..Pairs::SIZE {
        let first = pair * 2;
        let second = first + 1;
        let first_weight = weight.view().tile::<m![Group], 1, m![1 # 20, Out, Red]>(first);
        let first_trf: TrfTensor<bf16, Chip, Cluster, Slice, m![Out], m![Red]> = device
            .sub
            .begin(first_weight)
            .fetch::<m![Out, Red / 16], m![Red % 16]>()
            .collect::<m![Out, Red / 16], m![Red % 16]>()
            .to_trf();
        let second_weight = weight.view().tile::<m![Group], 1, m![1 # 20, Out, Red]>(second);
        let second_trf: TrfTensor<bf16, Chip, Cluster, Slice, m![Out], m![Red]> = device
            .sub
            .begin(second_weight)
            .fetch::<m![Out, Red / 16], m![Red % 16]>()
            .collect::<m![Out, Red / 16], m![Red % 16]>()
            .to_trf();

        device
            .main
            .begin(activation.view())
            .fetch::<m![Red / 16], m![Red % 16]>()
            .collect::<m![Red / 16], m![Red % 16]>()
            .contract_outer::<m![Red / 32], m![Red % 32], _, _, _>(&first_trf)
            .contract_packet::<m![1]>()
            .contract_time::<m![1]>()
            .contract_lane::<m![1], m![Out]>(LaneMode::Interleaved)
            .cast::<bf16, m![Out # 16]>()
            .commit_trim::<m![Out]>()
            .commit_view(output.view_mut().tile::<m![Group], 1, m![1 #{!} 20, Out]>(first));
        device
            .main
            .begin(activation.view())
            .fetch::<m![Red / 16], m![Red % 16]>()
            .collect::<m![Red / 16], m![Red % 16]>()
            .contract_outer::<m![Red / 32], m![Red % 32], _, _, _>(&second_trf)
            .contract_packet::<m![1]>()
            .contract_time::<m![1]>()
            .contract_lane::<m![1], m![Out]>(LaneMode::Interleaved)
            .cast::<bf16, m![Out # 16]>()
            .commit_trim::<m![Out]>()
            .commit_view(output.view_mut().tile::<m![Group], 1, m![1 #{!} 20, Out]>(second));
    }

    let mut result = HbmTensor::<bf16, Chip, m![Tok, Group, Out]>::new();
    output.view().to_hbm_view(&mut device.tdma, result.view_mut());
    result
}

전체 펼치기(full unrolling): 15,086사이클

#[unroll]은 수동으로 두 그룹씩 묶지 않아도 20개 그룹 전체를 스케줄러에 드러냅니다.

rust
use furiosa_opt_std::prelude::*;

type Chip = m![1];
type Cluster = m![Tok / 8 % 2];
type Slice = m![Tok % 8 # 256];

/// 그룹 루프(group loop)를 완전히 펼쳐(full unrolling) 모든 가중치 그룹(weight group)을 드러냅니다.
#[device(chip = 1)]
pub fn unrolled(
    device: &mut Device,
    activation: &HbmTensor<bf16, Chip, m![Tok, Red]>,
    weight: &HbmTensor<bf16, Chip, m![Group, Out, Red]>,
) -> HbmTensor<bf16, Chip, m![Tok, Group, Out]> {
    let activation: DmTensor<bf16, Chip, Cluster, Slice, m![Red]> = activation.to_dm(&mut device.tdma);
    let weight: DmTensor<bf16, Chip, Cluster, Slice, m![Group, Out, Red]> = weight.to_dm(&mut device.tdma);
    let mut output: DmTensor<bf16, Chip, Cluster, Slice, m![Group, Out]> = DmTensor::new();

    #[unroll]
    for g in 0..Group::SIZE {
        let weight_group = weight.view().tile::<m![Group], 1, m![1 # 20, Out, Red]>(g);
        let weight_trf: TrfTensor<bf16, Chip, Cluster, Slice, m![Out], m![Red]> = device
            .sub
            .begin(weight_group)
            .fetch::<m![Out, Red / 16], m![Red % 16]>()
            .collect::<m![Out, Red / 16], m![Red % 16]>()
            .to_trf();

        device
            .main
            .begin(activation.view())
            .fetch::<m![Red / 16], m![Red % 16]>()
            .collect::<m![Red / 16], m![Red % 16]>()
            .contract_outer::<m![Red / 32], m![Red % 32], _, _, _>(&weight_trf)
            .contract_packet::<m![1]>()
            .contract_time::<m![1]>()
            .contract_lane::<m![1], m![Out]>(LaneMode::Interleaved)
            .cast::<bf16, m![Out # 16]>()
            .commit_trim::<m![Out]>()
            .commit_view(output.view_mut().tile::<m![Group], 1, m![1 #{!} 20, Out]>(g));
    }

    let mut result = HbmTensor::<bf16, Chip, m![Tok, Group, Out]>::new();
    output.view().to_hbm_view(&mut device.tdma, result.view_mut());
    result
}
