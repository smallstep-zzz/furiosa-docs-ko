커널 최적화 도구(Kernel Optimizer)

커널 최적화 도구(Kernel Optimizer)는 Furiosa Optimizer 커널(kernel)의 빌드(build), 테스트(test), 실행(run), 직접 컴파일(direct compile) 작업 흐름을 제공합니다. cargo-furiosa-opt 명령이 이 작업들의 진입점(entry point)입니다.

cargo-furiosa-opt는 Furiosa NPU 컴파일러 도구 모음(compiler toolchain)을 위한 가벼운 cargo 래퍼(wrapper)입니다. cargo furiosa-opt는 NPU용으로 빌드하고, 일반 cargo 호출은 CPU용으로 빌드·실행합니다. 모든 cargo 인수(argument)는 그대로 전달되며, 래퍼가 해당 빌드에 필요한 커널(kernel)을 컴파일합니다.

설치 방법은 설치와 첫 프로그램(Installation and First Program)을 참고하세요.

먼저 실행할 명령(First Commands)

CPU에서 실행 파일(binary)을 먼저 실행한 다음, 매핑(mapping)을 검사하고 정답 기준(oracle)과 값을 비교한 뒤 스케줄 데이터(schedule data)를 내보냅니다.

bash
cargo run --release --bin gemm
cargo furiosa-opt compile
cargo test --release --bin gemm
cargo furiosa-opt compile gemm_kernel --dump-schedule schedule.json

빠른 시작(Quick Start)은 이 명령들을 실제 맥락과 함께 소개합니다. 이 절은 cargo-furiosa-opt의 전체 명령 참조(command reference)입니다. 컴파일(compile), CPU, NPU, 스케줄(schedule) 결과의 의미는 커널 검증(Kernel Validation)을 참고하세요.

사용법(Usage)

text
cargo furiosa-opt <command> [args]
cargo furiosa-opt compile [FILTER]... [options]

첫 번째 형태는 cargo 전달 호출(passthrough)입니다. <command>에는 build, test, run 등 cargo 하위 명령(subcommand)을 쓰며, [args]는 수정 없이 cargo에 전달되어 NPU용으로 컴파일됩니다. 두 번째 형태는 커널(kernel)을 직접 컴파일합니다. 직접 컴파일(Direct compilation)을 참고하세요.

일반적인 cargo build·cargo test·cargo run은 CPU 빌드(build)입니다. 커널(kernel)이 호스트(host)에서 실행되며 NPU 하드웨어나 SDK가 필요하지 않습니다.

래퍼가 추가하는 기능(What the wrapper adds)

일반 cargo와 비교하면 cargo furiosa-opt는 cargo 호출 전후에 두 가지를 추가합니다.

  • NPU를 대상으로 합니다(targets the NPU). 커널(kernel)이 실제 하드웨어(hardware)에서 실행됩니다. 물리적인 NPU와 Furiosa SDK가 필요합니다.
  • 필요한 커널을 자동으로 빌드합니다(automatic kernel builds). cargo 빌드 전에 필요한 #[device] 함수를 컴파일하여, 결과 실행 파일(binary)이 실행 시점(runtime)에 이를 적재(load)할 수 있게 합니다. 자동 커널 빌드를 참고하세요.

작업 중심의 개요는 빠른 시작: 커널 최적화 도구(Quick Start: Kernel Optimizer)를 참고하세요.

자동 커널 빌드(Automatic kernel builds)

cargo furiosa-opt는 cargo에 제어를 넘기기 전에 커널 사전 컴파일(kernel pre-compilation)을 수행합니다. 필요한 경우에만 실행되며, 다음 두 조건을 모두 만족하지 않으면 생략됩니다.

  • cargo 하위 명령(subcommand)이 코드를 빌드하거나 실행하는 명령(build, check, test, run, bench, doc)입니다.
  • 호출이 -h·--help 도움말 조회가 아닙니다.

사전 단계(pre-step)는 실행될 때도 해당 빌드에 실제로 필요한 커널(kernel)만 컴파일합니다.

  • -p·--package와 워크스페이스(workspace) 선택을 반영하여 cargo의 유닛 그래프(unit graph)를 읽고 커널 패키지(kernel package)를 찾습니다. Cargo.toml에 [package.metadata.furiosa-opt]가 선언된 크레이트(crate)가 커널 패키지입니다.
  • 명령이 테스트(test)·예제(example)·실행 파일(binary)처럼 특정 실행 대상(runnable target)으로 결정되면, 컴파일러(compiler)는 각 대상을 조사하여 그곳에서 도달 가능한(reachable) #[device] 함수만 컴파일합니다.
  • 그 밖의 경우에는 선택한 패키지(package)의 모든 커널(kernel)을 컴파일합니다.

컴파일 결과는 커널(kernel)별로 캐시(cache)하므로, 다음 실행에서 변경되지 않은 커널을 다시 컴파일하지 않습니다. 산출물(artifact)은 출력 디렉터리(output directory)에 저장됩니다(FURIOSA_OPT_OUT_DIR 참고).

직접 컴파일(Direct compilation): cargo furiosa-opt compile

cargo furiosa-opt compile은 cargo 전달 호출(passthrough) 없이 #[device] 함수를 직접 컴파일합니다.

bash
# 모든 커널 패키지(kernel package)의 모든 #[device] 함수를 컴파일합니다.
cargo furiosa-opt compile

# 패키지(package) 하나에서 필터(filter)에 맞는 함수만 컴파일합니다.
cargo furiosa-opt compile transpose_simple -p my_kernels

# 함수 하나를 컴파일하고 스케줄 뷰어(Schedule Viewer)용 스케줄을 덤프합니다.
cargo furiosa-opt compile transpose::transpose_simple \
  --dump-schedule schedule.json

[FILTER]...

컴파일할 #[device] 함수 집합(set)을 지정합니다. 필터(filter)는 #[device] 함수의 전체 경로(full path, abc::def::foo)에 대한 부분 문자열(substring)로 비교합니다. 하나의 필터라도 일치하면 해당 함수를 컴파일합니다. 생략하면 모든 장치 함수(device function)를 컴파일합니다.

-p, --package name

컴파일(compilation)을 지정한 커널 패키지(kernel package)로 제한합니다. 여러 패키지를 선택하려면 이 옵션(option)을 반복해서 쓸 수 있습니다. 생략하면 모든 커널 패키지를 컴파일합니다.

--message-format format

컴파일러(compiler)에 전달할 진단 형식(diagnostic format, 예: json)입니다. 도구가 커널 컴파일 실패 진단을 기계적으로 해석(machine-parse)할 수 있게 합니다.

--dump-visa file

중간 vISA(intermediate vISA)를 파일로 덤프(dump)합니다. 커널(kernel) 하나를 컴파일할 때만 사용해야 합니다.

--dump-schedule file

스케줄 뷰어(Schedule Viewer)용 스케줄(schedule)을 JSON으로 덤프합니다. 커널(kernel) 하나를 컴파일할 때만 사용해야 합니다.

환경 변수(Environment variables)

FURIOSA_OPT_OUT_DIR

커널 출력 디렉터리(kernel output directory)입니다. 기본값은 <workspace target>/furiosa-opt/kernel입니다.
