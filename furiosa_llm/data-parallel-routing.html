Data-Parallel Routing#

data_parallel_size가 1보다 크면 Furiosa-LLM은 같은 모델의 데이터 병렬(DP) 복제본을 여러 개 실행합니다. DP 라우터는 새 요청을 어느 복제본에 보낼지 결정합니다.

기본 정책은 점수 기반 DP 라우팅입니다. 요청의 프롬프트를 많이 캐시한 복제본을 우선하되, 이미 많은 토큰을 처리 중인 복제본에 요청이 몰리지 않도록 합니다.

How Scoring Works#

라우터는 실행 중인 각 DP 복제본에 대해 두 지표를 계산합니다.

  • 프롬프트 접두사 일치율(Prefix locality)은 새 프롬프트에서 해당 복제본의 Prefix Cache와 일치하는 부분이 차지하는 비율입니다.

  • 토큰 부하(Load pressure)는 해당 복제본에 배정된 활성 컨텍스트 토큰 수입니다. 프롬프트 토큰은 요청이 배정될 때 집계하고, 생성 토큰은 요청이 끝날 때까지 부하에 반영합니다.

라우터는 부하가 낮을수록 높은 부하 점수를 부여합니다. 이 점수와 접두사 일치 점수를 가중합해 최종 점수가 가장 높은 복제본에 요청을 보냅니다. 동점이면 실행 중인 복제본 가운데 첫 번째를 선택합니다.

final_score = prefix_weight * prefix_score + load_weight * load_score

라우터는 가상 Prefix Cache로 각 복제본의 KV Cache 이벤트를 추적해 접두사 일치율을 계산합니다. 캐시는 복제본별로 유지되므로, 지금 요청을 어디에 보내느냐에 따라 다음 요청이 캐시를 재사용할 수 있는 위치가 달라집니다.

라우팅 정책#

--data-parallel-routing-policy로 라우팅 정책을 선택합니다.

정책

행동

scoring

기본 정책입니다. 프롬프트 접두사 일치율과 토큰 부하를 함께 고려합니다.

round-robin

DP 복제본에 순서대로 요청을 보냅니다. 단순한 벤치마크나 캐시를 고려하지 않는 라우팅에 사용할 수 있습니다.

점수 프로파일#

scoring 정책에서 --data-parallel-scoring-profile로 접두사 일치와 부하 사이의 가중치를 조정합니다.

프로파일

접두사 일치 / 부하 가중치

사용할 때

balanced

0.55 / 0.45

기본값입니다. 여러 유형의 요청이 섞여 있거나 요청 특성을 아직 모를 때 적합합니다.

locality

0.90 / 0.10

시스템 프롬프트가 반복되는 요청, 여러 턴의 대화, 공통 문서를 프롬프트 앞부분에 넣는 RAG 요청에 적합합니다.

load

0.10 / 0.90

공통 접두사가 드물거나 부하를 고르게 분산하는 것이 중요할 때 적합합니다. 긴 시스템 프롬프트나 문서 접두사의 재사용을 우선하면 한 복제본에 부하가 몰릴 수 있습니다.

Prefix Caching을 끄면 접두사 일치율을 활용할 수 없으므로 Furiosa-LLM은 load 프로파일을 사용합니다. 이전 prefix-aware 프로파일에 해당하는 설정은 locality입니다.

구성#

기본 설정은 점수 기반 라우팅과 balanced 프로파일입니다.

furiosa-llm serve <model> --data-parallel-size 2

Prefix Cache 재사용을 더 우선하는 설정입니다.

furiosa-llm serve <model> \
  --data-parallel-size 2 \
  --data-parallel-routing-policy scoring \
  --data-parallel-scoring-profile locality

복제본을 순서대로 사용하는 설정입니다.

furiosa-llm serve <model> \
  --data-parallel-size 2 \
  --data-parallel-routing-policy round-robin

점수 프로파일은 scoring 정책에 적용됩니다. --data-parallel-routing-policy round-robin을 쓸 때는 점수 프로파일을 기본값으로 두세요.

Python API#

Python에서는 같은 설정을 SchedulerConfig에 전달합니다.

from furiosa_llm import LLM
from furiosa_llm.metadata.config_types import (
    DataParallelRoutingPolicy,
    DataParallelScoringProfile,
    SchedulerConfig,
)

scheduler_config = SchedulerConfig(
    data_parallel_routing_policy=DataParallelRoutingPolicy.SCORING,
    data_parallel_scoring_profile=DataParallelScoringProfile.LOCALITY,
)

with LLM(
    "furiosa-ai/Qwen3-4B-FP8",
    data_parallel_size=2,
    scheduler_config=scheduler_config,
) as llm:
    outputs = llm.generate(["Hello"])

운영 참고 사항#

  • DP 라우팅은 단일 Furiosa-LLM 프로세스 안에서 이루어집니다. 여러 모델 서버 Pod 사이에 요청을 분산하려면 llm-d를 참고하세요.

  • 점수 기반 라우팅은 Prefix Caching을 켰을 때 가장 효과적입니다. NPU 캐시는 Prefix Caching, 선택적으로 사용하는 호스트 캐시는 계층형 Prefix Caching에서 설명합니다.

  • 데이터 병렬 처리의 배경은 모델 병렬화(Model Parallelism)를 참고하세요.
