OpenAI 호환 서버#

Furiosa-LLM은 단일 모델을 호스팅하고 OpenAI 호환 채팅, 완료, 응답 및 임베딩 API를 제공하는 OpenAI 호환 서버를 제공합니다. 또한, 추가적인 풀링 API 지원도 제공합니다.

서버를 시작하려면, furiosa-llm serve에 Hugging Face 모델 ID 또는 로컬 모델 디렉토리를 전달합니다. FXB는 모델과 함께 묶여 있어야 하거나, 로컬 FXB 캐시에서 사용하거나, --fxb: 옵션을 사용하여 명시적으로 선택할 수 있습니다.

furiosa-llm serve [MODEL_ID_OR_PATH]

경고

본 문서는 Furiosa SDK 2026.4.1을 기반으로 작성되었습니다. 본 문서에 설명된 기능 및 API는 향후 변경될 수 있습니다. (Furiosa SDK 2026.4.1)

지원되는 API#

현재 다음과 같은 API를 지원합니다:

  • 완결 API (/v1/completions)

    • 텍스트 생성 모델에 적용됩니다.

  • 챗 완결 API (/v1/chat/completions)

    • 채팅 템플릿을 사용하는 텍스트 생성 모델에 적용 가능합니다. (텍스트 생성 모델, 채팅 템플릿)

  • 응답 API (/v1/responses) — OpenResponses 사양

    • 채팅 템플릿을 사용하는 텍스트 생성 모델에 적용 가능합니다. (텍스트 생성 모델, 채팅 템플릿)

    • 자세한 내용은 응답 API를 참조하십시오.

  • 임베딩 API (/v1/embeddings)

    • 임베딩 모델에 적용 가능합니다.

또한, pooling 모델에 대한 vLLM 호환 API는 다음과 같습니다:

  • 점수 API (/score, /v1/score)

    • Qwen3-Reranker 및 BGE-reranker-v2-m3 모델을 지원합니다.

  • 재순서 API (/rerank, /v1/rerank, /v2/rerank)

    • Qwen3-Reranker 및 BGE-reranker-v2-m3 모델을 지원합니다.

필수 구성 요소#

OpenAI와 호환되는 서버를 사용하려면 다음이 필요합니다:

  • 설치되는 예비 부품이있는 시스템 (see) 사전 설치)

  • Furiosa-LLM 설치

  • A Hugging Face 액세스 token 게이트된 모델

  • FXB 호환 모델, 로컬 캐시에서 사용할 수, 또는 공급 --fxb ( 참조) C Furiosa 실행 파일 묶음 (FXB))

  • 챗 애플리케이션용 챗 템플릿 (선택 사항)

OpenAI API 사용#

서버가 실행되면, HTTP 클라이언트를 사용하여 상호 작용할 수 있습니다. 다음 예제에서 확인할 수 있습니다:

curl http://localhost:8000/v1/chat/completions \
    -H "Content-Type: application/json" \
    -d '{
    "model": "EMPTY",
    "messages": [{"role": "user", "content": "What is the capital of France?"}]
    }' \
    | python -m json.tool

OpenAI 클라이언트를 사용하여 서버와 상호 작용할 수도 있습니다. OpenAI 클라이언트를 사용하려면 먼저 openai 패키지를 설치해야 합니다:

pip install openai

다음은 OpenAI 클라이언트를 사용하여 스트리밍 모드로 chat.completions API를 호출하는 예시입니다:

import asyncio
import os
from openai import AsyncOpenAI

base_url = os.getenv("OPENAI_BASE_URL", "http://localhost:8000/v1")
api_key = os.getenv("OPENAI_API_KEY", "EMPTY")

client = AsyncOpenAI(api_key=api_key, base_url=base_url)

async def run():
    stream_chat_completion = await client.chat.completions.create(
        model="EMPTY",
        messages=[{"role": "user", "content": "What is the capital of France?"}],
        stream=True,
    )

    async for chunk in stream_chat_completion:
        print(chunk.choices[0].delta.content or "", end="", flush=True)


if __name__ == "__main__":
    asyncio.run(run())

호환 가능한 비전-언어 모델을 사용하여 이미지 입력을 사용하는 경우, "Vision-Language Models"를 참조하십시오. Chat Completions 요청은 media_io_kwargs 및 mm_processor_kwargs를 요청 본체 (또는 OpenAI 클라이언트의 extra_body)를 통해 받습니다. "Multimodal Options"에서 서버 기본값, 요청 오버라이드 및 모델별 유효성 검사에 대한 정보를 확인하십시오.

컨텍스트 길이 제한, 디코딩 배치, NPU 샘플링 및 기타 성능 설정에 대한 정보는 "Performance Optimization"에서 확인하십시오.

챗 템플릿#

챗 애플리케이션에서 언어 모델을 사용하려면, 모델에 입력으로 제공할 구조화된 문자열을 준비해야 합니다. 이는 모델이 대화의 맥락을 이해하고, 특히 화자의 역할(예: "사용자" 및 "보조")과 메시지 내용을 파악하는 데 필수적입니다. 다른 모델들이 서로 다른 토큰화 방법을 필요로 하는 것처럼, 챗 모델들도 서로 다른 입력 형식을 요구합니다. 따라서 챗 템플릿이 필요합니다.

Furiosa-LLM은 Hugging Face Transformers와 유사하게, Jinja2 템플릿 엔진 기반의 챗 템플릿을 지원합니다. 만약 모델의 토크나이저에 내장된 챗 템플릿이 있다면, furiosa-llm serve는 자동으로 이를 사용합니다. 하지만 토크나이저에 내장된 템플릿이 없거나, 기본값을 덮어쓰고 싶다면 --chat-template 파라미터를 사용하여 지정할 수 있습니다.

참고로, Llama 3.1 모델 카드에 잘 구성된 챗 템플릿의 예시를 참고하십시오.

사용자 정의 챗 템플릿으로 서버를 시작하려면 다음 명령을 사용하십시오:

furiosa-llm serve [MODEL_ID_OR_PATH] --chat-template [CHAT_TEMPLATE_PATH]

도구 호출 지원#

도구 호출 (또는 함수 호출) 기능은 모델이 외부 도구 및 API와 상호 작용할 수 있도록 합니다. Furiosa-LLM은 이러한 기능을 갖춘 모델에 대한 도구 호출을 지원합니다.

도구 호출을 활성화하려면 서버를 시작할 때 --tool-call-parser 옵션을 사용하여 적절한 파서를 지정하십시오. 예를 들어, EXAONE-4.0 모델에 도구 호출을 활성화하려면 다음과 같이 사용하십시오:

furiosa-llm serve furiosa-ai/EXAONE-4.0-32B-FP8 --enable-auto-tool-choice --tool-call-parser hermes

도구 호출을 사용하려면 tools 및 tool_choice 매개변수를 지정하십시오. 다음은 예시입니다:

import json
import os
from openai import OpenAI

base_url = os.getenv("OPENAI_BASE_URL", "http://localhost:8000/v1")
api_key = os.getenv("OPENAI_API_KEY", "EMPTY")
client = OpenAI(base_url=base_url, api_key=api_key)

def get_weather(location: str, unit: str):
    return f"Getting the weather for {location} in {unit}..."
tool_functions = {"get_weather": get_weather}

tools = [{
    "type": "function",
    "function": {
        "name": "get_weather",
        "description": "Get the current weather in a given location",
        "parameters": {
            "type": "object",
            "properties": {
                "location": {"type": "string", "description": "City and state, e.g., 'San Francisco, CA'"},
                "unit": {"type": "string", "enum": ["celsius", "fahrenheit"]}
            },
            "required": ["location", "unit"]
        }
    }
}]

response = client.chat.completions.create(
    model=client.models.list().data[0].id,
    messages=[{"role": "user", "content": "What's the weather like in San Francisco?"}],
    tools=tools,
    tool_choice="required",
)

tool_call = response.choices[0].message.tool_calls[0].function
print(f"Function called: {tool_call.name}")
print(f"Arguments: {tool_call.arguments}")
assert tool_call.name == "get_weather", f"Expected 'get_weather' but got '{tool_call.name}'"
print(f"Result: {get_weather(**json.loads(tool_call.arguments))}")

예상되는 출력은 다음과 같습니다.

Function called: get_weather
Arguments: {"location": "San Francisco, CA", "unit": "fahrenheit"}
Result: Getting the weather for San Francisco, CA in fahrenheit...

도구 호출 파서, 도구 선택 옵션 및 추가 예에 대한 자세한 정보는 "Tool Calling"을 참조하십시오.

추론 지원#

Furiosa-LLM은 Deepseek R1과 같이 추론 능력을 갖춘 모델을 지원합니다. 이러한 모델은 먼저 추론 단계를 수행한 다음 최종 답변을 제공하는 구조화된 접근 방식을 따릅니다.

추론 과정은 다음과 같은 순서를 따릅니다:

  1. 모델별 시작 추론 토큰은 챗 템플릿을 통해 입력 프롬프트에 추가됩니다.

  2. 모델은 자체적으로 추론 과정을 수행합니다.

  3. 추론이 완료되면, 모델은 추론 종료 토큰 다음에 최종 답변을 출력합니다.

시작 및 종료 추론 토큰은 모델마다 다르므로, 모델별로 다른 추론 파서를 지원합니다. 지원되는 추론 파서를 확인하려면 --reasoning-parser 옵션에 대한 도움말 텍스트를 참조하십시오.

Qwen3 시리즈에 추론 기능을 갖춘 서버를 실행하려면 다음 예제 명령을 실행하십시오:

furiosa-llm serve furiosa-ai/Qwen3-32B-FP8 --reasoning-parser qwen3

추론 내용을 다음 응답 필드를 통해 접근할 수 있습니다:

  • response.choices[].message.reasoning

  • response.choices[].delta.reasoning

다음 예제는 reasoning 콘텐츠에 접근하는 방법을 보여줍니다:

import os
from openai import OpenAI

base_url = os.getenv("OPENAI_BASE_URL", "http://localhost:8000/v1")
api_key = os.getenv("OPENAI_API_KEY", "EMPTY")

client = OpenAI(api_key=api_key, base_url=base_url)


messages = [{"role": "user", "content": "9.11 and 9.8, which is greater?"}]
response = client.chat.completions.create(
    model=client.models.list().data[0].id,
    messages=messages,
)

message = response.choices[0].message
# The reasoning parser splits the chain-of-thought into a separate `reasoning`
# field, kept out of `content`.
assert message.reasoning, "expected a non-empty reasoning field"
print("Reasoning:", message.reasoning)
print("Answer:", message.content)

참고

reasoning 필드는 Furiosa-LLM에 특정한 확장 기능이며, 표준 OpenAI API의 일부가 아닙니다. 이 필드는 reasoning 콘텐츠를 포함하는 응답에서만 나타나며, reasoning 콘텐츠가 없는 응답에서 이 필드를 접근하려고 하면 AttributeError가 발생합니다.

중지 문자열 응답 필드#

Chat Completions 및 Completions의 각 응답 선택에는 stop_reason 필드가 있습니다. 이는 OpenAI 호환 응답 스키마에 추가된 Furiosa-LLM 확장 기능입니다. 설정된 중단 문자열이 생성 종료를 유발하면, 최종 선택 (또는 스트리밍된 덩어리의 최종 선택)의 finish_reason은 "stop"으로, stop_reason은 일치하는 문자열로 설정됩니다. 이전 스트리밍된 덩어리의 경우 및 생성 종료가 다른 이유로 발생한 경우 stop_reason은 null 값으로 설정됩니다.

원시 JSON 응답에는 항상 해당 필드가 포함됩니다. OpenAI Python SDK 응답 모델 중 OpenAI Embeddings API에 선언되지 않은 확장 기능을 choice.model_extra["stop_reason"]를 통해 노출합니다.

추가 엔드포인트#

위 API 외에도 Furiosa-LLM 서버는 다음과 같은 엔드포인트를 지원합니다.

모델 엔드포인트#

Models API를 사용하면 OpenAI의 Models API와 호환되는 엔드포인트를 통해 사용 가능한 모델에 대한 정보를 가져올 수 있습니다. 다음 엔드포인트가 지원됩니다:

  • GET /v1/models

  • GET /v1/models/{model_id}

이러한 엔드포인트를 OpenAI 클라이언트의 models.list() 및 models.retrieve() 메서드를 사용하여 액세스할 수 있습니다.

응답에는 OpenAI에서 정의한 표준 모델 객체와 함께, 다음과 같은 Furiosa-LLM에 특화된 확장 정보가 포함됩니다:

  • artifact_id: 로드된 FXB 파일에 대한 고유 식별자.

  • max_prompt_len: 허용되는 최대 입력 프롬프트 길이.

  • max_context_len: 전체 컨텍스트 윈도우의 최대 허용 길이.

  • runtime_config: 모델 실행 구성 매개변수, 여기에는 버킷 사양도 포함됩니다.

토크나이저 API#

토크나이저 API는 HuggingFace 스타일의 토크나이저를 간단하게 래핑한 것입니다. 모든 모델 유형에서 사용 가능하며, 세 가지 엔드포인트를 포함합니다:

  • POST /tokenize : 호출에 대응 tokenizer.encode(). 이는 prompt 문자열 (completion-style) 또는 messages 배열 (chat-style, 토큰화하기 전에 채팅 템플릿을 적용).

  • POST /detokenize는 tokenizer.decode()를 호출하는 것과 동일합니다.

  • GET /tokenizer_info는 토크나이저에 대한 메타데이터를 반환합니다. 여기에는 클래스 이름과 구성이 포함됩니다.

Chat-style /tokenize 요청이 제공된 정보를 유효성 검사하는 경우 mm_processor_kwargs 로드 모델의 스키마를 사용하여; 참조 멀티모달 옵션. Tokenization는 채팅 템플릿을 적용하고 이미지 입력을 fetch 할 수 있지만 이미지 프로세서를 실행하거나 비전 토큰을 확장하지 않습니다. 그것은 적용되지 않습니다 LLM/CLI 프로세서 기본, 무시 media_io_kwargs 요청 덮어쓰기 및 --media-io-kwargs 기본값. 이미지 fetching은 fetcher의 기본 타임아웃과 구성된 local-path, 도메인 및 image-count 제한을 사용합니다. 반환된 카운트는 템플릿 토큰을 설명하며 최종 확장된 멀티모드 prompt 길이가 아닙니다.

OpenAI 호환 서버 컨테이너 실행#

Furiosa-LLM은 더 빠른 배포를 위한 컨테이너화된 서버를 제공합니다. 다음은 Furiosa-LLM 서버를 Docker 컨테이너에서 실행하는 예시입니다 (Hugging Face Hub 토큰으로 $HF_TOKEN을 대체하십시오):

docker pull furiosaai/furiosa-llm:latest

docker run -it --rm \
  --device /dev/rngd:/dev/rngd \
  --security-opt seccomp=unconfined \
  --env HF_TOKEN=$HF_TOKEN \
  -v $HOME/.cache/huggingface:/root/.cache/huggingface \
  -p 8000:8000 \
  furiosaai/furiosa-llm:latest \
  serve furiosa-ai/Qwen2.5-0.5B-Instruct

또한 서버에 추가 옵션을 지정하고 -v $HOME/.cache/huggingface:/root/.cache/huggingface를 Hugging Face 캐시 디렉토리의 경로로 대체할 수 있습니다.
