Furiosa 실행 가능한 묶음 (FXB)#

Furiosa-LLM에서 제공되는 모델은 두 부분으로 구성됩니다: Hugging Face 형식의 모델 자산과 Furiosa NPU에서 해당 자산을 실행하는 컴파일된 프로그램입니다. 모델 자산은 구성, 토크나이저 및 가중치를 제공하는 반면, Furiosa 실행 가능한 묶음 (FXB)은 컴파일된 커널을 제공합니다. 실행 가능한 배포에는 두 부분 모두 필요합니다.

Furiosa-LLM은 FXB 파일을 필요로 합니다. 왜냐하면 NPU에서 실행되는 코드는 모델 아키텍처 및 실행 구성에 맞게 미리 컴파일되어 있으며, 그 결과 .fxb 파일은 컴파일된 바이너리와 모델을 로드하고 실행하는 데 필요한 메타데이터를 포함하는 단일 아카이브입니다.

컴파일된 프로그램을 모델 자산과 분리하면 다음과 같은 이점이 있습니다:

  • 모델은 서버 호스트에서 커널을 컴파일하지 않고 시작할 수 있습니다.

  • FXB 파일을 모델과 함께 복사, 캐싱 또는 배포할 수 있습니다.

  • 동일한 FXB 파일을 재사용하여 모델의 가중치만 변경된 경우 호환되는 모델도 동일하게 사용할 수 있습니다.

FXB 파일에는 모델 가중치가 포함되어 있지 않으며, Hugging Face 모델 디렉토리를 대체하지 않습니다. Furiosa-LLM은 여전히 해당 디렉토리 또는 저장소에서 구성, 토크나이저 및 가중치를 읽습니다.

이 페이지는 FXB 파일을 구축하여 모델 자산을 제공하고, 호환 가능한 모델과 함께 재사용하는 모델의 전체 라이프사이클을 다룹니다. 자세한 명령어 동작, 번들 메타데이터, 그리고 호환성 규칙은 다음 섹션에서 설명합니다.

팁

FuriosaAI는 대중적인 모형을 위한 pre-compiled FXB 뭉치의 세트를 발행합니다 Hugging Face 허브 - FuriosaAI 조직. 이 중 하나를 다운로드하고 아래의 작업 흐름과 호환 모델에 대해 제공합니다.

설치#

FXB는 번들을 구축, 배포, 그리고 로드하는 데 필요한 .fxb 번들 형식과 프레임워크를 포함합니다. Furiosa-LLM은 fxb CLI를 통해 이러한 라이프사이클을 노출합니다.

fxb CLI는 Furiosa-LLM 패키지에 포함되어 있으므로 별도로 설치할 필요가 없습니다. Furiosa-LLM을 아직 설치하지 않았다면, "Furiosa-LLM 설치" 섹션을 참조하십시오:

pip install --upgrade pip setuptools wheel uv
uv pip install --upgrade --torch-backend=auto furiosa-llm

CLI가 사용 가능한지 확인하십시오:

fxb --help

fxb CLI는 FXB의 전체 생명주기를 관리합니다: 빌드, 다운로드, 캐싱, 호환성 검사, 그리고 검사. 캐싱 및 검사 하위 명령어는 furiosa-llm serve가 서비스 시간에 참조하는 동일한 로컬 캐시를 사용합니다.

모델용 FXB 빌드#

필수 구성 요소#

FXB 빌드는 AArch64 GNU C 크로스 컴파일러와 대상 C 라이브러리 헤더가 필요합니다. Debian 또는 Ubuntu에서는 다음 명령으로 필요한 패키지를 설치합니다:

sudo apt-get update
sudo apt-get install --no-install-recommends gcc-aarch64-linux-gnu libc6-dev-arm64-cross

참고

현재 RHEL 또는 RPM 기반 배포판에서는 FXB 빌드를 지원하지 않습니다. EPEL 크로스 컴파일러는 furiosa-tcc가 필요로 하는 AArch64 glibc 유저스페이스 sysroot를 제공하지 않습니다.

fxb build 명령을 사용하여 모델을 .fxb 묶음으로 컴파일합니다:

fxb build Qwen/Qwen3-8B-FP8 qwen3-8b-fp8

첫 번째 인자는 Hugging Face 모델 ID 또는 로컬 경로입니다 (경로는 "." 또는 "/"로 시작해야 합니다). 두 번째 인자는 출력 경로이며, 경로에 확장자가 없으면 .fxb 확장자가 자동으로 추가됩니다. 위의 명령은 qwen3-8b-fp8.fxb를 생성합니다.

컴파일 없이 해결된 구성 및 버킷 계획을 미리 확인하려면 --dry-run 옵션을 사용합니다:

fxb build Qwen/Qwen3-8B-FP8 qwen3-8b-fp8 --dry-run

일반 옵션:

  • -tp/--tensor-parallel-size — 텐서 병렬 그룹당 PE(Processing Element)의 개수 (기본값: 모델 설정).

  • -pp/--pipeline-parallel-size — 파이프라인 병렬 크기 (기본값: 1).

  • --max-model-len — 버킷 선택을 위해 모델의 최대 컨텍스트 길이를 재정의합니다. 이는 어떤 부분이 번들에 컴파일되는지 결정합니다. furiosa-llm serve는 동일한 이름의 옵션을 사용하여 서비스 시간에만 제한할 수 있습니다 (컨텍스트 길이 제한 참조).

  • -O/--optim-level — 버킷 필터링 최적화 수준: O0 (최소), O1 (반), O2 (1/4), O3 (전체, 기본값).

  • --convert - 주변 건축물과 모델에 대한 작업 override: embed 다시 쓰기 *ForCausalLM → *Model; score/classify → *ForSequenceClassification (전기: auto, i.e. 아키텍처를 유지 config.json).

건물 후에, 캐시에 있는 뭉치를 이렇게 등록하십시오 fxb check and furiosa-llm serve 찾을 수 있습니다:

fxb add ./qwen3-8b-fp8.fxb

프로덕션 빌드에 대한 권장 사항은 "최적 사용법"을 참조하십시오.

Furiosa-LLM에서 실행 가능한 모델#

Furiosa-LLM은 모델 자산과 FXB 파일을 함께 로드합니다. 모델 자산은 Hugging Face Hub 디렉토리 형식을 따라야 하며, config.json, 토크나이저 파일, 모델 가중치와 같은 파일을 포함해야 합니다. 모델은 다음 두 가지 형태로 배포하거나 호출할 수 있습니다.

FXB 파일이 포함된 모델 디렉토리#

모델 구성, 토크나이저, 가중치와 함께 Hugging Face 모델 디렉토리에 호환되는 .fxb 파일을 배치하십시오:

my-model/
  config.json
  tokenizer.json
  model-00001-of-00002.safetensors
  model-00002-of-00002.safetensors
  model.safetensors.index.json
  my-model.fxb

디렉토리는 로컬에 저장하거나 Hugging Face Hub에 저장소로 게시할 수 있습니다. Furiosa-LLM은 묶인 FXB를 자동으로 감지합니다:

furiosa-llm serve ./my-model

furiosa-llm serve furiosa-ai/Qwen3-8B-FP8

이 형식은 자체 포함된 모델 저장소를 배포하는 데 편리합니다.

FXB를 직접 지정#

모델 자산과 FXB를 별도의 위치에 보관하고 --fxb 옵션을 사용하여 묶음을 선택합니다.

furiosa-llm serve Qwen/Qwen3-8B-FP8 --fxb ./qwen3-8b-fp8.fxb

첫 번째 인수는 여전히 Furiosa-LLM이 구성, 토크나이저 및 가중치를 로드하는 Hugging Face 모델 저장소 또는 로컬 디렉토리를 식별합니다. --fxb는 컴파일된 묶음만 선택합니다. 이 형식은 새로 빌드된 FXB를 테스트하거나 특정 묶음을 고정하거나 여러 호환 가능한 모델에서 하나의 FXB를 재사용하는 데 유용합니다.

Python API는 동일한 분리를 제공합니다:

from furiosa_llm import LLM

llm = LLM("Qwen/Qwen3-8B-FP8", fxb="./qwen3-8b-fp8.fxb")

로컬 FXB 캐시를 통해 자동 발견을 위해, 참조 호환 캐시 FXB와 모델 제공.

FXB 호환성#

FXB 호환성은 아키텍처 지문(architecture fingerprint)에 의해 결정됩니다. 이 지문에는 모델 아키텍처와 커널 생성에 영향을 미치는 설정 파일(config.json)의 필드, 예를 들어 은닉 차원(hidden dimensions), 어텐션 설정(attention configuration), 믹스드 전문가 설정(mixture-of-experts settings), 양자화 형식(quantization format) 등이 포함됩니다. 모델 가중치 자체는 지문에 포함되지 않습니다.

결과적으로, 다음 조건 중 하나가 충족되면 기존 FXB를 재사용할 수 있습니다:

  • 모델을 미세 조정(fine-tune)하면서 커널에 영향을 미치는 설정을 변경하지 않는 경우;

  • 아키텍처와 지문 필드가 동일하게 유지되는 동안 가중치를 업데이트하는 경우; 또는

  • 또 다른 모델 저장소는 동일한 아키텍처 지문(architecture fingerprint)을 가지고 있습니다.

컴파일된 커널(kernels)에 변경 사항이 발생하면 새로운 FXB가 필요합니다. 예를 들어 아키텍처, 모델 크기, 어텐션(attention) 또는 전문가 구성(expert configuration), 양자화(quantization) 형식 또는 다른 지문 필드를 변경하는 경우입니다. 호환성 매칭(compatibility matching)은 엄격하며, 구성이 변경된 경우에도 미세 조정된 모델이 자동으로 호환되지 않습니다.

아키텍처 호환성은 유일한 배포 제약 조건이 아닙니다. FXB는 설치된 Furiosa 소프트웨어 버전과 의도된 텐서-병렬(tensor-parallel) 및 컨텍스트 길이(context-length) 구성에 적합해야 합니다. 정확한 매칭 규칙 및 호환성 제한에 대한 Fingerprint and Compatibility를 참조하십시오.

호환된 캐시된 FXB를 사용하여 모델 제공#

모델 자체의 Hugging Face 저장소는 .fxb 파일을 제공하지 않을 수 있습니다. 이 경우 Furiosa-LLM은 지문(fingerprint)과 호환되는 묶음을 로컬 캐시에서 재사용하여 모델을 제공할 수 있습니다(Fingerprint and Compatibility에서 호환성이 어떻게 결정되는지 참조). 특히 모델 가중치가 업데이트되거나, 미세 조정된 모델 또는 지원되는 모델의 변형을 제공할 때 유용합니다. 아키텍처 지문이 변경되지 않는 한, 가중치 업데이트 또는 변형에 대해 매번 새 FXB를 컴파일하는 대신 기존 FXB를 재사용할 수 있습니다. 워크플로우는 다음과 같습니다:

  1. 캐시에 호환되는 FXB를 가져오기 — Hub에서 다운로드하거나, 디스크에 이미 있는 FXB를 추가합니다.

  2. 캐시된 묶음이 사용하려는 모델과 호환되는지 확인하십시오.

  3. 모델을 실행합니다. Furiosa-LLM은 자동으로 캐시된 묶음을 찾아서 사용합니다.

아래 예시는 furiosa-ai/Qwen3-8B-FP8 묶음을 재사용하여 Qwen/Qwen3-8B-FP8 (FXB 파일이 없는 모델)을 실행합니다. 이 묶음은 동일한 "fingerprint"를 가지고 있습니다.

1단계 — 캐시에 호환 가능한 FXB 파일을 추가합니다.#

Hub에서 게시된 묶음을 다운로드합니다:

fxb download furiosa-ai/Qwen3-8B-FP8

이 명령어는 저장소의 모든 .fxb 파일을 캐시에 가져오고, 각 파일이 저장된 위치를 출력합니다. 다운로드를 제한하려면 --file 옵션을 사용하고, 특정 브랜치/태그/커밋을 선택하려면 --revision 옵션을 사용하며, 캐시된 묶음을 다시 가져오려면 --force 옵션을 사용합니다.

또는, 이전 옵션 또는 설정을 등록합니다. .fxb 당신은 이미 디스크에 있다 — 예를 들어 하나만 내장 (see) FXB를 특정 모델에 맞게 구성하는 방법) 또는 다른 머신에서 복사된 경우:

fxb add ./qwen3-8b-fp8.fxb

add는 파일을 캐시에 복사하고, 번들의 매니페스트에서 이름을 표준화하여, out.fxb와 같은 파일이 다운로드된 번들과 일치하도록 합니다.

2단계 — 호환성 확인#

먼저, fxb cache ls 명령어를 사용하여 번들이 캐시에 제대로 추가되었는지 확인합니다:

fxb cache ls

REPO ID                  ARCH               SIZE     FuriosaIR           FURIOSA-LLM         FXB FILE
-----------------------  -----------------  -------  ------------------  ------------------  -----------------------------------
furiosa-ai/Qwen3-8B-FP8  Qwen3ForCausalLM   4.1 GiB  2026.3.0 (a1b2c3)   2026.3.0 (d4e5f6)   Qwen3-8B-FP8-<npu>-<rt>-<ts>.fxb

1 file(s), 4.1 GiB

A bundle added with fxb add appears here under the local repo id. Now confirm it is compatible with the target model. check reads the target repository’s model configuration and lists every cached FXB whose fingerprint matches:

fxb check Qwen/Qwen3-8B-FP8

Target: Qwen/Qwen3-8B-FP8  (Qwen3ForCausalLM)
  hidden_size=4096 intermediate_size=12288 num_attention_heads=32 vocab_size=151936 quant_method=fp8

Compatible cached FXB (1):
     REPO ID                  SIZE       FuriosaIR              FXB FILE
---  -----------------------  ---------  ---------------------  -----------------------------------------------
✔    furiosa-ai/Qwen3-8B-FP8  4.1 GiB    2026.3.0 (a1b2c3) — match  Qwen3-8B-FP8-<npu>-<rt>-<ts>.fxb

Recommended: /root/.cache/furiosa/llm/fxb/models--furiosa-ai--Qwen3-8B-FP8/snapshots/<sha>/Qwen3-8B-FP8-<npu>-<rt>-<ts>.fxb

✔ 표시된 번들이 권장되는 번입니다. "FuriosaIR" 열에는 빌드 일치 상태가 표시됩니다:

  • — match — 번들의 FuriosaIR (compiler) 개정은 당신의 운영하는 구조 일치합니다. 이 뭉치는 자동적으로 봉사됩니다.

  • — stale — 번들은 fingerprint-compatible이지만 내장되었습니다. 다른 FuriosaIR 버전입니다. 이는 not 자동적으로 제공 (다음 단계 참조).

만약 호환되는 팩이 캐시에 없으면, check는 메시지를 출력하고 비정상적인 상태로 종료됩니다.

3단계 — 모델 제공#

대상 모델을 정상적으로 제공합니다. Furiosa-LLM은 다음 순서로 FXB를 실행합니다:

  1. 명백한 --fxb <path> (이용된 as-is);

  2. 모델 자체의 저장소 내부에 배포된 .fxb 파일;

  3. 로컬 캐시 — 권장되는 호환되는 번들, 하지만 FuriosaIR 버전이 실행 중인 빌드와 일치하는 경우에만 사용됩니다.

furiosa-llm serve Qwen/Qwen3-8B-FP8

캐시를 사용하는 경우, Furiosa-LLM은 선택한 캐시 번들을 기록하는 INFO 레벨 로그를 출력합니다. Python LLM(...) API도 동일한 코드 경로를 거치므로 동일한 원칙이 적용됩니다.

경고

캐시에만 오래된 (FuriosaIR-버전 불일치) 호환 가능한 번들만 저장되어 있는 경우, 번들이 다른 컴파일러 버전용으로 빌드된 경우, 번들을 무시하고 오류를 발생시키는 대신, 명시적으로 선택하도록 안내합니다.

furiosa-llm serve Qwen/Qwen3-8B-FP8 --fxb /path/to/stale-bundle.fxb

참고

캐시는 기본적으로 ~/.cache/furiosa/llm/fxb 위치에 저장됩니다 ($XDG_CACHE_HOME/furiosa/llm/fxb는 $XDG_CACHE_HOME이 설정된 경우). 모든 fxb 캐시 명령은 --cache-dir 옵션을 사용하여 다른 위치를 지정할 수 있습니다. 캐시는 Hugging Face 저장소 ID에 대해서만 사용되며, 로컬 모델 경로는 캐시를 우회합니다.

팁

일부 저장소는 접근 제한되어 있습니다. Hugging Face Hub를 다운로드하거나 확인하기 전에, Authorizing Hugging Face Hub (Optional)와 동일하게 인증해야 합니다.

hf auth login --token $HF_TOKEN

명령어 참조#

캐시를 사용하는 모든 하위 명령어는 --cache-dir 옵션을 받습니다 (기본값: ~/.cache/furiosa/llm/fxb).

fxb build#

모델에서 FXB 아티팩트를 빌드합니다.

fxb build <model> <output_path> [options]

  • model — Hugging Face 모델 ID 또는 로컬 경로 (경로는 "." 또는 "/"로 시작해야 합니다).

  • output_path — .fxb 파일을 저장할 위치 (파일 이름에 ".fxb"가 누락된 경우 자동으로 추가됩니다).

  • -tp/--tensor-parallel-size N — 텐서 병렬 그룹당 PE 수 (기본값: 모델 설정).

  • -pp/--pipeline-parallel-size N — 파이프라인 병렬 크기 (기본값: 1).

  • --max-model-len N — 버킷 필터링에 사용되는 최대 컨텍스트 길이.

  • -O/--optim-level {O0,O1,O2,O3} — 버킷 필터링 수준 (기본값: O3).

  • --convert {auto,embed,score,classify} — 작업 설정 (기본값: auto).

  • --dry-run — 구성 및 버킷을 해결하고 컴파일 없이 빌드 요약을 출력.

  • --build-report — 빌드 후, 각 커널의 컴파일 시간을 보여주는 보고서를 출력합니다.

  • --slow-kernel-threshold DURATION - 이 기간을 초과하는 커널을 실행하는 로그는 각 5 초마다 유형, 버킷 및 탈출 된 시간, longest-running 첫째. 몇 초 또는 초에 non-negative 정수를 허용 s, m, or h 후자 (전기: 15m; 0 slow-kernel 보고를 비활성화합니다.

  • --concurrency N — 병렬로 실행할 최대 커널 컴파일 수 (기본값: 1).

  • --dump-tc DIR — 디버깅을 위해 생성된 TC/DSL 파일을 DIR 디렉터리에 저장합니다.

고급 옵션 (필요한 경우에만 설정):

  • --no-fast-fail — 컴파일 실패 후에도 나머지 커널을 계속 빌드합니다.

  • --skip-bucket-validation — 사전 채우기/디코딩 시 주의 크기 검사를 건너뜁습니다 (초기 설정 단계에서만 사용).

  • --enable-collective-dq — 집단 동적 양자화를 활성화합니다; 이 기능은 선택된 모델에서만 지원됩니다.

  • --tokenwise-buckets 1,2,4,8 / --attention-buckets '(1,128,128),(1,1024,1)' — 버킷 계획을 재정의합니다.

성공적으로 (실행 모드가 아닌 경우) "Artifact Build Completed" 메시지를 출력합니다.

느린 커널 보고는 기본적으로 활성화되어 있으며, FXB 빌드 CI에서도 사용됩니다. 컴파일 시간은 동시성 슬롯을 기다리는 시간을 제외합니다. 각 업데이트는 새로운 로그 라인을 추가하여 터미널 출력을 덮어쓰지 않으므로, 빌드 중에 느린 커널이 CI 로그에 표시됩니다. 보고는 컴파일을 중단하거나 시간 초과하지 않습니다. FXB 빌드 CI는 기본 CLI 설정을 사용하며 추가 구성이 필요하지 않습니다.

더 짧은 지연 시간을 파악하려면, 임계값을 낮추십시오:

fxb build Qwen/Qwen3-8B-FP8 qwen3-8b-fp8 \
    --concurrency 8 --slow-kernel-threshold 2m

fxb download#

Hugging Face 저장소에서 FXB 묶음을 캐시에 다운로드합니다.

fxb download <repo_id> [--file F] [--revision R] [--force] [--cache-dir D]

  • repo_id — Hugging Face 저장소 ID.

  • --file F — 파일 이름으로 다운로드 범위를 특정하여 단일 .fxb 파일만 다운로드합니다.

  • --revision R — 저장소 버전 (브랜치, 태그 또는 커밋).

  • --force — 캐시에 이미 있는 경우에도 묶음을 다시 다운로드합니다.

fxb add#

로컬을 추가 .fxb 캐시에 저장할 파일 (예: download, 그것은 캐시를 채우고 - 허브에서 디스크에 파일에서. 저장 파일 이름은 각 번의 표현에서 표준화되고, 파일은 복사됩니다 (원래는 장소에서 왼쪽). 여러 경로가 허용됩니다, 그래서 같은 쉘 glob 등 fxb add *.fxb 매칭 번들을 추가합니다. 잘못된 번들은 나머지를 낙태하지 않고 보고되며, 명령은 non-zero를 종료합니다.

fxb add <path>... [--cache-dir D]

fxb check#

Hugging Face 저장소의 모델 구성과 호환되는 캐시 된 FXBs 찾기 (see) 지문 및 호환성 어떻게 호환성이 결정되는지).

fxb check <repo_id> [--cache-dir D]

대상 지문을 인쇄, 호환 캐시 번들 테이블 (표시 된 것을 수정) ✔, 각 번의 FuriosaIR 개정으로 — match or — stale) 및 권장 경로. 호환 번들가 캐시되지 않을 때 non-zero 상태와 출구.

fxb cache#

Inspect 및 prune 이미 캐시 된 것. 상단 수준에서 캐시 생활에 추가 (fxb download / fxb add); fxb cache 순수 inventory-management 그룹, subcommands와 ls, rm, 그리고 prune.

fxb cache ls#

캐시된 FXB 묶음을 나열합니다.

fxb cache ls [-q/--quiet] [--cache-dir D]

  • -q/--quiet — .fxb 경로만 출력 (스크립트 사용에 유용).

fxb cache rm#

캐시된 FXB 묶음을 제거합니다. 최소 하나 이상의 선택자(repo ID 또는 .fxb 파일 이름) 또는 --all 옵션이 필요합니다. -y/--yes 옵션 없이 사용 시 제거될 항목을 보여주고 확인을 요청합니다.

fxb cache rm [<selector>...] [--all] [--dry-run] [-y/--yes] [--cache-dir D]

  • selectors — repo ids or .fxb filenames to remove.

  • --all — 캐시의 모든 항목을 제거합니다.

  • --dry-run — 실제로 삭제하지 않고 제거될 항목을 보여줍니다.

  • -y/--yes — 확인 프롬프트를 표시하지 않습니다 (표준 입력이 대화형이 아닌 경우에 필요).

fxb cache prune#

FuriosaIR 버전에 따라 캐시된 묶음을 제거합니다. 기본적으로 실행 중인 빌드에 해당하는 FuriosaIR (컴파일러) 버전이 일치하지 않거나 버전이 알 수 없는 묶음을 제거합니다. 따라서 이러한 묶이는 자동으로 제공되지 않습니다. --older-than 옵션을 사용하면 FuriosaIR 버전이 지정된 의미론적 버전보다 낮은 묶음을 제거합니다. rm과 유사하게 미리보기 및 확인 프롬프트를 표시하지만 -y/--yes 옵션을 제공하면 프롬프트가 표시되지 않습니다.

fxb cache prune [--older-than IR_VERSION] [--dry-run] [-y/--yes] [--cache-dir D]

  • --older-than IR_VERSION — FuriosaIR 버전이 IR_VERSION보다 오래된 번들을 제거합니다. 예: 2026.3.0, <2026.3.0, 또는 <=2026.2.0 (빈 버전은 <를 의미). FuriosaIR 버전이 기록되지 않은 번들은 유지됩니다. 생략하면, 대상은 현재 빌드에 존재하는 오래된 번들을 대상으로 합니다.

  • --dry-run — 실제로 삭제하지 않고 제거될 항목을 보여줍니다.

  • -y/--yes — 확인 프롬프트를 표시하지 않습니다 (표준 입력이 대화형이 아닌 경우에 필요).

지문 및 호환성#

FXB의 핵심은 아키텍처 지문입니다. Furiosa-LLM이 특정 모델과 묶음이 호환되는지 판단하는 데 사용하는 값입니다. 묶음의 MANIFEST에는 모델의 아키텍처와 커널을 컴파일하는 데 영향을 미치는 구성 필드가 기록되어 있으며, 묶음이 모델과 호환되는 것으로 간주되면 해당 묶음의 지문과 모델의 지문이 일치합니다. 따라서 단일 FXB는 동일한 지문을 공유하는 모든 Hugging Face 모델에서 재사용할 수 있습니다. 즉, 자체 저장소에 .fxb 파일이 없는 모델을 재사용하기 위해 로컬 캐시에서 호환 가능한 묶음을 사용할 수 있습니다.

지문은 모형 건축술에서 더하기 건축됩니다 config.json 커널 생성에 영향을 미치는 필드 - 치수, 관심 및 mixture-of-experts 설정 및 quantization furiosa — 빌드 시 커널 읽기대표적인 예시는 다음과 같습니다. hidden_size, num_attention_heads, sliding_window, MoE 모형을 위한 전문가 조사, 및 quantization format. 다른 커널에 이 컴파일과 다른 두 개의 저장소는 FXB를 공유하지 않아야 합니다; 로드 시간에만 사용되는 필드는 지문의 일부가 아닙니다.

일치는 엄격합니다. 두 모델이 호환되는 경우 아키텍처와 모든 지문 필드가 동일해야 합니다. 묶음을 재사용하기 전에 fxb check를 사용하여 일치 여부를 확인하십시오.

참고

지문을 기반으로 한 호환성 매칭은 실험적인 기능입니다. 지문을 구성하는 정확한 필드 집합과 비교 방법은 향후 릴리스에서 변경될 수 있습니다. 다른 모델에 대한 캐시된 묶음을 사용하기 전에 항상 fxb check를 사용하여 일치 여부를 확인하십시오.

최적 사용법#

fxb build runtime 적용 및 결과 번들의 성능에 대한 시간을 거래하십시오. 올바른 옵션은 건물에 따라 다릅니다. 아래의 시나리오는 일반적인 사례를 커버합니다. FuriosaAI의 자체 per-model 생산 구성은 빌드 매트릭스에서 라이브합니다. .github/fxb-artifacts.yaml.

빠른 테스트 빌드#

실행 가능한 묶음을 가능한 한 빨리 얻고 싶을 때 (예: 초기 설정, 간단한 테스트, 모델이 컴파일되는지 확인) — 컴파일되는 커널의 수를 최소화하고 병렬 빌드를 사용하십시오:

  • -O O0 — 최소 버킷 세트, 지금까지 몇 커널이 컴파일됩니다. 이것은 빌드 시간에 하나의 가장 큰 레버입니다.

  • --max-model-len — 컨텍스트 길이를 작게 제한하여 더 적은 수의 작은 커널 세트가 생성되도록 합니다.

  • --concurrency — 기본값인 1보다 높은 값을 설정하여, 빌드 호스트의 사용 가능한 코어를 활용하여 커널을 병렬로 컴파일합니다.

  • --dry-run — 구성 및 버킷 계획을 해결하고, 컴파일 없이 빌드 요약을 출력하여, 컴파일 시간을 낭비하기 전에 계획을 확인합니다.

# Preview the plan first, then build a minimal bundle quickly
fxb build Qwen/Qwen3-8B-FP8 qwen3-8b-test.fxb --max-model-len 4096 --dry-run
fxb build Qwen/Qwen3-8B-FP8 qwen3-8b-test.fxb -O O0 --max-model-len 4096 --concurrency 8

-O O0으로 빌드된 묶음은 실행되지만, 최소한의 버킷만 커버합니다. 따라서, 완전 빌드에 비해 성능 및 커버리지 측면에서 성능 저하 및 제한이 발생합니다. 프로덕션 환경에서는 사용하지 마십시오.

프로덕션 빌드#

실제로 배포하는 묶음의 경우, 완전한 버킷 커버리지와 배포 환경에 맞는 설정을 우선시하고, 더 긴 빌드 시간을 허용하십시오:

  • -O O3 — 전체 버킷 세트 (이것이 기본값이며, 명확성을 위해 명시적으로 설정하십시오).

  • -tp/--tensor-parallel-size — 실제 사용되는 서빙 토폴로지에 맞게 설정 (8개의 PE (Processing Element)를 1개의 카드당 사용하도록 설정, 예를 들어 1개의 카드에 8개, 4개의 카드에 32개).

  • --max-model-len — 실제 사용되는 최대 컨텍스트 길이에 맞게 설정하여, 낭비 없이 적절한 크기의 버킷을 구성합니다.

  • --concurrency — 높게 설정하여 빌드 호스트를 최대한 활용하고, (긴) 전체 빌드 시간을 단축합니다.

  • --build-report — 각 커널의 컴파일 시간을 출력하여, 예상치 못한 느린 커널을 식별합니다.

fxb build openai/gpt-oss-120b gpt-oss-120b.fxb \
    -O O3 -tp 32 --max-model-len 32768 --concurrency 24 --build-report

배포 토폴로지#

텐서 병렬 처리는 빌드 시에 고정되지만, 파이프라인 및 데이터 병렬 처리는 서빙 시에 설정합니다. 팩의 -tp/--tensor-parallel-size는 컴파일된 커널의 형태를 결정합니다 (각 커널은 해당 텐서 병렬 수준에 따라 샤딩됩니다), 따라서 FXB에 포함되며, 이후에는 변경할 수 없습니다. 빌드 시에 원하는 -tp를 사용해야 합니다. 반면, 파이프라인 및 데이터 병렬 처리는 이미 컴파일된 팩을 더 많은 PE (Processing Element)에 복제하고 스테이지하여 재컴파일하지 않고, furiosa-llm serve 시에 -pp/--pipeline-parallel-size 및 -dp/--data-parallel-size를 통해 설정합니다:

# Built once for tensor-parallel size 8; deployed with pipeline and data parallelism
furiosa-llm serve Qwen/Qwen3-8B-FP8 --fxb ./qwen3-8b-fp8.fxb -pp 2 -dp 4
