하이브리드 KV Cache 관리#

하이브리드 KV cache 관리는 글로벌 관심과 sliding-window주의 레이어를 혼합하는 모델에 대한 내부 최적화입니다. 같은 메모리 동작을 가지고있는 경우 모든 레이어를 치료하는 대신 Furiosa-LLM는 별도의 KV cache 풀 및 조정 할당 논리와 함께 관리합니다.

이 기능은 모형이 잡종 주의를 사용할 때 자동적으로 적용됩니다; 여분 사용자 윤곽은 요구되지 않습니다.

개요#

하이브리드 모델에서 global-attention 레이어와 sliding-window 레이어는 다른 캐시 성장 패턴이 있습니다.

  • 세계적 관심 전체 시퀀스 길이에 따라 증가합니다.

  • Sliding-window 어텐션 크기는 윈도우 크기에 의해 제한됩니다

sliding-window 레이어의 over-provision 메모리를 사용할 수 있습니다. 특히 long-context 워크로드를 위해 long-context를 사용할 수 있습니다. 하이브리드 KV cache 관리는 두 가지 메모리 경로 분리하여 이것을 방지합니다.

어떻게 작동 하는 것 입니까?#

풀 파티션#

초기화에서 Furiosa-LLM 파티션 KV cache 메모리로:

  • A global-attention 풀

  • A sliding-window 어텐션 풀

각 풀은 그 관심 유형에 대한 대응 KV cache 공간에 할당됩니다. 파티션 논리는 attention-aware이므로 메모리는 one-size-fits-all 분할 대신 예상 글로벌 대 창 사용에 따라 배포됩니다.

요청 생명주기#

각 요청 단계의 경우, 스케줄러는 다음과 같이 풀을 조정합니다.

  • Prefill: 들어오는 토큰을 위한 Global 및 sliding-window 풀에서 블록을 할당합니다.

  • 연장 / Decode: 기존의 캐시 블록을로드하고 새로운 토큰에 대한 새로운 쓰기 블록을 할당

  • 청소: full-prefix 역사에 대한 글로벌 블록 재사용을 유지하면서 검증된 창에서 이전되는 sliding-window 블록을 출시합니다.

이것은 주요 효율성 점입니다: sliding-window 캐시 항목 외부 활성 창은 요청 완료 될 때까지 메모리 대신 기억을 점유하는 대신 일찍 다시 인용됩니다.

Prefix Caching와의 상호 작용#

prefix caching가 활성화되면 하이브리드 캐시 관리는 글로벌 및 sliding-window 블록을 모두 복제하는 하이브리드 프리픽스와 함께 작동합니다. 일치한 프리픽의 일부가 더 이상 유효하지 않은 경우 sliding-window 캐시, Furiosa-LLM는 여전히 유효 부분을 재사용하고 필요한 것을 계산합니다. 하이브리드 prefix-match 행동에 대한 자세한 내용은 참조 하이브리드 어텐션 모델 in Prefix Caching. 호스트 메모리에 재사용 가능한 hybrid-attention 접두사를 유지하려면, 참조 계층적 Prefix Caching.

효과적 인 이유#

단일 풀 접근 방식과 비교하여 하이브리드 KV cache 관리는 다음과 같습니다.

  • 메모리 낭비를 줄이는 것 sparse 또는 혼합주의 패턴 모델

  • 서버 측에서 더 높은 효과적인 캐시 용량 long-context 전역 범위에 적용

  • 제거 압력을 줄임 stale sliding-window 블록을 이전

  • 안정적인 서비스 동작 수동 per-attention 메모리 풀을 조정하는 사용자 없이

최종 사용자의 경우, 주요 이점은 곧바로: hybrid-attention 모델에 더 나은 KV 메모리 활용 및 더 일관된 성능, 자동으로.

선택적 조율#

hybrid-attention 모형을 위해, 당신은 선택적으로 놓을 수 있습니다 EXPECTED_AVERAGE_SEQ_LENGTH KV 메모리가 글로벌 주의 versus sliding-window주의에 대해 자세히 알아볼 수 있는 환경 변수.

이것은 당신의 워크로드가 안정되어 있는 prompt 길이 본 (예를 들면, 일관되게 아주 긴 프롬프트를 위해)를 비치하고, 당신이 그 본을 더 나은 일치하기 위하여 분할하는 기억을 원할 때 유용합니다.

  • unset가 없다면, Furiosa-LLM는 모델의 global-attention 및 sliding-window주의 캐시 요구 사항에 따라 기본 비율을 사용합니다.

  • 설정하면 Furiosa-LLM는 workload-aware 분할을 보완하기 위해 제공된 예상 시퀀스 길이를 사용합니다.

  • 값은 긍정적 인 정수이어야합니다.

export EXPECTED_AVERAGE_SEQ_LENGTH=8192
furiosa-llm serve ...
