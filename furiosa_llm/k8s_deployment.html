Kubernetes에 Furiosa-LLM 배포#

이 가이드는 Furiosa-LLM을 Kubernetes에 배포하는 방법을 설명합니다. Furiosa AI RNGD에 최적화된, OpenAI와 호환되는 서버입니다.

필수 구성 요소#

  • Furiosa RNGD 장치가 장착된 Kubernetes 클러스터.

  • Hugging Face 계정 및 액세스 토큰.

  • 동적 볼륨 프로비저닝을 지원하는 Kubernetes 스토리지 클래스.

RNGD 클러스터를 설정하는 방법에 대한 자세한 내용은 "Installing Prerequisites and Kubernetes Plugins"를 참조하십시오.

1단계: Kubernetes Secret 준비#

Hugging Face 토큰에 대한 Kubernetes Secret을 생성합니다:

apiVersion: v1
kind: Secret
metadata:
  name: hf-token-secret
type: Opaque
data:
  token: <your_base64_encoded_hf_token>

다음 명령을 사용하여 토큰을 인코딩합니다:

echo -n '<your_HF_TOKEN>' | base64

그런 다음, 다음 단계를 적용합니다:

kubectl apply -f secret.yaml

2단계: Persistent Volume Claim (PVC) 생성#

참고

LLM 모델 캐시와 같이 대용량 파일을 Pod 내의 임시 스토리지에서 사용하는 경우, 디스크 압력으로 인해 Pod가 종료될 수 있습니다. 따라서 데이터의 내구성과 안정성을 보장하기 위해 Persistent Volume Claim (PVC)을 사용하는 것이 권장됩니다.

모델을 저장하기 위한 PVC(Persistent Volume Claim) 정의를 생성합니다. 아래에 지정된 스토리지 클래스(“default”)는 예시이며, 실제 Kubernetes 환경에서 사용 가능한 스토리지 클래스는 다를 수 있습니다. 클러스터에 적합한 스토리지 클래스를 확인하고 지정하십시오:

apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: llama-storage
spec:
  accessModes:
    - ReadWriteOnce
  resources:
    requests:
      storage: 10Gi
  # The storage class "default" is an example, use an appropriate one for your cluster.
  storageClassName: default

PVC 적용:

kubectl apply -f pvc.yaml

3단계: Furiosa-LLM 서버 배포#

Furiosa-LLM을 사용하여 furiosa-ai/Llama-3.1-8B-Instruct 모델을 실행하기 위한 배포 정의를 생성합니다. furiosa-ai/Llama-3.1-8B-Instruct 모델에 대한 자세한 내용은 Hugging Face 모델 페이지를 참조하십시오.

apiVersion: apps/v1
kind: Deployment
metadata:
  name: llama-3-8b
  labels:
    app: llama-3-8b
spec:
  replicas: 1
  selector:
    matchLabels:
      app: llama-3-8b
  template:
    metadata:
      labels:
        app: llama-3-8b
    spec:
      containers:
        - name: llama-3-8b
          image: furiosaai/furiosa-llm:latest
          args:
            - "serve"
            - "furiosa-ai/Llama-3.1-8B-Instruct"
          ports:
            - containerPort: 8000
          resources:
            # Recommended resources for one RNGD card: 10 CPU cores and 100GB memory
            limits:
              cpu: 10
              memory: 100Gi
              furiosa.ai/rngd: "1"
            requests:
              cpu: 10
              memory: 100Gi
              furiosa.ai/rngd: "1"
          env:
            - name: HF_TOKEN
              valueFrom:
                secretKeyRef:
                  name: hf-token-secret
                  key: token
          volumeMounts:
            - name: model-storage
              mountPath: /root/.cache/huggingface
          securityContext:
            capabilities:
              drop:
                - ALL
            seccompProfile:
              type: Unconfined
          # Increase initialDelaySeconds of livenessProbe and readinessProbe if larger models take longer to load
          livenessProbe:
            httpGet:
              path: /health
              port: 8000
            initialDelaySeconds: 180
            periodSeconds: 10
          readinessProbe:
            httpGet:
              path: /health
              port: 8000
            initialDelaySeconds: 180
            periodSeconds: 5
      volumes:
        # If dynamic PVC provisioning isn’t possible in your cluster, consider using a hostPath volume.
        - name: model-storage
          persistentVolumeClaim:
            claimName: llama-storage

배포 적용:

kubectl apply -f deployment.yaml

4단계: 배포를 서비스로 노출#

Furiosa-LLM 서버를 Kubernetes 서비스로 노출:

apiVersion: v1
kind: Service
metadata:
  name: llama-3-8b
spec:
  selector:
    app: llama-3-8b
  ports:
    - port: 8000
      targetPort: 8000
  type: ClusterIP

서비스 적용:

kubectl apply -f service.yaml

5단계: 배포 테스트#

로그를 검사하여 서버가 실행 중인지 확인:

kubectl logs deployment/llama-3-8b

다음과 같은 출력을 확인해야 합니다:

INFO:     Started server process [1]
INFO:     Waiting for application startup.
INFO:     Application startup complete.
INFO:     Uvicorn running on http://0.0.0.0:8000 (Press CTRL+C to quit)

추론 엔드포인트를 테스트:

kubectl port-forward svc/llama-3-8b 8000:8000

그런 다음, 테스트 요청을 실행합니다:

curl http://localhost:8000/v1/completions \
  -H "Content-Type: application/json" \
  -d '{
        "model": "furiosa-ai/Llama-3.1-8B-Instruct",
        "prompt": "San Francisco is a",
        "max_tokens": 7,
        "temperature": 0
      }'

Furiosa-LLM 서버로부터 유효한 응답을 받게 되며, 다음과 유사한 형태가 될 것입니다:

{

  "object": "text_completion",
  "created": 1748675715,
  "model": "furiosa-ai/Llama-3.1-8B-Instruct",
  "choices": [
    {
      "index": 0,
      "text": " city that is known for its vibrant",
      "logprobs": null,
      "finish_reason": "length",
      "prompt_logprobs": null
    }
  ],
  "usage": {
    "prompt_tokens": 5,
    "total_tokens": 12,
    "completion_tokens": 7,
    "completion_tokens_details": null
  }
}

결론#

Kubernetes를 사용하여 Furiosa-LLM을 배포하면, Furiosa RNGD 가속기의 효율성과 확장성을 활용할 수 있습니다. 이 가이드는 Kubernetes 클러스터를 효율적으로 설정하여 추론 워크로드를 실행하는 방법을 안내합니다.
