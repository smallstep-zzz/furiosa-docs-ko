모델 병렬 처리#

모델 병렬 처리는 모델을 여러 부분으로 나누어 여러 장치에서 동시에 실행하는 기술입니다. 특히, 단일 장치에 들어가지 않는 큰 모델을 처리하거나, 모델 추론의 처리량 또는 지연 시간을 개선하는 데 유용합니다.

모델 병렬화에는 세 가지 유형이 있습니다: 텐서 병렬화 (TP), 파이프라인 병렬화 (PP), 그리고 데이터 병렬화 (DP). 각 유형은 고유한 장점과 단점을 가지고 있습니다. 또한, 더 나은 성능을 위해 여러 유형의 병렬화를 결합할 수도 있습니다.

이 섹션에서는 세 가지 유형의 모델 병렬화, Furiosa-LLM에서 이를 구성하는 방법, 그리고 최적의 사용법을 설명합니다.

텐서 병렬화 (TP)#

텐서 병렬화 (TP)는 각 레이어를 특정 차원을 따라 여러 조각으로 나눕니다. 각 장치는 전체 레이어의 1/N만 보유하며, 계산 그래프의 정확성에 영향을 미치지 않습니다.

모델과 중간 결과의 일부만 각 장치에 존재하기 때문에, TP는 각 장치에서 가중치, KV 캐시, 활성화 메모리에 필요한 메모리 요구 사항을 줄입니다. 따라서, 모델 크기가 단일 장치의 메모리 용량을 초과하는 경우, TP는 특히 유용합니다. 더 많은 메모리 가용성은 더 큰 배치 크기와 더 긴 시퀀스를 가능하게 합니다.

또한, TP는 여러 장치의 집합 연산 능력과 메모리 대역폭을 활용하여 모델 추론의 지연 시간을 줄일 수 있습니다.

그러나, TP는 여러 장치 간에 데이터를 동기화하기 위해 추가적인 통신이 필요합니다. 이러한 작업, 즉 "집단 통신" (예: all-reduce 및 all-gather)은 모든 장치에서 데이터 일관성을 보장합니다. TP의 정도가 너무 높으면 통신 오버헤드가 성능에 영향을 미쳐 모델 추론 속도를 늦출 수 있습니다.

파이프라인 병렬 처리 (PP)#

파이프라인 병렬 처리 (PP)는 모델을 수평적으로 여러 장치에 분할 (일반적으로 레이어 수준에서) 하여, 단일 장치에 일부 모델 레이어만 존재하도록 합니다. 각 장치는 모델의 다른 부분 또는 "스테이지"를 처리하고, 중간 결과를 다음 장치로 전달합니다.

텐서 병렬 처리와 마찬가지로, PP도 단일 장치의 메모리 사용량을 줄입니다. 이는 각 장치에 모델과 중간 결과의 일부만 저장되기 때문입니다.

TP와 달리, PP는 지연 시간을 증가시키는 대신 모델 추론의 처리량을 증가시킵니다. 각 장치가 모델의 다른 부분을 순차적으로 처리하기 때문에, 전체 지연 시간은 각 스테이지의 누적 지연 시간에 의해 결정됩니다. 그러나 PP는 여러 요청을 병렬로 처리하여 처리량을 증가시킵니다.

데이터 병렬 처리 (DP)#

데이터 병렬 처리 (DP)는 SPMD (single program multiple data) 프로그래밍 모델을 기반으로 합니다. 이는 단순함으로 인해 가장 일반적인 병렬 처리 방식입니다. 추론의 경우, DP는 동일한 모델 인스턴스를 여러 번 복제하여, 각 복제본이 독립적으로 입력 요청의 일부를 처리합니다. 결과적으로, DP는 모델 추론의 처리량을 확장하는 데 매우 효과적입니다.

각 장치는 별도의 모델 가중치와 KV 캐시를 필요로 합니다. 따라서, 복제본의 수는 메모리 사용량에 영향을 미칩니다. 그러나, 단일 FuriosaAI 장치 내에서 DP를 사용할 때, 장치의 공유 메모리 아키텍처 덕분에 복제본의 가중치를 공유할 수 있습니다.

Furiosa-LLM에서 모델 병렬 처리 구성#

텐서 병렬 처리는 FXB 컴파일 시 고정됩니다. fxb build --tensor-parallel-size를 사용하여 구성합니다. 모델을 위한 FXB 빌드 방법에 대한 자세한 내용은 "Building an FXB for a model"을 참조하십시오.

파이프라인 및 데이터 병렬 처리는 서비스 시점에 선택됩니다. furiosa-llm serve를 사용하여 --pipeline-parallel-size (또는 -pp) 및 --data-parallel-size (또는 -dp) 옵션을 사용합니다. LLM, LLMEngine, AsyncLLMEngine API는 해당 pipeline_parallel_size 및 data_parallel_size 매개변수를 노출합니다.

Furiosa-LLM 사용에 대한 권장 사항#

각 병렬 처리 방식은 고유한 특징과 제약 조건을 가지고 있습니다.

pipeline_parallel_size 파라미터는 최대 장치 수만큼만 설정할 수 있습니다. tensor_parallel_size는 FXB에 컴파일된 값과 일치해야 하며, 서빙 시에는 변경할 수 없습니다. tensor_parallel_size는 텐서 병렬 그룹 내의 PE(Processing Element) 수를 나타내며, RNGD(RNG Distributed) 카드의 수를 의미하지 않습니다. 하나의 RNGD 카드는 8개의 PE를 포함합니다.

tensor_parallel_size, pipeline_parallel_size, 그리고 data_parallel_size의 곱은 사용 중인 머신의 총 PE 수를 같게 해야 합니다. pipeline_parallel_size가 1보다 큰 파이프라인 병렬 처리 방식은 단일 노드에서 데이터 병렬 처리와 함께 사용할 수 있습니다.

예를 들어, 4개의 RNGD 카드가 있고, 각 카드는 8개의 PE를 가지고 있다고 가정해 보겠습니다. 그러면 총 PE 수는 32개입니다. 이 경우 다음과 같은 설정을 사용할 수 있습니다:

  • tensor_parallel_size=8, pipeline_parallel_size=4, data_parallel_size=1

  • tensor_parallel_size=8, pipeline_parallel_size=2, data_parallel_size=2
