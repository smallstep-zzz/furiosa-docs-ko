모형 평행성#

모델 병렬은 여러 부품으로 모델을 분할하고 여러 장치에서 병렬로 실행하는 데 사용되는 기술입니다. 단일 장치 또는 throughput 또는 latency 모델 inference에 적합하지 않는 대형 모델을 처리하는 데 특히 유용합니다.

모델 병렬의 세 가지 유형이 있습니다 : 10sor 병렬 (TP), 파이프 병렬 (PP) 및 데이터 병렬 (DP). 각 유형에는 자체 혜택과 단점이 있습니다. 또한, 더 나은 성능을 달성하기 위해 병렬의 여러 유형의 결합 할 수 있습니다.

이 섹션에서는 모델 병렬의 세 가지 유형에 대해 설명합니다. Furiosa-LLM에서 구성하는 방법 및 모범 사례를 제공합니다.

텐서 병렬 처리 (TP)#

Tensor Parallelism (TP)는 특정 차원을 따라 여러 개의 펑크로 각 층을 분할합니다. 각 장치는 전체 층의 1 / N을 보유하고 있으며, 계산 그래프의 정확한 영향을받지 않고 있습니다.

모델과 중간 결과의 일부가 각 장치에서 떠오르기 때문에 TP는 무게, KV cache 및 각 장치에서 활성화 메모리에 대한 메모리 요구 사항을 감소시킵니다. 따라서 TP는 모델 크기를 단일 장치의 메모리 용량을 초과 할 때 특히 유용합니다. 증가 메모리 가용성은 더 큰 배치 크기와 더 긴 순서도 허용합니다.

또한 TP는 모델 inference의 latency를 여러 기기의 집계 전력 및 메모리 대역폭을 활용하여 줄일 수 있습니다.

그러나 TP는 여러 장치에서 데이터를 동기화 할 수있는 추가 통신이 필요합니다. 이 작업은 공동 통신 (e.g., all-reduce 및 all-gather)로 알려진이 작업은 모든 장치에서 데이터 일관성을 보장합니다. TP의 정도가 너무 높으면 통신 오버 헤드가 성능이 어울릴 수 있으므로 느린 모델 inference를 이끌 수 있습니다.

파이프라인 병렬 처리 (PP)#

Pipeline Parallelism (PP)는 여러 장치에서 모델 수직 (보통 층 수준)을 분할하므로 단일 장치에서 모델 층의 하위 세트 만 사용합니다. 각 장치는 다른 부분 또는 "단"을 처리하고 모델의 중간 결과를 다음 장치로 전달합니다.

10sor 병렬처럼, PP는 또한 단일 장치의 기억 발자국을 감소시킵니다. 이것은 모형의 단지 부분이고 그것의 중간 결과는 각 장치에 저장됩니다 때문에 입니다.

TP와 달리, PP는 inference 모델의 throughput를 증가시키는 대신 latency를 증가시킵니다. 각 장치는 모델의 서로 다른 부분을 순차적으로 처리하기 때문에, 종점-대-종점 latency는 각 단계의 누적된 latency에 의해 결정됩니다. 그러나 PP는 여러 요청을 병렬로 처리하여 throughput를 증가시킵니다.

데이터 병렬 처리 (DP)#

데이터 병렬화 (DP)는 SPMD (단일 프로그램 다중 데이터) 프로그래밍 모델에 근거합니다. 그것은 단순성 때문에 병렬화의 가장 일반적인 형태입니다. inference의 경우 DP는 입력 요청의 분수를 독립적으로 처리하는 각 복제와 같은 모델 인스턴스를 여러 번 복제합니다. 결과적으로 DP는 모델 inference를 사기에 매우 효과적입니다.

각 장치는 모델 무게와 KV cache의 별도 사본을 요구합니다. 따라서, 복제 수와 메모리 사용량. 그러나 단일 FuriosaAI 장치 내에서 DP를 사용할 때 복제 중량은 장치의 공유 메모리 아키텍처로 공유 될 수 있습니다.

Furiosa-LLM에서 모델 병렬 구성#

Tensor 평행은 FXB가 컴파일될 때 조정됩니다. 그것으로 구성하십시오 fxb build --tensor-parallel-size; 참조 FXB를 특정 모델에 맞게 구성하는 방법 세부사항을 알려주세요.

파이프 및 데이터 병렬은 서빙 시간에 선정됩니다. furiosa-llm serve, 사용 --pipeline-parallel-size (or -pp) 및 --data-parallel-size (or -dp) LLM, LLMEngine, 그리고 AsyncLLMEngine API는 해당 정보를 노출하여, pipeline_parallel_size and data_parallel_size 매개 변수

Furiosa-LLM에 대한 최적의 방법#

각 평행한 유형에는 그것의 자신의 특성 및 constraints가 있습니다.

The pipeline_parallel_size 매개변수는 대부분의 장치에서 일 수 있습니다. tensor_parallel_size FXB로 컴파일된 값과 서빙 시간에 변경할 수 없습니다. tensor_parallel_size 각 tensor-parallel 그룹에 있는 PEs의 수입니다, RNGD 카드의 수 아닙니다; 1개의 RNGD 카드는 8 PEs를 포함합니다.

이산물 tensor_parallel_size, pipeline_parallel_size, 그리고 data_parallel_size 당신의 기계에 있는 PEs의 총 수와 동등해야 합니다. 파이프라인 평행선과 pipeline_parallel_size 1보다 더 큰 단일 노드의 데이터 병렬과 결합 할 수 있습니다.

예를 들어, 4 RNGD 카드가 8 PE를 가지고있는 각 것을 가정하십시오. 그런 다음 PE의 총 수는 32입니다. 그 경우 다음 구성을 사용할 수 있습니다.

  • tensor_parallel_size=8, pipeline_parallel_size=4, data_parallel_size=1

  • tensor_parallel_size=8, pipeline_parallel_size=2, data_parallel_size=2
