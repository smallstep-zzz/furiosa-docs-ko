제마 4#

제마 4 Google의 dense 멀티모드 모델 제품군입니다. Gemma 4는 sliding-window 및 full-attention 레이어를 interleaves는 변압기 디코더와 비전 인코더를 결합합니다. 채팅 템플릿은 옵션 소싱 및 도구 (기능) 통화를 지원합니다.

에 저장합니다. FuriosaAI는 FP8 블록을 게시합니다. RedHatAI/gemma-4-31B-it-FP8-block 기하급수 furiosa-ai 구성 요소가 Hugging Face 허브에 연결됨Furiosa 실행 가능한 번들 (FXB)와 함께 FuriosaAI RNGD Furiosa-LLM로. 동일한 상류 무게는 또한 다른 기구 (vLLM, SGLang 및 변압기와 같은); 그와 함께 사용을 위해, 아래에 연결되는 상류 모형 카드를 보십시오.

사용 가능한 모델#

모델

Quantization

RNGD 카드

노트

furiosa-ai/gemma-4-31B-it-FP8-block

FP8 블록

4

31B dense; 생각은 기본적으로 꺼집니다

  • 건축: Gemma 4 (거밀), Gemma4ForConditionalGeneration

  • 입력 / 출력: 이미지 + 텍스트 / 텍스트

  • Quantization: 선형 레이어 가중치는 128×128 블록을 사용하는 정적 FP8 quantization 및 128개의 값으로 구성된 그룹을 사용하는 동적 FP8 quantization를 사용합니다. 비전 타워, 임베딩, 출력 헤드 및 KV cache는 16비트 정밀도로 유지됩니다.

사용#

Furiosa-LLM를 사용하여이 모델을 실행하려면 아래 예제 명령을 따르십시오 Furiosa-LLM 및 그 전제 조건 설치.

서버를 시작하세요#

모델을 실행하려면, 매칭을 위한 furiosa-ai/<repo> 식별자:

# Launch the server, listening on port 8000 by default
furiosa-llm serve furiosa-ai/gemma-4-31B-it-FP8-block \
  --reasoning-parser gemma4

제마 4가 들어갑니다 기본적으로 non-reasoning 모드를 사용- 계속 gemma4 파서가 활성화된 이유는 생각이 활성화될 때 별도의 필드에서 서버 수익의 이유를 알려줍니다(see) 발전 된 사용).

또한 도구 (기능) 호출을 활성화하려면 자동 도구 선택과 추가 gemma4 tool-call 파서:

furiosa-llm serve furiosa-ai/gemma-4-31B-it-FP8-block \
  --reasoning-parser gemma4 \
  --enable-auto-tool-choice \
  --tool-call-parser gemma4

서버가 준비되면 다음을 볼 수 있습니다.

INFO:     Started server process [27507]
INFO:     Waiting for application startup.
INFO:     Application startup complete.
INFO:     Uvicorn running on http://0.0.0.0:8000 (Press CTRL+C to quit)

기본 사용#

서버는 OpenAI 호환 API를 노출합니다. text-only 요청을 보낼 수 있습니다. curl:

curl http://localhost:8000/v1/chat/completions \
    -H "Content-Type: application/json" \
    -d '{
    "model": "furiosa-ai/gemma-4-31B-it-FP8-block",
    "messages": [{"role": "user", "content": "What is the capital of France?"}]
    }' \
    | python -m json.tool

이미지를 문의하려면 [구체적인 정보 삽입]을 전달하십시오. image_url 메시지의 내용 부분:

curl http://localhost:8000/v1/chat/completions \
    -H "Content-Type: application/json" \
    -d '{
    "model": "furiosa-ai/gemma-4-31B-it-FP8-block",
    "messages": [{
        "role": "user",
        "content": [
            {"type": "image_url", "image_url": {"url": "https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/p-blog/candy.JPG"}},
            {"type": "text", "text": "What animal is on the candy?"}
        ]
    }]
    }' \
    | python -m json.tool

The image_url.url 필드는 원격 연결을 허용합니다. http:///https:// URL, 즉, 내장된 base64 data: URL, 또는 지역 file:// 경로 (마지막 단계에서는 --allowed-local-media-path 아래에 설명된 깃발 발전 된 사용).

"생각 기능"이 활성화되면 (자세한 내용은 다음을 참조) 발전 된 사용), Gemma 4는 마지막 대답에서 따로따로 이유를 반환합니다:

  • response.choices[].message.reasoning (non-streaming)

  • response.choices[].delta.reasoning [ 스트리밍 ]

from openai import OpenAI

client = OpenAI(base_url="http://localhost:8000/v1", api_key="EMPTY")

response = client.chat.completions.create(
    model="furiosa-ai/gemma-4-31B-it-FP8-block",
    messages=[{"role": "user", "content": "How many r's are in 'strawberry'?"}],
    extra_body={"chat_template_kwargs": {"enable_thinking": True}},
)

print("Reasoning:", response.choices[0].message.reasoning)
print("Answer:", response.choices[0].message.content)

참고: The reasoning 필드는 OpenAI API 사양의 일부가 아니지만 다양한 컨벤션 (OpenAI Agents SDK, vLLM 및 기타)입니다. 그것은 그 대신 콘텐츠가 포함 된 응답에만 나타납니다. 그렇지 않으면 그에 도달 AttributeError.

발전 된 사용#

다중 모드 제공 옵션. 이 예제는 로컬 이미지를 허용합니다. /srv/media에서 확인하십시오. cdn.example.com, 각 4개의 이미지에 각 요구 한계:

furiosa-llm serve furiosa-ai/gemma-4-31B-it-FP8-block \
  --reasoning-parser gemma4 \
  --enable-auto-tool-choice \
  --tool-call-parser gemma4 \
  --allowed-local-media-path /srv/media \
  --allowed-media-domains cdn.example.com \
  --image-limit-per-prompt 4

See 서버 옵션 Vision-Language 모델은 전체 옵션 참조 및 기본값에 대한 가이드입니다.

이미지 처리 옵션. 이 예제는 10-second HTTP image-fetch 타임 아웃을 설정하고 Gemma 4의 image-token 제한을 설정 280 과 max_soft_tokens:

furiosa-llm serve furiosa-ai/gemma-4-31B-it-FP8-block \
  --reasoning-parser gemma4 \
  --media-io-kwargs '{"image": {"timeout": 10}}' \
  --mm-processor-kwargs '{"max_soft_tokens": 280}'

지원된 값에 대해서는, 행동을 정성화하고, per-request는 과대를 강화하고, 보기 멀티모달 옵션 Vision-Language 모델 가이드.

추론을 할 수 있게 해줍니다. Gemma 4는 기본적으로 non-reasoning 모드에서 실행됩니다. 통과하여 단일 요청에 대한 이유가 있습니다. enable_thinking 통행 chat_template_kwargs, 아래와 같이 기본 사용- 그리고 --reasoning-parser gemma4, 생각의 체인은 최종 응답에서 별도로 반환됩니다.

모든 요청 이유를 만들기 위해, 서버를 실행 --default-chat-template-kwargs (이 요청은 여전히 기본값을 무시할 수 있습니다):

furiosa-llm serve furiosa-ai/gemma-4-31B-it-FP8-block \
  --reasoning-parser gemma4 \
  --default-chat-template-kwargs '{"enable_thinking": true}'

tool-call 대화에 대한 준비. 챗 템플릿은 또한 preserve_thinking, false- 설정해 true multi-turn 에이전트 대화를 렌더링 할 때 이전 보조 tool-call 메시지에서 소감을 유지하십시오. 그것은 자체로 소감을 활성화하지 않습니다.

response = client.chat.completions.create(
    model="furiosa-ai/gemma-4-31B-it-FP8-block",
    messages=messages,
    tools=tools,
    extra_body={
        "chat_template_kwargs": {
            "enable_thinking": True,
            "preserve_thinking": True,
        }
    },
)

각 요청에 대한 기본으로 두 가지 옵션을 적용하려면 다음을 사용하십시오.

furiosa-llm serve furiosa-ai/gemma-4-31B-it-FP8-block \
  --reasoning-parser gemma4 \
  --enable-auto-tool-choice \
  --tool-call-parser gemma4 \
  --default-chat-template-kwargs '{"enable_thinking": true, "preserve_thinking": true}'

도구 호출. 서버를 [구체적인 정보 삽입]을 사용하여 시작할 때 --enable-auto-tool-choice --tool-call-parser gemma4 ( 참조) 서버를 시작하세요), 통과 tools 요청에서 모델을 결정할 때 호출합니다. 참조 도구 호출 가이드 tool-choice 옵션에 대한 완벽한 클라이언트 예 및 세부 사항.
