K-EXAONE#

K-EXAONE LG AI Research에서 개발한 large-scale 다국어 모델입니다. auto-regressive Mixture-of-Experts (MoE) token (128 전문가, 8는 1 공유된 1 플러스 활성화된 128 전문가, 128 및 세계적인 주의 층을 interleaves 잡종 주의 계획을 사용하여 236B 총 매개 변수와 23B 활성 변압기. 그것은 6개의 언어를 다룹니다 — 한국어, 영어, 스페인어, 독일어, 일본어, 베트남어 — 그리고 두 reasoning 및 non-reasoningQQQQ 채팅을 지원합니다.

Furiosa-LLM는 K-EXAONE를 실행하며 NVFP4A16 (NVFP4는 16-bit 활성화와 KV cache를 가진 무게를 답니다). FuriosaAI는 pre-compiled NVFP4A16의 밑에 건설합니다 furiosa-ai 구성 요소가 Hugging Face 허브에 연결됨, 각 발송 Furiosa 실행 가능한 번들 (FXB)에 그것을 달리기를 위해 FuriosaAI RNGD Furiosa-LLM와 함께. 상류 중량은 다른 프레임 워크 (vLLM, SGLang 및 변압기와 같은); 그와 함께 사용, 아래 링크 업스트림 모델 카드를 참조하십시오.

사용#

Furiosa-LLM를 사용하여이 모델을 실행하려면 아래 예제 명령을 따르십시오 Furiosa-LLM 및 그 전제 조건 설치.

서버를 시작하세요#

모델들을 통과시키세요 furiosa-ai/K-EXAONE-236B-A23B-NVFP4A16 식별자; 모델은 4 RNGD 카드에서 실행됩니다. 기본으로 K-EXAONE 이유와 요청에 따라 사고를 전환 할 수 있습니다 (참고 발전 된 사용).

샐러드와 함께 deepseek_v3 생각의 체인이 별도의 필드에 반환되는 이유 :

furiosa-llm serve furiosa-ai/K-EXAONE-236B-A23B-NVFP4A16 \
  --reasoning-parser deepseek_v3 \
  --default-chat-template-kwargs '{"enable_thinking": true}'

The --default-chat-template-kwargs '{"enable_thinking": true}' 플래그는 채팅 템플릿을 유지하고 파서 정렬 : K-EXAONE의 채팅 템플릿은 기본적으로 생각하지만, deepseek_v3 추론 기능을 비활성화한 상태로 처리합니다 (단, ...에 따라 다름) enable_thinking set이므로 이 플래그없이 omits 요청 enable_thinking 원료가 누출될 것입니다 <think>...</think> 텍스트를 응답에 포함합니다.

또한 도구 (기능) 호출을 활성화하려면, 추가 hermes tool-call 파서 (지침 파서와 동일) --default-chat-template-kwargs 플래그는 여전히 자신의 필드에 파싱됩니다.

furiosa-llm serve furiosa-ai/K-EXAONE-236B-A23B-NVFP4A16 \
  --reasoning-parser deepseek_v3 \
  --default-chat-template-kwargs '{"enable_thinking": true}' \
  --enable-auto-tool-choice \
  --tool-call-parser hermes

서버가 준비되면 다음을 볼 수 있습니다.

기본 사용#

서버는 OpenAI 호환 API를 노출합니다. 요청을 보낼 수 있습니다. curl:

curl http://localhost:8000/v1/chat/completions \
    -H "Content-Type: application/json" \
    -d '{
    "model": "furiosa-ai/K-EXAONE-236B-A23B-NVFP4A16",
    "messages": [{"role": "user", "content": "What is the capital of France?"}]
    }' \
    | python -m json.tool

그리고 --reasoning-parser deepseek_v3, K-EXAONE는 마지막 대답에서 따로따로 그것의 reasoning를 돌려줍니다:

  • response.choices[].message.reasoning (non-streaming)

  • response.choices[].delta.reasoning [ 스트리밍 ]

K-EXAONE는 기본적으로 생각하므로 일반 요청은 두 가지 이유와 최종 응답을 반환합니다.

from openai import OpenAI

client = OpenAI(base_url="http://localhost:8000/v1", api_key="EMPTY")

response = client.chat.completions.create(
    model="furiosa-ai/K-EXAONE-236B-A23B-NVFP4A16",
    messages=[{"role": "user", "content": "How many r's are in 'strawberry'?"}],
)

print("Reasoning:", response.choices[0].message.reasoning)
print("Answer:", response.choices[0].message.content)

참고: The reasoning 필드는 OpenAI API 사양의 일부가 아니지만 다양한 컨벤션 (OpenAI Agents SDK, vLLM 및 기타)입니다. 그것은 그 대신 콘텐츠가 포함 된 응답에만 나타납니다. 그렇지 않으면 그에 도달 AttributeError.

발전 된 사용#

생각하는 것을 멈추는 것. 기본적으로 K-EXAONE 이유. 단일 요청에 대해 생각하기 위해, 패스 enable_thinking 통행 chat_template_kwargs; 응답은 그 후에 이유가 없는 내용을, 그래서 단지 읽습니다 message.content:

# Disable thinking for a single request
response = client.chat.completions.create(
    model="furiosa-ai/K-EXAONE-236B-A23B-NVFP4A16",
    messages=[{"role": "user", "content": "What is the capital of France?"}],
    extra_body={"chat_template_kwargs": {"enable_thinking": False}},
)
print(response.choices[0].message.content)

도구 호출. 서버를 [구체적인 정보 삽입]을 사용하여 시작할 때 --enable-auto-tool-choice --tool-call-parser hermes ( 참조) 서버를 시작하세요), 통과 tools 요청에서 모델을 결정할 때 호출합니다. 참조 도구 호출 가이드 tool-choice 옵션에 대한 완벽한 클라이언트 예 및 세부 사항.
