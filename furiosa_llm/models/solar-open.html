태양광 개방#

태양광 개방 large-scale open-weight 언어 모델은 Upstage에 의해 개발되었습니다. auto-regressive Mixture-of-Experts (MoE) 영어와 한국어를 지원하는 변압기, 그리고 그것은 두 가지 이유와 non-reasoning 채팅뿐만 아니라 도구 (기능) 호출을 처리.

Furiosa-LLM는 Solar Open을 실행합니다. NVFP4A16 (NVFP4는 16-bit 활성화와 KV cache를 가진 무게를 답니다). FuriosaAI는 pre-compiled NVFP4A16의 밑에 건설합니다 furiosa-ai 구성 요소가 Hugging Face 허브에 연결됨, 각 발송 Furiosa 실행 가능한 번들 (FXB)에 그것을 달리기를 위해 FuriosaAI RNGD Furiosa-LLM와 함께. 상류 중량은 다른 프레임 워크 (vLLM, SGLang 및 변압기와 같은); 그와 함께 사용, 아래 링크 업스트림 모델 카드를 참조하십시오.

사용#

Furiosa-LLM를 사용하여이 모델을 실행하려면 아래 예제 명령을 따르십시오 Furiosa-LLM 및 그 전제 조건 설치.

서버를 시작하세요#

모델에 다음을 제공합니다: solar_open 생각의 체인이 별도의 필드에 반환되는 이유 :

furiosa-llm serve furiosa-ai/Solar-Open-100B-NVFP4A16 \
  --reasoning-parser solar_open

또한 도구 (기능) 호출을 활성화하려면, 추가 solar_open : tool-call 파서; 저장 --reasoning-parser solar_open 그래서 생각은 여전히 자신의 필드에 패러다임 :

furiosa-llm serve furiosa-ai/Solar-Open-100B-NVFP4A16 \
  --reasoning-parser solar_open \
  --enable-auto-tool-choice \
  --tool-call-parser solar_open

서버가 준비되면 다음을 볼 수 있습니다.

INFO:     Started server process [27507]

기본 사용#

서버는 OpenAI 호환 API를 노출합니다. 요청을 보낼 수 있습니다. curl:

curl http://localhost:8000/v1/chat/completions \
    -H "Content-Type: application/json" \
    -d '{
    "model": "furiosa-ai/Solar-Open-100B-NVFP4A16",
    "messages": [{"role": "user", "content": "What is the capital of France?"}]
    }' \
    | python -m json.tool

그리고 --reasoning-parser solar_open, Solar Open은 최종 응답에서 별도로 주장을 반환:

  • response.choices[].message.reasoning (non-streaming)

  • response.choices[].delta.reasoning [ 스트리밍 ]

from openai import OpenAI

client = OpenAI(base_url="http://localhost:8000/v1", api_key="EMPTY")

response = client.chat.completions.create(
    model="furiosa-ai/Solar-Open-100B-NVFP4A16",
    messages=[{"role": "user", "content": "How many r's are in 'strawberry'?"}],
)

print("Reasoning:", response.choices[0].message.reasoning)
print("Answer:", response.choices[0].message.content)

참고: The reasoning 필드는 OpenAI API 사양의 일부가 아니지만 다양한 컨벤션 (OpenAI Agents SDK, vLLM 및 기타)입니다. 그것은 그 대신 콘텐츠가 포함 된 응답에만 나타납니다. 그렇지 않으면 그에 도달 AttributeError.

발전 된 사용#

추론 노력을 제어합니다. 요청 당 모델의 이유를 제어 할 수 있습니다. reasoning_effort 파라미터 ("low", "medium", or "high"; 결제 "high"). Solar Open의 채팅 템플릿은 생각 행동에 이것을 맵: "high" and "medium" 추론 과정을 생성합니다 — "high" 보다 큰 reasoning-token 예산을 허용 "medium" ⁇ 그 동안 "low" (그리고 "minimal") prefill는 빈 생각 구획 그래서 모형은 이유를 건너고 직접 대답합니다:

response = client.chat.completions.create(
    model="furiosa-ai/Solar-Open-100B-NVFP4A16",
    messages=[{"role": "user", "content": "How many r's are in 'strawberry'?"}],
    extra_body={"reasoning_effort": "high"},
)

print("Reasoning:", response.choices[0].message.reasoning)
print("Answer:", response.choices[0].message.content)

도구 호출. 서버를 [구체적인 정보 삽입]을 사용하여 시작할 때 --enable-auto-tool-choice --tool-call-parser solar_open ( 참조) 서버를 시작하세요), 통과 tools 요청에서 모델을 결정할 때 호출합니다. 참조 도구 호출 가이드 tool-choice 옵션에 대한 완벽한 클라이언트 예 및 세부 사항.
