Mooncake를 Furiosa-LLM와 함께 사용하는 것을 지원#

이 가이드는 Kubernetes에 Mooncake, cluster-wide 배포 KV cache 풀, Kubernetes에서 KV cache 공유를 동시에 사용할 수 있도록 Furiosa-LLM 팟을 배포하고 활용하는 방법을 설명합니다.

전제 조건#

  • Furiosa RNGD 장치가 장착 된 Kubernetes 클러스터.

  • 설치 furiosa-llm[mooncake] 또는 소스 코드에서 Mooncake 라이브러리 구축

  • Mooncake 스토어 라이브러리에 대한 라이브러리의 다음 세트를 설치:

    • 우분투: libcurl4 libibverbs1 rdma-core librdmacm1 libnuma1 liburing2

    • 로키 Linux / RHEL: libcurl libibverbs rdma-core librdmacm numactl-libs liburing

RNGD 클러스터 설정에 대한 자세한 지침은 참조하시기 바랍니다 사전 설치 and Kubernetes.

라이브러리 구축 Mooncake#

Furiosa-LLM는 Mooncake 라이브러리를 사용하여 6c721ee. Mooncake 설치 가이드 빌드 지침. 라이브러리는 다음과 같은 구성으로 구성됩니다:

cmake .. \
    -DBUILD_UNIT_TESTS=OFF \
    -DUSE_HTTP=ON \
    -DUSE_ETCD=ON \
    -DUSE_CUDA=OFF \
    -DWITH_EP=OFF \
    -DSTORE_USE_ETCD=ON \
    -DCMAKE_BUILD_TYPE=Release \
    -DWITH_STORE_C_SHARED=ON \
    -DBUILD_EXAMPLES=OFF \
    -DBUILD_BENCHMARK=OFF \
    -DWITH_STORE_GO=OFF \
    -DENABLE_DEBUG_SYMBOLS=OFF

이것은 libmooncake_store.so (그리고 그에 따른 종속성 libtransfer_engine.so). Furiosa-LLM는 그것을 연결하기 보다는 오히려 runtime에 이 도서관을 적재합니다, 그래서 그것입니다 not 뭉쳐서 furiosa-llm 휠; Furiosa-LLM에 사용할 수 있습니다. MOONCAKE_STORE_LIB_PATH 설명된 바와 같이 단계 4 아래쪽

단계 1: Mooncake 마스터 배포#

Mooncake Master Service는 Mooncake Storages 중 데이터 전송 및 KV cache 할당 정책을 조정합니다. 다음은 분산 메모리 풀로 활용되는 호스트 DRAM 및 SSD를 활성화하는 권장 Mooncake 마스터 배포입니다. 현재 Furiosa-LLM는 TCP-based Mooncake 마스터 서비스를 지원합니다.

apiVersion: apps/v1
kind: Deployment
metadata:
  name: mooncake-master
spec:
  replicas: 1
  selector:
    matchLabels:
      app: mooncake-master
  template:
    metadata:
      labels:
        app: mooncake-master
    spec:
      containers:
      - name: mooncake-master
        image: kvcacheai/mooncake:0.3.12.post1
        command:
        - mooncake_master
        args:
        - --rpc_address
        - $(POD_IP)
        - --rpc_port
        - "50051"
        - --rpc_thread_num=32
        - --http_metadata_server_host
        - $(POD_IP)
        - --http_metadata_server_port
        - "8080"
        - --enable_http_metadata_server
        - --enable_metric_reporting=true
        - --metrics_port
        - "9003"
        - --enable_offload=true
        - --offload_on_evict=true
        - --promotion_on_hit=true
        - --offloading_queue_limit=500000
        - --offload_cap_ratio=0.8
        - --default_kv_lease_ttl=300000
        - --enable_metadata_cleanup_on_timeout=true
        env:
        - name: POD_IP
          valueFrom:
            fieldRef:
              apiVersion: v1
              fieldPath: status.podIP
        - name: MC_TCP_ENABLE_CONNECTION_POOL
          value: "1"
        - name: MC_TE_METRIC
          value: "1"
        - name: MC_TE_METRIC_INTERVAL_SECONDS
          value: "10"
        ports:
        - containerPort: 8080
          name: http
          protocol: TCP
        - containerPort: 9003
          name: metrics
          protocol: TCP
        - containerPort: 50051
          name: rpc
          protocol: TCP
        readinessProbe:
          failureThreshold: 3
          initialDelaySeconds: 10
          periodSeconds: 10
          successThreshold: 1
          tcpSocket:
            port: 8080
          timeoutSeconds: 1

배포 적용:

kubectl apply -f deployment.yaml

참고: Mooncake 튜닝 가이드 유효한 모수 및 튜닝 가이드를 위해.

단계 2: 서비스로 Mooncake 주인을 드러냅니다#

Mooncake Master Service를 Kubernetes 클러스터에 노출시키려면 FQDN 해상도를 활성화하려면 Mooncake Master를 Kubernetes Service를 사용하여 Mooncake Master를 노출하십시오.

apiVersion: v1
kind: Service
metadata:
  name: mooncake-master
spec:
  ports:
  - name: http
    port: 8080
    protocol: TCP
    targetPort: 8080
  - name: metrics
    port: 9003
    protocol: TCP
    targetPort: 9003
  - name: rpc
    port: 50051
    protocol: TCP
    targetPort: 50051
  selector:
    app: mooncake-master

서비스를 적용:

kubectl apply -f service.yaml

단계 3: (선택) Deploy Mooncake 상점#

Furiosa-LLM는 L3 캐시가 활성화되면 자체 Mooncake 스토어를 출시하는 동안 안정성과 더 큰 메모리 풀을위한 전용 Mooncake Store를 출시하는 것이 좋습니다. 다음 구성은 TCP-based Mooncake Store를 배포하여 64GB의 호스트 DRAM 및 256GB의 SSD를 메모리 풀에 제공합니다. 교체 MOONCAKE_MASTER_SERVICE_FQDN 단계 2에서 생성된 서비스에서 얻어지는 FQDN로.

apiVersion: apps/v1
kind: Deployment
metadata:
  name: mooncake-store
spec:
  replicas: 1
  selector:
    matchLabels:
      app: mooncake-store
  template:
    metadata:
      labels:
        app: mooncake-store
    spec:
      containers:
      - name: mooncake-store
        image: kvcacheai/mooncake:0.3.12.post1
        command:
        - mooncake_client
        args:
        - --master_server_address=(MOONCAKE_MASTER_SERVICE_FQDN):50051
        - --metadata_server=http://(MOONCAKE_MASTER_SERVICE_FQDN):8080/metadata
        - --host=$(POD_IP)
        - --protocol=tcp
        - --global_segment_size=64GB
        - --enable_offload=true
        - --threads=32
        - --port=8088
        - --enable_http_server=true
        env:
        - name: POD_IP
          valueFrom:
            fieldRef:
              apiVersion: v1
              fieldPath: status.podIP
        - name: MOONCAKE_OFFLOAD_FILE_STORAGE_PATH
          value: /mnt/ssd_offload
        - name: MOONCAKE_OFFLOAD_LOCAL_BUFFER_SIZE_BYTES
          value: "8589934592"
        - name: MOONCAKE_OFFLOAD_TOTAL_SIZE_LIMIT_BYTES
          value: "274877906944"
        - name: MOONCAKE_OFFLOAD_BUCKET_MAX_TOTAL_SIZE
          value: "247390116249"
        - name: MOONCAKE_OFFLOAD_HEARTBEAT_INTERVAL_SECONDS
          value: "2"
        - name: MOONCAKE_OFFLOAD_USE_URING
          value: "true"
        - name: MC_TCP_ENABLE_CONNECTION_POOL
          value: "1"
        - name: MC_TE_METRIC
          value: "1"
        - name: MC_TE_METRIC_INTERVAL_SECONDS
          value: "10"
        ports:
        - containerPort: 8088
          name: mooncake
          protocol: TCP
        - containerPort: 9300
          name: metrics
          protocol: TCP
        readinessProbe:
          failureThreshold: 3
          initialDelaySeconds: 10
          periodSeconds: 10
          successThreshold: 1
          tcpSocket:
            port: 8088
          timeoutSeconds: 1
        resources:
          limits:
            ephemeral-storage: 256Gi
            memory: 80Gi
          requests:
            ephemeral-storage: 256Gi
            memory: 80Gi
        volumeMounts:
        - mountPath: /mnt/ssd_offload
          name: ssd-offload
      volumes:
      - emptyDir: {}
        name: ssd-offload

배포 적용:

kubectl apply -f deployment.yaml

단계 4: Furiosa-LLM를 Mooncake에 연결하십시오#

Furiosa-LLM 팟에서 다음 환경 변수를 설정하여 Mooncake를 사용합니다. 다음 환경 변수는 Furiosa-LLM에 TCP 기반의 Mooncake 전송 프로토콜을 활성화하며, 6.25 GiB의 호스트 DRAM이 분산 메모리 풀에 기여합니다.

Furiosa-LLM는 Mooncake를 묶지 않습니다: furiosa-llm 휠 링크 Mooncake 라이브러리 및 유지 야윈. L3이 활성화되면 Furiosa-LLM 검색 libmooncake_store.so 뒤에 오는 순서에 있는 첫번째 사용:

  1. 다음 디렉토리를 지정합니다. MOONCAKE_STORE_LIB_PATH.

  2. 설치되는 라이브러리 경로 furiosa-llm-mooncake 파이프 패키지

  3. 역동적 인 링크터의 정상적인 모습 soname, 디렉토리를 포함 하 여 LD_LIBRARY_PATH 및 시스템 라이브러리 경로.

  4. 이 소스의 none가 사용 가능한 라이브러리를 제공한다면 설정 오류를 보고하십시오.

설정 오류는 경고로 기록되며 Furiosa-LLM는 실패 대신 L2-only를 실행합니다.

export L3_ENABLED=1
export MOONCAKE_STORE_LIB_PATH=/path/to/mooncake_store
export MOONCAKE_MASTER=(MOONCAKE_MASTER_SERVICE_FQDN):50051
export MOONCAKE_TE_META_DATA_SERVER=http://(MOONCAKE_MASTER_SERVICE_FQDN):8080/metadata
export MOONCAKE_PROTOCOL=tcp
export MOONCAKE_LOCAL_HOSTNAME=$(hostname -i)
export MC_TCP_ENABLE_CONNECTION_POOL=1
export L3_GLOBAL_SEGMENT_SIZE=6710886400
export L3_LOCAL_BUFFER_SIZE=2147483648
export L3_NAMESPACE=(Desired Mooncake Namespace)
