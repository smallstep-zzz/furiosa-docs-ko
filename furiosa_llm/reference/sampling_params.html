SamplingParams 클래스#

클래스 furiosa_llm샘플링제품(*, n: int = 1, repetition_penalty: 파운드 = 1.0, temperature: 파운드 = 1.0, top_p: 파운드 = 1.0, top_k: int = -1, min_p: 파운드 = 0.0, 멈춰라: str | 목록[str] | None = None, stop_token_ids: 목록[int] | None = None, include_stop_str_in_output: bool = False, ignore_eos: bool = False, max_tokens: int | None = 16, min_tokens: int = 0, skip_special_tokens: bool = True, 로그보드: int | None = None, prompt_logprobs: int | None = None, output_kind: 요청OutputKind = RequestOutputKind.CUMULATIVE, structured_outputs: 구조화된 OutputsParams | None = None, reasoning_structured_outputs: 구조화된 OutputsParams | None = None, extra_args: 명령 | None = None)[원]#

기본: object

텍스트 생성을위한 Sampling 매개 변수.

매개 변수:

  • n – 주어진 prompt를 위한 반환에 산출 순서의 수.

  • repetition_penalty – prompt와 지금까지 생성 된 텍스트에 나타나는지 여부를 기준으로 새로운 토큰을 포괄하는 Float. Values > 1는 새로운 토큰을 사용하는 모델을 권장합니다. 값 < 1는 토큰을 반복하는 모델을 권장합니다.

  • temperature – sampling의 임의성을 제어하는 Float. 더 낮은 값은 모델보다 세분화되어 더 높은 값이 모델보다 무작위로 만듭니다. Zero는 sampling를 의미합니다.

  • top_p – 고려할 토큰의 누적 확률을 제어하는 Float. (0, 1]에 있어야합니다. 1로 설정하여 모든 토큰을 고려하십시오.

  • top_k – 고려해야 할 최고 토큰의 수를 제어하는 정수. 모든 토큰을 고려하기 위해 -1로 설정하십시오.

  • min_p – token에 대한 최소 확률을 나타내는 Float는 가장 가능성이 token의 확률과 상대로 간주됩니다. [0, 1]에 있어야합니다. 0로 설정하여 이것을 비활성화하십시오.

  • 멈춰라 – 목록 또는 단일 non-empty 문자열(s)는 첫 번째 문자열이 일치할 때 생성을 중지합니다. 기본적으로, 일치된 스톱 문자열은 반환된 텍스트에서 제거됩니다. 스트리밍할 때, Furiosa-LLM는 가장 긴 구성된 스톱 문자열까지 추적 창을 유지하여 방출되는 부분 일치를 방지할 수 있습니다.

  • stop_token_ids – 생성될 때 생성을 중지하는 Token ID. 반환된 출력은 정지 토큰이 특별한 토큰이 없는 중지 토큰을 포함합니다.

  • include_stop_str_in_output - 반환된 텍스트의 일치한 정지 문자열을 유지 여부. False에 기본값. True가 완료된 token 내에서 일치 후 텍스트가 제거됩니다. 스트리밍은이 모드에서 stop-string 창을 추적 할 필요가 없습니다.

  • ignore_eos – EOS token를 무시하고 EOS token가 생성된 후 토큰을 생성하는 것.

  • max_tokens – 출력 시퀀스 당 생성하는 토큰의 최대 수. 값이 None인 경우 최대 시퀀스 길이로 캡핑됩니다.

  • min_tokens – EOS 또는 stop_token_ids 이전에 출력 시퀀스 당 생성하는 토큰의 최소 수는 생성될 수 있습니다.

  • skip_special_tokens – 출력에 있는 특별한 토큰을 건너는 것.

  • 로그보드 – 출력당 반환할 로그 확률의 개수 ZXQ. None로 설정하면 확률이 반환되지 않습니다. None 이외의 값을 설정하면 지정된 개수의 가장 가능성 있는 토큰의 로그 확률뿐만 아니라 선택된 토큰도 포함된 결과를 얻을 수 있습니다. 참고: 구현은 OpenAI, API를 따릅니다. API는 항상 샘플링된 token의 로그 확률을 반환하므로, 최대 로그보드+1 응답에서 요소.

  • prompt_logprobs 까지의 로그 확률을 얻을 수 있습니다. 경고: -1를 사용하여 중요한 메모리와 네트워크 오버 헤드를 유발할 수 있습니다. 전체 어휘 (e.g., 각 prompt 위치에 Qwen 모델의 ~150K 토큰).

  • structured_outputs – Structured 출력 요구 사항을 지정하는 매개 변수.

  • reasoning_structured_outputs – 모델 출력의 원인과 일치하는 매개 변수. 이것은 응답 내용에 구조 출력 요구 사항을 적용하기 전에 이유 토큰을 스트립하는 데 사용됩니다.

  • extra_args - 표준 sampling 매개 변수와 함께 수행되는 중재 추가 인수. API 요청의 모든 추가 (undeclared) 키는 여기에 수집됩니다. 특정 소비자는 그들이 돌보는 키를 추출; e.g. kv_transfer_params 이 딕셔너리에서 추출됩니다.

  • kv_transfer_params – 원격 KV 커넥터의 액세스 포인트, 추출 extra_args["kv_transfer_params"]. 2개의 ZMQ 엔드포인트 중 하나가 있을 수 있습니다 ("host:port"): "remote_decoder" and "remote_prefiller". 설정된 경우, worker는 PD-disaggregated prefill 또는 디코딩을 활성화하기 위해 주어진 endpoint에 연결됩니다. "id" P-D 쌍의 공유 식별자입니다: 그것은 prefiller와 암호해독기 둘 다에 동일한 값이어야 하고, 연결관은 2개의 측과 일치하기 위하여 그것을 이용합니다.

기본 샘플링 파라미터는 generation_config.json#

모델 저장소 또는 로컬 디렉토리가 포함 된 경우 generation_config.json 파일, Furiosa-LLM는 아래 나열된 필드에 효과적인 기본으로 값을 사용합니다. 이 값은 소스 모델 구성에서 직접 읽고 사용자 정의되지 않습니다. 파일이 absent 인 경우, 일반 SamplingParams() 기본값이 적용됩니다.

아래와 같이 generation_config.json 키는 존중되며, 다음과 같이 매핑됩니다. SamplingParams 표시된 필드:

오프라인 API (LLM.generate / LLM.chat / LLM.stream_generate)#

: 오프라인 API는 바이너리 결정 호출자가 전달하는 경우 sampling_params:

  • sampling_params=None (기본 설정) — 모델의 generation_config.json 기본 설정이 적용됩니다. furiosa_llm.LLM.get_default_sampling_params().

  • sampling_params=SamplingParams(...) — 사용자의 객체는 as-is를 사용합니다. 모델의 per-field 병합이 없습니다. generation_config.json 수행됩니다.

OpenAI 호환 서버#

Chat Completions, Completions 및 응답 엔드포인트는 세 계층의 각 sampling 관련 필드를 해결합니다.

  1. 요청 몸에서 지정된 값은 설정된 경우.

  2. 모델의 generation_config.json, 현존하는 경우

  3. API 기본값은 endpoint의 매개 변수 테이블에 표시됩니다. API 챗 (/v1/chat/completions), 완료 API (/v1/completions), 그리고 API 참조).

예제#

이 섹션은 SDK에서 사용할 수있는 token 세대 방법을 사용하는 방법을 제공합니다.

1. 기본적인 탐욕적 검색#

SamplingParams(min_tokens=10, max_tokens=100)

Basic Greedy Search 메소드는 토큰의 순서를 생성하고 최소한의 것을 보장합니다. min_tokens 그리고 max_tokens 생산됩니다.

  • 매개 변수:

    • min_tokens: 생성하는 토큰의 최소 수.

    • max_tokens: 생성하기 위한 토큰의 최대 수.

  • 행동:

    • 세대는 도달하기 전에 종결 될 수있다 max_tokens Sequence (EOS) token의 끝이 생성되는 경우에.

    • EOS token는 지정된 도달하기 전에 생성되지 않습니다 min_tokens.

2. 무작위 샘플링을 지원하며 top_p / top_k 매개 변수#

SamplingParams(min_tokens=10, max_tokens=100, top_p=0.3, top_k=100)

이 방법은 token 세대의 임의 sampling 기술을 사용하여 다양한 출력을 허용합니다.

  • 매개 변수:

    • min_tokens: 생성하는 토큰의 최소 수.

    • max_tokens: 생성하기 위한 토큰의 최대 수.

    • top_p: nucleus sampling를 위한 Cumulative 확률.

    • top_k: 가장 높은 확률 토큰의 수를 고려합니다.

  • 행동:

    • 각 세대는 동일한 입력 텍스트 및 매개 변수와 다른 결과를 산출 할 수 있습니다, variability을 강화.

    • 세대는 도달하기 전에 종결 될 수있다 max_tokens Sequence (EOS) token의 끝이 생성되는 경우에.

    • EOS token는 지정된 도달하기 전에 생성되지 않습니다 min_tokens.

3 스톱 문자열#

non-empty 문자열 목록을 전달하고 stop 첫 번째 문자열이 일치할 때 최종 세대. 기본적으로, 일치 문자열은 반환된 텍스트에서 제거됩니다. stop-string 일치 세트 finish_reason to "stop" 을 기록하고, 일치하는 문자열을 stop_reason:

params = SamplingParams(stop=["<END>"])
output = llm.generate("Write a short answer.", params)[0].outputs[0]
# If the model generates "Answer<END>", output.text is "Answer".
# output.stop_reason is "<END>".

Set include_stop_str_in_output=True 일치 문자열을 유지하려면. token를 완료하면 일치하는 문자는 여전히 제거됩니다.

params = SamplingParams(
    stop=["<END>"],
    include_stop_str_in_output=True,
)
output = llm.generate("Write a short answer.", params)[0].outputs[0]
# If the model generates "Answer<END>", output.text is "Answer<END>".

기본 배제 동작을 가진 스트림 출력을 위해 Furiosa-LLM는 가장 긴 설정된 정지 문자열까지 추적 창을 지연시킬 수 있으므로 부분 일치는 출력으로 누출되지 않습니다. Retained-stop 모드는 지연이 필요하지 않습니다.
