응답 API#

Furiosa-LLM는 다음을 구현합니다. OpenResponses 사양, multi-provider, 상호 운용 가능한 LLM 인터페이스. 응답 API는 채팅 템플릿으로 텍스트 생성 모델을 사용할 수 있습니다. 그것은 텍스트 입력, 호환 vision-language 모델과 이미지 입력, 스트리밍, multi-turn 대화, 도구와 함께 호출 tool_choice 제어 ( 참조) 도구 호출 지원), 및 JSON Schema를 통해 구조상 산출.

참고

다음 OpenResponses 사양의 기능은 아직 지원되지 않습니다:

  • 오디오 및 파일 입력 — input_audio 및 input_file은 지원되지 않습니다. 이미지는 input_image.image_url을 필요로 합니다. 파일 ID만으로 지정된 이미지는 거부됩니다.

  • 내장된 도구 — web_search, file_search, code_interpreter, computer_use, mcp 도구는 지원되지 않습니다. 단, 사용자 정의 함수 도구만 사용 가능합니다.

  • 백그라운드 처리 — background=true는 허용되지만, 아무런 효과가 없습니다.

  • 자동 자르기 — truncation="auto"는 허용되지만, "disabled"만 구현되어 있습니다. (자동으로 잘림 기능)

엔드포인트#

  • POST /v1/responses — 응답 생성 (스트리밍 또는 비스트리밍)

  • GET /v1/responses/{response_id} — 저장된 응답 조회

  • POST /v1/responses/{response_id}/cancel — 진행 중인 응답 취소

응답 저장소#

응답 저장소는 응답을 메모리에 보관하여 나중에 검색하거나, 다중 대화 시 이전 응답의 previous_response_id를 사용하여 참조할 수 있도록 합니다. 저장소는 기본적으로 비활성화되어 있으며, --enable-responses-api-store 서버 옵션을 명시적으로 활성화해야 합니다.

furiosa-llm serve [MODEL_ID_OR_PATH] --enable-responses-api-store

다음 서버 옵션은 저장소 동작을 제어합니다:

옵션

기본값

설명

--enable-responses-api-store

거짓 (false)

메모리 기반 응답 저장소를 활성화합니다.

--responses-api-store-max-entries

10000

저장할 응답의 최대 개수. 제한이 도달하면 가장 오래된 항목이 삭제됩니다.

--responses-api-store-ttl

3600

저장된 응답의 보존 기간 (초 단위).

스토어가 활성화되어 있고, 요청에서 store=true가 설정된 경우 (기본값), 서버는 응답과 전체 채팅 메시지 기록을 저장합니다. 이를 통해 다음 기능을 사용할 수 있습니다.

  • GET /v1/responses/{response_id}를 통해 응답 검색.

  • POST /v1/responses/{response_id}/cancel을 통해 응답 취소.

  • previous_response_id를 사용한 멀티턴 대화

특정 요청에 대한 저장 기능을 건너뛰려면, store=false로 설정합니다.

저장 기능을 비활성화하면, GET /v1/responses/{response_id}, POST /v1/responses/{response_id}/cancel, 그리고 previous_response_id는 사용할 수 없습니다.

참고

저장된 응답과 그 대화 기록은 메모리에 저장되며, 서버가 재시작될 때 사라집니다. 대량의 저장된 응답을 예상하는 경우, 서버의 메모 소비를 모니터링하십시오.

다중 턴 대화#

Responses API는 다중 턴 대화를 위한 두 가지 방법을 지원합니다:

previous_response_id 사용 (권장)#

서버는 참조된 응답에서 저장된 대화 기록을 자동으로 추가합니다. 이는 가장 간단한 방법이며, 참조된 응답에 대해 store=true를 설정해야 합니다.

previous_response_id는 대화 기록을 포함하지만, 이전 요청의 media_io_kwargs 또는 mm_processor_kwargs를 상속하지 않습니다. 각 요청은 현재 서버의 기본 설정에 따라 이러한 옵션을 해결합니다. 저장된 기록에서 이미지를 처리할 때도 마찬가지입니다. 필요한 경우 원하는 설정을 다시 지정하십시오.

import os
from openai import OpenAI

base_url = os.getenv("OPENAI_BASE_URL", "http://localhost:8000/v1")
api_key = os.getenv("OPENAI_API_KEY", "EMPTY")
client = OpenAI(api_key=api_key, base_url=base_url)
model = client.models.list().data[0].id

# Turn 1: store the response for later continuation
res1 = client.responses.create(
    model=model,
    input="My name is Alice.",
    store=True,
)
print(f"Turn 1: {res1.output[0].content[0].text}")
print(f"Response ID: {res1.id}")

# Turn 2: continue the conversation using previous_response_id
res2 = client.responses.create(
    model=model,
    input="What is my name?",
    previous_response_id=res1.id,
    store=True,
)
print(f"Turn 2: {res2.output[0].content[0].text}")

수동 컨텍스트 사용#

대안으로, 이전 출력 항목을 승인하여 대화 컨텍스트를 수동으로 구축 할 수 있습니다. input 배열:

# Turn 1
res1 = client.responses.create(model=model, input="My name is Alice.")

# Turn 2: manually include previous context
context = [{"role": "user", "content": "My name is Alice."}]
context += res1.output
context.append({"role": "user", "content": "What is my name?"})
res2 = client.responses.create(model=model, input=context)

예제#

기본 사용법:

import os
from openai import OpenAI

base_url = os.getenv("OPENAI_BASE_URL", "http://localhost:8000/v1")
api_key = os.getenv("OPENAI_API_KEY", "EMPTY")
client = OpenAI(api_key=api_key, base_url=base_url)
model = client.models.list().data[0].id

# Non-streaming
response = client.responses.create(
    model=model,
    input="What is the capital of France?",
)
print(response.output[0].content[0].text)

스트리밍:

import os
from openai import OpenAI

base_url = os.getenv("OPENAI_BASE_URL", "http://localhost:8000/v1")
api_key = os.getenv("OPENAI_API_KEY", "EMPTY")
client = OpenAI(api_key=api_key, base_url=base_url)
model = client.models.list().data[0].id

with client.responses.stream(
    model=model,
    input="What is the capital of France?",
) as stream:
    for event in stream:
        if event.type == "response.output_text.delta":
            print(event.delta, end="", flush=True)
print()

이미지 입력#

호환 가능한 비전-언어 서버를 시작합니다 (예: furiosa-llm serve furiosa-ai/Qwen3-VL-32B-Instruct), 그런 다음 input_text와 함께 input_image 부분을 전송합니다:

import os
from openai import OpenAI

client = OpenAI(
    base_url=os.getenv("OPENAI_BASE_URL", "http://localhost:8000/v1"),
    api_key=os.getenv("OPENAI_API_KEY", "EMPTY"),
)
response = client.responses.create(
    model=client.models.list().data[0].id,
    input=[{
        "role": "user",
        "content": [
            {"type": "input_text", "text": "Describe this image."},
            {
                "type": "input_image",
                "image_url": "https://developer.furiosa.ai/latest/en/_images/Furiosa_RNGD_image.png",
                "detail": "auto",
            },
        ],
    }],
    max_output_tokens=32,
    extra_body={
        "media_io_kwargs": {"image": {"timeout": 10}},
        "mm_processor_kwargs": {"min_pixels": 1024},
    },
)
print(response.output_text)

input_image.image_url URL 문자열입니다. HTTP(S) URL, Base64를 수용합니다. data: URL 및 지역 file:// 허용된 URL --allowed-local-media-path. 원격 URL는 준수합니다 --allowed-media-domains, 그리고 이미지 개수는 응답에 포함됩니다. --image-limit-per-prompt. A file_id 무단 image_url HTTP 400로 거부됨. 다음을 참조하십시오. Vision-Language 모델과 함께 구성됩니다. 입력 형식 및 멀티모달 옵션 — 기본값 및 요청 덮어쓰기를 위해

API 참조#

설명이 없는 매개변수는 해당 OpenResponses 사양의 해당 매개변수에서 동작 및 기능을 상속받습니다.

참고

샘플링 관련 필드 (temperature, top_p, top_k, max_output_tokens, stop)에 대해서는 각 필드가 다음 순서로 해석됩니다:

  1. 요청 본문에 지정된 값 (해당하는 경우).

  2. 모델의 generation_config.json에 정의된 값 (max_output_tokens은 max_new_tokens에서 채워집니다).

  3. 아래 파라미터 테이블에 표시된 API 기본값.

See generation_config.json의 기본 Sampling 매개 변수 supported-field 맵핑 및 offline-API 행동을 위해.
