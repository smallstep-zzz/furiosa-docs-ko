도구 호출#

도구 호출 (일컬어 함수 호출) 모델은 외부 도구와 API와 상호 작용할 수 있습니다. Furiosa-LLM는 이 기능으로 훈련 된 모델에 대한 도구 통화를 지원합니다.

도구 호출 파서#

시스템은 지정된 파서 구현을 통해 OpenAI 응답 형식으로 모델 출력을 변환합니다. 파서를 호출하는 도구는 model-dependent이며, 다른 모델은 도구 통화에 대한 다른 형식을 사용합니다.

현재 Furiosa-LLM는 다음과 같은 도구가 파서스를 호출합니다.

  • hermes: 헤르메스 도구 호출 형식 (e.g., EXAONE-4.0, Qwen3 시리즈)를 사용하여 모델. Qwen3-Coder는 Qwen3 시리즈 내에서 예외입니다. 사용 qwen3_xml 그 때문에

  • llama3_json: Llama 시리즈 모델 용 (e.g., Llama 3.1, Llama 3.2)

  • openai: OpenAI 툴을 사용하여 모델의 경우 형식을 호출 (e.g., gpt-oss-20b, gpt-oss-120b)

  • gemma4: Gemma 4 모델에 대해

  • qwen3_xml (명칭) qwen3_coder): Qwen3-Coder 모형을 위해, 그의 채팅 템플렛은 XML 외침 체재를 요구합니다 (<tool_call><function=...><parameter=...>) 대신 Hermes JSON를 사용하는 경우.

자동 도구 호출을 위해, 서버를 시작 --enable-auto-tool-choice 그리고 적절한 파서 선택 --tool-call-parser.

도구 선택 옵션#

The tool_choice 매개 변수는 모델이 호출하는 도구를 선택하는 방법을 제어합니다. Furiosa-LLM는 다음과 같은 옵션을 지원합니다.

  • auto (기본 도구가 공급될 때): 모델은 도구로 호출하거나 대화 상황에 따라 직접 응답할 것인지 결정합니다.

  • none (기본 도구가 공급되지 않을 때): 요청을 호출하는 도구가 비활성화됩니다.

  • required: 적어도 하나의 도구를 호출하는 모델을 강제합니다. 이 모델은 도구 호출없이 응답 할 수 없습니다.

  • {"type": "function", "function": {"name": "<function_name>"}}: 특정 이름 함수를 호출하는 모델을 강제합니다.

이 옵션은 스트리밍 및 non-streaming Chat Completions 요청을 모두 적용하여 툴 호출을 지원하는 모델입니다.

non-empty를 공급 tools 목록 required 또는 이름 함수 선택. 이러한 선택의 경우, 도구의 JSON 스키마에 서버 제약 생성 및 결과 반환 tool_calls.

그리고 tool_choice="none", 도구 정의는 prompt 및 도구 호출에서 부유 한 응답에 억제됩니다.

더 자세한 내용은 도구 호출 사양에 대한, 참조 OpenAI 채팅 API 문서를 참조.

Named Function Calling을 사용한 온라인 예#

Named Function Calling을 사용한 온라인 예#
import json
import os
from openai import OpenAI

base_url = os.getenv("OPENAI_BASE_URL", "http://localhost:8000/v1")
api_key = os.getenv("OPENAI_API_KEY", "EMPTY")
client = OpenAI(base_url=base_url, api_key=api_key)

def get_weather(location: str, unit: str):
    return f"Getting the weather for {location} in {unit}..."

def get_time(timezone: str):
    return f"Getting the current time in {timezone}..."

tools = [
    {
        "type": "function",
        "function": {
            "name": "get_weather",
            "description": "Get the current weather in a given location",
            "parameters": {
                "type": "object",
                "properties": {
                    "location": {"type": "string", "description": "City and state, e.g., 'San Francisco, CA'"},
                    "unit": {"type": "string", "enum": ["celsius", "fahrenheit"]}
                },
                "required": ["location", "unit"]
            }
        }
    },
    {
        "type": "function",
        "function": {
            "name": "get_time",
            "description": "Get the current time in a given timezone",
            "parameters": {
                "type": "object",
                "properties": {
                    "timezone": {"type": "string", "description": "Timezone, e.g., 'America/Los_Angeles'"}
                },
                "required": ["timezone"]
            }
        }
    }
]

# The user asks for both weather and time, but ``tool_choice`` forces the
# model to call ``get_weather`` only. The response is constrained to
# ``get_weather``'s schema, so the model cannot smuggle a ``timezone``
# argument (which belongs to ``get_time``) into the call.
response = client.chat.completions.create(
    model=client.models.list().data[0].id,
    messages=[{"role": "user", "content": "What's the weather and time in San Francisco?"}],
    tools=tools,
    tool_choice={"type": "function", "function": {"name": "get_weather"}},  # Force specific function
    temperature=0.0,
)

tool_call = response.choices[0].message.tool_calls[0].function
print(f"Function called: {tool_call.name}")
print(f"Arguments: {tool_call.arguments}")
assert tool_call.name == "get_weather", f"Expected 'get_weather' but got '{tool_call.name}'"
print(f"Result: {get_weather(**json.loads(tool_call.arguments))}")
