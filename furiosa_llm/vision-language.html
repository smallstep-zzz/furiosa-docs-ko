Vision-Language 모델과 함께 구성됩니다.#

Furiosa-LLM는 OpenAI와 API와 API를 통해 텍스트 및 이미지를 받아 들여지는 Vision-Language (VL) 모델을 제공합니다. 답변 API. 첫번째 지원된 건축은 입니다 Qwen3-VL (e.g., Qwen/Qwen3-VL-32B-Instruct); 참조 지원 된 모델 권위 있는 목록을 위해.

이미지 입력은 리모트로 통과될지도 모릅니다 https:// URL, 베이스64 data: URL, 또는 지역 file:// 경로. 사전 처리 (저장, 패치, prompt-token 확장)는 Hugging Face에 의해 처리됩니다 AutoProcessor 모델에 기본적으로 포함된 구성품.

참고

Video 입력은 현재 지원되지 않습니다. 지원이 계획 중입니다 Furiosa SDK 2026.5.0.

빠른 시작#

호환 FXB를 포함하는 vision-language 모델로 서버를 실행:

furiosa-llm serve furiosa-ai/Qwen3-VL-32B-Instruct

이미지와 텍스트 prompt와 chat-completion 요청 보내기:

curl http://localhost:8000/v1/chat/completions \
    -H "Content-Type: application/json" \
    -d '{
    "model": "Qwen/Qwen3-VL-32B-Instruct",
    "messages": [
        {
            "role": "user",
            "content": [
                {
                    "type": "image_url",
                    "image_url": {
                        "url": "https://developer.furiosa.ai/latest/en/_images/Furiosa_RNGD_image.png"
                    }
                },
                {"type": "text", "text": "Describe this image in one short sentence."}
            ]
        }
    ],
    "max_tokens": 128
    }' \
    | python -m json.tool

( Python 예제 Python 클라이언트 예제의 아래 섹션).

이미지 입력 형식#

The image_url.url chat-completion 메시지의 필드는 3 URL 계획을 받아들입니다:

  1. 원격 URL (http:// / https://) — 서버는 이미지를 fetches httpx.

    {
  "type": "image_url",
  "image_url": {"url": "https://example.com/photo.png"}
}

  2. 데이터베이스64 URL — 인라인 페이로드에 유용합니다:

    {
  "type": "image_url",
  "image_url": {"url": "data:image/png;base64,iVBORw0KGgoAAAANSUh..."}
}

  3. 로컬 파일 (file://) - 기본적으로 비활성화; 필요 --allowed-local-media-path 서버 플래그 (아래 참조).

    {
  "type": "image_url",
  "image_url": {"url": "file:///srv/media/photo.png"}
}

요청에는 여러 image_url 는 text 부품. 모델의 채팅 템플릿은 이미지 홀더가 prompt로 렌더링되는 방법을 제어합니다.

  • OpenAI 형식의 채팅 템플릿 (일반적인 경우) 반복합니다. content 자체적으로, 그래서 이미지 placeholders 토지는 원래 위치에 자동으로 - 추가 서버 플래그가 필요하지 않습니다.

  • String-format 템플릿 납작한 content 단일 텍스트 문자열로. 기본적으로, 어떤 이미지에 대한 위주자는 prompt에 prepended; 패스 --interleave-mm-strings 대신 자신의 원래 위치에 보관하십시오.

멀티모달 옵션#

media_io_kwargs 사용 image 객체 mm_processor_kwargs 프로세서 옵션 및 옵션 허용 images_kwargs. videos_kwargs and audio_kwargs 현재는 이미지 처리가 지원되기 때문에 거부됩니다. CLI와 서버 기본값을 설정하십시오:

furiosa-llm serve furiosa-ai/Qwen3-VL-32B-Instruct \
    --media-io-kwargs '{"image": {"timeout": 10}}' \
    --mm-processor-kwargs '{"min_pixels": 1024}'

Chat Completions 및 Responses 요청은 이러한 기본값을 override 할 수 있습니다. media_io_kwargs and mm_processor_kwargs JSON 요청 몸에서. OpenAI Python 클라이언트로, 이 필드를 통해 전달 extra_body:

import os
from openai import OpenAI

client = OpenAI(
    base_url=os.getenv("OPENAI_BASE_URL", "http://localhost:8000/v1"),
    api_key=os.getenv("OPENAI_API_KEY", "EMPTY"),
)
response = client.chat.completions.create(
    model=client.models.list().data[0].id,
    messages=[{
        "role": "user",
        "content": [
            {"type": "image_url", "image_url": {
                "url": "https://developer.furiosa.ai/latest/en/_images/Furiosa_RNGD_image.png"
            }},
            {"type": "text", "text": "Describe this image."},
        ],
    }],
    max_completion_tokens=32,
    extra_body={
        "media_io_kwargs": {"image": {"timeout": 5}},
        "mm_processor_kwargs": {"min_pixels": 4096},
    },
)
print(response.choices[0].message.content)

Overrides는 해당 요청에만 적용되며 서버 기본값을 변경하지 않습니다. 사전 설정, 설정 null, 또는 통과 {} 기본값을 유지합니다. 두 개의 사전에는 다음과 같은 다른 합병 규칙이 있습니다.

프로세서 옵션#

요청 키는 일치 top-level 프로세서 기본을 대체, 전체 배열 개체를 포함. 예를 들어, override of size 는 전체 기본 설정을 대체합니다. size 그 차원을 merging 보다는 오히려 목표.

Image-specific 옵션은 공급할 수 있습니다. images_kwargs:

{"mm_processor_kwargs": {"min_pixels": 1024, "images_kwargs": {"max_pixels": 200704}}}

이 두 컨트롤을 사용합니다. 요청의 images_kwargs 전체를 대체합니다. 기본 설정 images_kwargs 객체 {"images_kwargs": {}} 그룹을 명확하고 나머지 top-level 옵션을 유지합니다. 옵션은 최고 수준과 내부에 모두 나타나지 않아야합니다. images_kwargs기본 및 요청 옵션이 결합된 후 ,. 이 값이 동등할 때 모든 옵션 이름에 적용된다.

등록된 이미지 프로세서 옵션#

카탈로그 목록은 모든 상류 프로세서 аргументи보다는 runtime 컨트롤을 권장합니다. 아래의 일반적인 옵션은 Qwen-VL, EXAONE 4.5 및 Gemma 4에 적용됩니다. EXAONE는 추가 window-aligned 크기를 변경하는 Qwen 이미지 프로세서를 사용합니다. 기본값은 로드 프로세서 구성에서 발생합니다. 테이블은 트랜스포머 5.8 클래스 패러백을 보여줍니다. 체크포인트 구성은 정상화 값을 포함하여 그들을 초과 할 수 있습니다. 허용된 옵션은 해당 로드 된 기본값을 사용합니다. null 일반적으로 배출과 동일하지 않습니다.

정수: 70, 140, 280, 560, or 1024

이미지 및 컴파일된 용량에 대한 자동 선택, 로드된 프로세서 제한에서 시작 (HF fallback: 280).

FXB 비전 버킷없이, sizing은로드 프로세서의 설정으로 돌아갑니다. images and return_tensors runtime에 의해 공급되고 사용자 가공업자 선택권이 아닙니다.

문자열, 불리언, 부동 소수점 숫자 등이 포함됩니다. null 거절당하는 경우 min_pixels, max_pixels, 그리고 max_soft_tokens. 과태, 요청 overrides 및 합병 결과가 검증됩니다. Cross-field 경계는 결합 된 옵션에 체크됩니다. 등록 된 옵션은 계속 통과합니다. 로드 된 프로세서는 지원 여부를 결정합니다. 이 옵션은 캐시 정체성에 참여합니다.

처리는 로드 된 FXB의 컴파일된 시각 용량에 따라 남아 있습니다. 유효한 옵션 값은 혼자 이미지 적합을 보장하지 않습니다. 변환기는 용량 검사 및 출력 변환에 대한 로드 된 프로세서의 패치 및 결합 기하학을 계속 사용합니다. 기하학 오버라이드는 동의해야합니다.

처리 캐시는 건너뛰기 이미지 처리를 기록합니다. 그들의 열쇠는 서버 과태 후에 공급한 가공업자 kwargs를 포함하고 요구 overrides는 합병되고 images_kwargs flattened입니다. 공급된 선택권을 그런 것과 같이 바꾸기 do_rescale 별도의 캐시 입력을 선택합니다. 캐시되지 않은 옵션 세트를 요청할 때 이미지를 다시 공급하십시오. UUIDs는 여전히 원본 이미지를 식별합니다.

프로세서 구성 기본 및 자동 선택된 sizing 값은 사전 처리 키에 추가되지 않습니다. 옵션을 조정하고 기본적으로 다른 항목을 선택 할 수 있습니다. 재사용 여전히 기존에 적용 min_pixels / max_pixels checks for Qwen-VL and EXAONE 4.5, or the max_soft_tokens Gemma 4에 대한 체크. 요청한 경계 밖에 서 항목은 눈에 떨어지고 처리됩니다. 이 체크는 자동으로 크기 캐시 된 결과가 신선한 가공 실행에 일치한다는 것을 보장하지 않습니다.

유효성 오류#

잘못된 요청 옵션 반환 HTTP 400 또는 422; 잘못된 오프라인 옵션 인상 ValueError. 잘못된 CLI 옵션 구조 또는 fetch 옵션은 model-specific 프로세서 유효성 검사가 모델을 로드할 때 발생합니다. 이 체크는 이미지없이 요청에 적용됩니다.

네이티브 비전 인코딩 또는 embedding 재사용은 처리 된 이미지 레이아웃에 동의하는 token 카운트를 반환하면 요청은 텍스트 생성 전에 낙태됩니다. 채팅 완료 및 응답은 HTTP 500를 반환 InternalServerError 스트리밍 요청을 포함하여 JSON로, SSE 이벤트를 전송하기 전에. 오프라인 통화는 수신됩니다 MultimodalTokenCountError (a RuntimeError); LLMEngine 그것을 전달합니다 step(), 그리고 AsyncLLMEngine 반복 중에 발생 generate().

See 도케니저 API tokenization-specific 행동 및 Multi-Turn 대화 저장된 대화를 가진 선택권 취급을 위해.

UUID를 사용하여 다중 모달 입력을 캐싱#

이미지는 내용에 의해 자동적으로 해져지고, 그들의 가공한 결과는 조차 때 아무 때도 시동됩니다 uuid 공급됩니다. 반복 된 이미지는 캐시 된 결과를 재사용 할 수 있으며 pre-processing를 건너 뛸 수 있으며 processor-bound 체크인에 따라 달라질 수 있습니다. 멀티모달 옵션.

그 결과 prompt의 독립적 인 이미지 처리 출력이 포함되어 있습니다. 나중에 prompt의 다른 위치에서 다른 텍스트 또는 다른 위치로 이미지를 재사용 할 수 있습니다. 각 요청은 여전히 이미지 홀더를 검증하고 상황에 따라 확장 할 수 있습니다. 이미지가 이전 응답을 재사용하지 않습니다.

사전 처리 캐시가 놓은 후, 서버는 재사용 가능한 인코딩 된 embeddings를 검사하기 전에 공급 된 이미지를 다시 처리합니다. 자동 재처리는 요청에 다른 이미지로 변경할 수 있습니다. 인코딩 된 embeddings는 미디어 ID, 공급 된 프로세서 옵션, 처리 된 픽셀 및 레이아웃 일치 할 때만 재사용됩니다. UUID없이 또는이 적용됩니다.

각 이미지를 안정시킬 수 있습니다. uuid 이미지를 다시 보류하지 않고 follow-up 요청에 대한 캐시 된 결과를 참조하십시오. UUIDs는 추가 검색 메커니즘을 제공합니다. UUID가 캐싱을 선택하지 않도록 설정하십시오.

Add uuid 그 옆에 image_url 내용에 대해서는:

{
  "type": "image_url",
  "image_url": {"url": "https://example.com/receipt.png"},
  "uuid": "receipt-2026-05-01-abc"
}

follow-up는 이미지 바이트를 올릴 수 있습니다 ("image_url": null) 및 업로드에 대한 참조 uuid 혼자:

{
  "type": "image_url",
  "image_url": null,
  "uuid": "receipt-2026-05-01-abc"
}

UUID 및 효과적인 프로세서 옵션에 대한 재사용 가능한 항목이 존재하지 않는 경우 (예를 들어, 알 수없는 UUID, 비활성, 변경 옵션 또는 요청된 경계 밖에 항목), 서버 re-runs pre-processing image_url 또한 공급됩니다; 그렇지 않으면 HTTP 400를 반환합니다 unknown multimodal uuid, 그리고 클라이언트는 이미지로 붙어 있어야 합니다. UUID-only 참고는 또한 fetching를 건너갑니다; URL를 아직도 fetches 공급하고 처리 캐시를 검사하기 전에 이미지를 삭제하십시오. 따로 잇기 외침은 사용할 수 있습니다 multi_modal_uuids 는 동일한 재사용 동작 [을 갖습니다 (자세한 내용은 다음 참조)] 오프라인 API 아래와 같다).

캐시 용량은 [제어] --mm-processor-cache-gb (전기적으로) 4.0, 0 preprocessing caching를 비활성화합니다. 캡은 전체 서버 메모리에 있는 preprocessing 입력에서 픽셀 버퍼를 계산합니다. least-recently-used 항목은 캐시가 가득하다가 배제됩니다. 암호화 된 embeddings은 별도의 수명을 가지고 있으며, 사전 처리 배제 후 또는 사전 처리 캐시가 비활성화되면 여전히 재사용 할 수 있습니다. UUID-만 요청은 레지던트 사전 처리 입력이 필요합니다. 복제 된 embedding은 그 자체로 만족시킬 수 없습니다. 캐시 및 UUID 매핑은 프로세스에 로컬이며 휴식에서 재설정됩니다.

Python 예제#

OpenAI Python 클라이언트를 사용하여 Furiosa-LLM 서버:

"""
OpenAI-Compatible Server - Vision-Language Chat Completion Example

Sends a chat-completion request containing an image and a text prompt
to a running Furiosa-LLM server.

The image URL below is hosted on the Furiosa developer documentation
site and is intended to be stable. For other image-input forms (base64
``data:`` URLs and local ``file://`` paths), see the Vision-Language
Models documentation page.
"""

import os

from openai import OpenAI

base_url = os.getenv("OPENAI_BASE_URL", "http://localhost:8000/v1")
api_key = os.getenv("OPENAI_API_KEY", "EMPTY")
client = OpenAI(base_url=base_url, api_key=api_key)

IMAGE_URL = "https://developer.furiosa.ai/latest/en/_images/Furiosa_RNGD_image.png"

response = client.chat.completions.create(
    model=client.models.list().data[0].id,
    messages=[
        {
            "role": "user",
            "content": [
                {"type": "image_url", "image_url": {"url": IMAGE_URL}},
                {"type": "text", "text": "Describe this image in one short sentence."},
            ],
        }
    ],
    max_completion_tokens=32,
    temperature=0.0,
)

print(response.choices[0].message.content)

오프라인 API#

동일한 이미지 입력은 오프라인으로 허용됩니다. LLM / LLMEngine API를 통해 multi_modal_data prompt dict에 필드. modality에 의해 키 PIL 이미지를 전달:

from PIL import Image
from furiosa_llm import LLM, SamplingParams

image = Image.open("photo.png")
prompts = [
    {
        "prompt": "<|vision_start|><|image_pad|><|vision_end|>Describe this image.",
        "multi_modal_data": {"image": [image]},
        "mm_processor_kwargs": {"min_pixels": 4096},
    }
]

with LLM(
    "Qwen/Qwen3-VL-32B-Instruct",
    fxb="/path/to/qwen3-vl-32b.fxb",
    mm_processor_kwargs={"min_pixels": 1024},
) as llm:
    outputs = llm.generate(prompts, SamplingParams(max_tokens=64))
    print(outputs[0].outputs[0].text)

LLM(mm_processor_kwargs=...) 프로세서 기본값을 설정합니다. 각 prompt mm_processor_kwargs 같은 기본을 overrides 프로세서 병합 규칙 을 사용합니다. 예시 min_pixels=4096 이 prompt를 위해. 따로 잇기 외침은 이미지를, 이렇게 분리했습니다 media_io_kwargs 오프라인으로 연결되지 않습니다. LLM 선택의 여지가 있습니다.

Content-based 캐싱 및 UUID 참조 UUID를 사용하여 다중 모달 입력을 캐싱 위의 오프라인 API를 통해 사용할 수 있습니다. 추가 multi_modal_uuids 옆으로 multi_modal_data, 동일한 순서로; 다음을 전달 None UUID 참조가 필요하지 않은 항목에 대한. 이러한 항목은 여전히 content-based 캐싱에 참여합니다.

각 modality의 UUID 목록은 이미지 목록으로 많은 항목으로 정확히해야합니다. bare UUID 문자열은 단일 이미지로도 허용됩니다. UUID를 반복하면 prompt의 각 발생률을 유지합니다. 각 발생시 해당 이미지 홀더를 제공하므로 동일한 캐시 결과를 재사용 할 수 있습니다.

예를 들어:

prompts = [
    {
        "prompt": "<|vision_start|><|image_pad|><|vision_end|>Describe this image.",
        "multi_modal_data": {"image": [image]},
        "multi_modal_uuids": {"image": ["receipt-2026-05-01-abc"]},
    }
]

follow-up prompt는 이미지와 참조를 혼자 UUID에 의해 - 통과 할 수 있습니다 None 이 multi_modal_data 슬롯:

followup = [
    {
        "prompt": "<|vision_start|><|image_pad|><|vision_end|>Translate to Korean.",
        "multi_modal_data": {"image": [None]},
        "multi_modal_uuids": {"image": ["receipt-2026-05-01-abc"]},
    }
]
