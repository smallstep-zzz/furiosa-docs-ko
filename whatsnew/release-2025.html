Furiosa SDK 2025.3.1 베타3 (2025-08-25)#

2025.3.1 릴리스는 미성년자 업데이트이지만 몇 가지 중요한 새로운 기능을 소개합니다. 이 기능은 Furiosa-LLM frontend에 추가되기 때문에, 그들은 어떤 끊는 변화를 소개하지 않습니다. 이 릴리스는 또한 버그 수정의 수를 포함합니다.

참고: FuriosaAI 소프트웨어 업그레이드 이 업데이트를 얻기에 대한 지침에 대한 섹션.

⁇ 주요 내용#

기능 및 개선 사항#

  • 평균 throughput, KV cache 사용 및 running/waiting 요청의 로그를 정기적으로 인쇄하십시오.

  • 더 많은 생산 미터 (running/waiting 요청, 총 KV cache 및 사용)를 통해 노출 /metrics 끝점

  • Qwen 2.5 0.5B/1.5B와 같은 작은 LLMs의 컴파일 오류를 수정합니다.

  • 같은 Python 해석기에서 runtime 여러 번 초기화 할 때 발생하는 버그를 수정합니다.

  • 지원 tool_choice: "required" and tool_choice : 이름이 지정된 함수와 함께.

  • 구조화된 출력을 지원합니다. guided_choice, guided_regex, guided_json, 그리고 guided_grammar ( 참조) 구조화된 출력).

  • 기본 가이드 디코딩 백엔드로 llguidance를 추가합니다.

  • NPU 프로그램의 세트를 하나의 zip 파일로 묶습니다.

  • fine-tuned 모델을 할당하고 빌드 할 수 있습니다.

확장된 모델 지원#

  • 추가 Qwen 2.5 제품군 모델에 대한 지원 추가:

    • Qwen2.5-32B-Instruct

    • Qwen2.5-Coder-14B-Instruct

⁇ 변화 를 끊는 것#

  • 전혀 변경 사항 없음

Furiosa SDK 2025.3.0 베타3 (2025-08-04)#

2025.3.0 릴리스는 주로 inter-chip 10sor 병렬 및 성능 최적화에 초점을 맞추고 있습니다. 이 노력은 Llama 3.1 70B의 최대 3x throughput 증가를 포함하여 극적인 성능 개선으로 결과졌습니다. first-token latency의 latency의 3.1 8XQXQ 8XQXQXQ8XQ8XQ8XQ8XQ8XQ8XQ8XQ8XQ8XQ8XQ8XQ8XQ8XQ8XQ8XQ8XQ8XQ8XQ8XQ8XQ8XQ8XQ8XQ8XQ8XQ8XQ8XQ8XQ8XQ8XQ8XQ8XQ8XQ8XQ8XQ8XQ8XQ8XQ8XQ8XQ8XQ8XQ8XQ8XQ8XQ8XQ8XQ8XQ8X

참고: FuriosaAI 소프트웨어 업그레이드 이 업데이트를 얻기에 대한 지침에 대한 섹션.

⁇ 주요 내용#

주요 기능 및 개선 사항#

  • Inter-chip 텐서 병렬 처리

    • 여러 NPU 카드에 걸쳐 Tensor 병렬은 이제 공식적으로 지원되며 큰 모델의 효율적인 스케일링을 가능하게하고 throughput를 크게 개선했습니다.

    • 성능을 극대화하려면, 이 기능은 다음과 같은 주요 최적화에 의해 백업됩니다: peer-to-peer (P2P) 통신, 고급 통신 스케줄링 및 compiler 전술에 대한 최적화 된 PCIe 경로는 계산과 inter-chip DMA.

  • Compiler 및 Runtime 최적화

    • 향상된 글로벌 Compiler 최적화 : Furiosa compiler의 글로벌 최적화 기능은 변압기 블록 사이에 SRAM 재사용을 극대화하기 위해 향상된 기능입니다. 이 메모리 액세스 latency를 감소시키고 전반적인 throughput를 높입니다.

    • Runtime 최적화: 더 이상 호스트와 NPU 사이의 방해를 줄이기 위해 runtime를 최적화, 장치 전체에 동기화를 개선, 연속 디코딩 단계 사이의 오버 헤드를 최소화.

주요 성능 특징#

이 릴리스의 최적화는 이전 릴리스 2025.2와 비교된 다음 성능 개선을 수 있습니다.

  • Llama 3.1 8B: 4.5% 평균 throughput 개선 및 55 % 평균 감소 Time-to-First-Token (TTFT).

  • Llama 3.1 70B: 최대 3x 평균 throughput 개선 및 35 % 평균 감소 Time-to-First-Token (TTFT).

  • 실험 구성은 다음과 같습니다:

    • 입력 길이: 1k ~ 12k

    • 출력 길이: 128 ~ 10k

    • 배트 크기는: 1 ~ 128

확장된 모델 지원#

  • 새로운 모델 가족 : Qwen 2 및 2.5 모델 (e.g.,에 대한 추가 지원 Qwen2.5-Coder-32B-Instruct).

  • 새로운 Quantization 지원: W8A16 quantization (e.g를 위한 추가 지원., Llama-3.3-70B-Instruct-INT8).

  • 새로운 pre-compiled artifacts는 유효합니다 Hugging Face 허브:

    • EXAONE-3.5-32B-Instruct

    • DeepSeek-R1-Distill-Llama-70B

    • Llama-3.3-70B-Instruct

    • Llama-3.3-70B-Instruct-INT8

    • Qwen2.5-Coder-32B-Instruct

  • 더 긴 콘텍스 길이: 모든 pre-compiled artifacts에 Hugging Face 허브 이제 최대 32k 토큰의 컨텍스트 길이를 지원합니다.

⁇ 변화 를 끊는 것#

  • SDK 2025.2.0는 2025.3.x로 건축된 artifacts를 적재할 수 없습니다. 2025.3.x로 건축된 artifact를 사용하거나 새로운 SDK로 모형을 다시 재건하십시오.

  • furiosa-mlperf는 deprecated이고 이 방출에서 제거됩니다. 다른 벤치 마크 도구를 사용하시기 바랍니다 vLLM 기준 or LLMPerf.

Furiosa SDK 2025.2.0 베타2 (2025-04-25)#

RNGD SDK 2025.2.0은 광범위한 새로운 기능 및 상당한 개선 사항을 제공하는 네 번째 주요 릴리스입니다. 여기에는 추론 모델, 메트릭 엔드포인트, 챗 API, Hugging Face 허브, abort() API 및 덩크된 prefill 기능의 지원이 포함됩니다. 이 릴리스는 Hugging Face 허브에서 bfloat16, float16 및 float32 모델을 직접 구축할 수 있도록 합니다. quantization 단계를 거치지 않고도 가능합니다. 또한, Hugging Face 허브에서 사전 컴파일된 모델 아티팩트가 이제 제공되므로, 직접 구축할 필요 없이 즉시 사용할 수 있습니다.

참고: FuriosaAI 소프트웨어 업그레이드 이 업데이트를 얻기에 대한 지침에 대한 섹션.

⁇ 주요 내용#

  • 지원 추가 stream_options.include_usage in OpenAI 호환 서버.

  • 소개 LLM.chat() API 지원 chat-based 모델 (보기 채팅 예제, 도구 호출 가이드).

  • Mitigate out-of-memory 문제의 기본 값 설정 spare_block_ratio=0 in OpenAI 호환 서버.

  • 중복 버킷에 의한 버그 수정 furiosa-llm.

  • 지원 추가 /v1/models and /v1/models/{model_id} 최종점 furiosa-llm ( 참조) 모델 최종점).

  • 지원 추가 /version 최종점 OpenAI 호환 서버 ( 참조) 버전 최종점).

  • 실행의 중단을 방지하는 버그 수정 OpenAI 호환 서버. by Ctrl+C.

  • chunked prefill 기능 추가 furiosa-llm ( 참조) ⁇ ⁇ ⁇ ⁇ ).

  • quantization 단계 없이 bfloat16/float16/float32 모델의 직접적인 건물을 사용 (see 오토B플로트16 캐스트).

  • reasoning model parser에 대한 지원 추가 OpenAI 호환 서버 ( 참조) 논리적 지원).

  • LLM API, furiosa-mlperf, furiosa-llm serve 이제 Hugging Face 허브에서 로딩 아트팩트를 지원합니다.

  • 지원 추가 npu_queue_limit 선택 사항 furiosa-llm serve NPU queue 제한을 구성하려면 명령을 지정합니다.

  • furiosa-llm 는 이제 Python, 3.11 및 3.12를 지원합니다.

  • NPU DRAM 스택 사용 최적화 furiosa-llm.

  • 지원 Ubuntu 24.04 (Noble Numbat).

  • 그룹을 제거 furiosa Linux 시스템에 NPU 장치에 액세스 할 수 있습니다.

  • Pre-compiled 모델은 Hugging Face 허브에서 사용할 수 있습니다.

  • 지원 추가 abort() in LLMEngine and AsyncLLMEngine API.

  • 메트릭 엔드포인트에 대한 지원 추가 (/metrics)은 관리 구성 요소의 상태를 모니터링하는 데 사용됩니다. OpenAI 호환 서버 ( 참조) 매트릭스 최종점).

  • Furiosa-LLM에서 sampling 매개 변수 "logprobs" 지원 (보기 SamplingParams 클래스).

  • 컨테이너 실행 시간 (e.g., docker, containerd 및 crio)에 대한 컨테이너 장치 인터페이스 (CDI)에 대한 지원 추가 (참고 컨테이너 지원).

Furiosa SDK 2025.1.0 베타1 (2025-02-24)#

2025.1.0는 RNGD를 위한 제 3의 중요한 SDK 방출입니다. 이 방출은 뜻깊은 LLM latency 최적화, tool-calling 지원, 콘테이너 환경을 위한 장치 remapping 지원, 명령 선 공구 개선 및 버그 수정을 포함하여 많은 새로운 특징 및 뜻깊은 개선을 포함합니다.

참고: FuriosaAI 소프트웨어 업그레이드 이 업데이트를 얻기에 대한 지침에 대한 섹션.

⁇ 주요 내용#

  • LLM Latency 최적화 (11.66% TTFT까지, 30k 입력, 1k 산출을 위한 11.45% TPOT 개선)

  • Furiosa-LLM에 있는 지원 Tool-calling (도구 호출)

  • 장치 재매핑 지원 (e.g., /dev/rngd/npu2pe0-3 -> /dev/rngd/npu0pe0-3) 컨테이너

  • 새로운 명령줄 도구를 추가 furiosa-llm build 쉽게 Hugging Face 모델에서 artifact를 구축하기 (모델 아티팩트 구축)

  • 일정한 배치 스케줄링 버그를 수정하여 일정한 길이와 일괄 크기로 발생하는

  • 최대 KV-cache 메모리 할당의 자동 구성

  • runtime 메모리 할당에서 파편 감소

  • 허락해 furiosa-mlperf 지정하는 명령 pipeline_parallel_size and data_parallel_size

  • Add --allowed-origins 주장 furiosa-llm serve (오픈AIS 서버)

  • Fix trust_remote_code furiosa-llm에서 발생하는 버그 지원

  • Min-p 샘플링을 지원하는 SamplingParams (SamplingParams 클래스)

  • 허락해 npu:X 또한 npu:X:* in devices 선택

    • e.g., furiosa-llm serve ./model --devices "npu:0"

  • furiosa-mlperf 명령 지원 npu_queue_limit, spare_blocks_ratio, 성능을 최적화 할 수 있도록

⚠️ 폐지 및 예정된 변경 사항#

  • LLM.from_artifacts() API는 2025.2.0 릴리스에서 나타날 것입니다. 사용하시기 바랍니다 LLM.load_artifact() 대신 (LLM급).

⁇ 변화 를 끊는 것#

  • --model 선택 사항 furiosa-llm serve 위치의 인수가 됩니다. 사용하시기 바랍니다 furiosa-llm serve <model> 그 대신 furiosa-llm serve --model <model>. (오픈AIS 서버)

Furiosa SDK 2024.2.0 베타0 (2024-12-23)#

2024.2.0는 RNGD를 위한 두번째 중요한 SDK 방출입니다. 이 방출은 새로운 모형 지원을 포함하여 많은 새로운 특징 및 뜻깊은 개선, 최대 8k의 컨텍스트 길이를 위한 지원, Tensor 평행선을 위한 지원, PyTorch 2.4, 최적 API 및 다수 성과 개선을 포함합니다.

참고: FuriosaAI 소프트웨어 업그레이드 이 업데이트를 얻기에 대한 지침에 대한 섹션.

⁇ 주요 내용#

  • 새로운 모델 지원: 태양, EXAONE-3.0, CodeLLaMA2, Vicuna

  • LLaMA 3.1와 같은 모델에서 최대 8k 컨텍스트 길이 지원

  • 텐서 병렬 처리 지원 (tensor_parallel_size <= 8)

  • PyTorch 2.4.1 지원

  • Transformers 4.44.2 지원

  • Furiosa-LLM
    • ArtifactBuilder API 및 CLI 도구 (refer to 인공물 제작자)

      • 사용자는 Huggingface 변압기 호환 API를 가진 Huggingface 허브 모형에서 artifacts를 건설할 수 있습니다

    • Huggingface 변압기 호환 API 지원 (furiosa_llm.optimum)

      • AutoModel, AutoModelForCausalLM, AutoModelForQuestionAnswering API

      • QuantizerForCausalLM API 캘리브레이션 및 quantization 지원

    • LLMEngine, vLLM와 호환되는 AsyncLLMEngine API 지원

  • LlamaForCausalLM을 기반으로 모델의 20% 성능 향상

    • e.g., 3580 tokens/sec LLaMA 3.1 8B 모델 단일 RNGD 카드

⁇ 변화 를 끊는 것#

  • LLM.from_artifacts () API는 deprecated되었습니다. 대신 LLM.load_artifacts ()를 사용하십시오.

  • 2024.1.x는 2024.2.x와 호환되지 않습니다. 2024.2.x에서 내장 된 artifact를 사용하십시오.
