Furiosa SDK 2025.3.1 베타3 (2025-08-25)#

2025.3.1 버전은 주요 기능이 추가된 미미한 업데이트이지만, 이러한 기능은 Furiosa-LLM 프론트엔드에 추가되어 호환성 문제를 일으키지 않습니다. 이 릴리스에는 여러 버그 수정도 포함되어 있습니다.

이 업데이트를 얻는 방법에 대한 지침은 "FuriosaAI 소프트웨어 업그레이드" 섹션을 참조하십시오.

🚀 주요 기능#

기능 및 개선 사항#

  • 평균 처리량, KV 캐시 사용량, 그리고 실행/대기 요청의 로그를 주기적으로 출력합니다.

  • /metrics 엔드포인트를 통해 더 많은 프로덕션 메트릭 (실행/대기 요청, 총 KV 캐시 및 사용량)을 노출합니다.

  • Qwen 2.5 0.5B/1.5B와 같은 작은 LLM의 컴파일 오류를 수정합니다.

  • 동일한 Python 인터프리터에서 여러 번 런타임을 초기화할 때 발생하는 버그를 수정합니다.

  • 지원 tool_choice: "required" and tool_choice : 이름이 지정된 함수와 함께.

  • guided_choice, guided_regex, guided_json, guided_grammar 등을 사용하여 구조화된 출력을 지원합니다 (구조화된 출력 참조).

  • 기본적으로 llguidance를 디코딩 백엔드로 사용합니다.

  • 여러 개의 NPU 프로그램을 하나의 ZIP 파일로 묶습니다.

  • 미세 조정된 모델을 양자화하고 빌드할 수 있도록 합니다.

모델 지원 확장#

  • 추가 Qwen 2.5 모델 지원 추가:

    • Qwen2.5-32B-Instruct

    • Qwen2.5-Coder-14B-Instruct

🚨 주요 변경 사항#

  • 변경 사항 없음

Furiosa SDK 2025.3.0 베타3 (2025-08-04)#

2025.3.0 버전은 주로 칩 간 텐서 병렬 처리 및 성능 최적화에 중점을 둡니다. 이러한 노력을 통해 Llama 3.1 70B의 처리량은 최대 3배 증가하고, Llama 3.1 8B의 첫 번째 토큰 지연 시간은 최대 55% 감소하는 등 상당한 성능 개선이 이루어졌습니다. 이 버전에서는 Qwen 2 및 2.5 모델, W8A16 양자화 지원도 추가합니다.

이 업데이트를 얻는 방법에 대한 지침은 "FuriosaAI 소프트웨어 업그레이드" 섹션을 참조하십시오.

🚀 주요 기능#

주요 기능 및 개선 사항#

  • 칩 간 텐서 병렬 처리

    • 여러 개의 NPU 카드에 걸쳐 텐서 병렬 처리가 공식적으로 지원되면서, 대규모 모델의 효율적인 확장 및 상당한 성능 향상이 가능합니다.

    • 성능 극대화를 위해 다음과 같은 핵심 최적화가 적용됩니다: * P2P (Peer-to-Peer) 통신을 위한 최적화된 PCIe 경로 * 고급 통신 스케줄링 * 칩 간 DMA (Direct Memory Access)를 계산과 겹치는 컴파일러 전략

  • 컴파일러 및 런타임 최적화

    • 향상된 전역 컴파일러 최적화: Furiosa 컴파일러의 전역 최적화 기능이 트랜스포머 블록 간 SRAM 재사용을 극대화하도록 개선되었습니다. 이를 통해 메모리 접근 지연 시간을 줄이고 전반적인 처리량을 향상시킵니다.

    • 런타임 최적화: 호스트와 NPU 간의 간섭을 줄이고, 장치 간 동기화를 개선하며, 연속적인 디코딩 단계 간 오버헤드를 최소화하여 런타임을 더욱 최적화했습니다. (Runtime Optimization: Further optimized the runtime by reducing interference between the host and NPU, improving synchronization across devices, and minimizing overhead between consecutive decoding steps.)

성능 향상#

이번 릴리스의 최적화는 이전 버전 2025.2에 비해 다음과 같은 성능 개선을 제공합니다:

  • Llama 3.1 8B: 평균 처리량에서 최대 4.5% 향상 및 첫 번째 토큰 생성 시간(TTFT)에서 최대 55% 감소.

  • Llama 3.1 70B: 평균 처리량에서 최대 3배 향상 및 첫 번째 토큰 생성 시간(TTFT)에서 최대 35% 감소.

  • 실험 설정은 다음과 같습니다:

    • 입력 길이: 1k ~ 12k

    • 출력 길이: 128 ~ 10k

    • 배치 크기: 1 ~ 128

모델 지원 확장#

  • 새로운 모델 패밀리: Qwen 2 및 2.5 모델 지원 추가 (예: Qwen2.5-Coder-32B-Instruct)

  • 새로운 양자화 지원: W8A16 양자화 지원 추가 (예: Llama-3.3-70B-Instruct-INT8)

  • 새로운 사전 컴파일된 아티팩트는 Hugging Face Hub에서 제공됩니다:

    • EXAONE-3.5-32B-Instruct

    • DeepSeek-R1-Distill-Llama-70B

    • Llama-3.3-70B-Instruct

    • Llama-3.3-70B-Instruct-INT8

    • Qwen2.5-Coder-32B-Instruct

  • 더 긴 컨텍스트 길이: Hugging Face Hub에 있는 모든 사전 컴파일된 아티팩트는 이제 최대 32k 토큰의 컨텍스트 길이를 지원합니다.

🚨 주요 변경 사항#

  • SDK 2025.2.0은 2025.3.x로 빌드된 아티팩트를 로드할 수 없습니다. 2025.3.x로 빌드된 아티팩트를 사용하거나, 새로운 SDK로 모델을 다시 빌드하십시오.

  • furiosa-mlperf는 더 이상 사용되지 않으며, 이 릴리스에서 제거되었습니다. vLLM benchmark 또는 LLMPerf와 같은 다른 벤치마크 도구를 사용하십시오.

Furiosa SDK 2025.2.0 베타2 (2025-04-25)#

RNGD SDK 2025.2.0은 네 번째 주요 릴리스이며, 추론 모델 지원, 메트릭 엔드포인트, 채팅 API, Hugging Face Hub, abort() API, 그리고 분할된 사전 채우기 기능 등 다양한 새로운 기능과 상당한 개선 사항을 제공합니다. 이 릴리스는 Hugging Face Hub에서 직접 bfloat16, float16, float32 모델을 생성할 수 있도록 지원합니다. 또한, Hugging Face Hub에서 사전 빌드된 모델 아티팩트가 제공되므로, 직접 빌드할 필요 없이 즉시 사용할 수 있습니다.

이 업데이트를 얻는 방법에 대한 지침은 "FuriosaAI 소프트웨어 업그레이드" 섹션을 참조하십시오.

🚀 주요 기능#

  • OpenAI-Compatible Server에서 stream_options.include_usage를 지원하도록 추가합니다.

  • 채팅 기반 모델을 지원하기 위해 LLM.chat() API를 도입합니다 (채팅 예제, 도구 호출 가이드 참조).

  • Mitigate out-of-memory 문제의 기본 값 설정 spare_block_ratio=0 in OpenAI 호환 서버.

  • furiosa-llm에서 중복된 버킷으로 인한 버그를 수정합니다.

  • /v1/models 및 /v1/models/{model_id} 엔드포인트에 대한 지원을 furiosa-llm에 추가 (참조: Models Endpoint).

  • 지원 추가 /version 최종점 OpenAI 호환 서버 ( 참조) 버전 최종점).

  • 실행의 중단을 방지하는 버그 수정 OpenAI 호환 서버. by Ctrl+C.

  • furiosa-llm에 덩어리별 사전 채우기 기능을 추가 (참조: ChunkedPrefill).

  • 양자화 단계를 거치지 않고 bfloat16/float16/float32 모델을 직접 빌드할 수 있도록 AutoBfloat16Cast 기능을 활성화 (참조: AutoBfloat16Cast).

  • reasoning model parser에 대한 지원 추가 OpenAI 호환 서버 ( 참조) 논리적 지원).

  • LLM API, furiosa-mlperf, furiosa-llm serve 이제 Hugging Face 허브에서 로딩 아트팩트를 지원합니다.

  • furiosa-llm serve 명령에 npu_queue_limit 옵션을 추가하여 NPU 큐 제한을 구성할 수 있습니다.

  • furiosa-llm은 이제 Python 3.11 및 3.12를 지원합니다.

  • furiosa-llm의 NPU DRAM 스택 사용을 최적화합니다.

  • Ubuntu 24.04 (Noble Numbat)를 지원합니다.

  • Linux 시스템에서 NPU 장치에 액세스하기 위해 furiosa 그룹을 제거합니다.

  • 사전 컴파일된 모델 아티팩트가 이제 Hugging Face Hub에서 사용 가능합니다.

  • LLMEngine 및 AsyncLLMEngine API에 abort() 기능 지원을 추가합니다.

  • OpenAI 호환 서버의 상태를 모니터링하는 데 사용되는 /metrics 엔드포인트에 대한 지원을 추가합니다 (Metrics Endpoint 참조).

  • Furiosa-LLM에서 "logprobs" 샘플링 매개변수에 대한 지원을 추가합니다 (SamplingParams 클래스 참조).

  • 컨테이너 런타임(예: docker, containerd, crio)에 대한 컨테이너 장치 인터페이스 (CDI) 지원을 추가합니다 (Container Support 참조).

🚨 주요 변경 사항#

  • SDK 2025.2.0은 2025.1.x로 빌드된 아티팩트를 로드할 수 없습니다. 2025.2.x로 빌드된 아티팩트를 사용하거나, 새로운 SDK로 모델을 다시 빌드하십시오.

  • Furiosa 그룹은 이제 Linux 시스템에서 NPU 장치를 액세스할 필요가 없습니다. (더 이상 NPU 장치에 직접 접근할 필요가 없음)

Furiosa SDK 2025.1.0 Beta1 (2025-02-24)#

2025.1.0은 RNGD용의 세 번째 주요 SDK 릴리스입니다. 이 릴리스에는 상당한 LLM 지연 최적화, Furiosa-LLM에서 도구 호출 지원, 컨테이너 환경에 대한 장치 재매핑 지원, 명령줄 도구 개선 및 버그 수정 등 많은 새로운 기능과 상당한 개선 사항이 포함되어 있습니다.

이 업데이트를 얻는 방법에 대한 지침은 "FuriosaAI 소프트웨어 업그레이드" 섹션을 참조하십시오.

🚀 주요 기능#

  • LLM 지연 최적화 (30,000 입력, 1,000 출력에 대해 최대 11.66% TTFT, 11.45% TPOT 개선)

  • Furiosa-LLM에서 도구 호출 지원 (Tool Calling)

  • 컨테이너 환경에 대한 장치 재매핑 지원 (예: /dev/rngd/npu2pe0-3 -> /dev/rngd/npu0pe0-3)

  • 새로운 명령줄 도구를 추가 furiosa-llm build 쉽게 Hugging Face 모델에서 artifact를 구축하기 (모델 아티팩트 구축)

  • 특정 시퀀스 길이 및 배치 크기 범위에서 발생하는 지속적인 배치 스케줄링 오류를 수정합니다.

  • 최대 KV-캐시 메모 할당 자동 구성

  • 런타임 메모 할당에서의 분할을 줄입니다.

  • furiosa-mlperf 명령에 pipeline_parallel_size 및 data_parallel_size를 지정할 수 있도록 합니다.

  • furiosa-llm serve (OpenAIServer)에 --allowed-origins 인수를 추가합니다.

  • furiosa-llm에서 trust_remote_code 지원 버그 수정

  • Min-p 샘플링을 지원하는 SamplingParams (SamplingParams 클래스)

  • devices 옵션에 npu:X 뿐만 아니라 npu:X:*도 허용

    • 예: furiosa-llm serve ./model --devices "npu:0"

  • furiosa-mlperf 명령이 npu_queue_limit, spare_blocks_ratio를 지원하여 성능 최적화 가능

⚠️ 주요 변경 사항 및 예정된 기능#

  • LLM.from_artifacts() API는 2025.2.0 릴리스부터 사용이 중단됩니다. 대신 LLM.load_artifact()를 사용하십시오 (LLM 클래스).

🚨 주요 변경 사항#

  • furiosa-llm serve 명령어의 --model 옵션이 위치 인수로 변경되었습니다. furiosa-llm serve <model>를 사용하십시오, 대신 furiosa-llm serve --model <model>를 사용하지 마십시오. (OpenAIServer)

Furiosa SDK 2024.2.0 Beta0 (2024-12-23)#

2024.2.0은 RNGD용의 두 번째 주요 SDK 릴리스입니다. 이 릴리스에는 새로운 모델 지원, 최대 8k 컨텍스트 길이 지원, 텐서 병렬 처리 지원, PyTorch 2.4, Optimum API, 그리고 여러 성능 개선 사항을 포함한 많은 새로운 기능과 상당한 개선 사항이 포함되어 있습니다.

이 업데이트를 얻는 방법에 대한 지침은 "FuriosaAI 소프트웨어 업그레이드" 섹션을 참조하십시오.

🚀 주요 기능#

  • 새로운 모델 지원: Solar, EXAONE-3.0, CodeLLaMA2, Vicuna

  • LLaMA 3.1과 같은 모델에서 최대 8k 길이의 컨텍스트 지원

  • 텐서 병렬 처리 지원 (tensor_parallel_size <= 8)

  • PyTorch 2.4.1 지원

  • Transformers 4.44.2 지원

  • Furiosa-LLM
    • ArtifactBuilder API 및 CLI 도구 (ArtifactBuilder 참조)

      • Huggingface Hub에 있는 모델에서 Huggingface Transformers 호환 API를 사용하여 아티팩트를 생성할 수 있습니다. (Huggingface Transformers 호환 API)

    • Huggingface Transformers 호환 API 지원 (furiosa_llm.optimum)

      • AutoModel, AutoModelForCausalLM, AutoModelForQuestionAnswering API 지원

      • QuantizerForCausalLM API를 사용하여 캘리브레이션 및 양자화를 지원

    • LLMEngine, AsyncLLMEngine API가 vLLM과 호환되도록 지원

  • LlamaForCausalLM 기반 모델에서 약 20%의 성능 향상

    • 예: LLaMA 3.1 8B 모델에서 단일 RNGD 카드로 3580 토큰/초

🚨 주요 변경 사항#

  • LLM.from_artifacts() API는 더 이상 사용되지 않습니다. 대신 LLM.load_artifacts()를 사용하십시오.

  • 2024.1.x 버전으로 생성된 아티팩트는 2024.2.x 버전과 호환되지 않습니다. 2024.2.x 버전으로 생성된 아티팩트를 사용하십시오.
