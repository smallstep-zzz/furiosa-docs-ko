Furiosa SDK 배포 2026.1#

이번 릴리스는 throughput, 효율성 및 확장성에 중점을 둔 주요 아키텍처 개선 사항을 제공합니다. 주요 기능으로는 고 throughput와 낮은 latency 사이의 균형을 맞추는 하이브리드 Batching, 다중 턴 애플리케이션에서 latency를 줄이는 데 사용되는 Prefix Caching, 그리고 포털 모델(임베딩, 점수, Reranking)에 대한 포괄적인 지원 등이 있습니다. 또한, PCIe 토폴로지 기반 전략을 사용하여 분산된 inference 기능을 활용하여 생산 준비성을 향상시켰습니다. LLM-D, NPU 운영자, 동적 리소스 할당 (DRA) K8s 및 고급 관찰 기능에 대 한.

참고: FuriosaAI 소프트웨어 업그레이드 이 업데이트를 얻기에 대한 지침에 대한 섹션.

주요 기능 및 개선 사항#

  • 하이브리드 Batching

    • 단일 배치 내에서 여러 prefill 및 decode 요청을 지능적으로 결합하는 하이브리드 batching 기능을 도입했습니다.

    • 이 기능은 throughput를 향상시키고 낮은 꼬리 latency를 유지하면서 이전 버전과 비교하여 두 번째로 더 높은 요청을 달성합니다.

  • Prefix Caching

    • branch-compressed Radx 나무를 사용하여 요청에 따라 prompt prefixes를 자동으로 감지하고 재사용하여 중복 계산을 제거하십시오.

    • 시스템 프롬프트 및 RAG 시스템과 같은 채팅봇과 같은 공유된 컨텍스트와 애플리케이션에 이상적입니다.

    • SIMD-optimized 접두사 매칭 및 캐시 퇴치와 같은 Time-To-First-Token (TTFT)를 재현합니다.

    • Smart eviction 전략은 높은 캐시 히트율을 유지하면서 메모리 오버 헤드를 최소화 할 수 있습니다.

  • 풀링 모델 지원

    • 풀 모델에 대한 포괄적 인 지원을 추가하여 중요한 NLP 작업을 가능하게합니다.

      • Embeddings: semantic 검색에 대한 벡터 표현 생성 encode() and embed() API.

      • 점수: query-document 쌍 사이 굴절률 score() API

      • Reranking: 재주문 후보자에 의한 검색결과 개선 rerank() API

    • 포함 PoolingParams.normalize 정상적인 embedding 산출을 위한 지원.

    • 현재 지원 Qwen3-8B embedding 및 reranking 모델(향후 지원 확대를 계획)

  • 여러 백엔드와 구조 출력

    • Production-ready는 JSON 스키마 검증, 정규식 식 제약 및 Grammar-based 생성을 지원하는 출력 생성을 구조화했습니다.

    • 둘 다 포함됩니다 outlines and xgrammar 다양한 용도 케이스에 유연성과 성능을 제공합니다.

    • NPU 작업 실행 중 latency 감소를 위해 비트 마스크 prefetching와 최적화 된 가이드 디코딩.

  • 분산 및 확장 Inference 값 및

    • LLM-D (LLM 분산형): 여러 노드를 가로지르는 대형 언어 모델의 원활한 배포를 통해 지능적으로 처리 요청 여정을 처리할 수 있습니다.

      • 지원 KV-cache 사용 aware 여정, prefix-aware 여정, 및 LLM-aware 여정.

      • See LLM-D 문서 더 자세한 내용은

    • 동적 리소스 할당 (DRA): PCIe 토폴로지에 대한 인식을 바탕으로 NPU 리소스를 할당/해제하는 지능형 리소스 관리.

    • NPU 운영자 지원: 기본 NPU 통신 사업자 통합, 장치 검색, driver/fw 롤링 업그레이드 및 수명주기 관리와 함께 Kubernetes 환경을 포괄적 인 지원을 추가했습니다.

  • 향상된 관측 가능성

    • 향상된 성능과 향상된 오버 헤드를 위한 Rust Native 구현에 대한 Migrated 메트 수집.

    • per-device 메트릭, KV cache 활용, 요청 풀 통계 및 하이브리드 batching에 대한 상세한 스케줄러 로그를 포함하여 종합 계측이 추가되었습니다.

    • 통합 오픈텔레미트리 생산 환경을 위한 조용한 경간을 가진 지원.

    • 삶의 질을 향상시키고, 건강 모니터링 능력.

    • configurable Prometheus endpoint export를 기본으로 설정한다.

성능 및 효율성#

  • 최적화

    • Ahead-of-Time (AOT) 유선 파이프라인: 낮은 latency 작업 시작 및 감소된 runtime 오버헤드를 위한 사전 구성된 실행 그래프.

    • SIMD 최적화: prefix caching, Radx 나무의 지점 운영 및 기타 performance-critical 경로 디코딩 전략을 위한 호스트 runtime를 통해 적용.

      • Softmax, log-softmax 및 정상화 가동은 AVX-512 16-lane 벡터화로 가속했습니다 (f32x16, u16x16).

      • libmvec SIMD-optimized exponential 기능을 위한 통합은, 동적인 연결을 통해 적재했습니다.

      • 고유 bf16 (bfloat16)는 수치 정밀도를 위해 자동적인 f32로 지원합니다.

      • Runtime CPU는 non-AVX-512 체계를 위한 자동적인 사기그레이 fallback를 가진 탐지를 특색짓습니다.

    • 메모리 관리: 확장 가능한 버퍼 풀, 스마트 KV cache 할당 전략 및 긴 컨텍스트 모델에 관심있는 슬라이딩 창에 대한 효율적인 메모리 사용으로 개선되었습니다.

    • 파이프라인 로딩: next-gen Artifact 빌드에 대한 Ray-based 병렬화와 병렬화 파이프로드.

    • 따뜻 해 주세요: Warm-up 토큰화기 및 템플릿의 cold-start latency를 감소시키기 전에.

확장된 모델 및 Quantization 지원#

  • 새로운 모델 지원:

    • Qwen3 가족: 32B 변형 및 8B embedding/reranking 모델 지원

    • 엑소네4: 최대 128k 컨텍스트 길이, 비소주의, 슬라이딩 윈도우주의를 포함한 종합 지원

  • Quantization:

    • Fine-grained FP8 quantization 지원, DeepSeek-style 2D 블록 무게 quantization 및 per-token 그룹 활성화 quantization를 활성화.

API 및 사용성 개선#

  • 도구 호출 개선:

    • 지원 tool_choice="required", tool_choice="auto"도구에서 도구 선택 이름을 따서 API를 호출합니다.

  • Sampling 파라미터:

    • 추가 repetition_penalty 반복적인 출력을 제어하기 위한 기능.

    • 추가 return_token_ids token ID를 뒤집어 텍스트로 반환합니다.

    • 추가 skip_special_tokens 산출에 있는 특별한 token inclusion 통제를 위해.

    • 추가 ignore_eos end-of-sequence token 취급 우회를 위해.

    • 추가 stop_token_ids 사용자 정의 중지 기준을 설정합니다.

  • Prompt 로그 확률 지원:

    • 추가 prompt_logprobs prompt 토큰에 대한 로그 확률을 반환하는 매개 변수.

    • 모델의 신뢰와 token-level 예측을 분석하는 데 도움이.

  • 보안 및 인증:

    • API 키 인증 구축 --api-key 안전한 서버 액세스를 위한 인자.

  • 콘텐츠 형식 개선이 필요합니다.:

    • 지원 Harmony 응답 형식 token 계산을 적절한 이유를 가진 채팅 완료 API에서.

    • 지원 내용 부분 형식 채팅 완료에 multi-part 메시지를 위해.

🚨 주요 변경 사항 및 폐기#

  • 레거시 아티팩트 형식은 더 이상 사용되지 않습니다.:

    • Blockwise artifact 형식은 더 이상 지원되지 않습니다. 이주: 모든 artifacts는 새로운 ArtifactBuilder를 사용하여 재건해야합니다.

  • Python 버전 요구 사항:

    • 최소 Python 버전은 3.10+로 증가했습니다. 이주: 이 릴리스를 설치하기 전에 Python 3.10 또는 나중에로 업그레이드하십시오.

  • 변압기 및 PyTorch 라이브러리 업데이트:

    • 트랜스포머를 4.57.1로 업그레이드했습니다.

    • PyTorch를 2.7.1로 변경했습니다. 이주: 환경 지원 PyTorch 2.7.x.

  • Beam Search 지원 제거:

    • 빔 검색 디코딩은 LLM 엔진에서 제거되었습니다. 이주: top-k, top-p 또는 temperature sampling와 같은 sampling 기반 디코딩 방법을 사용합니다.

  • furiosa-pert-rngd 패키지를 제거:

    • The furiosa-pert-rngd 패키지가 제거되었습니다. PERT는 이제 runtime를 통해 장치에 동적로드되어 별도의 패키지 설치에 필요한 것을 제거합니다.

    • 이주: 참조 FuriosaAI 소프트웨어 업그레이드 세부사항을 알려주세요.
