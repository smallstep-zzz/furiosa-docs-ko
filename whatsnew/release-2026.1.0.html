Furiosa SDK 2026.1 릴리즈#

이번 릴리스는 throughput, 효율성 및 확장성에 중점을 둔 주요 아키텍처 개선 사항을 제공합니다. 주요 기능으로는 고 throughput와 낮은 latency 사이의 균형을 맞추는 하이브리드 Batching, 다중 턴 애플리케이션에서 latency를 줄이는 데 사용되는 Prefix Caching, 그리고 포털 모델(임베딩, 점수, Reranking)에 대한 포괄적인 지원 등이 있습니다. 또한, PCIe 토폴로지 기반 전략을 사용하여 분산된 inference 기능을 활용하여 생산 준비성을 향상시켰습니다. LLM-D, NPU 운영자, 동적 리소스 할당 (DRA) K8s 및 고급 관찰 기능에 대 한.

이 업데이트를 얻는 방법에 대한 지침은 "FuriosaAI 소프트웨어 업그레이드" 섹션을 참조하십시오.

🚀 주요 기능#

주요 기능 및 개선 사항#

  • 하이브리드 배치

    • 여러 프리필 및 디코딩 요청을 단일 배치 내에서 지능적으로 결합하는 하이브리드 배치 기능을 도입했습니다.

    • 이 기능은 낮은 지연 시간을 유지하면서 처리량을 크게 향상시켜 이전 버전보다 훨씬 더 많은 요청당 초당 처리량을 달성합니다.

  • 접두사 캐싱

    • 분기 압축된 래디스 트리를 사용하여 요청 간에 공통 프롬프트 프리픽스를 자동으로 감지하고 재사용하여 불필요한 계산을 제거합니다.

    • 시스템 프롬프트 및 RAG 시스템과 같이 공유 컨텍스트가 필요한 애플리케이션에 적합합니다.

    • SIMD 최적화된 프리픽스 매칭 및 캐시 제거를 통해 첫 번째 토큰 생성 시간을 크게 단축합니다.

    • 지능형 제거 전략은 유휴 시간을 활용하여 메모리 오버헤드를 최소화하면서 높은 캐시 히트율을 유지합니다.

  • 모델 풀링 지원

    • 핵심 자연어 처리 작업을 가능하게 하기 위해 모델 풀링에 대한 포괄적인 지원이 추가되었습니다:

      • 임베딩: encode() 및 embed() API를 사용하여 의미 검색을 위한 벡터 표현을 생성합니다.

      • 점수: query-document 쌍 간의 관련성을 score() API를 사용하여 평가합니다.

      • 재순위: rerank() API를 사용하여 검색 결과를 개선하기 위해 후보 항목의 순서를 재정렬합니다.

    • PoolingParams.normalize를 통해 정규화된 임베딩 출력 지원.

    • 현재 Qwen3-8B 임베딩 및 재순위 모델을 지원하며, 지원 범위를 확장할 계획입니다.

  • 다중 백엔드 기반의 구조화된 출력

    • JSON 스키마 유효성 검사, 정규 표현식 제약 조건, 문법 기반 생성 등 생산 환경에 적합한 구조화된 출력 생성 지원.

    • 둘 다 포함됩니다 outlines and xgrammar 다양한 용도 케이스에 유연성과 성능을 제공합니다.

    • NPU 작업 실행 시 지연 시간을 줄이는 비트마스크 사전 로딩을 활용한 최적화된 가이드 디코딩. (Optimized guided decoding with bitmask prefetching for reduced latency during NPU task execution)

  • 분산 및 확장 가능한 추론

    • LLM-D (LLM Distributed): 여러 노드에 걸쳐 대규모 언어 모델을 원활하게 배포하고, 요청 라우팅을 지능적으로 처리합니다.

      • KV-캐시 사용, 프리픽스 기반 라우팅, LLM 기반 라우팅을 지원합니다.

      • 자세한 내용은 LLM-D 문서를 참조하십시오.

    • 동적 리소스 할당 (DRA): PCIe 토폴로지 기반 전략에 따라 NPU 리소스를 할당/해제하는 지능적인 리소스 관리.

    • NPU 운영자 지원: Kubernetes 환경에 대한 포괄적인 지원을 추가했으며, NPU 운영자 통합, 장치 검색, 드라이버/펌웨어 롤링 업그레이드, 그리고 라이프사이클 관리를 처리합니다. (NPU Operator)

  • 향상된 관측성

    • 성능 향상 및 오버헤드 감소를 위해, 메트릭 수집을 Rust 네이티브 구현으로 마이그레이션했습니다.

    • 하이브리드 배치에 대한 포괄적인 측정 장치를 추가했습니다. 여기에는 장치별 메트릭, KV 캐시 활용률, 요청 풀 통계, 그리고 상세 스케줄러 로그가 포함됩니다.

    • 프로덕션 환경에 Quiet Span 필터링을 지원하는 OpenTelemetry 통합을 추가했습니다.

    • 라이브니스 체크 엔드포인트를 개선하고, 건강 모니터링 기능을 향상했습니다.

    • 기본적으로 활성화되는 지표, 설정 가능한 Prometheus 엔드포인트 내보내기 기능과 함께.

성능 및 효율성#

  • 최적화

    • 사전 구성된 워크플로우 (AOT): 낮은 지연 시간으로 작업 실행 및 실행 시간 오버헤드를 줄이기 위한 사전 구성된 실행 그래프.

    • SIMD 최적화: 호스트 런타임 전반에 걸쳐 적용, 디코딩 전략, 프리픽스 캐싱, 래디스 트리의 분기 연산 및 기타 성능에 중요한 경로에 사용.

      • AVX-512 16개의 라인 벡터화 (f32x16, u16x16)를 사용하여 Softmax, log-softmax, 및 정규화 연산 가속화.

      • SIMD-최적화된 지수 함수를 위한 libmvec 통합, 동적 링크를 통해 로드. (SIMD-최적화된 지수 함수, libmvec 통합)

      • f32로의 자동 확장과 함께 네이티브 bf16 (bfloat16) 지원, 수치적 정밀도를 위해. (네이티브 bf16 (bfloat16), 자동 f32 확장)

      • AVX-512 시스템이 아닌 경우, 자동 스칼라 대체 기능과 함께 런타임 CPU 기능 감지. (런타임 CPU 기능 감지, 자동 스칼라 대체)

    • 메모리 관리: 확장 가능한 버퍼 풀, 지능형 KV 캐시 할당 전략, 그리고 긴 컨텍스트 모델에서 슬라이딩 윈도우 어텐션에 대한 효율적인 메모리 사용으로 개선됨. (메모리 관리, 확장 가능한 버퍼 풀, 지능형 KV 캐시 할당 전략, 슬라이딩 윈도우 어텐션)

    • 파이프라인 로딩: Ray 기반 병렬화를 사용하여 차세대 아티팩트 빌드를 위한 병렬 파이프라인 로딩. (파이프라인 로딩, Ray 기반 병렬화)

    • 토크나이저 및 템플릿의 사전 워밍, 서비스 시작 시의 초기 지연 시간을 줄이기 위해. (사전 워밍, 토크나이저 및 템플릿)

확장된 모델 및 양자화 지원#

  • 새로운 모델 지원:

    • Qwen3 시리즈: 32B 모델 및 8B 임베딩/재랭킹 모델 지원.

    • Exaone4: 최대 128k 컨텍스트 길이, 희소 어텐션 및 슬라이딩 윈도우 어텐션 등 포괄적인 지원.

  • 양자화:

    • Fine-grained FP8 quantization 지원, DeepSeek-style 2D 블록 무게 quantization 및 per-token 그룹 활성화 quantization를 활성화.

API 및 사용성 개선#

  • 도구 호출 기능 강화:

    • Tool Calling API에서 tool_choice="required", tool_choice="auto", 그리고 이름으로 도구를 선택하는 기능을 지원합니다.

  • 샘플링 매개변수:

    • 반복적인 출력을 제어하기 위한 repetition_penalty를 추가했습니다.

    • 텍스트와 함께 토큰 ID를 반환하기 위한 return_token_ids를 추가했습니다.

    • 특별 토큰의 포함 여부를 제어하기 위한 skip_special_tokens 기능 추가.

    • 시퀀스 종료 토큰 처리를 우회하기 위한 ignore_eos 기능 추가.

    • 사용자 정의 중지 기준을 설정하기 위한 stop_token_ids 기능 추가.

  • 프롬프트 로그 확률 지원:

    • 프롬프트 토큰에 대한 로그 확률을 반환하기 위한 prompt_logprobs 매개변수 추가.

    • 모델의 신뢰도 분석 및 토큰 수준 예측에 유용.

  • 보안 및 인증:

    • 서버에 안전하게 접근하기 위한 --api-key 인수를 사용하여 API 키 인증을 구현했습니다.

  • 콘텐츠 형식 개선:

    • Chat Completions API에서 Harmony 응답 형식을 지원하며, 적절한 추론 토큰 계산을 수행합니다.

    • 챗 컴플리션에서 다중 메시지 파트를 위한 콘텐츠 파트 형식을 지원합니다.

🚨 주요 변경 사항 및 기능 제거#

  • 기존 아티팩트 형식 (Legacy Artifact Format) 은 더 이상 지원되지 않습니다:

    • 블록 단위 아티팩트 형식은 더 이상 사용되지 않습니다. 마이그레이션: 모든 아티팩트는 새로운 ArtifactBuilder를 사용하여 다시 빌드해야 합니다.

  • Python 버전 요구 사항:

    • 최소 Python 버전이 3.10 이상으로 변경되었습니다. 마이그레이션: 이 버전을 설치하기 전에 Python 3.10 또는 그 이상으로 업그레이드하십시오.

  • Transformer 및 PyTorch 라이브러리 업데이트:

    • transformers 버전이 4.57.1로 업그레이드되었습니다.

    • PyTorch를 2.7.1 버전으로 업그레이드했습니다. 마이그레이션: 환경이 PyTorch 2.7.x 버전을 지원하는지 확인하십시오.

  • Beam Search 지원을 제거했습니다:

    • LLM 엔진에서 Beam Search 디코딩 기능이 제거되었습니다. 마이그레이션: top-k, top-p, 또는 온도 샘플링과 같은 샘플링 기반 디코딩 방법을 사용하십시오.

  • furiosa-pert-rngd 패키지를 제거했습니다:

    • furiosa-pert-rngd 패키지가 제거되었습니다. PERT는 런타임을 통해 동적으로 장치에 로드되므로 별도의 패키지 설치가 필요하지 않습니다.

    • 마이그레이션: FuriosaAI 소프트웨어 업그레이드 방법에 대한 자세한 내용은 참조하십시오.
